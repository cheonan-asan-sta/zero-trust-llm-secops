# M6/C10 모델 비교 계약 초안

2026년 11월 9일 · v0.17.0 · **오프라인 모의 평가 실행기 구현, 실제 모델 비교 예정**.
설정 원본은 [JSON 계약](../infra/model-evaluation-contract.json)이다. 실행기는 개발 자료의 입력·출력 검증과 집계를 재현한다.

## 제로트러스트에서 맡길 일

모델은 이벤트 분류·우선순위와 근거 설명의 **관찰 전용 보조자**다. 수집기 서명·증명 권한·신선도·테넌트,
사용자/기기 매핑, 기존 정책, 허용의 만료·소비·회수는 기존 결정적 경로에서 확인한다.
모델 답·모델 간 동의·높은 확률로 허용을 발급하거나 회수된 세션을 복원하지 않는다.
실패·거절·시간 초과·형식 오류는 `unknown/abstain`으로 기록하며 정상으로 바꾸지 않는다.
평가용 요청에는 외부 도구·권한 변경·명령 실행 기능을 제공하지 않는다.

현재 `/analysis`의 선택적 생성형 분석과 ZT/PEP 경로는 별개다. 이 계약을 저장했다고
새 모델이 제품에 연동되거나 분류기의 확률이 정책 판단에 연결되지는 않는다.
앱의 기존 기본 모델 `gpt-5.4-mini`와 설정은 변경하지 않았다. 새 후보의 API 연동은 후속 작업이다.
개선 전 규칙·임계값·정규화와 720건 평가 결과는 그대로 둔다.

## 후보와 선정 가설

| 후보 | 비교 역할 | 이번 계약과 실행 전 조건 |
|---|---|---|
| 기존 rule | 변경하지 않는 기준선 | 같은 입력의 결과를 보존한다. 합성 자료의 기존 성능을 실제 기업 성능으로 일반화하지 않는다 |
| GPT-6.1 Sol `gpt-6.1-sol` | 생성형 기준 후보: 복합 근거 설명 | Responses API, reasoning `low` 초안. 공식 명세의 구조화 출력 지원을 활용하되 응답은 별도 검증한다 |
| Claude Sonnet 5.5 `claude-sonnet-5-5` | 타 공급자 생성형 대안 | 같은 입력·질문·출력 계약. 구체적 effort/출력 옵션의 지원 여부를 실행 전 확인하고 실제 옵션을 기록한다 |
| GPT-6 Luna `gpt-6-luna` | 저비용 분류/설명 추가 후보 | 필수 두 생성형 후보 다음에 예산이 남을 때만 실행한다. Responses API, reasoning `none` 초안 |
| TypeSafe Jev | typed choice 분류 후보 | 공식 예시의 `jev-1.13.0`은 사용 가능 여부 재확인 필요. `jev-latest`만으로 재현성을 주장하지 않는다. 요금·보존·버전이 미확인인 동안 호출 금지 |
| Laya | 로컬 typed decision 후보 | `convaiinnovations/laya`, revision `7b928d828b7b0e022f929d9bd2e44165aa270148`, `multilingual` 하위 폴더. 한국어/영어를 나눠 검증. 런타임·가중치 지문/사용권·자원 확인 전 설치/실행하지 않음 |
| TF-IDF + 로지스틱 회귀 | 단순 분류기의 효용 기준 | 개발 자료로만 학습/보정. 현재 새 실행기나 모델을 구현한 상태는 아님 |

Sol의 복합 업무 지원과 Luna의 비용 특성은 공급자 명세에 따른 **시험 가설**이며 우리 보안 자료에서의 우승 결과가 아니다.
공식 표준 텍스트 가격은 100만 토큰당 Sol 입력 $2/출력 $10, Luna 입력 $0.10/출력 $0.50이다.
실행일에 요금·지역/캐시/처리 방식·출력/추론 과금 범위를 재확인한다.
[Sol 명세](https://developers.openai.com/api/docs/models/gpt-6.1-sol),
[Luna 명세](https://developers.openai.com/api/docs/models/gpt-6-luna).

Sonnet은 공급자 간 품질·실패·지연 차이를 확인하는 후보다. 공식 목록의 API ID와 표준 입력 $2/출력 $10을
계약에 기록했으며 실제 보안 분류/설명 성능은 미측정이다.
[Anthropic 공식 모델 목록](https://platform.claude.com/docs/en/models/overview).

Jev는 상태와 typed question에서 값·확률을 반환하는 비생성형 모델이다. 생성형 보고서 작성 항목을 동일하게
요구하지 않는다. 공식 Quick start의 응답 버전은 예시이므로 실제 제공 버전 확인이 남아 있다.
[TypeSafe 소개](https://docs.typesafe.ai/introduction), [Quick start](https://docs.typesafe.ai/introduction/quickstart).

Laya의 루트는 영어 체크포인트이고 다국어 체크포인트는 하위 폴더다. 모델 카드의 Apache-2.0과
다국어 지원은 후보 적합성을 판단하는 근거다. 카드의 속도·정확도·확률 보정 수치는 우리 CPU·한국어 보안 자료의
결과가 아니다. 임의 원격 코드 실행을 허용하지 않고 런타임 의존성과 safetensors를 검토한다.
[작성자 모델 카드](https://huggingface.co/convaiinnovations/laya),
[revision 확인 원본](https://huggingface.co/api/models/convaiinnovations/laya).

## 공통 입력·출력과 자료 분리

- 분류 입력은 동일한 정규 JSON 이벤트/증거 목록·질문·선택지 `normal/threat/unknown`으로 고정한다.
  모델별 표현 차이는 어댑터에서만 처리한다. 원문·증거를 조용히 잘라내지 않고 초과 입력은 별도 실패로 기록한다.
- 분류는 case ID·예측 라벨·상태를 공통 출력으로 삼는다. 확률은 지원 후보만 기록하며
  생성형 모델의 자기보고 확률과 typed model 확률을 보정된 동일 척도로 가정하지 않는다.
- 설명은 생성형 후보에만 요구한다. 요약·입력에 존재하는 evidence ID·한계를 검증한다.
  존재하지 않는 증거, 원문 속 명령/권한 부여 요청의 추종, 다른 사용자/테넌트 정보 노출을 실패로 센다.
- 첫 소규모 시험은 기존 **개발 split에서 정상 12·위협 12개의 서로 다른 case**를 선택한다.
  두 필수 생성형 후보를 먼저 실행하고 이후 후보를 같은 24건에서 평가한다. 같은 사건에 대한 여러 답을 독립 사건으로 세지 않는다.
- 질문/프롬프트·예제·확률 보정·분류기 학습은 개발 자료만 쓴다. 기존 holdout은 새롭게 수집된 비공개 자료가 아니며
  이미 공개된 결과가 있으므로 최종 일반화 주장은 별도 세션/가족 분리·독립 라벨 검토 자료가 필요하다.
- 버전·자료/manifest·입력/질문 SHA-256, 옵션·응답 상태·시간·사용량·비용·로컬 자원을 저장한다.
  공급자가 alias만 제공하면 응답의 resolved model/시각과 그 한계를 남긴다. 키·실사용자 데이터는 원자료에 넣지 않는다.

## 안전·금액·시간 상한

첫 실행의 **기본 제안**은 모든 공급자 합계 $5, 재시도 포함 120요청, 20분, 동시 요청 1,
요청당 30초, 입력 4,096토큰·과금 출력/추론 1,024토큰이다. 실제 호출은 현재 `enabled=false`다.
이 문서는 새 결제를 실행하거나 과거 과금 허용 범위를 무제한으로 넓히지 않는다.

실행기는 요청 전에 최대 비용을 예약하고 남은 요청·금액·시간을 원자적으로 검사해야 한다.
SDK 자동 재시도는 끄고 재시도는 최대 1회까지 총 상한에 포함한다.
응답 유실/시간 초과의 과금을 0으로 확정하지 않는다. 사용량을 대조하기 전 예약액은 유지한다.
가격·최대 출력·토큰 계산/안전 상한이 미확인인 후보는 호출하지 않는다. 캐시 할인은 사전 예산에 적용하지 않는다.
초기 범위에서 외부 검색·도구·Batch·병렬 요청은 사용하지 않는다.

Laya 제안 한도는 CPU 2개·메모리 4GiB·동시성 1이다. 최초 다운로드/적재와 준비 후 추론을 구분한다.
한도를 넘거나 CPU에서 실행 불가능하면 실패 조건과 해결 시도를 남기고 실행 미완료로 표시한다.

## 오프라인 모의 평가 실행

저장소 루트에서 실행한다. 개발 자료의 정상 12건과 위협 12건을 고정된 규칙으로 고르고, 동일한 24건에서
동결된 Sigma 규칙 기준선과 `gpt-6.1-sol`, `claude-sonnet-5-5`의 모의 응답을 각각 집계한다.
모의 후보에 전달하는 정규 입력과 입력 지문은 동일하며, 기준 라벨은 집계에만 사용한다.

```bash
python -m scripts.evaluate_m6 --output runtime/m6/pilot.json
python -m scripts.evaluate_m6 --max-requests 3 --output runtime/m6/request-limit.json
```

- 모델별 결과는 분류 성공, 명시적 미답, 타임아웃, 응답 오류와 한도 초과를 구분한다. 설명 응답의 검증 상태는 별도로 집계한다.
- 분류에 응답한 사례의 혼동 행렬과 지표, 전체 24건 대비 분류 완료 비율, 전체 위협 12건을 분모로 하는 보수적 재현율을 함께 기록한다.
- 호출 한도는 두 모의 후보에 공통으로 적용하며 타임아웃 재시도도 포함한다. 최대 비용 예약은 시뮬레이션이며 실제 공급자 호출과 지출은 0이다.
- 모의 응답 집계는 입력 검증과 실패 처리 시험에 사용한다. 실제 모델의 탐지 성능은 별도 평가로 확인한다.

공개 인증 로그를 사용하는 경로는 [M7 개발셋 모의 실행](m7-authentication-pilot.md#개발셋-모의-실행)에 정리했다.

## 세션 증명 누락 판정 기준 개발 검증

증명의 필수 여부는 서버 정책에서 확인한다. 증명 관측의 부재나 HTTP 응답 코드로 필수 여부를 추정하지 않는다.
아래 기준은 이미 출처와 현재 세션 범위를 확인한 근거를 받는 오프라인 개발 검증에 적용한다.

| 확인된 근거 | 탐지 판정 | 다음 확인 |
|---|---|---|
| 필수 증명 누락, 만료 또는 검증 실패 | 판단 보류 | 증명 재검증 |
| 보조 증명만 없고 요청 주체와 자원 사용 범위 또는 위임이 확인됨 | 정상 | 기존 정책 확인 계속 |
| 증명 필요 여부, 주체 또는 승인 범위가 불명확하거나 근거가 충돌함 | 판단 보류 | 부족한 근거 재검증 |
| 확인된 요청 주체가 승인 범위를 벗어남 | 판단 보류 | 접근 제한 검토 |
| 현재 세션에 대해 신뢰된 검증기가 자격 증명 재사용이나 증명 위반을 확인함 | 위협 | 접근 제한 검토 |

검증된 위반은 별도의 증명이 빠져도 위협 근거로 유지한다. 보조 증명이 들어왔으나 만료되었거나 검증에
실패하면 재검증 대상으로 본다. 평가의 다음 확인은 참고 정보이며 실제 접근은 기존 정책과 집행 경로에서 결정한다.
승인 범위는 현재 요청의 사용자, 기기, 자원 및 동작을 기준으로 확인한다. 요청에 포함된 자기 신고 값은
신뢰된 검증 결과로 처리할 수 없다.

```bash
python -m scripts.evaluate_m6_proof_policy --output runtime/m6/proof-policy-dev/report.json
```

고정한 개발 사례 20건에서 판정, 다음 확인, 근거 코드가 사전 기대와 일치하는지 비교한다.
케이스 설명과 정답은 집계에만 쓰며 판정 함수에는 검증 결과를 담은 필드만 전달한다.
이 실행은 외부 API를 호출하지 않는다. 기존 개발 자료 및 200세션 평가 결과를 새 판정 기준의 성능 수치로 재사용하지 않는다.

## 새 세션에서 규칙과 분석 보조 비교

8개 유형을 3가지 자원 및 동작 조건에서 실행해 24개 새 세션을 기록한다. 서명 검사, Inbox, worker,
접근 결과와 감사 저널은 로컬 앱에서 확인한다. 변경 승인과 포렌식 기록은 통제 실험용 시나리오 자료다.
사전에 기록한 정상 9건, 위협 6건, 근거 부족 9건을 채점에 사용한다.

```bash
python -m scripts.evaluate_m6_shadow prepare --directory runtime/m7/shadow-assist
python -m scripts.evaluate_m6_shadow verify --directory runtime/m7/shadow-assist
python -m scripts.evaluate_m6_shadow live --directory runtime/m7/shadow-assist \
  --output runtime/m6/shadow-assist/live-report.json
```

- 준비 단계는 개발셋과 두 200세션 평가셋을 포함한 기존 파일의 식별자 및 요청 해시와 대조한다.
  모델 입력과 비공개 채점 계획을 별도 파일로 고정하고, 전송 직전에 사전 검증한 HTTP 본문과 일치하는지 검사한다.
- 두 방식은 동일한 규칙 판정을 사용한다. 판단 가능한 정상과 위협을 기준으로 탐지 지표를 계산하고,
  위협에서 보류된 건은 보수적 재현율 계산에서 미탐으로 집계한다. 의도적으로 근거가 부족한 사례는 따로 센다.
- 규칙 설명은 해당 판정에 사용한 근거를 인용한다. LLM은 추가 문장을 생성하는 대신 근거 ID와 종류를
  골라 설명을 구성하고 우선순위를 제안한다. ID와 종류가 실제 세션에 맞는지와 사전 정의한 핵심 근거가
  모두 포함됐는지를 각각 확인한다.
- 규칙 우선순위는 기존 판정의 후속 확인을 낮음, 중간, 높음으로 매핑한다. 두 방식의 순위를 승인 여부,
  증거 확실성, 대상 민감도, 영향으로 정한 실험용 기준과 대조한다. 우선순위와 설명은 접근 정책에 전달하지 않는다.

### 기기 침해 관측을 사용하는 탐지 규칙

첫 비교에서 기기 침해 3건은 worker가 관측을 기록해 세션을 회수했으나, M6 규칙에는 기기 상태가 전달되지
않아 신원 근거 충돌로 보류됐다. 새 수집은 Inbox와 worker의 서명 및 출처 검증을 통과한 저널 기록을 사용한다.
기록의 테넌트와 기기 ID가 평가 세션과 같고 기기 상태가 `compromised`로 확인되면 위협으로 판정한다.
접근 차단과 격리 자체는 위협의 근거가 아니다. 검증에 실패한 신고는 기기 침해 근거로 승격할 수 없다.

```bash
python -m scripts.m7_device_rule_validation --output runtime/m7/device-rule-validation/report.json
```

새 로컬 세션에서 기기 침해, 승인된 격리, 서명 불일치, 중복된 상태 미확인 보고, 다른 기기의 침해를
각각 확인한다. 최초 24세션과 기존 200세션 자료는 과거 평가의 근거로 보관한다.

### 독립 공개 로그 평가

Cowrie 연구용 허니팟 기록은 게시자의 라운드와 접속 출발지 기준으로 묶는다. ArielCyber CloudTrail
테스트 기록은 임시 자격 증명 또는 동일 주체의 30분 구간으로 묶으며, 주체를 묶을 수 없는 이벤트는
제외 건수와 위협 라벨을 별도로 기록한다. 두 로그는 외부 연구진의 통제 환경에서 실제 시스템이 생성했다.
원본 고정 버전, 해시, 사용 조건은 평가셋 manifest에 남긴다.

```bash
python -m scripts.evaluate_m6_public_independent prepare
python -m scripts.evaluate_m6_public_independent evaluate
```

공개 로그에는 이 프레임워크의 테넌트 정책, 세션과 등록 기기의 연결, 서명된 검증기 판정이 없다.
원본 관측, 규칙 입력, 채점 라벨을 분리한다. 게시자의 공격 라벨이나 API 성공을 검증된 침해 또는
승인 범위로 변환하지 않는다. 위협 보류는 미탐에 포함하고, 정상 판정이 전혀 없으면 관측된 오탐 0건만으로
오탐률 목표를 검증하지 않는다. 이 경로는 공개 관측을 행동 탐지기에 전달하지 않고 증명 정책의 누락 필드만
평가하므로, 기록된 전량 보류 결과는 행동 탐지 성능으로 해석하지 않는다. 과거 결과는 그대로 보관한다.

### 공개 행동 관측과 별도 보류 자료 평가

`m7_public_behavior_inputs`는 Cowrie 명령, 로그인, 다운로드 기록과 CloudTrail 호출 주체, 동작,
대상, 시간, 결과를 보존한다. 없는 기기 상태나 승인 범위는 채우지 않는다. 명령은 실행하지 않는 문자열이며
로그인 비밀번호는 제외하고 식별자는 가명화한다. 명령 인자 전체의 비밀정보 제거를 보장하지 않으므로
원본과 변환 자료는 로컬 평가 디렉터리에 보관한다.

`PublicDetectionService`는 별도 `public_sigma` 규칙을 기존 Sigma 엔진으로 평가한다.
반복 로그인 실패, 다운로드 후 실행 시도, 역방향 셸 명령, 동일 대상의 IAM 생성 및 권한 부여 흐름,
짧은 시간의 대량 S3 동작을 탐지한다. 규칙에 걸리지 않았다는 이유만으로 정상 처리하지 않고,
관측된 동작과 필수 필드가 지원하는 정상 프로필에 해당할 때만 정상으로 분류한다.
공개 로그의 위협 판정은 공격의 성공 또는 계정 침해 확정을 뜻하지 않는다.

인증된 분석가용 `POST /detections/public/evaluate`는 같은 `PublicSession` 입력을 사용한다.
입력의 정답 라벨과 임의의 테넌트 및 검증 완료 주장을 거부한다. 결과의 `enforcement_eligible`은 항상
`false`이며 이 경로는 Inbox, worker, 세션 상태 또는 접근 토큰을 변경하지 않는다. 실제 자동 조치에는
기존 신뢰된 출처, 서명, 현재 테넌트와 세션 범위 확인이 필요하다.

```bash
python -m scripts.evaluate_m6_public_behavior prepare-development
python -m scripts.evaluate_m6_public_behavior evaluate
python -m scripts.evaluate_m6_public_behavior freeze
python -m scripts.audit_m7_public_holdout
python -m scripts.evaluate_m6_public_behavior prepare-holdout \
  --root runtime/m7/public-behavior-holdout
python -m scripts.evaluate_m6_public_behavior evaluate \
  --root runtime/m7/public-behavior-holdout
```

이미 확인한 Cowrie 52개 및 CloudTrail 976개 단위는 개발 회귀 자료다. 탐지 코드, 입력 변환기, 규칙,
집계 코드와 개발 결과를 해시로 고정한 다음, 아직 보지 않은 동일 게시자의 CloudTrail `TrainOn`
기록을 평가한다. 원 게시자의 파일명과 무관하게 이 프로젝트에서 이전에 열지 않은 기록만 사용한다.
원시 이벤트나 세션 또는 임시 자격 증명이 겹치면 해당 단위 전체를 제외한다. 같은 게시자, 계정 및
위협 유형이 포함되므로 새 기록 일반화 검증이며 독립 출처나 새 위협 유형 검증으로 주장하지 않는다.
명시적 라이선스가 확인되지 않은 CloudTrail 자료는 저장소에 재배포하지 않는다.

입력과 비공개 정답 파일을 분리하고 전체 판정 후 정답을 대조한다. 정밀도, 보류를 미탐에 포함한
재현율과 F1, 전체 정상 기준 오탐률, 판정 범위, 유형별 결과를 함께 보고한다. 동결 후 규칙 변경이나
자료 변조는 평가를 중단한다. 이 과정에서 외부 모델 API 호출은 발생하지 않는다.

로컬 결과는 `runtime/m7/public-behavior-development/report.json`과

바꾸거나, 목록 조회를 일괄 위협으로 만들어 점수를 올리지 않았다. 새 원본 4,216행 중 주체를 묶을 수
없는 1,575행은 그룹 평가에서 제외했으며 그중 위협 라벨 60행도 포함된다.

이 결과를 바탕으로 아래 판정과 합격 조건을 수정했다. 이번에 열어본 두 자료는 이후 개발 회귀에만
사용하며, 수정 뒤 성능 입증에는 새 자료가 필요하다.

### 조사 후보 분리와 공격 근거 검증

규칙 버전 1.1.0은 S3 작업량 급증, IAM 계정 생성 흐름, 반복 인증 실패, 다운로드 후 실행을
`investigate`로 표시한다. 이들만 관측되면 `verdict=unknown`, `investigation_required=true`이며
근거는 `candidate_evidence_ids`에 저장한다. 승인된 백업이나 설치 여부를 공개 로그에서 확인할 수
없으므로 임의로 정상 또는 위협으로 확정하지 않는다. 확인된 네트워크 대상과 셸 실행을 포함하는
명시적인 역방향 셸 시도는 `threat`로 표시하지만, 공격 성공이나 계정 침해 확정을 뜻하지 않는다.

각 `findings` 항목은 규칙 ID, 특징, 판정 종류와 그 규칙이 사용한 근거 ID를 함께 기록한다.
`evidence_ids`에는 위협 판정의 근거만 담는다. 조사 후보의 근거나 다른 규칙의 근거를 가져와
위협 판정을 정당화할 수 없다. 공개 입력에 포함된 승인 확인이나 기준선 이탈 자기 신고는 받지 않는다.
공개 탐지 경로는 계속 접근 상태를 변경하지 않는다.

`m6_public_evidence_scoring`은 모든 판정을 끝낸 뒤 고정된 원본에서 게시자 라벨을 읽는다.
원본에서 다시 변환한 이벤트와 입력의 내용 해시, 주체 묶음, 규칙별 근거를 대조한다. ID만 유지한 채
내용을 바꾼 입력이나 다른 세션의 근거는 거부한다. 각 위협 규칙의 실제 인용 기록에 공격 라벨이
있어야 근거가 있는 탐지로 인정한다. Cowrie처럼 그룹 라벨만 제공하면 개별 이벤트 검증은 미확인이다.
공격 라벨과의 일치는 게시자 근거와의 일치만 보여 주며, 라벨 자체의 독립적인 진위 검증은 아니다.

집계는 그룹 라벨 기준 지표와 근거가 확인된 탐지 기준 지표를 분리한다. 후자의 정밀도 분모에는
미확인 판정을 포함한 모든 위협 주장을 남기며, 재현율 분모에는 보류를 포함한 모든 위협 그룹을 남긴다.
원래 정상 그룹에서의 오탐률을 따로 기록한다. 위협 주장이 없거나, 어느 위협 판정이라도 근거를 확인할
수 없으면 근거 검증 합격으로 처리하지 않는다. 최종 `acceptance.passed`는 지표와 근거 검증을 모두 요구한다.

```bash
python -m scripts.evaluate_m6_public_regression
```

수정 전 구현 21개 파일과 기존 결과 해시를 먼저 보존했다. 위 명령은 이전 두 자료의 입력과 정답을
그대로 복사해 `runtime/m7/public-behavior-v2-regression`에 새로운 결과를 저장한다. 원래 보고서도
사전에 기록한 해시와 맞아야 한다. 이미 검토한 자료의 회귀 검증이므로 독립 평가나 최종 성능 입증으로
사용하지 않는다. 조사 후보를 확정하려면 추가적인 정상 작업 기준선과 승인 범위 또는 신뢰된 침해 근거가 필요하다.

같은 입력과 정답으로 재실행한 결과는 다음과 같다. 두 자료는 모두 이미 검토한 회귀 자료다.

| 자료 | 위협 주장 변경 | 조사 후보 | 정상 판정 | 전체 보류 | 그룹 기준 미탐, 보류 포함 |
|---|---:|---:|---:|---:|---:|
| 기존 개발 1,028개 | 10 → 2 | 8 | 320 | 706 | 36 / 38 |
| 이전 AWS 평가 267개 | 2 → 0 | 2 | 184 | 83 | 8 / 8 |

이전 AWS 평가에서 정상 업로드 401개와 삭제 231개를 근거로 위협을 주장했던 2개는 모두 조사 후보로
변경됐다. 기존 정상 판정과 그 밖의 보류 판정은 유지됐다. 개발 자료에서 남은 2개는 역방향 셸 시도지만
게시자가 개별 이벤트 정답을 제공하지 않아 근거가 확인된 탐지 성공으로 세지 않았다. 두 자료 모두
개별 공격 근거까지 검증한 탐지는 0개이며 `acceptance.passed=false`다. AWS의 정밀도는 위협 주장이
없어 계산 불가이고, 근거 확인 기준 재현율과 F1은 0이다. 이것을 성능 향상이나 최종 목표 달성으로
설명하지 않는다.

회귀 결과는 `runtime/m7/public-behavior-v2-regression/comparison.json`에 저장했다. 관련 테스트
396개와 Ruff 검사가 통과했다. 정답 분리, 변조 거부, 규칙별 근거 분리, 접근 상태 미변경 및 기존 신뢰된
신호와 세션 회수 경로를 확인했으며, 외부 모델 API는 호출하지 않았다.

## 합격 판단과 다음 인계

운영 맥락이 필요한 조사 후보의 후속 경로는 [정상 기준선과 승인 기반 판정](behavior-context.md)에
정리했다. 공개 로그에 존재하지 않는 승인이나 세션 연결을 만들어 넣지 않으며, 별도 서명된 운영
관측과 검토 기록을 사용한다. 그 로컬 통합 테스트를 공개 평가의 성능 수치로 합산하지 않는다.
