# 최신 aitest와 extra 통합 기록 — 2026년 11월 13일

팀원의 업로드 완료 후 사용자가 `aitest` 병합을 허용했다. 별도 소유자 브랜치에서 두 이력을 합치고
충돌 6곳을 해결했다. `main`은 대상이 아니다. 실제 게시·병합 여부와 최종 커밋은 GitHub PR 기록을 따른다.

| 기준 | 커밋 / 브랜치 |
|---|---|
| 팀원 최신 aitest, PR #57 포함 | `07ef9cc3fb685d2c31ceeea299819db8a4841a78` |
| 로컬 extra 최신, v48 포함 | `668096b3288ff5fbb9d97837c5270f3cb6b9d065` |
| 공통 조상 | `c83b8579c59c96972648df55f446df018c4dd1bd` |
| 통합 소유자 브랜치 | `feature/chaeheeju-extra-aitest-integration` |

기존 원격 `extra`의 v42 이후 로컬 6개 커밋도 통합 대상에 포함한다. 강제 푸시나 파일 덮어쓰기로
팀원 이력을 없애지 않는다. 사용자 `docs.zip`, `docs/week03.zip`과 비밀키·원시 실행 DB는 공유 대상에 넣지 않는다.

## 충돌 해결과 실제 동작

| 파일 / 경계 | 결정과 확인 |
|---|---|
| `app/main.py` | 팀원 `/response/requests`만 앱에 연결한다. 이전 `/response/plans` 라우터를 추가 연결하는 자동 병합 결과를 제거했다. |
| `app/config.py` | 서버 행위 문맥 DB 설정을 유지한다. 이전 승인 DB 설정은 오프라인 호환 시험에만 보존한다. |
| `scripts/app_state_recovery.py` | 최신 문맥·승인 이력과 입장 검증을 유지한다. 이전 원장도 있으면 full-state와 명시적 response-state 동의가 필요하며 복원 시 미완료 모의 계획을 폐기한다. |
| 복구 서명 / 크기 제한 | 이전 원장이 없는 경우에도 부재를 검사하는 복구 코드를 모든 모드에서 고정한다. 앱 DB·문맥 DB·JSONL·이전 원장을 합산해 백업과 복원 한도를 검사한다. |
| `scripts/test_app_recovery_runtime.py` | 최신 문맥 복구와 이전 원장 복구 스크립트를 모두 이미지 소스 지문에 포함한다. |
| 계획표 / 김택희 역할 문서 | 양쪽 날짜별 기록을 보존하고 현재 통합 허용 사실을 앞에 적는다. 과거 `extra 제외`는 당시 팀원 작업 범위다. |
| 신호 검증 시험 호환 | 최신 공용 검증기가 키 활성화 전 신호를 더 일찍 거부한다. 이전 시험의 오류명을 현재 계약에 맞추고, 이벤트 저장 0과 활성화 후 정상 수신도 검사한다. 런타임 검증은 약화하지 않았다. |
| 고정 역사 자료 줄바꿈 | `historical-approval.json`은 Git에 있던 원래 LF 바이트로 복원하고 `.gitattributes`로 고정한다. 원래 SHA-256 `12cf6f71…`과 평가 내용을 바꾸지 않는다. |

실제 앱의 고위험 대응은 **요청자 외 서로 다른 승인 주체 두 명**이 필요하다.
과거 `extra` 모의 원장의 요청자+승인자 한 명 절차로 대체하지 않는다.
모의 대응은 실제 계정 비활성화나 외부 기기 격리를 수행하지 않는다.
관련 계약은 [고위험 대응 승인](response-approval.md), [팀원 개발 인수표](kim-handoff-ready-20261113.md)를 따른다.

`extra`의 F1·VPN·웹 문맥 실험과 자료 출처·이전 측정 결과는 보존한다. 이 실험 코드를 실제 앱 탐지기에
자동으로 연결하거나 기존 모델·라벨·임계값을 변경하지 않는다. 현재 앱 `main.py`는 팀원 최신 구현과 같다.

초기 개발 도중의 집중 실행은 175 통과·1 실패였다. 체크포인트 시험 중 앱 소스를 수정해 자식 프로세스가
`application_version_mismatch`로 거부했다. 소스를 고정한 최종 재실행 결과는 위에 별도로 기록한다.
소스 해시 검증을 해제해 통과시키지 않았다.
첫 Linux 전체 실행의 4,709 통과·2 실패는 위 신호 오류명과 Windows 줄바꿈 문제였다.
그 실행의 로그와 결과도 보존하고, 수정 후 전체 재실행을 최종 결과로 구분했다.
최종 실행 전 복구 검사기 지문을 모든 모드에 적용하기 위해 직전 재검증은 94.505초에 소유 컨테이너만
중단했다. 이 실행의 exit 137은 OOM이나 시험 통과로 세지 않으며, 소유 자원 제거 결과와 함께 보존한다.

검증 요약과 이미지·소스 아카이브 지문은 [공유 JSON 근거](infrastructure-results/extra-aitest-integration-20261113.json)에 있다.
원본 로그·JUnit·소스 명세는 `runtime/integration/`에 로컬 보관하며 Git에 올리지 않는다.
실제 mTLS·CA·DB·Lambda CI 범위와 승인 여부는 이 통합 PR의 Checks에서 정확한 커밋별로 확인한다.
이전 PR #55의 419개 런타임 검사를 이번 소스의 실행 결과로 재사용하지 않는다.

## PR CI 설정 호환 후속 — 11월 14일

첫 통합 커밋 `0349d302`의 PR #58 코드 검사는 `DTZ001`용 예외 주석을 CI에서 사용하지 않는다는
`RUF100` 오류로 중단됐다. 해당 unit 작업은 pytest까지 진행하지 않았으며 통과로 세지 않는다.
시간대 없는 입력을 `START.replace(tzinfo=None)`로 만들고 일반 설명 주석을 붙였다.
검증 예외를 추가하거나 시간대 없는 입력의 거부 조건을 낮추지 않았다.

이 변경 후 Windows와 Linux Docker의 공개 탐지 관련 시험 **91개씩**과 Ruff 전체/RUF100 검사가
통과했다. Docker 린트 스냅샷은 Git의 실행 권한을 보존했고 소유 컨테이너도 제거했다.
앱과 복구/실험 스크립트는 `0349d302`와 동일하다. 위 로컬 전체 4,714개 결과는 이 시험 입력 표현을
바꾸기 전 소스의 기록이며 최종 PR head의 전체 검증은 새 CI 결과로 확인한다.
최초 lint 스냅샷의 실행 권한 손실(EXE001)은 시험 포장 문제로 구분해 기록했다.

## 해석과 후속

- 유료 LLM 호출·AWS 배포 또는 실제 계정 변경은 수행하지 않았다.
- 과거 F1 결과와 동결 해시는 당시 소스의 기록이다. 이번 기능 회귀는 새 독립 성능 평가가 아니며 P/R/F1 95%·오탐률 5% 목표 달성을 뜻하지 않는다.
- 자동 승인/복구 시험을 팀원의 수동 수행이나 독립 인수 완료로 표시하지 않는다.
- 다음 개발은 병합된 최신 `aitest`를 다시 가져와 시작한다. 최종 성능 평가에는 새 데이터 분할·라벨 근거 검토·해당 소스에서의 후보 재현이 필요하다.
