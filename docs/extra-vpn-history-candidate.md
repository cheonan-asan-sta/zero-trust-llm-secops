# extra: VPN 과거 접속 이력 후보와 개발 비교

2026-11-12 · v32. **후보 구현과 로컬 검증은 완료했지만 최종/운영 후보로 채택하지 않았다.**
원래 여섯 영역의 새 독립 평가 목표는 그대로 미완료다. 아래 결과는 이미 관찰한 AIT 개발 자료의 진단이다.
[실행·모델·시험 근거](infrastructure-results/extra-vpn-history-v32-20261112.json)를 함께 본다.

## 해결하려고 한 문제

v23 단일 트리는 santos 전체에서 높은 micro F1을 보였지만 VPN 공격28건을 모두 놓쳤다.
기존 VPN 특징에서는 정상 연결과 공격 연결이 같은 특징 벡터를 공유했다.
TLS 인증서 검증 성공과 로그인 성공 자체는 현재 사용자의 업무 권한/승인 근거가 아니다.
그래서 계정명·IP 문자열을 학습시키는 대신 실제 로그에서 관측할 수 있는 과거 접속 이력을 추가했다.

## 구현 범위와 누수 통제

- 새 프로필은 `raw-rich-vpn-history-3`다. 기존 `base`·`raw-rich-http-window-2`의 특징 계약은 유지한다.
  기존 준비 명령의 기본값도 유지하고 새 프로필은 `--feature-profile raw-rich-vpn-history-3`로 선택한다.
- 한 VPN 로그/호스트 안에서 IPv4 접속점·포트를 해시 연결 키로만 사용한다. 이름은 존재 여부만 관측한다.
  키/이름/절대 시각/시뮬레이션 시작 이후 시간은 학습 특징으로 출력하지 않는다.
  네트워크 접속점을 검증된 사람·기기 ID로 해석하지 않는다. NAT 등으로 같은 IP를 공유할 수 있다.
- 이전24시간의 같은 IP/접속점 관측 수, 이전 이름 표기/초기 패킷 관측 여부를 집계한다.
  이는 불완전할 수 있는 로그 이력이며 정상 목록·건강 상태·신뢰 승인으로 바꾸지 않는다.
- **VPN 창은 같은 시각의 전체 기록을 먼저 질의한 뒤 이력에 넣는다.** 같은 초의 다른 행이나 미래 행을 보지 않는다.
  기존 HTTP 프로필의 동일 시각 ordinal 처리와는 별도 계약이다.
- 동일 원시 바이트는 이력에서 한 번 세되 평가 행은 전부 남긴다. 파싱 불가/IPv6/미확정 시각의 VPN 이력은 unavailable이다.
  다른 행이나 전역 IP 이력으로 대체하지 않는다. 최대10만 기록·입력64MiB·연결 그룹 각1만개를 제한한다.
- 준비 단계는 고정 원시 해시·행·case ID를 대조하고 정답/참조 sidecar를 바이트 그대로 복사한다.
  모델 추론에는 정답을 전달하지 않는다. 원본 앱과 기존 라벨은 변경하지 않았다.

실제 실행 전에 [프로토콜](../infra/f1-lab/vpn-history-protocol.json)에 소스/입력 지문·특징·모델 조건을 고정했다.
russellmitchell295,243행에서 class-balanced 순서 이진 트리(depth8/min_leaf5/threshold0.5)를 적합했다.
모델 SHA256은 `06f8df701f82a72a55e78a8c54c3320a4d3c6ac8fa332b49aa3bc05d300360c2`다.
이 JSON을 고정하고 santos295,976행에 재학습 없이 적용했다. harrison/wilson 최종 예약 본문은 읽지 않았다.

## 이력 자체의 기여와 남은 구분 한계

드문 VPN 행이 큰 DNS 스트림과 경쟁하는 문제와 특징 부족을 분리하기 위해 추가 비교를 고정했다.
각 프로필의 **VPN 전체 행만** 같은 depth8/min_leaf5/class balance로 학습하고 같은 threshold0.5로 전이했다.
R 학습 뒤 모델 두 개를 고정하고 S를 예측했다. 자료·클래스·정상 행을 줄여 정밀도를 맞추지 않았다.
이 추가 비교도 이미 본 개발 자료이며 단일 후보의 결과를 덮어쓰지 않는다.

이력은 구분력을 높였지만 아직 목표 정밀도에 훨씬 못 미친다. 동일 특징을 공유하는 정상·공격 집계를
정답으로 최적으로 나누는 **개발 자료의 이상적 진단**도 수행했다. S의 이력 추가 특징은128개 벡터,
정상·공격 혼합11개 벡터/108행이며 최소 오분류28건이다. 이때 이상적 최대 F1은47.273%,
R≥95%에서 가능한 최대 P는30.682%였다. **정답을 이용한 계산이므로 모델 성능·독립 평가가 아니다.**
이 숫자는 현재 특징과 관찰한 VPN 자료의 한계이며 모든 모델/공개 자료가 불가능하다는 주장은 아니다.
