## 평가 대상과 방법

인도네시아 공공기관 X의 공개 Apache 로그를 새 출처로 선택했다. 발행자 ZIP의 MD5 `b4bf79effa6f3ee1b9e53f278d916620`과 수집 파일의 SHA-256 `1429caba2803c3e8c90e9fb287bc04f6f8249f8bb34712b39127044e134d631f`를 확인했다. 물리 로그 행 213,205개를 평가 단위로 정했다. 완전히 동일한 문자열이 한 파일 안에서 반복된 2,004행을 그대로 포함했고, 로그 파일 간 정확히 동일한 행은 없었다. 동일 문구의 반복은 그 자체로 별도 공격을 뜻하지 않는다. [발행자 데이터와 라벨 기준](https://zenodo.org/records/20001206)

저장소의 v114 고정 웹 모델과 0.95 경보 기준, 기존 웹 근거 보강을 그대로 적용했다. Apache 각 파일 안의 시각순으로 기존 HTTP 이력을 구성했다. 기존 모델과 기존 웹 근거 보강의 전후 경보를 같은 행에 저장한 다음 SHA-256으로 고정하고 채점 단계에서 발행자 YAML을 적용했다. 원시 요청은 로컬 파일에서 읽었으며 외부로 재전송하지 않았다. 발행자 라벨 규칙 구조는 도입 전에 검토했다. 실제 예측 코드에는 라벨·필터가 들어가지 않았다.

발행자 설명에 따라 규칙 내 필터는 모두 일치해야 하고, 규칙 중 하나라도 일치하면 양성이다. 이 실행은 대소문자를 구분하는 리터럴 포함 여부를 사용했다. 동일 ID에 여러 대체 조건이 있는 YAML을 처음 집계할 때 일부 조건이 덮어써지는 문제를 발견했다. 조건을 모두 보존해 재채점하고, 수정 전후 예측 SHA-256이 같은지 비교했다. 발행자 라벨은 패턴 일치 기반이므로 비일치 행에는 미확인 사건이 있을 수 있다. 이 결과는 별도 공개 출처에 대한 오프라인 비교이며, 라벨을 사람이 다시 판정한 독립 인수 결과는 아직 없다.

최종 예측과 봉인에는 약 70초가 걸렸다. strict 두 규칙으로만 다시 대조했을 때 양성이 0건이어서 재현율을 계산할 수 없었다. 행별 경보 변화, 새 오탐, 기존 탐지 손실, 추론 오류는 각각 0건이다. **기존 웹 감사의 100% 결과는 이 새 출처에서 재현되지 않았다.** 발행자 라벨 기준 오탐 34,506행 중 `GET 3xx` 15,228행, `POST 2xx` 10,151행, `HEAD 3xx` 4,287행이 총 85.97%를 차지했다. 기존 웹 모델에서 정상 근거로 점수를 낮출 수 있는 경로는 GET·HEAD 2xx에 한정돼 위 세 집단에는 적용되지 않는다. 같은 응답군에도 라벨이 붙은 요청이 있으므로 상태 코드만으로 경보를 일괄 해제하면 탐지를 잃을 수 있다. 다음 개선에서 해당 세 집단의 요청 문맥과 라벨 근거를 검토하되, 이 평가에 맞춰 수정한 후보의 최종 채점은 새로운 자료에서 따로 한다.

원래 KREONET 비교 구간의 F1 96.05%는 공개 OIDC·SAML 합성 인증 흐름의 별도 결과다. Apache 접근 행만으로 해당 모델에 필요한 인증 단계·세션을 복원할 수 없었다. 같은 X 자료의 인증 로그는 4,334행 중 SSH 기록 2행이었고, [IAM-UEBA 발행자 스키마](https://zenodo.org/records/22871318)는 실제 OIDC 로그인·세션 이벤트를 포함하지만 공격 정답과 HTTP 상태·메서드·컴포넌트 단계가 없다. IAM-UEBA는 데이터 설명 파일의 MD5만 대조했다. 두 자료에서 KREONET 모델의 외부 정밀도·재현율·F1과 승인·MFA 탐지 성능은 미측정이다. 기존 6영역 독립 인수도 계속 열어 둔다.

## Keycloak 로컬 재검증

로컬 Docker의 기존 Keycloak 26.8.0 이미지에서 새 시험 realm을 생성했다. 정상 TOTP는 200, 오류·누락은 각각 400이었다. 승인된 읽기는 허용됐고 범위를 벗어난 원격 접속은 거부됐다. 분석자 역할 제거와 로그아웃 뒤 기존 토큰은 다음 요청에서 각각 401이었다. 역할을 낮춘 뒤 발급된 새 토큰은 보호 요청에서 403이었고, 수동 회수 파일은 쓰지 않았다. 시험 컨테이너는 제거했다. 테스트 환경의 정상·위협 점수를 공개 로그 지표에 더하지 않는다.

관련 회귀는 인증·KREONET 44개 통과·1개 제외, HTTP 컨텍스트 7개 통과, 웹·공유 감사·VPN 240개 통과·4개 제외, 새 라벨 중복과 봉인 검사 1개 통과였다. 묶음별 결과이며 독립 사례 수에는 합산하지 않는다.

## 재현

발행자 ZIP을 로컬에 내려받고 위 지문을 확인한다. 제품 코드 `85eeb46`의 깨끗한 체크아웃에 [평가 실행기](../scripts/evaluate_public_apache_transfer.py)를 두고, 출력 위치는 새 디렉터리로 잡는다. `capture`는 원본 ZIP을 읽어 예측과 봉인을 저장한다. `score`는 `seal.json`의 SHA-256을 인자로 받아 원래 예측과 라벨을 대조한다.

```powershell
python -m scripts.evaluate_public_apache_transfer capture <archive> <new-output> 85eeb464abf1de1184a3abf02a22d6e697f74535
python -m scripts.evaluate_public_apache_transfer score <archive> <output> <seal-sha256> --mode publisher
python -m scripts.evaluate_public_apache_transfer score <archive> <output> <seal-sha256> --mode strict
```
