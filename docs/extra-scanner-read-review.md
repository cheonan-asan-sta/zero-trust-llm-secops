## 변경 근거와 경계

남은 웹 미탐 중 기존 관측 특징에 스캐너 징후가 있었지만 모델 점수가 낮아 경보되지 않은 읽기 요청이 있었다.
기존 core `scanner_agent`와 HTTP User-Agent의 scanner 분류가 모두 있고, 정상적으로 파싱한
GET/HEAD·관측된 응답2xx~5xx·유효한 시간창이 있을 때만 경보 검토 점수를 최소0.95로 올리는 가설이다.
기존 경보/점수는 낮추지 않는다. 알려진 계정·주소·호스트·공격 시각이나 정답을 특징에 추가하지 않았다.

User-Agent는 클라이언트가 바꿀 수 있고 허가된 스캐너도 같은 문자열을 사용할 수 있다.
따라서 이 후보는 악성·무허가 여부를 입증하지 않으며, 모든 결과는 `automatic_enforcement_allowed=False`다.
접근 허용·grant 발급·권한 복원·차단·회수에는 연결하지 않았다.
실제 정상 점검 도구·허가된 스캔의 오탐 영향과 별도 출처 재현은 추가 검증 대상이다.

## 재현 절차와 검증

`scripts/run_web_scanner_review.py`는 외부에서 고정한 계획/이전 결과 SHA와 후보 소스 SHA를 확인한다.
네 출처의 관측과 기존 예측으로 모든 새 예측을 먼저 고정하고, 그 뒤에만 정답을 읽는다.
원래 혼동행렬·모집단을 재현하고 SHA가 바뀐 입력·추가/누락/재정렬 행을 거부한다.
추론 실패는 분모에서 제거하지 않는다. 기존 미탐을 다른 새 탐지로 상쇄해 숨기지 않도록 TP 손실도 따로 센다.

```text
python -m scripts.run_web_scanner_review --plan <고정_개발계획.json> --expected-plan-sha256 <SHA> --prior <v52_run.json> --expected-prior-sha256 <SHA> --output <새_결과폴더>
```
