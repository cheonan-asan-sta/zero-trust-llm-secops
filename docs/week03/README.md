# 3주차 산출물

## 이번 주 목표

3주차는 3~4주차 계획의 앞부분인 **위협 시나리오 상세화와 보안 이벤트 구조 확정**에 집중했다. 제로 트러스트 판단에 필요한 관찰값을 고정하고, 5개 위협 시나리오에 ATT&CK 기법·관찰 신호·정상 예외·예상 대응을 연결했다.

## 산출물

| 문서 | 주요 내용 |
|---|---|
| [threat-model.md](threat-model.md) | 5종 위협 시나리오의 ATT&CK 매핑, 관찰 신호, 정상 예외, 예상 대응 |
| [event-schema.md](event-schema.md) | 사용자·기기·네트워크·자원·인증·행위 필드와 검증 규칙 |
| [architecture.md](architecture.md) | 시나리오 카탈로그에서 분석·정책 검증으로 이어지는 논리 구조 |
| [requirements.md](requirements.md) | 3주차 기능·안전 요구사항과 코드·테스트 추적표 |

## 코드 반영 범위

- `ScenarioSummary`에 시나리오 분류, 설명, ATT&CK 기법, 관찰 신호, 정상 예외, 예상 대응을 추가했다.
- 위협 시나리오는 ATT&CK 기법을 하나 이상 가져야 하고, 정상 시나리오는 공격 기법을 주장하지 못하도록 검증했다.
- 시나리오 카탈로그의 위험도·예상 대응을 합성 이벤트의 `ground_truth`가 재사용하게 해 중복 정의를 제거했다.
- `GET /scenarios/{scenario_id}`로 특정 시나리오의 상세 기준을 조회할 수 있게 했다.

## 완료 조건

- [x] 각 위협 시나리오에 관찰 신호와 정상 예외를 하나 이상 기록함
- [x] 사용자·기기·네트워크·자원·인증·행위를 공통 이벤트 계약으로 정리함
- [x] 관찰 사실과 평가 라벨을 분리함
- [x] 시나리오 카탈로그와 합성 이벤트의 일관성을 자동 테스트함

## 이번 주 증빙에서 제외한 것

저장소에 이후 주차에 해당하는 분석기·정책 엔진·대시보드 초안이 존재하더라도 3주차 완료 성과로 계산하지 않는다. 이번 주차의 핵심 결과는 **위협 모델과 입력 데이터 계약을 코드와 문서로 일치시킨 것**이다.
