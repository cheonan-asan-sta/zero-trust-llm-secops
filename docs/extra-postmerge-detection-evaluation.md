[v51 선행 위험 문맥](extra-command-history-development.md)에 있다. 아래 동결된 v49 결과는 보존한다.

작업 브랜치는 `feature/chaeheeju-postmerge-detection-evaluation`이다.

## 구현한 개선

웹 요청 안에 인코딩된 명령이 있다는 사실만으로 모두 경보를 올리지 않는다.
이미 관측한 개발 자료에서 그런 넓은 경보안은 정상 라벨의 `bash -c` 요청까지 경보로 바꾸었다.
이번 후보는 업로드된 서버 스크립트 경로의 요청에서 **구조화된 `cat` 인자와 민감 파일 읽기 의도**가 함께 확인될 때만
기존 점수 이상으로 검토 경보를 올린다. 프로그램·옵션·입력 길이·디코딩 횟수를 제한하고 명령은 실행하지 않는다.

`/etc/shadow`, `wp-config.php`, `.env`, AWS credentials 등은 자격증명 탐색의 근거로,
`/etc/passwd`, `/etc/group`는 계정 열거 의도로 구분한다. `/etc/passwd`를 비밀번호 비밀 파일이라고 설명하지 않는다.
이런 관측은 요청 의도이며 서버에서 실제 읽기·침해가 성공했다는 증거가 아니다.
파일 자격증명 탐색의 분류 근거는 [MITRE T1552.001](https://attack.mitre.org/techniques/T1552/001/),
WordPress 설정 파일의 민감성 근거는 [WordPress 공식 설명](https://developer.wordpress.org/advanced-administration/wordpress/wp-config/)이다.
이 분류 자체가 실제 기업에서의 정답 라벨을 보증하지는 않는다.

구현 위치:

- `scripts/f1_lab/web_sensitive_read.py`: 요청 파싱·의도 분류·원본 SHA/물리 행/특징 지문 결속.
- `scripts/run_postmerge_detection.py`: 현재 병합본에서 이전 기준선 재현 후 동일 모집단의 후보 비교.
- `scripts/f1_lab/transfer_evaluation.py`: 코드·모델 동결, 라벨 없는 예측, 별도 채점.
- `scripts/prepare_transfer_source.py`: ZIP 제한 읽기, 정확한 로그/라벨 쌍, 호스트 UTC 확인, 단계별 접근 기록.
- `scripts/prepare_native_stream.py --observations-only`: 정답 파일을 열거나 만들지 않는 특징 준비.
- `scripts/run_frozen_transfer.py`: 동결 → 원본/특징 준비 → 예측 봉인 → 라벨 채점의 분리된 명령.
- `scripts/audit_transfer_overlap.py`: 예측 봉인 후 기존 개발 자료와의 특징/원본 겹침 검사. 사례 제거 없음.

현재 앱의 분석기·승인·PEP에 후보를 연결하지 않았다. 점수는 보정된 확률이라는 뜻이 아니며,
임계값 0.95에서의 오프라인 경보 결정에 사용한다. 경보 자동 해제·접근 허용·권한 회수는 수행하지 않는다.
실제 앱의 `/response/requests`와 요청자 외 두 승인 주체 계약은 그대로다.
여기서 고정한 세 모델은 기존 원시 로그 특징용 검출기다. 이번 수치를 OpenAI/Jev/Laya 호출이나
LLM 출력의 품질 평가 결과로 해석하지 않는다. 유료 LLM 호출은 0회다.

## 이미 관측한 개발 자료: 전후 비교

기존 v44를 현재 병합본에서 먼저 재현한 뒤, 동일한 **1,259,637개 물리 로그 행**을 다시 비교했다.
새 독립 표본 수나 고유 공격 수를 뜻하지 않는다. 모델 재학습·라벨 변경·정상 예외 추가는 하지 않았다.

Santos 웹 access F1은 **99.8459% → 99.8652%**이다. 이는 이미 분석한 자료의 개발 성능이다.
VPN은 FPR 약 1.07~1.21%라도 정밀도가 **24.14~31.82%**, F1은 **38.89~48.28%**에 머문다.
전체 행을 합친 높은 F1/정확도로 이런 약점을 가리지 않는다. 정상 표본이 없는 집계의 FPR은 `null`이며 0%로 바꾸지 않는다.

VPN 경보를 단순히 낮추면 기존 공격 탐지를 잃는 이전 실험을 유지한다.
실제 IdP/MDM/EDR·세션·현재 자원 권한 근거 없이 정상 기기·MFA·업무 승인을 만들어 넣지 않는다.
따라서 이번 후보는 VPN의 오탐을 줄였다고 주장하지 않는다.

개발 비교는 최종 코드 지문을 실행 전후 대조했고, 각 자료에서 이전 v44 집계가 같은지 자동 확인했다.
초기 기준선 실행의 상대 경로 인자 실패는 보존하고, 절대 프로토콜 경로로 재실행한 성공본 `postmerge-baseline-v49-20261114-02`를 비교 기준으로 사용한다.
개발 후보의 초기 확인본도 보존하며, 최종 코드가 고정된 `postmerge-development-final-v49-20261114`가 공유 수치의 근거다.

## 새 출처 평가의 범위와 누수 방지

평가 대상으로 AIT LDS 2.1의 Harrison 한 testbed를 사전 지정했다.
자료 설명·사용 조건·다운로드 크기·시뮬레이션 시간은 [발행자 원문](https://zenodo.org/records/19483937)을 따르며,
비상업 연구용 CC BY-NC-SA 4.0 자료를 이용한다. 보고서에는 집계와 지문을 공유하고 원시 로그는 Git에 추가하지 않는다.
출처 표기: Landauer, Skopik, Frank, Hotwagner, Wurzenberger, Rauber,
**AIT Log Data Set V2.1** (`v2_1`), DOI `10.5281/zenodo.19483937`.
원본 라벨은 변경하지 않았으며 새 특징·예측·성능 집계는 이 프로젝트에서 생성했다.

원본은 다운로드/hash 검증만 먼저 수행하고, **코드·모델·임계값·선정 문법을 고정한 뒤** 본문을 연다.
Harrison 결과를 본 뒤 이 후보를 다시 튜닝하지 않는다. 아래 순서는 실제 실행 지문·접근 대장으로 확인한다.

1. 세 기존 모델과 정책, 앱/스크립트 Python 및 실험 JSON을 동결하고 외부 SHA를 기록한다.
2. 모든 정확한 라벨 미러 쌍의 Apache `*-access.log`, `*-error.log`, `openvpn.log`를 정해진 문법으로 고른다.
   쌍이 없는 파일은 정상으로 추정하지 않는다. 파일 크기·행 수·전체 모집단 상한을 넘기면 실행을 실패로 남긴다.
3. 호스트 메타데이터에서 UTC를 확인하고 원시 로그만 읽는다. 정답 라벨은 열지 않는다.
4. `observations-only`로 특징과 참조를 만들고, 별도 예측 컨테이너에 원본 ZIP·Harrison 정답을 제공하지 않는다.
5. 코드·모델을 재검사하고 전체 예측 파일을 봉인한다. 예측 컨테이너를 제거한 다음 정답을 연다.
6. 발행자의 정확한 물리 행 라벨을 순서·사례 ID·모집단까지 일치시켜 채점한다.
   실패 행은 분모에 남겨 정상에서는 FP, 위협에서는 FN으로 불이익을 준다. 부분 성공을 전체 성능으로 보고하지 않는다.
7. 기존 개발 자료와 특징 지문의 겹침을 별도 공개한다. 겹친 사례를 골라 지워 수치를 올리지 않는다.

고정 SHA는 무결성 경계이며 독립 심사자 서명·신원 증명은 아니다.
로컬 접근 대장도 관리자 권한 사용자의 조작까지 막는 별도 보안 장치는 아니다.

## 새 출처의 실제 평가 결과

Harrison **OpenVPN 11,090개 물리 행**을 코드 고정 후 예측·봉인·채점했다.
발행자 라벨 기준 정상11,062행·위협28행이며 이전 v44와 후보 결과는 같다.

| 지표 | 이전 v44 | 후보 v49 |
|---|---:|---:|
| TP / FP / FN / TN | 28 / 168 / 0 / 10,894 | 28 / 168 / 0 / 10,894 |
| 정밀도 | **14.29%** | **14.29%** |
| 재현율 | 100% | 100% |
| F1 | **25%** | **25%** |
| 오탐률 | 1.5187% | 1.5187% |
| 정확도 | 98.4851% | 98.4851% |
| 추론 오류 | 0 | 0 |

**목표 미달이다.** 낮은 오탐률·높은 정확도만으로 운영 품질을 합격 처리하지 않는다.
FN0도 28개의 연관된 위협 라벨 행에 대한 관측이며 독립 공격28건의 보증이 아니다.
VPN 후보를 바꾸지 않았으므로 이번 웹 기능이 VPN 성능을 개선했다는 주장도 하지 않는다.

중요한 범위 제한: 고정한 문법은 회전되지 않은 `*-access.log`/`*-error.log`만 선택했다.
ZIP **목록 메타데이터**를 확인하니 Harrison의 Apache 라벨 쌍은 `.log.1`에 있었고,
비회전 Apache 후보4개에는 정확한 라벨 쌍이 없어 제외됐다.
따라서 이번 새 출처 결과는 **VPN만** 평가했고, **웹 개선의 독립 전이 성능은 미측정**이다.
빠진 웹을 정상으로 넣거나 결과를 본 뒤 모집단/선정 규칙을 바꾸지 않았다.
회전 로그 지원은 다음 별도 개발 단계에서 고정한 뒤 새로운 예약 출처로 평가해야 한다.

사후 겹침 검사에서 **동일 원본 파일 SHA 겹침은 0**, 그러나 **현재 검출기 입력 특징 벡터는
11,090/11,090행 전부 기존 개발 자료의 벡터와 같았다**.
거친 특징이 같다는 것이 원시 이벤트까지 중복이라는 뜻은 아니다. 반대로 새 testbed라는 이유만으로
새 패턴·주체·세션의 독립성을 보증하지도 않는다. 겹친 행을 제거하지 않고 전체 수치를 유지했다.
따라서 이 결과는 출처를 분리한 제한적 전이 측정이며, 패턴까지 분리한 최종 독립 성능 평가 통과가 아니다.

동결 SHA:
`66fd8015cdd49245cefd1685b19be2f2315db06e312131d75b22065a793093d9`

예측 manifest SHA:
`1095eedf0fbeea381b7c5db160a1f1200b11e96c7823c101412db34482231ece`

코드는 `d21f11d`이며 세 모델 지문은 공유 JSON의 `models`에 있다.
원본667,985,140바이트의 발행자 MD5·로컬 SHA를 확인했고 전체 ZIP 추출 없이 필요한 멤버만 읽었다.
예측 컨테이너는 network none·비root·읽기 전용 root였고 원본 ZIP/정답은 마운트하지 않았다.
**예측 컨테이너를 제거한 뒤** 호스트 채점 단계에서 정확한 정답 쌍을 열었다.
실제 환경·마운트 경계·실행 로그 지문은 공유 JSON에서 확인한다.

Harrison은 이번 동결 후보 평가로 **소비한 출처**다. 이후 튜닝에는 이미 본 자료로 취급한다.
Wilson은 이번 작업에서도 원시 로그·라벨 본문을 열지 않은 예약 출처로 남겼다.

## 원래 목표와 남은 일

정밀도·재현율·F1 **95% 이상**, 오탐률 **5% 이하**라는 원래 목표는 유지한다.
이번 출처 분리 평가가 성공해도 **여섯 영역의 최종 독립 목표 통과가 아니다**.
Harrison은 같은 합성 데이터 생성 계열의 하나의 testbed이며 공격 템플릿·주체·기기·세션의 분리가 검증되지 않았다.
물리 행 라벨은 실제 기업 사고의 사람 검토 정답이나 세션 단위 탐지율과 다르다.
서로 연관된 많은 행을 독립 공격 표본으로 보고 신뢰구간을 좁히지 않는다.
평가 모집단도 정확한 라벨 쌍이 있는 파일에 한정한다. 라벨 없는 파일을 정상으로 간주해
분모를 늘리지 않았으므로 전체 기업 배경 트래픽의 오탐률을 대표한다고 주장하지 않는다.

다음 우선순위는 다음과 같다.

| 순서 | 할 일 | 완료에 필요한 근거 |
|---|---|---|

## 재현 방법과 보관 경계

원시 자료와 큰 특징/예측 파일은 `runtime/f1/` 아래의 무시된 로컬 산출물이다.
Git에는 코드·시험·이 문서와 비밀값 없는 집계/지문만 공유한다.
기존 개발 자료의 준비 디렉터리와 세 모델이 없으면 Git clone만으로 과거 수치가 재현되지는 않는다.
해당 로컬 모델/자료 receipt의 지문부터 대조해야 한다.

개발 전후 비교 명령은 다음과 같다. 출력은 매번 새 디렉터리여야 한다.

```powershell
.venv\Scripts\python.exe -m scripts.run_postmerge_detection --prior runtime/f1/postmerge-baseline-v49-20261114-02/run.json --output runtime/f1/postmerge-development-replay-new
```

단계별 실행기의 사용법은 `.venv\Scripts\python.exe -m scripts.run_frozen_transfer --help`에서 확인한다.
`freeze`는 완료된 수집 receipt와 원본 SHA를 고정하고, `prepare`/`predict`/`score`는 그 외부 동결 SHA를 필수로 받는다.
`score`에는 추가로 봉인된 prediction manifest의 SHA가 필요하다.
같은 출력 덮어쓰기나 사용한 출처의 새 후보 동결은 차단한다.
이미 소비한 Harrison은 고정 후보의 재현에만 사용하며 새 튜닝/독립 최종 자료로 되돌리지 않는다.

무료 집중 기능 검증:

```powershell
.venv\Scripts\python.exe -m pytest tests/test_f1_transfer_evaluation.py tests/test_f1_observations_only.py tests/test_f1_web_sensitive_read.py tests/test_f1_native_stream.py -q
```

이 테스트의 소규모 ZIP과 가짜 모델은 단계 경계·실패 처리를 검사하는 작성형 fixture다.
공개 로그의 성능이나 독립 목표 통과 사례 수에 합산하지 않는다.
