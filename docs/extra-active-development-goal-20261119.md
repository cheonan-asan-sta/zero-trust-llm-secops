# 회귀 결과 정리 전까지의 개발 목표와 완료 범위

사용자 요청으로 지속 목표를 활성화해 extra 로컬에서 아래 개발을 완료했다. 업로드·CI·병합·유료 API·AWS·Docker 자원 생성은 하지 않았다. 최종 전체 회귀 결과 정리와 실제8시간 soak는 이번 목표 범위에서 제외하며 미완료로 남긴다. 아래의 초기 진행 상황과 실패 기록은 당시 시점의 이력이다.

| 항목 | 상태 |
|---|---|
| 전체 감사 기록 문자열 검색·분석기 필터 | [구현·두 화면 연결·기능 검증 완료](extra-audit-search-20261119.md). 세션/사고 페이지 단계로 진행 |
| 세션·사고 목록 페이지 탐색 | [서버·두 화면 연결 완료](extra-collection-pages-ui-20261119.md). 네 경로 브라우저112조건, 관련 Python 양 OS72건 통과 |
| 기존 호출 경로 점검·필수 검토 정책 적용 준비 | [저장소 내 호출자 이관·로컬 검증 완료](extra-review-callers-20261119.md). Windows11통과/2제외·Linux21통과. 외부 호출자 목록·실제 조직 배포는 별도 미완료 |

감사 검색은 regex가 아닌 NFKC/casefold 기반 literal 부분 문자열 검색이다. event/analysis/actor ID, analyzer, 판단 근거·evidence, reviewer·review note를 대상으로 하며 raw payload·credential·LLM trace 전체를 검색하지 않는다. 검색어는256문자·정규화 후 UTF-8 512바이트로 제한한다. 분석기 이름은 최대64자의 식별자이며 대소문자를 구분한다. 기존 tenant·신원·원본 chain 검증은 유지한다.

현재 원본은 runtime/audit-search-focused-20261119.xml에 보존했다. 초기 묶음은80통과·3실패·2제외이며 실패3건은 검토 메타데이터를 미검토 행에 넣은 새 fixture 오류였다. 수정 과정의 SQLite CAS 요구도 기존 정책대로 유지하고 fixture를 save_review 경로로 바꿨다. 재검증 원본은 runtime/audit-search-fixture-*-20261119.xml이다. 아직 새 확대 묶음 전체 통과나 UI 완료로 기록하지 않는다.

새 cursor에는 검색 조건이 포함된다. 이전 배포의 cursor를 유지한 롤링 배포에서는 snapshot 식별 표현이 달라질 수 있으므로, client가 오류/기준 불일치 시 명시적으로 새 목록을 읽어야 한다. 과거 cursor를 자동 변환하거나 다른 검색 조건에 재사용하지 않는다.

이번 목표의 개발 범위는 완료했다. 로컬 기능 검증을 기업 SSO·실제 독립 보관·다중 호스트 인수나 탐지 F1 목표 달성으로 바꾸지 않는다.

검색 단계 후속 검증: Windows/Linux 각각83통과·2제외, 이후 추가 커서 경계3건 양쪽 통과. 실제 새 브라우저18·기존 워크벤치45·대시보드38조건 통과. 초기 실패 원본은 보존하며 위 기록은 당시 시점이다. 후속 목록·호출자·witness 개발도 위 표의 범위에서 완료했다.

남긴 작업은 최종 전체 회귀와 결과 정리, 실제8시간 soak, 실제 조직의 외부 client 목록·필수 정책 배포, 기업 신원·별도 권한/호스트의 독립 보관 인수다. 추가 탐지 성능 개선도 이번 UI·감사 기능 개발과 별개다. 모델·정답·평가 예측을 바꾸지 않아 기존 합성 개발360건의 F1 93.41%는 그대로다. witness는 일회성 로컬 CLI이며 online 필수 gate·자동 수집 scheduler를 구현 완료로 표시하지 않는다.
