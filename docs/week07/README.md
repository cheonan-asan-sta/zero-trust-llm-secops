# 7주차: 1차 분석 프로토타입 구현

## 계획 목표

로그 생성기, LLM 분석 모듈, 구조화 응답 파서, 정책 매핑 모듈을 하나의 분석 경로로 연결한다.

## 구현 결과

- 공통 `Analyzer` 인터페이스 아래 규칙 기반 분석기와 OpenAI 분석기를 분리했다.
- 규칙 분석기는 인증, 기기, 행위, 자원 민감도, 정책 위반 신호를 합산해 0~100 위험 점수를 계산한다.
- OpenAI 분석기는 Responses API의 구조화 출력 결과를 `SecurityAssessment`로 직접 검증한다.
- 분석 결과에 위험도, 위반 유형, 한국어 판단 근거, 권고 조치, 신뢰도, 증거 필드와 사람 검토 필요 여부를 포함했다.
- `POST /analysis`에서 분석, 안전 보정, 정책 미리보기, 감사 저장을 연속 처리한다.
- API 키가 없는 환경에서도 규칙 모드로 전체 기능을 실행할 수 있게 기본 모드를 분리했다.

## 처리 흐름

`합성 이벤트 → 분석기 → 안전 보정 → 정책 미리보기 → 감사 저장 → API 응답`

분석 제공자가 실패하면 내부 오류나 키 정보를 노출하지 않고 안전한 오류 응답을 반환한다. 실제 계정이나 세션을 변경하는 실행기는 연결하지 않았다.

## 코드 근거

- 분석기 계약: `app/analyzers/base.py`
- 규칙 기준선: `app/analyzers/rule_based.py`
- OpenAI 구조화 분석: `app/analyzers/openai_analyzer.py`
- 통합 경로: `app/main.py`의 `_analyze_event`
- 구조화 출력 검사: `tests/test_openai_analyzer.py`, `tests/test_models.py`
