# 구조화 탐지와 반복 평가

## 구조화 탐지 조건

시나리오는 설명용 `observable_signals`와 별도로 실행 가능한 `detection_conditions`를 가진다. 조건은 이벤트의 허용된 필드 경로, 연산자, 비교값, 사람용 설명으로 구성된다.

허용 연산자는 `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `in`, `not_in`이다. 동적 코드 실행이나 임의 표현식 평가는 사용하지 않는다. 조건 평가기는 Pydantic 모델의 필드만 순회하며, 알 수 없는 경로는 실패 처리한다.

## 반복 평가

`POST /evaluation/run`은 평가 라벨을 분석기 입력에서 제외한 뒤 8개 기준 사례를 분석한다. 결과는 다음 지표를 제공한다.

- 위험도 정확도와 대응 정확도
- 위협 탐지 정밀도, 재현율, F1
- 구조화 결과 유효율
- 평균과 P95 응답시간
- 계획서 목표별 통과 여부

규칙 분석기는 외부 비용 없이 회귀 기준선으로 사용한다. OpenAI 평가는 명시적으로 `analyzer=openai`를 요청하고 API 키가 준비된 경우에만 실행한다. 평가 실패는 정상 결과로 간주하지 않고 JSON 유효 실패와 오답으로 계산한다.

## API 연결

| 경로 | 역할 |
|---|---|
| `POST /scenarios/evaluate` | 한 이벤트의 시나리오별 조건 충족률과 정확 일치 조회 |
| `POST /analysis/batch` | 최대 20건, 동시 3건 제한 분석 및 감사 기록 |
| `POST /evaluation/run` | 8개 기준 사례를 1~3회 반복 평가 |

대시보드의 반복 평가 버튼은 현재 분석 모드에 맞춰 같은 지표를 표시한다.

## 2026년 11월 1일 확장 탐지 평가

상태: **개선 전 기준선 확정**. 탐지기 기준 커밋은 `54d43af`이며, 이번 작업에서는 Sigma 규칙·탐지 임계값·정규화·제로트러스트 정책 집행 로직을 개선하지 않는다. 아래 목표 미달 결과와 실패 사례를 후속 개선의 비교 기준으로 보존한다.

기존 공개 로그 12건은 원본 재생·정규화·규칙 연결의 고정 회귀 표본으로 보존한다. 새 평가는 **운영상 정상 업무와 위협을 구분할 수 있는가**를 확인하는 별도 합성 평가다. 현재 Sigma 탐지기의 한계를 확인하는 작업이며 LLM 성능·세션 정책 집행·사건 상관분석 전체를 검증한 결과가 아니다.

### 데이터와 시나리오

| 구분 | 입력 | 정상 / 위협 | 시나리오 계열 | 고유 신호 패턴 |
|---|---:|---:|---:|---:|
| 개발용 | 360건 | 180 / 180 | 36개 | 310개 |
| 평가용 holdout | 360건 | 180 / 180 | 36개 | 321개 |
| 합계 | 720건 | 360 / 360 | 72개 | 631개 |

시나리오는 인증 이상·기기 상태·권한 범위·원격 접속·횡적 이동·자료 유출의 6개 영역으로 나눈다. 각 영역은 개발용 정상 3계열·위협 3계열과 평가용 정상 3계열·위협 3계열을 가진다. 각 계열에서 10개 입력을 만들며 역할·행위·기본 공격 수법을 유지하면서 실패 횟수·요청 빈도·접근 자원 수·민감도 등 보조 맥락을 변화시킨다. 시나리오에서 고정한 핵심 조건은 보조 변형으로 덮어쓰지 않는다.

정상 업무에는 MFA를 완료한 출장/VPN 접속, 건강한 기기·승인된 BYOD 등록, 역할에 맞는 관리 작업, 승인된 원격 지원·배포·백업·이관을 포함한다. 위협에는 비인가 기기·권한 초과·대량 유출뿐 아니라 분산 로그인 시도, 성공한 도난 자격증명, 관리 기기의 침해, 임계값 바로 아래의 횡적 이동·저속 유출, 원격 행위나 필수 역할이 로그에 제대로 기록되지 않은 사례를 포함한다.

라벨은 탐지 결과에서 만들지 않는다. `scripts/build_detection_benchmark.py`에 업무 권한·공격 의도와 근거를 먼저 선언하고 데이터·라벨·대상 규칙·분할을 고정한다. 승인 사례는 사용자·자원·행위·시간 범위가 있는 합성 승인 정보를 포함한다. 라벨의 기준은 현재 규칙 선택 조건의 만족 여부와 다르다. 승인된 정상 업무에서 경보가 발생하면 오탐이고, 현재 선택 조건 밖의 실제 위협은 미탐으로 집계한다. 관측 정보만으로 구분하기 어려운 사례도 삭제하지 않는다.

이 자료는 팀 프로젝트용으로 새로 작성한 **합성 데이터**이며 MIT 라이선스를 적용한다. 공개 원본을 추가 확보한 것으로 기록하지 않는다. 라벨 상태는 `author_assigned_pending_independent_team_review`로, 다른 팀원의 독립 검토가 아직 필요하다. 기존 규칙을 알고 작성한 자료이므로 외부 블라인드 검증이라고 표현하지 않는다.

### 분할과 재현성

- 같은 시나리오 계열의 모든 변형을 한 분할에 둔다. 개발·평가 사이의 계열·세션·사용자·기기와 동일 신호 패턴 중복은 모두 0건이다.
- 개발 시각은 2026년 10월 1일 이후, 평가 시각은 10월 20일 이후로 고정하고 개발의 마지막 관측이 평가의 첫 관측보다 앞서는지 검사한다.
- 이벤트·사용자·기기·자원 식별자는 시나리오명 대신 불투명 식별자를 사용한다. 라벨·라벨 근거·기대 규칙 목록·분할 정보는 탐지 입력에서 제외한다.
- 식별자·시각·부서·IP 등의 부수 맥락을 제거한 신호 패턴도 대조한다. 같은 분할에 남은 반복 패턴은 건수를 공개하고 중복 제거 성능을 별도로 제공한다.
- `app/data/benchmark/manifest.json`에 생성기·시나리오 목록·JSONL 지문과 판정 기준을 고정한다. 파일 손상, 라벨/분할 불일치, 중복 ID, 분할 간 누출은 평가를 시작하기 전에 거부한다.

평가 자료를 확인한 이번 결과에 맞춰 규칙이나 95%/5% 기준을 변경하지 않았다. 이후 개선은 개발 자료에서 진행하고, 공개된 v1 평가 자료는 회귀 자료로 취급한다. 다음 독립 성능 주장을 위해서는 새 미공개 평가 계열과 실제 로그 검증이 필요하다.

### 집계와 불확실성

이벤트별로 경보가 하나 이상 발생했는지와 운영상 위협 라벨을 비교해 TP·FP·FN·TN을 센다. 정밀도는 `TP/(TP+FP)`, 재현율은 `TP/(TP+FN)`, F1은 `2TP/(2TP+FP+FN)`, 오탐률은 `FP/(FP+TN)`이다. 분모가 0인 지표는 `null`로 남기고 합격시키지 않는다. 실행 오류도 버리지 않고 개별 오류와 건수를 기록하며 품질 게이트를 실패시킨다.

규칙별로 기대 규칙과 실제 탐지를 다시 비교한다. 예를 들어 원격 접속 경보가 발생해 전체 이벤트는 탐지됐더라도 횡적 이동 규칙을 놓쳤으면 해당 규칙의 미탐이다. 영역별 지표와 6개 규칙의 매크로 평균도 제공한다. 전체 지표가 좋아도 개별 규칙이 기준에 미달하면 합격시키지 않는다.

같은 계열의 변형을 독립 공격 표본으로 가정하지 않는다. 정상·위협 계열을 각각 복원추출하는 **계열 단위 부트스트랩 1,000회**, 고정 시드 `20261101`로 전체 지표의 95% 백분위 구간을 계산한다. 동일 행을 반복해서 늘려도 이 구간이 좁아지지 않는지 시험한다. 이는 작성한 36개 평가 계열 사이의 변동성 추정으로, 실제 기업 모집단의 보장 구간이 아니다. 정상/위협 50:50 구성도 실제 침해 발생 비율을 대표하지 않는다.

### 실행과 결과 확인

```powershell
# 생성기와 데이터 변경 시에만 재생성하고 새 지문을 검토한다.
python -m scripts.build_detection_benchmark

# 두 분할의 전체 결과와 실패 사례를 파일로 남긴다. 실행 성공과 품질 합격은 다르다.
python -m scripts.evaluate_detection_benchmark --output-dir runtime/detection-benchmark

# 목표 미달이면 결과를 보존한 뒤 종료 코드 1을 반환한다.
python -m scripts.evaluate_detection_benchmark --require-targets

python -m pytest -q
python -m ruff check .
```

`GET /evaluation/detection-benchmark`는 viewer 권한으로 평가용 결과를 반환한다. `?split=development`로 개발용을 지정할 수 있으며 두 분할을 섞는 `all`은 허용하지 않는다. 기존 `/evaluation/detection-quality` 응답에는 공개 고정 회귀 범위와 확장 평가 경로를 명시했고, 대시보드의 기존 공개 12건 판정도 해당 범위가 드러나도록 표시했다.

재현 가능한 전체 사례·예측·실패·지문은 [개발 결과 JSON](../benchmark-results/development.json)과 [평가 결과 JSON](../benchmark-results/holdout.json)에 있다. API와 명령행은 로컬 정규화·Sigma 규칙만 사용하며 유료 모델·AWS·실계정에 연결하지 않는다.

## 로컬 접근 집행 검증

사전에 예상 허용 여부를 기록한 로컬 사례 200건에서 접근 API의 HTTP 응답과 보호 콘텐츠 반환을 확인한다. 허용과 거절은 각각 100건이며, 시나리오 계열 10개를 각각 20회 실행한다. 실제 API 키 검사, 서명된 인증 신호, 격리된 SQLite 저널을 사용해 인프로세스 FastAPI 경로를 검증한다.

```sh
python -m scripts.evaluate_local_access --output-dir runtime/m7/local-access
```

새 출력 디렉터리를 지정한다. `plan.json`에 시나리오와 기대 결과를 먼저 기록하고 `report.json`에 응답, 요청 주체 및 대상의 저널 대조 결과와 계열별 집계를 저장한다. 접근 집행의 분모는 시나리오 실행 건수다. 탐지 성능은 위 Sigma 기준선과 M7 평가에서 별도로 집계한다.

로컬 전체 자동 테스트는 기존 381건에 평가기 검증 40건을 더한 **421건 통과**, Ruff와 JavaScript 문법 검사도 통과했다. 품질 기준 미달을 올바르게 계산·보고하는지 검증하는 시험이므로 자동 테스트 통과를 탐지 성능 합격으로 해석하지 않는다. Docker 엔진이 꺼져 있어 이번 컨테이너 시험은 수행하지 않았다. 데이터·지문 파일은 운영체제가 달라도 같은 바이트를 사용하도록 LF로 고정한다.

방법 참고는 [그룹이 분할 사이에 겹치지 않는 scikit-learn의 GroupKFold](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupKFold.html)와 [백분위 부트스트랩 절차를 설명한 SciPy 문서](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)다. 이 프로젝트는 해당 라이브러리를 추가 설치하지 않고 표준 라이브러리로 계열 분할 검증과 재표집을 구현했다.
