# 정책 예외 설계

## 목적

단순한 승인 여부 불리언만으로는 누가, 언제까지, 어떤 범위에 예외를 승인했는지 감사할 수 없다. 예외 객체는 승인 사실과 적용 범위를 함께 검증하며, 조건을 벗어난 예외는 이벤트 입력 자체를 거부한다.

## 필드

| 구분 | 필드 | 검증 |
|---|---|---|
| 식별 | `exception_id` | `EXC-` 접두사와 제한된 문자 |
| 승인 | `approved_by`, `reason` | 승인자와 사유 필수 |
| 시간 | `valid_from`, `valid_until` | 시간대 필수, 종료가 시작보다 늦어야 함 |
| 주체 | `scope.user_ids`, `scope.roles` | 비어 있으면 해당 축 전체 허용 |
| 대상 | `scope.resource_ids`, `scope.resource_types` | 이벤트 자원과 일치해야 함 |
| 행위 | `scope.actions` | 허용된 이벤트 행위만 사용 |
| 용량 | `scope.max_download_volume_mb` | 이벤트 다운로드량이 상한 이하여야 함 |

`policy_exception_approved=true`이면 예외 객체가 반드시 있어야 하며, 예외 객체가 있으면 승인 불리언도 반드시 참이어야 한다. 이 이중 검사는 기존 관찰 신호와의 호환성을 유지하면서 상세 감사 정보를 강제한다.

## 안전 처리

- 유효기간이 지난 예외는 분석기로 전달하지 않는다.
- 역할·자원·행위·용량 중 하나라도 범위를 벗어나면 입력을 거부한다.
- 유효한 예외가 있어도 위험 신호를 삭제하지 않는다.
- 예외 ID는 대응 미리보기에 기록해 어떤 승인 근거가 사용됐는지 남긴다.
