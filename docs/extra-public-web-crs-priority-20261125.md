# CRS 추가 신호의 우선 검토 분리

2026년 11월 25일 · `extra` · 평가기 `bd13425` · 로컬 CPU 검증.

## 변경

이전 공개 Apache 평가에서 CRS 보강으로 위협 72건과 정상으로 표시된 76건이 기존 경보에 추가됐다. 후자의 응답은 302 또는 404였고, 위협 회복 72건 중 71건도 302 또는 404였다. 응답 코드만으로 경보를 억제하면 위협도 다수 떨어지므로 우선순위 판단에 사용하지 않았다.

새 로컬 실행기는 CRS 일치와 기존 분석기가 추출한 요청 대상의 근거가 같은 계열에서 일치하면 우선 검토로 분류한다. 일치한 분류에 민감 파일, SQL 삽입, 명령 실행 근거를 대응시킨다. Referer·User-Agent는 이 판단에 쓰지 않는다. 두 판정의 입력은 같은 요청이므로 별도 인증원에서 확인한 권한·실행 증거로 보지 않는다. 근거가 충분하지 않은 CRS 일치도 일반 검토에 남긴다. 기존 경보를 뒤집거나 자동 정책을 실행하는 경로는 추가하지 않았다.

## 결과

| 재사용한 평가 집단 | 기존에 더해진 전체 CRS 신호 (위협 / 정상) | 우선 검토 (위협 / 정상) | 일반 검토 (위협 / 정상) |
| --- | ---: | ---: | ---: |
| 합성 HTTP 요청 791건 | 53 / 0 | 30 / 0 | 23 / 0 |
| 공개 Apache 로그 213,205행 | 72 / 76 | 22 / 9 | 50 / 67 |

Apache에서 정상 라벨을 가진 우선 검토는 **76건에서 9건으로 감소**했다. 회복한 위협 72건 중 22건이 우선 검토에 남고 50건은 일반 검토로 이동했다. 정상 67건도 일반 검토로 이동했으므로 사람에게 보이는 전체 검토량과 전체 CRS 오탐은 그대로다. 이전 웹 탐지기의 기탐 위협은 두 집단 모두 손실 0건이다.

| 기존 경보 + 우선 검토만 양성으로 계산 | 정밀도 | 재현율 | F1 | 오탐률 |
| --- | ---: | ---: | ---: | ---: |
| 합성 HTTP 791건 | 100.00% | 41.67% | 58.82% | 0.00% |
| 공개 Apache 213,205행 | 1.32% | 84.95% | 2.61% | 16.23% |

우선 검토만 채점하면 이전 전체 CRS 결합보다 재현율이 내려간다. Apache에서 우선 검토의 새 정상 9건이 남았고, 기존 오탐도 그대로여서 운영 경보 통합은 보류했다. 이 수치는 앞서 본 합성 자료와 Apache 회귀 자료의 검토 결과이며 새 독립 평가 성적으로 합산하지 않는다. [이전 CRS 실험](extra-public-web-target-crs-20261125.md)

## Apache 정답 매칭 방식 검증

정상 라벨을 가진 우선 검토 9건과 위협 라벨을 가진 22건의 봉인된 판정을 유지하고, 발행자 YAML의 리터럴을 로그에 대조하는 방법만 바꿨다. 기존 채점은 규칙 하나의 문자열을 모두 찾아야 일치로 판정하고, 대소문자와 인코딩을 원문 그대로 비교한다.

| 대조 방식 | 전체 213,205행에서 새로 일치 / 기존 일치에서 제외 | 새 우선 검토 31행에서 새로 일치 / 기존 일치에서 제외 |
| --- | ---: | ---: |
| 기존 리터럴 일치 | 0 / 0 | 0 / 0 |
| 대소문자를 무시한 일치 | 68 / 0 | 6 / 0 |
| URL percent 디코딩 1회 후 대소문자를 무시한 일치 | 97 / 5 | 7 / 1 |

발행자 필터 일치 여부가 대조 방식에 따라 달라졌다. 이 결과만으로 요청의 실제 공격 여부를 확정할 수 없어 기존 라벨 9건과 22건, 운영 탐지 규칙, 평가 지표를 유지했다. 상태 코드와 인코딩 유무는 정상 라벨과 위협 라벨 양쪽에 나타나므로 경보 제외 조건으로 사용하지 않았다. 소스와 두 예측 봉인을 대조한 로컬 재실행에서 집계 지문이 일치했다. 원시 요청은 로컬에 두었다. [Apache 정답 민감도 집계](infrastructure-results/public-web-crs-label-sensitivity-20261125.json)

원인을 좁히기 위해 구조가 일치하는 Apache 행 중 Referer가 있는 126,153행에서 해당 헤더의 문자만 같은 길이의 `-`로 바꾸고 기존 탐지기를 다시 돌렸다. 시각·요청 대상·상태·User-Agent·행 길이를 유지했다. 전체 213,205행의 전후 예측 파일 지문이 `62fd7968be166a06f7b2036f32aca7a75dd686eb1700b77aba6e341d3963b563`으로 같았다. 이 자료의 기존 오탐 34,506건은 Referer를 제거하는 것만으로 줄지 않았다. 현재 라벨에서 이 오탐을 유지한 채 위협 545건을 전부 찾아도 정밀도는 최대 1.55%다. 우선 검토에 신호를 더하는 실험과 기존 경보의 오탐을 줄이는 검증이 모두 필요하다. [Referer 영향 집계](infrastructure-results/public-apache-referer-sensitivity-20261125.json)

11월 26일에는 동일 집단의 고정 웹 모델 원점수를 다시 추출했다. 기존 경보 34,947건은 모두 최고 점수 `1.0`이었다. 기존 위협 탐지 441건과 정상 경보 34,506건이 이 값에 함께 있었다. 원점수는 전체에서 6개 값만 나왔고, 유효한 임계값으로 만들 수 있는 모든 판정을 검사해도 오탐률 5% 이하인 경우는 없었다. 임계값과 기존 경보는 그대로 두었다. [임계값 진단 집계](infrastructure-results/public-apache-frozen-score-ceiling-20261126.json)

기존 모델에 전달되는 원래 특징 전체를 비교하니 7,607개 조합 중 16개 조합에서 정상과 위협 라벨이 함께 나타났다. 이 가운데 기존 기탐 441건을 유지하려면 동일 특징의 정상 26건도 경보에 남는다. 모든 위협을 탐지한다고 가정한 정밀도의 낙관적 상한은 95.45%다. 이론 상한은 현재 모델이 재현한 수치가 아니다. 원래 특징으로도 점수 표현이 더 세밀해질 여지가 있지만, 같은 특징을 가진 요청은 요청별 본문·권한·인증 결과처럼 별도 관측이 있어야 구분할 수 있다. [특징 충돌 집계](infrastructure-results/public-apache-existing-feature-collisions-20261126.json)

같은 자료에서 User-Agent가 관측된 212,714행의 ASCII 영숫자만 같은 길이로 치환했다. 요청 대상, 응답, Referer와 원본 라벨을 유지했다. 기존 위협 탐지 441건은 그대로이고 오탐은 34,506건에서 34,518건으로 늘었다. Referer나 User-Agent를 중립화하는 방법은 이 표본에서 큰 오탐 원인을 제거하지 못했다. 초기 실행은 Apache 파서가 이미 소비한 응답 코드를 다시 기대해 유효하게 치환한 행이 0건이었다. 수정 실행에서 치환 건수와 행 길이 보존을 확인했다. [User-Agent 영향 집계](infrastructure-results/public-apache-user-agent-sensitivity-20261126.json)

기존 웹 모델의 점수 1.0은 확률 변환 과정에서 반올림된 결과가 아니라 고정 분류 트리의 두 말단 노드에서 나왔다. 두 노드 모두 기존에 탐지한 위협이 있어 노드 기준으로 오탐을 줄이면 이 탐지를 잃는다. 보조 트리의 말단과 기존 보정 사유를 함께 가르면, 정답을 알고 구분에 유리한 조합만 남기는 낙관적 계산에서도 기존 위협 441건을 모두 유지하려면 오탐 최소 21,098건이 필요했다. 오탐률은 최소 9.92%, 정밀도는 최대 2.05%였다. 이 계산은 같은 데이터의 구조적 한계이며, 트리나 운영 임계값을 변경하지 않았다. [고정 분류 트리의 판정 집계](infrastructure-results/public-apache-web-leaf-diagnostics-20261126.json)

## 재현

로컬 회귀 159개와 Ruff를 통과했다. 요청 대상에 근거가 없거나 규칙 계열이 다른 경우, Referer와 User-Agent를 입력에서 제외하는 경우를 별도로 확인했다. 네트워크 연결을 차단한 합성 791건 재실행에서 봉인이 같았다. 유료 API·AWS 호출은 0회다. [집계 결과와 지문](infrastructure-results/public-web-crs-priority-20261125.json)

이전 웹 탐지 봉인과 CRS 봉인을 지정한다. `capture`는 관측과 CRS 결과를 읽고, `score`에서만 발행자의 정답을 대조한다. 출력은 새 로컬 디렉터리를 사용한다.

```powershell
python -m scripts.evaluate_public_web_crs_priority capture <access|apache> <원본> <기존-봉인-폴더> <CRS-봉인-폴더> <새-출력> <기존-seal-SHA256> <CRS-seal-SHA256>
Get-FileHash <새-출력>/seal.json -Algorithm SHA256
python -m scripts.evaluate_public_web_crs_priority score <access|apache> <원본> <기존-봉인-폴더> <CRS-봉인-폴더> <새-출력> <기존-seal-SHA256> <CRS-seal-SHA256> <새-seal-SHA256>
```

python -m scripts.audit_public_web_crs_labels <Apache-원본> <기존-봉인-폴더> <우선-검토-봉인-폴더> <새-집계-JSON> <기존-seal-SHA256> <우선-검토-seal-SHA256>
