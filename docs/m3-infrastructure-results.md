# M3 인프라 검증 결과 · Windows / Linux Docker

2026년 11월 3일 · 작업 브랜치 `feature/chaeheeju-m3-infra-validation` · M3 기준 `82285c6` + 실행 코드 지문은 [원자료 JSON](infrastructure-results/m3-windows-20261103.json)의 `source_sha256`를 따른다. GitHub PR #1의 백엔드를 재사용한 인프라 담당 검증이며 독립 팀원 검토는 대기 상태다.

전체 시험 시간은 업무 처리 지연이 아니다. 545건은 새 계측 검증21건을 기존524건에 더한 조건별 자동 시험 수이며 코드 커버리지·탐지 합격률을 뜻하지 않는다. Docker 테스트 컨테이너는 네트워크 없이 CPU2·메모리1GiB로 실행했다.

## 환경과 지연 관측

호스트는 Windows11, Docker Desktop Linux x86_64 엔진29.8.2이며 엔진에 CPU18개·메모리8,104,210,432바이트를 제공했다. 두 측정 서비스는 각각 CPU1·메모리256MiB·PID128로 제한했다. Windows pytest와 Docker 테스트 작업을 병행한 개발 환경이다. 무부하·고정 부하 운영 평가와 다르다.

client clock은 QueryPerformanceCounter 기반 `perf_counter`, 기록 해상도는 100ns다. 이 값은 측정 정확도 보장이 아니다. polling은 0.1초, worker 시험 프로필은 0.05초이며 기본 운영 poll 0.5초와 구분한다. 아래 수치는 ms 단위, nearest-rank 경험 분위수다. 각 군이 3건이므로 P95는 그 군의 최대값이다.

| 구간 | 관측 수 | 서버 접수→완료 P50 | 서버 접수→완료 P95 | client POST 시작→첫403 확인 P50 | client POST 시작→첫403 확인 P95 |
|---|---:|---:|---:|---:|---:|
| 정상 worker | 3 | 112.588 | 183.882 | 194.034 | 356.852 |
| 의도적 worker 중단 | 3 | 11180.894 | 13520.752 | 11313.693 | 13604.511 |

정상 처리와 의도적 중단을 합산하지 않았다. 중단 구간에는 worker를 멈춘 시간·앱 재시작·재개가 포함된다. client 값은 영수증 polling과 다음 접근 요청을 포함한 관찰 상한이며 실제 공격 발생부터의 지연·지속 연결 강제 종료·RTO를 뜻하지 않는다.

## 자원 표본

총 56개 컨테이너 표본을 수집했다. 표본 요청 간격은 1초이며 CLI 실행 시간이 추가되므로 실제 관측 시각은 JSON을 따른다. CPU는 CLI 보고 비율 그대로, 메모리는 cache를 차감한 CLI 반올림값의 MiB 변환이다. 블록I/O·네트워크 누적 카운터와 PID도 원자료에 포함한다.

| 서비스 | 표본 수 | 표본에서 관찰한 CPU 최대 | 표본에서 관찰한 메모리 최대 |
|---|---:|---:|---:|
| app | 28 | 106.22% | 90.12MiB |
| signal-worker | 28 | 100.50% | 71.78MiB |

표본 사이의 순간 최대값을 보장하지 않는다. I/O 누적 카운터는 저장 공간 사용량·IOPS가 아니다. 소표본 수치로 정상 운영 P95·처리량·확장성·RPO/RTO 목표 달성을 주장하지 않는다.

## 확인한 기능과 범위

- 정상 서명 세션 접근200, 관련 사용자 세션 두 개 회수 후 미사용 허용도403, 무관 세션200 유지.
- 정확한 재전송은 효과·버전 중복 없음, 같은 ID의 다른 내용은409.
- worker 중지 중 접수한 pending이 앱 재시작 후 유지되고 worker 재개 후 completed로 전환.
- 앱·worker를 다시 시작해도 영수증·회수 버전이 보존되고 무관 세션 접근은 유지.
- 네트워크가 없는 worker가 공유 SQLite와 공개 등록만으로 같은 기능을 수행.

실제 IdP/EDR·GuardDuty·mTLS·독립 업무 PEP·운영 백업 복원은 검증하지 않았다. C03 스캐너·신규 AI 후보의 실제 비교와 팀원의 독립 검토도 남아 있다. 기존 holdout 정밀도64.29%·재현율50.00%·F1 56.25%·오탐률27.78%와 품질 gate=false는 변경하지 않았다.

## 실패와 보완 이력

초기 Windows 전체 실행은522건 통과·2건 실패였다. POSIX 모드0644/0755를 Windows에도 요구한 공개 파일·디렉터리 시험이었다. 시험 개인키의 명시적 디스크 저장을 제거하고 공개 파일의 모드 검사는 POSIX에서 수행하며 내용·서명·비밀값 비노출 검사는 모든 플랫폼에서 유지했다.

첫 Docker 테스트 이미지는 Windows에서 복사한 모듈 스크립트가 실행 가능 모드로 보여 Ruff EXE002 5건에서 멈췄으며 pytest는 실행하지 못했다. 테스트 이미지에서 모듈은0644, shebang 수집기는0755로 정규화한 뒤 최종 전체545건이 통과했다.

첫 Compose 반복도 기능3회는 통과했지만 Windows의 기본 monotonic 시계가15.625ms 해상도임을 확인했다. 고해상도 시계로 바꿔3회를 다시 실행한 최종 측정만 위 표와 공유 JSON에 사용했다. 최초 기록은 로컬 `runtime/m3-validation/infra-652c5a242897/`에 보존했다.
