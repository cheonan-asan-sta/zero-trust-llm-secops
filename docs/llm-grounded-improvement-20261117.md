# LLM 분석 개선·실제 API 검증 기록

2026-11-17 · 로컬 구현 및 실제 OpenAI 호출 · 개발 평가 · 목표 미달 · CI/push/병합 없음

## 결론

LLM에 기존 서버 탐지 정책과 관측 근거를 전달하고, 관측 필드 경로만 인용하는 구조화 응답과 전체 이벤트 교차 검토 옵션을 구현했다. 실제 OpenAI 요청 **168회**, 사용량 기반 비용 추정 **$0.365284**다. 관련 기능 테스트 **60건 통과**, Ruff 통과. AWS·Docker를 새로 실행하지 않았다.

최신 grounded+policy 후보는 12건 전이 재점검에서 기존 legacy F1 **71.43% → 85.71%**, TP5→6·FN1→0이었다. 정상 2건은 UNKNOWN이어서 보수 집계상 FP2다. 그러나 24건에서 legacy F1 69.23% 대비 최종 후보 71.43%인 반면 FP5→6으로 늘었다. 두 비교의 legacy는 앞선 요청 결과를 재사용했으므로 같은 시각의 재실행 대조가 아니다. 단일 호출 변동도 포함한다. **전체 개선·오탐 비증가·95% 목표 달성으로 승인하지 않았다.**

이 자료는 36개 합성 개발 family를 반복 사용한 탐색 결과다. 기존 1,681,815행 native 실측이나 원래 6영역 독립 평가를 대체하지 않는다. 공유 감사/VPN F1 80%라는 마지막 native 검증 결과는 그대로이며 이번에 native 판정기를 재평가하지 않았다.

## 주제에 맞춘 LLM 역할과 구현

1. **관측 결합과 의미 분석:** 사용자·기기·인증·네트워크·행동 관측 및 OCSF 정규화 문맥을 읽고 위반 종류·위험·우선 검토 이유를 제안한다. IP나 계정 이름만으로 실제 사람·권한·기기 건강을 검증했다고 쓰지 못하게 했다.
2. **정책을 고려한 분석:** 저장소의 approved Sigma 6개에서 제목·설명·탐지 조건·오탐 설명·등급만 서버가 로드한다. 예를 들어 500MB 경계는 모델이 추측할 값이 아니라 기존 정책 조건이다. 이벤트 텍스트로 정책 문맥을 덮어쓸 수 없다. label·test_case_ids·예상 rule ID·ground_truth는 모델에 보내지 않는다.
3. **근거 설명:** 이벤트별 non-null 필드 경로를 응답 schema enum으로 제한하고 반환 뒤에도 존재·중복을 검사한다. 첫 초안의 없는 경로 인용은 거절됐다. enum 도입 뒤 형식 오류는 줄었지만 **인용 경로 존재가 설명의 의미적 타당성이나 사실·신원 검증을 보증하지 않는다.**
4. **적극적 교차 검토:** `HYBRID_REVIEW_ALL=true`이면 규칙 confidence가 높아도 LLM을 호출한다. 기존에는 confidence 기준으로 호출을 생략할 수 있었다. 기본값 false는 유지했다.
5. **판정과 실행 경계:** LLM은 구조화된 분류·이유·권고만 반환하며 도구나 권한 변경 수단을 받지 않는다. grounded 결과는 항상 사람 검토를 요구한다. hybrid는 기존 규칙의 위험을 낮추지 않는 max 병합을 유지한다. 그러므로 아래 **LLM 단독** 수치를 hybrid의 오탐 감소나 실제 차단 성능으로 설명하면 안 된다.

API timeout·오류·없는 근거 경로는 hybrid에서 기존 규칙 결과와 사람 검토로 전환한다. 현재 기본 `ANALYZER_MODE=rule`, `OPENAI_PROMPT_MODE=legacy`, `HYBRID_REVIEW_ALL=false`는 유지했다. 개선 모드는 선택 설정이며 이 작업이 백그라운드 서버를 켜거나 운영 트래픽에 유료 호출을 활성화한 것은 아니다.

## 평가 자료와 재현 근거

- `app/data/benchmark/cases.jsonl`의 `development` split만 사용했다. 앞 묶음은 domain×정상/위협별 서로 다른 family2개씩 총24건(12/12), 뒤 묶음은 앞 family를 제외하고1개씩 총12건(6/6)이다. 별도 독립 평가 split은 사용하지 않았다.
- case를 정렬해 선택하며 정답은 채점용 별도 truth 파일에만 보관했다. 이벤트 ID는 SHA256으로 치환하고 분석 입력에서 제거했다. 기존 정답·라벨 정책·모집단을 수정하지 않았다. 이벤트의 현장 신호 자체에는 정답과 상관되는 특징이 존재하며 합성 개발 자료라는 한계가 있다.
- 원본 cases SHA256: `de6ecc654b55450a9b5636dd29f08742c056e9be43c6458aabecf000a407775f`.
- 12건은 첫 점검 이후 응답을 읽고 수정에 사용했으므로 최종 독립 holdout이 아니다. 새 독립 자료/라벨 검토와 후보 동결이 남아 있다.
- 실행기 [evaluate_llm_grounded.py](../scripts/evaluate_llm_grounded.py), 공개 [계획·행별 예측·사용량·지문 JSON](infrastructure-results/llm-grounded-improvement-20261117.json), [기능 JUnit](infrastructure-results/llm-grounded-functional-20261117.xml).
- 정확한 요청·응답·truth와 실행 중 source snapshot은 로컬 `runtime/llm/grounded*-20261117/`에 보존했다. Git 제외 경로라 팀원이 checkout만으로 당시 원문 응답까지 얻지는 못한다. 공개 JSON에는 원문 대신 익명 사례별 예측·오류·토큰·모델·시간과 원문 파일 SHA를 담았다.
- 정책 문맥 실험의 3개 실행 소스는 기록된 source_pins와 일치하는 snapshot으로 보존했다. 그 뒤에는 formatter·미시도 분모 보존·실패 시 종료 코드·요금 URL 수정만 했고 추가 API 호출은 하지 않았다. 초기 run은 반환 전 검증 실패 응답의 raw assessment를 저장하지 않았으므로 그13건의 의미적 응답은 복원할 수 없다.

## 선택 설정과 다음 개발 순서

[선택 분석 profile](../infra/llm-grounded.example.env)은 mini 고정 버전과 grounded/full review를 지정한다. 기존 secret 설정을 재사용하고 필요한 값만 적용한다. 키를 profile에 적거나 Git에 올리지 않는다. 실제 환경 설정은 이번에 수정하지 않았다. 예를 들어 다음 명령은 **유료 재실행**이며 자동으로 실행되는 테스트가 아니다.

```powershell
python -m scripts.evaluate_llm_grounded --directory runtime/llm/new-review --key-env-file <기존-키-env-경로> --grounded-only --max-budget 1
```

1. 남은 FP의 승인 예외·역할 비교·불확실성 처리를 분리해 검토한다. 모델 설명과 violation 종류가 충돌하는 사례도 있다. 정답을 프롬프트에 넣거나 모델 출력을 정답으로 쓰지 않는다.
2. 호출 신원·기기·권한 검증기의 실제 증명 결과와 신선도/범위를 구조화해 전달한다. 현재 이벤트 주장이나 정규화 값은 검증 완료 증명과 다르다.
3. 분류 성능과 별도로 설명의 의미적 근거, 누락된 근거, 정책 인용 정확성, prompt injection 저항성을 독립 검토한다. 현재 테스트는 구조적 분리/오류 회귀를 확인할 뿐 실제 공격 저항100%를 증명하지 않는다.
4. 관찰 모드에서 비용/지연/abstain과 규칙 대비 추가 경보를 함께 측정하고, 새 family·source·사람 검토 라벨을 고정해 평가한다. 전체목표 충족 전 CI·push·병합은 계속 보류한다.

[M6 비교 계약](m6-evaluation-contract.md)의 별도 세션/typed decision 실행기와 이번 SecurityEvent 파일럿은 다른 평가다. 이번 결과로 M6의 모든 후보 비교나 원래 독립 인수를 완료 처리하지 않았다. 이번 사용자 요청으로 **이 LLM 비교의 유료 호출 보류만 해제**됐으며 AWS 비용 발생은 허용/실행하지 않았다.

## 공식 근거

- [OpenAI mini 모델 명세·가격](https://developers.openai.com/api/docs/models/gpt-5.4-mini): 입력 $0.75/출력 $4.50 per million을 사용했다.
- [Sol 모델 명세·가격](https://developers.openai.com/api/docs/models/gpt-6.1-sol): 입력 $2/출력 $10 per million을 사용했다.
- [평가 권장 절차](https://developers.openai.com/api/docs/guides/evaluation-best-practices): 개발/평가 분리, 실제 업무별 비교와 반복 측정이 필요하다.
- [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs): schema 준수가 의미적 정확성을 보증하지 않는다.
- [NIST SP 800-207](https://csrc.nist.gov/pubs/sp/800/207/final): 접근 판단을 모델의 추측/확신으로 대체하지 않고 실제 인증·인가 근거로 유지한다.
