## 구현과 경계

[SensitiveAuthReview](../scripts/f1_lab/sensitive_auth_context.py)는 기존 원본 SHA·연속 행·UTC 시각·같은 호스트·바로 앞 행·0~1초 간격·서로 다른 보고 PID 배제 조건을 유지한다. 원래 root 재귀 탐색과 동일한 웹 저장 경로 파서를 재사용한다. 명령은 직접 cat/head/tail의 정확한 `/etc/passwd` 또는 `/etc/group` 한 파일 조회여야 한다. 다른 경로·shell 복합문·리다이렉션·명령 치환·다른 파일·이름이 유사한 파일은 이 추가 신호가 아니다. 도메인·사용자·IP·날짜·사례ID를 규칙에 넣지 않았다.

해당 신호는 [위험 추가 함수](../scripts/f1_lab/audit_auth_review.py)를 통해 경보와 검토를 추가한다. 명시적 위험을 먼저 처리하므로 학습된 정상 의도 표가 이 위험을 낮추지 못한다. 기존 경보는 보존하고 자동 집행·접근 허용은 하지 않는다. 운영 기본 탐지기는 바꾸지 않고 기존 선택적 로컬 판정 경로에 연결했다. 정상 관리자도 비슷한 경로에서 작업할 수 있으므로 이 문맥을 무조건 악의·권한 부재로 해석하지 않으며 실제 기관의 추가 검증이 필요하다.
