## 무엇을 바꿨는가

v39의 HTTP 증거 트리는 모든 HTTP 학습 행으로 만들어졌지만 점수를 낮추는 적용 범위는 GET/HEAD 성공 응답으로 제한돼 있었다.
이번에는 그 **동일한 모델**을 성공한 POST에도 선택적으로 적용한다. 재학습·임계값 조정은 하지 않았다.

[SuccessfulPostRefinement](../scripts/f1_lab/web_post_refinement.py)는 다음 조건을 모두 요구한다.

- POST·2xx 응답이고, HTTP 이력/의미 특징을 사용할 수 있으며 파싱 오류나 문자 치환이 없다.
- SQL·경로 탐색·쉘·명령 인자·업로드 스크립트·민감 파일·스캐너 등 기존 보안 징후가 없다.
- 기존의 극단적 요청률 보호 조건을 그대로 통과한다. 정적 파일이라는 이유로 요청률 보호를 해제하지 않는다.
- 이전 단계의 이유가 일반 `unchanged`이며 이전 점수가 고정된 원래 모델의 점수와 정확히 같다.
  선행 위험 이력·민감 파일 읽기·검토 필요 등 다른 이유의 판단은 덮어쓰지 않는다.
- 고정 증거 트리의 점수가 기존 기준 **0.05 이하**다. 그 밖의 점수는 보존한다.

낮은 모델 점수는 신원·권한이나 실제 정상 행위를 인증한 것이 아니다. access 로그에 POST 본문이 없다는 관측 한계도 남는다.
이 보정은 오프라인 탐지 실험이며 PDP/PEP에 접근 허용·권한 복원·자동 차단을 요청하지 않는다.
기존 모델 파일/라벨/이전 예측은 수정하지 않았고 `automatic_enforcement_allowed=False`를 유지한다.

## 검증·재현과 독립 평가 경계

- 새 Windows 경계/재생 테스트 **45개 통과**: 공격 신호·요청률·불명 문맥·기존 위험 이유 보존,
  임계 경계·잘못된 모델 값·기준선 불일치·정답 없는 예측·오류 분모·부분 출력 봉인 금지 등.
- 관련 Linux Docker 회귀 **176개 통과**, 실패/skip0, 전체 Ruff+RUF100 통과.
  최초 Linux 시도는 새 테스트의 import 정렬 오류로 lint에서 멈췄고, 정렬 후 새 출력 디렉터리에서 통과했다.
- 4개 실제 개발 시나리오를 구현 코드로 전부 재생했다. 모델/입력/소스 불변, 사례 순서·전체 분모,
  예측 파일 SHA를 확인했다. 예측을 완성·고정한 다음에 정답을 열어 채점했다.
- Linux 시험은 캐시 이미지·network none·비root·읽기 전용 root를 사용했다. 해당 컨테이너 제거를 확인했다.
  유료 LLM/AWS 호출0. 176개는 관련 묶음이며 전체 저장소 테스트를 재실행한 수치가 아니다.

실행기는 [run_web_post_refinement.py](../scripts/run_web_post_refinement.py)다.
원자료·고정 모델이 있는 환경에서 로컬 계획의 SHA와 새로운 출력 폴더로 실행한다.

```text
python -m scripts.run_web_post_refinement --plan <plan.json> --expected-plan-sha256 <SHA256> --output <fresh-output-directory>
```

실제 산출물은 `runtime/f1/post-refinement-development-v52-20261114/run.json`과 그 옆의 전체 예측이다.
모든 소스/모델을 먼저 고정한 별도 출처 평가를 이어서 준비한다. Wilson 압축파일은 수집 중이지만
현재 원문·라벨 본문은 열지 않았다. [게시자의 메타데이터](https://zenodo.org/records/19483937)는 확인했다.
같은 모의망 생성 계열과 겹치는 시기라는 한계가 있어 Wilson 평가 역시 원래 여섯 영역의 최종 인수로 대체할 수 없다.
