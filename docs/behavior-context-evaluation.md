# 정상 작업 기준선과 승인 내역의 비교 평가

이 평가는 같은 관측에 기존 공개 행동 규칙만 적용한 결과와 정상 작업 기준선, 사전 승인,
신뢰된 침해 신호를 연결한 결과를 비교한다. 입력은 새로 생성한 통제된 로컬 실험 자료다.
공개 로그에 실제로 존재하지 않는 승인이나 기기 상태를 원본의 사실처럼 추가하지 않는다.
두 방식은 동일한 관측을 받지만 추가 맥락 정보는 두 번째 방식에만 제공한다.
따라서 결과는 추가 근거를 연결한 효과이며 동일 정보량의 모델 비교가 아니다.

## 실행

저장소 루트의 개발 가상환경에서 실행한다. 외부 API 키, Docker, AWS 계정은 필요하지 않다.
이미 존재하는 평가 디렉터리나 결과를 덮어쓰지 않는다.

```bash
./.venv/bin/python -m scripts.evaluate_m7_context prepare \
  --directory runtime/m7/behavior-context-evaluation --repetitions 10
./.venv/bin/python -m scripts.evaluate_m7_context verify \
  --directory runtime/m7/behavior-context-evaluation
./.venv/bin/python -m scripts.evaluate_m7_context evaluate \
  --directory runtime/m7/behavior-context-evaluation
```

준비 단계에서 애플리케이션, 규칙, 정책과 실행기 코드를 해시로 고정한다. 이후 코드, 입력,
정답 또는 대조한 기존 자료가 바뀌면 평가를 거부한다. 결과를 확인하고 구현을 수정한 경우에는
해당 자료를 회귀 자료로 남기고 새 디렉터리에 새 평가 자료를 준비한다.

## 자료 구성과 판정 경로

기본 구성은 24개 상황을 각각 10회 실행하는 240개 평가 세션이다. 각 사례는 별도의 임시 저장소와
실험용 키를 사용한다. 정상 기준선용 과거 수집 3개는 대상 세션과 분리하며, 승인 사용량 시험에는
먼저 승인받은 별도 수집 건을 추가한다. 이러한 준비 세션은 240개 평가 분모에 포함하지 않는다.

관측은 CloudTrail과 Cowrie 입력 구조를 사용하지만 이 실험이 새 공개 원본을 수집했다는 뜻은 아니다.
기존 개발 자료와 평가 자료의 세션, 이벤트, 원본 그룹, 연결 식별자 및 입력 해시를 대조한다.
상황 유형은 기존 구현에서 다루는 유형을 포함하므로 처음 보는 위협 유형에 대한 검증으로 설명하지 않는다.
10회 반복도 서로 다른 실제 공격 사건 10개를 의미하지 않는다.

실행기는 실제 서명 검증으로 세션과 행동 수집을 접수한다. 기준선과 승인은 대상 관측 전에 등록한다.
침해 신호는 기존 Inbox와 worker를 거쳐 정책 저널에 기록하며, 단순 신고나 다른 대상의 신호를
현재 대상의 확인된 침해로 취급하지 않는다. 판정 함수는 평가 정답이나 상황 이름을 받지 않는다.
두 방식의 관측 해시와 판정 전후 정책 저널을 대조해 같은 입력 및 접근 상태 불변 여부를 확인한다.

## 정답과 근거 분리

`inputs.jsonl`에는 실행할 관측과 운영 기록만 저장한다. 정답, 상황 이름, 판단 이유와 채점용 근거는
`private/scoring.jsonl`에 따로 저장한다. 준비할 때 두 파일을 고정하고, 평가에서는 모든 판정을
`predictions.jsonl`에 저장한 후 정답을 해석한다. 정답 파일의 해시 확인은 판정 전에 수행할 수 있지만
정답을 판정 함수에 전달하지 않는다. 이는 실행 경로의 분리이며 같은 호스트 관리자에 대한 비밀 격리는 아니다.

실행 후에는 원래 고정한 관측과 실제 수집 원문을 직접 비교한다. 과거 기준선 표본, 승인 기간과
사용 한도, 취소 기록, 신고 내용과 접수 여부, 수동 세션 회수도 고정된 운영 명세와 대조한다.
실행기가 유효 기간이나 신고 대상을 다르게 만들어 유리한 결과를 얻으면 평가를 중단한다.
평가 중 manifest와 정답을 함께 바꿔 해시를 다시 맞춘 경우도 최초 manifest 해시와 달라지므로 거부한다.

정상으로 계획된 작업도 승인이 없거나 만료된 경우에는 정상 정답을 유지한다. 판정기가 보류하면
정상 사례의 보류로 집계한다. 공격으로 계획됐지만 로그나 신뢰된 신호에서 증거를 확보하지 못한
사례도 위협 정답을 유지하며, 보류나 정상으로 판정하면 미탐이다. 실제 상태 자체를 확정할 근거가
부족한 상황에만 정답 `unknown`을 사용한다. 현재 판정 결과로 정답을 바꾸지 않는다.

## 집계와 해석

- 미탐은 정상으로 잘못 판단한 위협과 보류 또는 오류로 해결하지 못한 위협을 모두 포함한다.
- 정상 사례의 보류는 TN에 넣지 않고 별도 표시한다. 전체 정상 수를 분모로 한 오탐률과 판정 범위를 함께 제공한다.
- 정밀도, 전체 위협 기준 재현율과 F1, 판정된 사례만의 조건부 지표를 구분한다. 분모가 없으면 `null`이다.
- 정답 `unknown` 사례는 정상 또는 위협의 혼동 행렬에서 제외하고, 근거 없는 확정 판정과 올바른 보류를 따로 센다.
- 근거 검증은 실제 인용 이벤트, 승인 범위와 사용량, 시점, 세션 연결 및 committed 침해 기록을 대조한다.
  관측 사실과 일치하는 설명인지와 정답을 뒷받침하는 근거인지를 구분한다.
- 상황별 결과와 두 방식의 판정 변화도 기록한다. 전체 평균만으로 실패한 유형을 숨기지 않는다.

원자료는 `manifest.json`, `predictions.jsonl`, `report.json`, `execution.json`에 남긴다.
원본 코드가 알려진 상태에서 설계한 실험이고 독립적인 사람의 라벨 검토를 완료한 자료가 아니므로,
높은 점수가 나와도 공개 로그의 독립 성능이나 프로젝트 최종 탐지 목표 달성으로 처리하지 않는다.
실행기 자체의 회귀 검증은 `tests/test_m7_context_*.py`에서 수행한다.

## 2026년 11월 10일 실행 결과

`runtime/m7/behavior-context-evaluation/report.json`에 240세션 결과를 보관했다.
정상 100개, 위협 60개, 근거 부족 80개이며 기준선 720세션과 승인 선행 사용 10세션은
평가 분모에서 제외했다. 기존 자료 39개 파일과의 식별자 및 관측과 요청 지문 겹침은 0건이었다.
입력의 정답 필드는 0개이며 대상과 기준선의 세션 및 이벤트 재사용도 없었다.

두 방식 모두 실제 기록과 판정 근거의 추적 검사는 240개 모두 통과했다. 이는 정확도가 100%라는
뜻이 아니다. 기록과 일치하는 승인을 인용해도 숨겨진 악의적 사용을 정상으로 판단할 수 있다.
정답과 일치하며 근거도 충족한 결과는 기존 규칙 90개, 맥락 연결 180개이며 각각 근거 부족 사례의
올바른 보류 80개를 포함한다. 이 수를 위협 탐지 건수나 정밀도로 표시하지 않는다.

맥락 연결에서 남은 미탐 20개는 유효한 승인을 가진 작업의 대량 자료 유출과 소량 자료 탈취다.
두 유형 모두 별도 침해 신호나 목적지 및 실행 주체를 확인할 관측이 없어 정상으로 판정됐다.
특히 대량 유출 10개는 기존 규칙의 보류가 정상으로 바뀌었다. 실제 운영에서 참고해야 할 실패이며
평가 정답을 변경하거나 해당 자료를 제외하지 않았다. 이 판정 경로는 접근 권한을 새로 부여하지 않는다.

승인 누락, 만료, 취소와 정상 정비로 회수된 정상 작업 40개는 맥락 연결 후에도 보류됐다.
근거 부족 정답 80개는 두 방식 모두 보류했다. 알려진 정상 및 위협 160개 전체에서 보류까지 포함한
정확도는 각각 6.25%와 62.5%이며, 판단한 사례만 계산한 결과와 구분한다.

현재 탐지 계약의 재현율 및 F1 95% 목표는 미달이다. 최초 계획의 정확도 70%와도 다른 지표이므로
서로 대체해 합격으로 표시하지 않는다. 정상과 위협이 인위적으로 구성된 로컬 실험의 관측 오탐률
0%는 실제 운영 오탐률을 보장하지 않으며, 이번 자료는 결과를 확인한 이후 회귀 자료로 취급한다.

평가 도구 관련 테스트 85개를 포함해 전체 로컬 회귀 3,186개가 통과했다. 기존 Linux 컨테이너
전용 검사 2개는 제외됐고, Ruff와 `git diff --check`도 통과했다. 처음 제한된 환경에서 실행했을 때의
69개 실패 및 준비 오류는 모두 로컬 서버 포트의 `PermissionError`였으며 원자료를 남긴 뒤,
로컬 서버 실행이 가능한 권한에서 전체 회귀를 다시 통과했다. 검증 기록은
`runtime/m7/behavior-context-comparison-validation/verification.json`과 `pytest.xml`에 있다.
