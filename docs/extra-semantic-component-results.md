# extra: 개선이 발생한 입력의 분리 비교

2026-11-12 · v35. [v34 후보](extra-http-auth-semantics.md)의 성분 비교다.
R 전체295,243행으로 같은 depth8/min_leaf5/class balance의 트리를 각각 적합하고,
이미 관찰한 S 전체295,976행에 재학습 없이 적용했다. **새 독립 최종 평가가 아니다.**
[프로토콜·모델·결과 지문](infrastructure-results/extra-semantic-components-v35-20261112.json)을 보존한다.

각 비교는 새 프로필의 해당 성분만 남기고 나머지 새 필드는 계약의 기본값으로 치환했다.
기존 rich2 관측·모든 행·정답·case ID를 그대로 유지했다. 좋은 파일의 결과만 골라 합친 점수가 아니다.

새 필드를 모두 끈 제어군은 이전 고정 v23 모델의 **트리 root 전체와 S 혼동행렬을 정확히 재현**했다.
다른 자료를 쓰거나 정답을 고쳐 점수가 달라진 것이 아닌지 확인한 것이다.

이 개발 자료/모델 조건에서 HTTP 성분은 FP111건 감소·TP15건 증가, 계정 과거 이력은 TP7건 증가에 기여했다.
정적 인증/감사 필드만으로는 이번 비교의 혼동행렬이 개선되지 않았다. 정적 필드의 일반적인 무가치를 뜻하지 않는다.
이번에는 두 성분의 건수가 합쳐진 결과였지만 다른 모집단에서도 효과가 가산적이라고 가정하지 않는다.

VPN·공유 감사 등 남은 문제와 원래 여섯 영역의 독립 평가 부족은 그대로다.
성분 비교를 보고 최종 예약 사례를 다시 고르거나, 정상 행을 줄이거나, 배포 모델을 교체하지 않았다.
프로덕션 코드 변경/새 pytest 실행은 없으며 관련 Windows/Linux287개는 v34 소스의 기록이다.
