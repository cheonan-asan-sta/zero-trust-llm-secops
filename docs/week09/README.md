# 9주차: 자동 대응 JSON과 정책 실행 엔진

## 계획 목표

계정 차단, 권한 축소, 추가 인증과 같은 대응 판단을 구조화하고 정책 엔진에 연결한다. 안전을 위해 실제 조치 대신 대응 미리보기를 생성한다.

## 구현 결과

- 분석기가 반환할 수 있는 대응을 `ALLOW`, `REQUIRE_MFA`, `REDUCE_PRIVILEGE`, `ISOLATE_SESSION`, `HOLD_FOR_REVIEW`로 제한했다.
- 위험 점수와 위반 유형을 이용해 권고 조치를 결정하는 기준선을 구현했다.
- 정책 엔진은 권고 조치를 다시 검증하고 `PolicyDecision` JSON으로 변환한다.
- 모든 결정에 `mode: simulation`을 강제해 실제 실행과 명확히 분리했다.
- 고위험, 낮은 신뢰도, 권한 축소, 세션 격리는 자동 실행하지 않고 사람 검토로 전환한다.
- `POST /response/preview`에서 분석 결과에 대한 대응 미리보기를 별도로 확인할 수 있게 했다.

## 정책 매핑 기준

| 위험·상황 | 기본 대응 |
|---|---|
| 낮은 위험 | 접근 허용 미리보기 |
| 중간 위험 | 추가 MFA 요청 미리보기 |
| 높은 위험의 권한 초과 | 권한 축소 검토 |
| 그 외 높은 위험 | 사람 검토 대기 |
| 심각한 위험 | 사람 검토 대기 |

이 매핑은 대응 후보를 정할 뿐 실제 계정, 권한, 세션을 변경하지 않는다.

## 코드·테스트 근거

- 대응 모델: `app/models.py`
- 위험 점수·대응 기준선: `app/analyzers/rule_based.py`

- 정책 안전성 테스트: `tests/test_policy.py`, `tests/test_week04.py`
