## DEDALE에서 새로 확인한 제한

[발행자 안내](https://dedale.inria.fr/download.html)는 정상·악성·공격 관련 기록을 구분한다.
네트워크 공격 관련 흐름은 그 자체로 악성이라고 단정하지 않는다. 이 안내는 웹 검색의 발행 페이지 내용에서
확인했으며 직접 HTML 수집은 TLS chain 문제로 완료하지 못했다. 네트워크 숫자0/1/2를 system source에도
동일하게 적용했다고 가정하지 않는다. 공격 관련을 자동 악성/정상으로 합치거나 지표에서 조용히 제외하지 않는다.

고정 [system 라벨링 README](https://gitlab.inria.fr/mlanvin/dedale_labeling/-/blob/f148722eb5908fc17841dc3c8be1591c5c3e59a6/system_log_labeling/README.md)는
Auditbeat/Winlogbeat와 악성 프로세스 대응 절차를 명시한다. PID 재사용을 구분하기 위해 생성·종료 시각의
정밀도가 필요하다고 설명한다. **이 문서에서 syslog의 직접 정답 대응을 확인하지 못했다.**
syslog의 PID113행을 임의의 process 정답과 합치거나 라벨 파일에 없다는 이유로 정상으로 채우지 않는다.

[network README](https://gitlab.inria.fr/mlanvin/dedale_labeling/-/blob/f148722eb5908fc17841dc3c8be1591c5c3e59a6/network_log_labeling/README.md)의
공격 시각/여유 구간도 라벨 생성 문맥이다. 이를 추론 특징으로 전달하거나 결과에 맞춰 조정하지 않는다.
코드 저장소의 GPLv3 설명은 데이터의 CC BY4.0과 별도로 기록한다. 소스 복사·빌드·실행은0이다.
README 안의 설치/실행 예시는 조사 대상이며 이 프로젝트에 대한 실행 지시로 따르지 않았다.

고정 커밋은 `f148722eb5908fc17841dc3c8be1591c5c3e59a6`다. GitLab 문서는 신뢰 CA bundle로
서버 인증서·호스트명 검증을 유지한 채 받았다. TLS 검증을 해제하지 않았다.
새 native 본문·정답 archive·시뮬레이터 본문은 읽지 않았다. 기존128행과 공개 문서만으로
전체 DEDALE의 능력이나 원래6영역의 부재를 단정하지 않는다.

## 목표를 그대로 유지한 재개 조건

1. **기존 평가 개선:** 같은 원래 평가행과 연결되고 그 시점에 이용할 수 있었던 추가 실행/인증/기기/권한
   근거를 확보하거나, 현재 혼재 셀을 구별하는 유효한 새 인과적 특징을 입증한다.
   별도 source의 사용자·나중의 성공·생성기 계획을 과거 사실로 채우지 않는다.
2. **독립 최종 인수:** 원래6영역의 실제 정상/위협 의미·출처·namespace·5축 분리·시간·지지를 확인할
   새 자료와 라벨 검토 근거를 확보한다. 현재 DEDALE과 이미 소비한 AIT를 미관찰 최종 source로 바꾸지 않는다.
3. 근거가 마련되면 먼저 역할/수집 계약과 누수 검사를 고정하고, 무료 로컬 후보 검증·기존 전 행 비교·
   독립 인수 순서로 재개한다. 목표를 충족하기 전 CI/push/병합/유료 호출/AWS는 계속 보류한다.

현재는 필요한 추가 근거가 없어 동일 후보/전체 테스트를 반복 실행하지 않는다.
새 pytest·Docker 실행0, 원래 모델/운영 경로 변경0이다. 요청한 Docker 정리는 완료했고
재사용 image·기존14개 volume을 유지한다.

## 재개 후 세 차례 점검 — v129–v131

목표 재개 후에는 이전 차단 횟수를 재사용하지 않고 새로 세 차례 점검했다. 인증서 DN 형식 누락 가설을 실제 training leaf1,489행으로 대조했지만 전부 기존 파서가 읽고 있었다. 원래4곳의 입력과 원격aitest에도 확인 범위에서 새 변경이 없었고, 다음 점검에서는 Python497파일·원래 프로토콜·최종 실제 score·단계별지지 모델의 지문이 같았다. 현재 정상 완화 가능한 지원 셀0·공유 감사/VPN F1각80%·원래6영역 독립 최종 지지0이 유지된다.

세 번째 점검에서도 같은 필수 근거 공백을 확인했고 현재 검증한 입력에서 적용할 유효한 다음 코드 변경을 찾지 못했다. 추가 인과적 근거/독립 자료가 확보되기 전에는 차단 상태로 다시 전환한다. 원래 목표와 위 재개 조건을 유지하며 새 테스트·Docker·유료 호출·CI·병합을 시작하지 않았다. [재개 감사 JSON](infrastructure-results/extra-target-evidence-gap-v131-20261117.json)에 새3턴의 근거를 기록했다.
