2026-11-12 · [수집·라벨 검토](extra-cloud-identity-and-rba.md)의 실제 완료 후속이다.
**자료 수집·구조 검사가 완료됐으며 탐지 모델의 독립 평가나 목표 달성은 아니다.**

후속 [v30 고정 메타데이터 감사](extra-rba-metadata-audit.md)는 별도 계약 후 전체 CSV를 기계적으로 읽기 시작했다.

## 전체 ZIP의 무결성과 재개 기록

[고정 발행자 자료](https://zenodo.org/records/6782156)의 `rba-dataset.zip`1,093,700,330바이트를 받았다.
발행자 MD5 `cc1b1078b3929650e6c08678caffcc57`와 일치하며, 저장된 전체 파일을 별도로 다시 읽어 MD5도 대조했다.
최종 ZIP SHA256은 `ca1d974e97aebfb30878a613f4ca5c793860a98ba2acb5185c9bc610d7432a33`이다.
SHA256은 ZIP 인덱스/실제 probe 실행 전후에도 대조했다. 체크섬은 발행자 서명이나 현재 기업 신뢰 검증을 뜻하지 않는다.

| 회차 | 실제 결과 | 재시도 | 종료와 보존 |
|---|---|---:|---|
| 첫 수집 | 1,069,547,520바이트(97.8%)에서 `public_asset_transfer_bound` | 타임아웃2회 | 실행3611.219초·exit1. 실패 receipt/범위 기록/부분 파일 보존 |
| 새 디렉터리 재개 | 같은 고정 자산의 나머지24,152,810바이트 수집·전체 MD5/SHA 검증 | 0 | 실행79.625초·exit0. 앞선 부분은 검증하며 복사, 새 전체 파일만 완료로 게시 |

첫 세션34025와 재개 세션4416의 실제 종료를 확인했다. 단순 관측 timeout으로 다시 시작하지 않았다.
첫 작업의 종료·실패 기록을 확인한 뒤 기존 재개 절차를 사용했고 범위/시간/크기 제한을 늘리지 않았다.
부분 파일만 발행자 검증 완료로 승격하지 않았다. 재개한 **전체** 파일의 체크섬이 최종 근거다.
원래 실패 기록은 `runtime/f1/public-rba-20261112`, 완료본은 `runtime/f1/public-rba-20261112-02`다.

ZIP 인덱스에는12개 멤버가 있고 CSV는 `rba-dataset.csv` 하나다.
CSV 선언 크기는9,052,907,531바이트·압축 크기1,091,167,086바이트다. 큰 CSV를 디스크에 통째로 풀지 않았다.
범용512MiB 멤버 복사 제한도 유지한다. `runtime/f1/rba-zip-inspection-20261112`에 인덱스와 검증 receipt를 보존했다.

## 실제 제한 리더 결과

사전 계약의 첫128개만 `scripts/probe_rba_schema.py`와 같은 리더로 조사했다.
파서에 전달한 prefix는37,393바이트·129개 물리 행(헤더 포함)이며 SHA256은
`b3a5750370c126fa381784e136431de4b994555bf76ecc1d791c126eb4d79fd5`다.
ZIP 해제기의 내부 선읽기 가능성과 CSV 이후 행 파싱0을 구분하고 **전체 CSV CRC 검증은 주장하지 않는다.**

| 첫128개에서 확인한 것 | 결과 | 해석 경계 |
|---|---:|---|
| 로그인 성공/실패 | 65/63 | 실패가 곧 계정 탈취/공격이라는 정답은 아님 |
| 알려진 공격 IP 표식 | true9·false119 | 계정 탈취 라벨과 별개 |
| 계정 탈취 표식 | false128·true0 | 이 표본에서 재현율/F1을 계산할 공격 지지 없음 |
| RTT 빈 값 | 122 | 누락을0 또는 정상 반응으로 채우지 않음 |
| 시간대 없는 ISO 형식 시각 | 128 | UTC/현지 시간대를 추측하지 않음 |
| 관찰한 사용자 참조 | 81 | 개발 관찰로 기록, 미관찰 사용자 최종 평가로 재사용 금지 |

문자 boolean은 모두 알려진 값으로 파싱됐다. 실제 헤더는 index, 시각, 사용자, RTT, IP/지역/ASN,
브라우저/OS/기기 유형, 로그인 결과와 두 라벨이다. `index`는 관측 특징이 아니다.
헤더에 계정 활성·MFA 결과·기기 관리/건강·자원 소유자 역할 정책·업무 승인·민감 전송량은 없다.
빈 RTT와 로그인 성공을 이용해 이 근거를 만들어 내지 않는다. 사용자/사례의 원시 값은 출력하지 않았다.

`runtime/f1/rba-schema-probe-20261112/probe.json`에는 prefix/스키마/집계와 관찰 사용자 해시를 보존한다.
전체 CSV의 클래스 수·분할 지지·결측 비율을 이128개에서 추정하지 않는다.
이후 CSV 기록은 아직 파싱하지 않았고 새로운 독립 최종 집합으로 인증하지 않았다.

## 다음 단계와 전체 목표

다음은 별도 **메타데이터 감사·분할·정답 계약**을 먼저 정한 뒤 전체 클래스 지지와 주체/시간/중복·누락을 확인하는 것이다.
