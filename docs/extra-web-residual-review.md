# 웹 잔여 미탐 보강과 검토 분리 v44

후속 [v45 웹 서버 근거 검증](extra-web-verified-context.md)에서 인증·권한·실행의 서명된 요청별
결속 어댑터와 기능 제어군을 추가했다. 실제 관측 수집/새 F1 측정은0이며 아래 v44 실측 기록은 보존한다.

2026-11-13 · `extra`의 무료 로컬 후속이다. [v43 오류 검토 목록](extra-independent-evaluation-preparation.md)에서
웹 access/error를 실제 사례 ID까지 확인하고, 기존 R/S/Fox 전체1,259,637행을 같은 입력·라벨·0.95 경보 기준으로 비교했다.
**Fox 오류 로그 미탐4→0, 웹 전체 미탐34→30이며 경보 오탐19건은 유지했다.**
인코딩된 명령 요청은 별도 검토 대상으로 남겼고 이것을 경보 탐지 성공으로 계산하지 않는다.
원래 여섯 영역의 독립 최종 목표·운영 채택·자동 차단을 완료한 결과가 아니다.

[공개 근거 JSON](infrastructure-results/extra-web-residual-v44-20261113.json)은 최종 비교·검토 사례 ID,
미채택 시험안의 새 오탐·최초 결속 실패·소스/입력/시험 지문을 포함한다.
기존 앱·규칙·모델·라벨·분할과 팀원 `aitest`의 승인/복구 경로는 그대로다.

## 확인한 원인과 변경 범위

기존 [v39 웹 보정](extra-web-false-positive-reduction.md)은 의심 신호가 있으면 점수를 낮추지 않지만
낮은 기준 점수 자체를 경보로 올리지는 않는다. 실제 잔여 미탐에는 다음 관측이 있었다.

| 관측 | 최종 처리 | 한계 |
|---|---|---|
| 업로드 경로의 스크립트 요청 + query의 base64 JSON 명령/인자 목록 | 기존 경보 점수·경보 여부 유지, 검토 표시만 추가 | 명령 목록이 있다는 사실만으로 무허가/악성을 확정하지 않음 |
| 동일 원본·동일 client의 PHP missing-script 오류가60초 안에 서로 다른 이전3개 경로를 가진 뒤 새 경로를 요청 | 경보 점수 최소0.95, 검토 표시. 기존 높은 점수/경보 유지 | 파일 탐색 징후이며 실제 사용자 신원·공격 성공·권한 위반의 증명은 아님 |
| POST·리다이렉트·일반404와 신호 없는 요청 | 기존 결정 유지 | 본문·서버 인증·자원 권한 근거 없이 정상 예외를 만들지 않음 |
| VPN·인증·감사 등 나머지 원본 | 점수·경보·검토 결정 유지 | 기존 v40b VPN 위험 유지 경로를 재사용 |

신규 [관측/보정 모듈](../scripts/f1_lab/web_residual.py)은 원문 SHA+물리 행 번호에서 사례 ID를 만들고
원문에서 재현할 수 있는 단일 행 특징의 지문을 준비 데이터와 대조한다.
기존 준비 단계가 나중에 붙이는6개 HTTP 시간창 특징은 이 단일 행 지문과 분리한다.
단일 행 method/status/보안 관측 등이 바뀌면 거부하며 시간창 차이를 정상 기본값으로 덮지 않는다.
모델에 정답·원본 파일명·IP·계정·절대시각·사례 ID를 피처로 전달하지 않는다.

오류 문맥은 실제 파싱된 PHP error의 `script '…' not found or unable to stat`만 센다.
동일 시각 묶음은 서로의 과거가 될 수 없고, 미래/다른 원본/다른 client/미상시각/잘못된 client는
문맥 근거가 되지 않는다. 같은 경로 반복은 서로 다른3개 경로를 대신하지 않는다.
client IP는 해당 원본 안의 관측 키이며 검증된 기기/사용자 신원이 아니다.

명령 요청은 origin-form의 `/uploads/…` 실행 스크립트 경로와 bounded JSON 문자열 목록을 함께 요구한다.
query key의 특정 이름이나 시나리오별 파일명·계정·시각을 규칙으로 사용하지 않는다.
URL 디코딩 최대2회·값4096자·값32개·명령 목록32개 등 한도를 넘거나 형식이 불확실하면
추가 근거를 만들지 않는다. 문자열을 명령으로 실행하거나 URL을 따라가지 않는다.
브라우저/스캐너 User-Agent·referer만으로 정상/악성을 확정하지 않는다.

최종 [고정 프로토콜](../infra/f1-lab/web-residual-review-protocol.json)은 명령 요청을 `review_only`로 지정한다.
기존 경보/검토/높은 점수를 낮추지 않으며 새 접근 허용·권한 회수·권한 복원·자동 집행은 없다.
후보는 실험 스크립트에서만 사용하고 운영 API에 연결하지 않았다.

## 같은 자료의 전후 비교

아래는 **HTTP 원시 물리 행** 기준이다. R=Russell/Mitchell, S=Santos, Fox이며 모두 이미 관찰한 자료다.
별도 이벤트720건·세션·정책 제어군과 분모를 합치지 않는다.

| 출처 | 로그 | 행 수 | FP 전→후 | FN 전→후 |
|---|---|---:|---:|---:|
| R | access | 8,530 | 0→0 | 7→7 |
| R | error | 36 | 0→0 | 0→0 |
| S | access | 9,462 | 7→7 | 17→17 |
| S | error | 44 | 0→0 | 0→0 |
| Fox | access | 412,922 | 12→12 | 6→6 |
| Fox | error | 1,338 | 0→0 | 4→0 |
| 웹 합계 | 두 종류 | 432,332 | 19→19 | 34→30 |

수정한4건은 원래 게시자 변환 라벨이 위협이고 경보는 없던 오류 행이다.
새 경보 FP0·기존 TP 손실0이며 이전 미탐을 정상으로 고치거나 평가 행을 삭제하지 않았다.
원자료 전체1,259,637행은 Windows 로컬에서 읽었으며 원래 v40b 전후 비교 기준이
자료별 전체·파일별 혼동행렬까지 재현됐다. 비웹827,305행의 점수·경보·검토 결정 지문이 전후 동일하다.

새 검토 표시는 게시자 위협 라벨23건·정상 라벨3건이다.
이 중4건만 새 경보이고, **명령 요청19건은 여전히 경보 미탐**이다.
게시자 정상 라벨3건도 검토 부담으로 공개한다. 경보 오탐이 늘지 않았다는 결과를
검토 오탐/업무 부담까지0이라는 주장으로 바꾸지 않는다.
남은 웹 미탐30건은 명령 요청19건과 일반 루트 요청·스캐너/404 등11건이다.
신호가 부족한 사례를 정상 기본값이나 넓은 경보 조건으로 채우지 않는다.

원래 라벨 변환과 모집단은 보존했지만 게시자의 공격 표기에 없는 행이 독립적으로 검토된
조직 정상 업무라는 의미는 아니다. 이 자료는 공격 행 비중이 매우 높아 전체 F1도 이를 반영한다.
새 독립 정상·위협 자료, 원래 여섯 영역 매핑, 라벨 검토와 군집 불확실성은 여전히 필요하다.
목표 달성/기업 일반화 판정은 계속 false다.

## 실패한 시험안도 보존

처음에는 인코딩 명령 목록도 경보 점수0.95로 올렸다.
그 안은 기존 웹 FN34→11로 줄었지만 **R/S/Fox에서 각각 새 FP1건**, 합계FP19→22가 생겼다.
정답을 바꾸거나 그3행을 빼지 않고 이 넓은 경보안은 미채택했다.
최종안은 명령 목록의 동작 의도를 검토 증거로 남기되 무허가 여부를 추정하지 않는다.
오류 반복 경보와 명령 검토의 서로 다른 분모/성과를 분리해 보고한다.

그보다 앞선 최초 원자료 실행은 단일 행 특징 지문에 나중에 더해진 HTTP 시간창 값까지
비교해서 결속 실패로 멈췄다. 결과를 완료로 쓰지 않았으며, 단일 행 특징과 시간창을 분리하고
준비 HTTP 문맥이 있는 실제 형태의 반례를 추가했다.
첫 실패·넓은 시험안·최종안은 각각 별도 runtime 폴더에 보존했다.

## 검증·재현·후속 작업

최종 신규 테스트45개를 포함해 관련 **Windows256개·network none Linux Docker256개 통과**,
실패/skip0이며 Ruff도 통과했다. 이전 시험 스냅샷의255/256개를 합쳐 한 번의 실행으로 쓰지 않는다.
Linux는 캐시 이미지를 재사용하고 비root·읽기 전용 root·cap-drop으로 시험했다.
728개 소스가 전후 동일했고 exit0·OOM false·해당 소유 컨테이너 제거를 확인했다.
실제1,259,637행 비교는 Windows에서 수행했고 Linux에서는 관련 pytest를 실행했다.
전체 앱 회귀/분산 환경/실제 IdP·기기 연결/유료 LLM 평가는 이번 범위에 포함하지 않는다.

최종 실행은 `runtime/f1/web-residual-review-v44-20261113`이다.
`run.json`과 출처별 `*-web-errors.jsonl`에 전후 점수·경보/검토·사례 ID·출처/특징 지문을 남겼다.
원문과 디코딩한 인자를 공유 JSON에 복사하지 않았다. 개별 물리 행 번호는 고정 준비 자료의
`references.jsonl`에서 같은 사례 ID로 대조할 수 있다.
프로토콜·실행·시험 지문과 전체 검토 목록은 공개 근거 JSON에 있다.

```powershell
.venv\Scripts\python.exe -m scripts.run_web_residual --plan infra/f1-lab/web-residual-review-protocol.json --expected-plan-sha256 ef7d803f017b18ba080a5c8dfcc8f0a511053e8bbee33058334d853573d87115 --output runtime/f1/web-residual-review-new
```

재현에는 프로토콜이 참조하는 기존 로컬 준비 자료·v40/v40b 결과·동일 모델이 필요하다.
입력 SHA·물리 행 수·정답 결합·EOF 지문을 검증하고 새 출력 폴더만 허용한다.
기존 잘못된 결과를 덮어쓰거나 오래된 프로토콜을 최종안으로 다시 해석하지 않는다.

다음은 명령 검토 사례의 실제 서버 측 인증/허용 업무·스크립트 실행·기기/주체 신호와
POST/리다이렉트 오탐의 누락된 본문/권한 맥락을 확보하는 작업이다.
새 자료는 개발/보정 용도를 먼저 확정하고 후보 동결 전 최종 예약 자료를 열지 않는다.
최종 독립 사례0·독립 검토 완료0을 유지하며 `aitest`/`main` 병합과 GitHub 업로드는 하지 않았다.
유료 API·AWS 호출·모델 재학습·새 다운로드도0이다.
