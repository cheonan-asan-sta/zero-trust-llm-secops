# 채희주 개인 실행 계획

천안아산역 팀 · 아키텍처 AI 인프라 담당 · 2026년 11월 1일 작성

기존 역할에 따라 제로트러스트 설계·AI 분석·인프라 실행 환경을 맡는다. 김택희가 구현할 입력·저장·정책·집행 기능에 필요한 계약과 실행 조건을 먼저 전달하고 상대 구현을 독립 재현한다. 아래 항목은 예정 업무다.

## 1 담당 범위와 이번 주 실행

주담당은 신뢰 경계·정책 판단 조건, AI 후보·프롬프트·구조화 응답, 서비스 신원·통신 보호·키 구성, Compose·관측·배포 재현성이다. 정책 엔진의 상태 전이·허용 소비·회수와 저장 구현은 김택희가 맡고, 기대 판단은 함께 확인한다.

현재 기준은 v0.17.0의 로컬 모의 운영이다. 실제 IdP·EDR·GuardDuty 수신과 운영 배포가 검증된 상태로 표현하지 않는다. 11/1까지 끝나지 않은 신호 권한 분리·범위 정의를 먼저 이월한다.

### 11월 2일부터 8일까지 우선 작업

1. M1·M2의 보호 자원·행위·정상 업무·제외 범위와 인증/기기 신호의 증명 권한을 정리한다. 각 조건을 정상·거부 예시와 연결한다.
2. M3·I1의 수집기→수신기→저장→처리기→정책 엔진 구조와 서비스별 쓰기·키 권한표를 만든다. 김택희와 접수 확인·오류·중복 처리 계약을 확정한다.
3. I2~I6의 통신 허용표와 서비스 신원 검증 방식을 정하고 처리 지연·신호 최대 나이·대기량·복구 시간/소실 허용 구간·경보 기준을 수치로 합의한다.
4. M6의 생성형 기준 1개·타 공급자 비교 1개, Jev·Laya의 공통 분류 질문·정보 부족 선택지·평가 지표·호출 한도를 정한다. 추천과 채택 상태를 구분한다.
5. 김택희의 최소 수신·처리 경로를 별도 로컬 환경에서 재현하고 저장 실패·중복·재시작 결과가 설계와 일치하는지 확인한다.

11/8 전달물은 범위·구조도, 서비스/키 접근표, 이벤트·판단 계약 검토본, 운영 목표와 모델 비교 계약이다. 김택희에게 최소 입력·응답·오류 예시와 재시작 결과를 받아 Compose 실행 조건과 대조한다.

공동 작업은 위협 시나리오·라벨 검토, 통합 시험, 멘토 확인 자료와 주간 보고서·인스타·최종 발표다. 개인 성과에는 실제로 수행한 변경·검토·재현만 기록한다.

매주 보고서에는 문제와 멘토링 연결, 내 설계·AI·인프라 변경, 실제 검증과 한계, 다음 작업을 작성한다. 인스타의 핵심 메시지·구조도를 준비하고 김택희가 제공한 결과 수치·화면·조건을 함께 확인한다. 발표·보고서 최종 검토는 공동으로 수행한다.

완료 기록에는 작업 ID(M/I)·날짜·변경 파일/버전·재현 방법·기대/실제 결과·상대 검증자·남은 결함을 남긴다. 계획에 이름이 있다는 이유로 개인 기여나 구현 완료를 소급 기재하지 않는다. 시험 증거가 없으면 미완료로 남긴다.

개발은 로컬 Docker Compose에서 수행한다. 유료 모델 비교는 합의한 요청·토큰·금액·시간 상한으로 별도 실행한다. AWS 생성·배포, GitHub 업로드와 실계정 변경은 수행하지 않는다. API 키나 서명 개인키를 문서·화면·이미지에 넣지 않는다.

역할 근거는 기존 수행계획서의 「역할 분담 및 협업 방법」이다. 세부 일정은 [멘토링 우선 계획](../mentoring-priority-roadmap.md), 모델 근거는 [후보 검토](../model-candidate-review.md), 두 사람의 경계는 [역할·협업 기준](../team-responsibilities.md)을 따른다. 이 문서와 Word 공유본을 함께 갱신한다.
