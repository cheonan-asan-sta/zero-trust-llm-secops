# 채희주 개인 실행 계획

천안아산역 팀 · 아키텍처 AI 인프라 담당 · 2026년 11월 1일 작성

기존 역할에 따라 제로트러스트 설계·AI 분석과 인프라의 구성·실행·측정을 맡는다. 서버·도구를 직접 실행하고 장애·자원·지연·복구 원자료를 남긴다. 김택희와 입력·저장·정책·집행 계약을 맞추고 상대 구현을 검증한다. 아래 항목은 예정 업무다.

2026년 11월 3일 수행 기록: 동료의 M3 PR #1을 `aitest`에서 받은 뒤 `feature/chaeheeju-m3-infra-validation`에서 Windows/Docker 재현과 반복 측정을 진행하고 [PR #2](https://github.com/cheonan-asan-sta/zero-trust-llm-secops/pull/2)로 병합했다. 실제 결과·조건·한계는 [인프라 측정 기록](../m3-infrastructure-measurement.md)을 따른다. 후속 `feature/chaeheeju-c03-supply-chain`에서 [C03 첫 비교](../technology-decisions/C03-supply-chain.md)와 [M6 후보·조건 계약](../m6-evaluation-contract.md)을 진행했다. 이는 이 대화의 도구를 통한 실행이며 다른 팀원의 검토·전체 주간 계획 완료로 기록하지 않는다. 개인 이름 브랜치와 PR 기록은 [작업 절차](../contribution-workflow.md)를 따른다. C03 채택·독립 재현, 신규 모델 실제 비교·운영 복원은 여전히 후속 작업이다.

## 1 담당 범위와 이번 주 실행

11/3 후속 수행: `feature/chaeheeju-c01-observability`에서 [C01 수집/경보 비교](../technology-decisions/C01-observability.md)를 진행했다.
기존 앱의 viewer 요약 API를 그대로 사용하고 최소 권한 수집기·망 분리·같은 경보의 두 구성을 직접 실행/측정한다.
최종 채택·타 팀원 재현·고부하/운영 인증 검증은 별도이며 김택희의 교차 검토 완료로 기록하지 않는다.

주담당은 신뢰 경계·AI 설계, 서비스 인증·키·네트워크, Compose·프록시·관측·스캐너·배포·백업/복원 실행과 성능/자원 측정이다. 인프라 원자료·집계·선정 근거도 작성한다. 김택희는 인가 API·정책 상태·허용 소비·회수·저장 일관성과 앱 지표를 맡는다.

현재 기준은 v0.17.0의 로컬 모의 운영이다. 실제 IdP·EDR·GuardDuty 수신과 운영 배포가 검증된 상태로 표현하지 않는다. 11/1까지 끝나지 않은 신호 권한 분리·범위 정의를 먼저 이월한다.

### 11월 2일부터 8일까지 우선 작업

1. M1·M2의 보호 자원·행위·정상 업무·제외 범위와 인증/기기 신호의 증명 권한을 정리한다. 각 조건을 정상·거부 예시와 연결한다.
2. M3·I1 구조·통신/키 권한표와 Compose 실행 경로를 구성한다. 김택희와 접수·오류·중복 계약을 맞추고 준비된 서비스를 실행한다.
3. I2~I6 인증·통신 방식과 자원/지연 측정 틀을 준비한다. 신호 나이·대기량·복구 시간/소실 구간·경보 목표를 합의한다.
4. M6와 C01~C10 후보·입력·안전 조건·한도를 정한다. C03 두 스캐너를 직접 실행하고 출처·검사 시간/자원·발견 원자료를 기록한다.
5. 수신·처리 환경의 재시작·통신 장애를 주입하고 자원·지연을 측정한다. 김택희의 저장 실패·중복·회수 시험과 결과를 대조한다.

11/8 전달물은 구조·권한표, Compose 실행 조건·측정 틀, C03 원자료와 운영/모델 비교 계약이다. 김택희에게 입력·오류·처리 상태·시각을 받아 인프라 기록과 대조한다.

공동 작업은 위협 시나리오·라벨 검토, 통합 시험, 멘토 확인 자료와 주간 보고서·인스타·최종 발표다. 개인 성과에는 실제로 수행한 변경·검토·재현만 기록한다.

11/3 후속 [C02 HTTP 집행 비교](../technology-decisions/C02-http-pep.md): NGINX/Envoy 구성·망 분리·독립
합성 문서 서버·장애 주입·자원/지연 측정과 근거 작성을 수행한다. 기존 인가 API/worker를 재사용하며
앱 정책·탐지 기준선을 바꾸지 않는다. 운영 채택·김택희 검토/독립 재현 완료와 구분한다.

## 2 주차별 작업과 제출물

11/3 추가 [선택 경로 전체 mTLS](../all-hops-mtls.md): 서비스별 CA/leaf·신원·호출 범위·망·관측 경로를
구성하고 실패/회전/등록 취소와 문서·경보 전달을 도구로 실행·검증한다. 과거 HTTP 비교·탐지 기준선은
보존하고 운영 CA/HA·최종 채택·상대 독립 재현과 구분한다.

11/3 추가 [I2 mTLS](../i2-service-mtls.md): 인가 경계의 인증서/신원/호출 범위, 격리망과 키 교체/폐기를
구성·실행하고 증거를 남긴다. Codex 도구 실행 기록이며 팀원 수동 실행/독립 검토로 바꾸지 않는다.
기존 앱/worker를 재사용하며 운영 CA·다른 hop·백업 복원은 후속으로 유지한다.

매주 보고서에는 내 설계·AI·인프라 변경과 직접 실행·측정한 수치·조건·한계를 작성한다. 인스타의 메시지·구조도·인프라 결과를 준비하고 김택희의 백엔드·데이터·모델 평가 결과와 함께 확인한다. 발표·보고서는 공동 검토한다.

완료 기록에는 작업 ID·날짜·버전·실행자·측정자·원자료·기대/실제·상대 검증자·남은 결함을 남긴다. 인프라 후보별 측정/집계와 채택·미채택 근거를 작성해 상대 검토를 받는다. 설치 성공이나 계획 배정을 과거 기여·비교 완료로 기록하지 않는다.

개발은 로컬 Docker Compose에서 수행한다. 유료 모델 비교는 합의한 요청·토큰·금액·시간 상한으로 별도 실행한다. AWS 생성·배포와 실계정 변경은 수행하지 않는다. GitHub 업로드·병합은 사용자가 요청한 개인 브랜치·PR 절차를 따른다. API 키나 서명 개인키를 문서·화면·이미지에 넣지 않는다.

역할 근거는 기존 수행계획서의 「역할 분담 및 협업 방법」이다.
