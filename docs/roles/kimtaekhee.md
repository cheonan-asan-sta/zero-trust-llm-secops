# 김택희 개인 실행 계획

11/5 C03 후속 인계 [발견 차이 재분석](../supply-chain-findings-review.md): 공급자 alias와 실제 영향의
구분, 변조/누락 거부·패키지 범위 혼동을 독립 대조하고 앱 영향 검토를 보탠다. 이 검토는 미완료다.
재분석기 구현·실행·인프라 원자료는 채희주 담당이며 이 기록을 김택희의 수행 실적으로 취급하지 않는다.

11/5 후속 인계 [CA·DB·leaf 데몬 복구](../service-daemon-recovery.md): 사본/pending/DB 역할 충돌·
다른 서비스 신원 거부, 접속 재개 후 새 토큰 소비·폐기·leaf pause 보존을 독립 대조한다.
인프라 구성·실행·측정은 채희주 담당이며 도구 보조 실험과 팀원 독립 검토 완료를 구분한다.

11/4 후속 인계 [부모 Docker 데몬 복구](../parent-docker-recovery.md): 다른 데몬·사본/owner
충돌·살아 있는 작업 거부와 완료 후 같은 영수증/새 profile 보존을 독립 대조한다. 인프라 구성·실행·측정은
채희주 담당이며 이 문서는 실제 팀원 검토 완료 증거가 아니다. 새 실제 CA 검증과 합성 marker도 구분한다.

11/4 후속 인계 [전환 실행기 컨테이너 유실 복구](../actor-container-recovery.md): 같은 작업/epoch
재개와 이전 ID 잔존·사본/owner 충돌 거부, 완료 후 새 토큰 소비 보존을 독립 대조한다.
인프라 구성·실행·측정은 채희주 담당이며 이 기록은 실제 팀원 재현/검토 완료 증거가 아니다.

11/4 후속 인계 [관리 호스트 전환 실행기 재개](../executor-transition-recovery.md): 완료 뒤 새 토큰
소비/폐기를 반복 재개가 되돌리지 않는지, pending/다른 actor ID·부분 사본 충돌을 거부하는지 독립 대조한다.
인프라 구성·실행·측정은 채희주 담당이며 이 문서를 실제 팀원 재현/검토 완료로 취급하지 않는다.

11/4 후속 인계 [관리 실행 호스트·기록 이중화](../executor-host-high-availability.md): 생존 journal이
같은 전환 ID·키 후보·authority epoch를 이어가고 새 보안 상태와 미만료 토큰 소비/폐기가 보존되는지
독립 대조한다. 대기/이전 실행 epoch 거부도 재현한다. 인프라 구성·실행·측정은 채희주 담당이며 이 기록은
실제 검토 완료 증거가 아니다. 물리 HA·운영자 전환 중단 복구는 후속 조건으로 남긴다.

11/4 후속 인계 [관리 전환 중단 복구](../control-transition-recovery.md): 전환 미완료 중 관리
작업 거부, 동일 키/epoch 재개, 접속 재개 후 신규 토큰 소비가 되돌아가지 않는 의미를 대조하고 독립
재현한다. 인프라 실행/측정은 채희주 담당이며 이 기록은 김택희의 실제 검토 완료 증거가 아니다.

11/4 후속 인계 [관리 영역 이중화](../control-plane-high-availability.md): 관리 사본 이전/캐시 손실
후 동일 키 계획·커밋 epoch·토큰 소비/폐기 보존, 미완료 작업/오래된 역할의 거부를 독립 대조한다.
채희주는 인프라 실행·측정을 맡는다. 이 문서는 김택희의 실제 재현/검토 완료 증거가 아니다.

11/4 인계 [CA DB·서비스 호스트 복구](../ca-db-host-recovery.md): 최신 토큰 소비·인증서 폐기가
과거 dump 복원 후에도 보존되는 의미, 불확실한 상태의 거부, 앱 권한/회수 경계의 독립성을 대조하고
독립 재현한다. 인프라 구성·실행·측정은 채희주 담당이다. 이 추가는 김택희의 검토 완료 기록이 아니다.

천안아산역 팀 · 백엔드 데이터 테스트 담당 · 2026년 11월 1일 작성

기존 역할에 따라 FastAPI·데이터·자동 테스트·대응 엔진을 맡는다. 정책·운영 조건을 입력·저장·상태 전이·인가 API로 구현한다. 채희주가 실행·측정하는 인프라에 앱 지표를 제공하고 결과를 교차 검증한다. 아래 항목은 예정 업무다.

11/3 인계 자료: 채희주 작업에서 [M6/C10 후보·안전·예산 계약 초안](../m6-evaluation-contract.md)과
[C03 로컬 비교](../technology-decisions/C03-supply-chain.md)를 작성했다. M6 실행기·예산 중단/오류 시험·모델 집계와
C03 발견의 앱 영향 대조·독립 재현은 후속 업무다. 이 기록은 김택희의 실행·검토 완료를 뜻하지 않는다.

추가 인계: [C01 관측·경보 비교](../technology-decisions/C01-observability.md)는 기존 viewer inbox 요약 API를 재사용한다.
앱 API·정책·탐지 규칙은 변경하지 않았으며, 상태 건수/age 의미·오류 시 지표 누락·키 폐기 후 failed 전이와
실제 알림의 대조 및 독립 재현을 검토할 수 있다. 별도 모델/백엔드 평가 실행기 업무는 유지한다.

추가 인계: [C02 HTTP 집행 비교](../technology-decisions/C02-http-pep.md)는 기존 보호 접근·회수 API와
위험 관찰 worker를 재사용한다. 후속 검토는 API reason code/저널과 실제 자원 전달 대조, 인가 시점과
진행 중 요청의 회수 한계, 운영 통합 계약·독립 재현이다. 이번 실행을 김택희의 검토 완료로 기록하지 않는다.

## 1 담당 범위와 이번 주 실행

추가 [CA 프로세스 HA 인계](../ca-high-availability.md): 노드 전환 후에도 token 단일 소비·공유 폐기·
기존 인가/회수 의미가 같은지 원자료와 대조하고 독립 재현한다. 앱 SQLite의 PostgreSQL 전환 업무가
아니며 이번 도구 실행을 김택희의 검토 완료로 기록하지 않는다. DB/호스트 HA는 후속이다.

추가 [CA·JWK 교체 인계](../authority-key-rotation.md): 새 신뢰/발급자에서도 grant 소비·회수·테넌트 경계가
같은지 대조하고, 전체 이행 전 구 신뢰 제거 금지·구 JWK 거부·정상 업무/경보를 독립 재현한다. 도구 보조
구현·실행과 상대 팀원의 검토 완료를 구분한다. 앱 정책·탐지 기준선은 변경하지 않는다.

추가 [개인키 교체 인계](../private-key-rotation.md): 새 키로 바뀐 후에도 기존 grant 소비·회수·테넌트
경계가 같은지 대조하고, 중단 복구·CA 장애·구 키 거부를 독립 재현한다. 아래 시험의 도구 실행과 팀원
독립 검토 완료를 구분하며 탐지 기준선은 변경하지 않는다.

추가 [C04 인계](../certificate-automation.md): 후속 검토는 갱신 신원이 업무 권한을 얻지 않는지,
인증서/pin 교체 뒤에도 기존 출처·grant·회수·저널 계약과 정상 사용자 영향이 같은지 대조하고 독립 재현하는 것이다.
이번 인프라 실행을 김택희 검토 완료로 기록하지 않는다.

추가 [전체 경로 인계](../all-hops-mtls.md): 앱 소스/정책은 유지하고 native TLS wrapper와 기존 API 키·
source 서명·grant 판단을 연결했다. 후속 검토는 실제 TLS peer의 권한, 저널/소비/회수 상태, viewer 경계,
경보 episode와 독립 재현이다. 이 인프라 실행을 김택희 검토 완료로 기록하지 않는다.

추가 [I2 인계](../i2-service-mtls.md): transport 인증이 앱 역할/테넌트·source 서명·grant 판단을 대신하지
않는지, 회수/만료/재시작 상태가 mTLS 경로에서도 같은지 대조한다. 기존 API·worker는 변경하지 않았다.
해당 검토와 독립 재현은 후속이며, 이번 인프라 실행을 검토 완료로 기록하지 않는다.

주담당은 API·내구 수신/처리·중복 방지·정책 상태·허용 소비/회수·승인·저장 일관성, 앱 지표·자료·평가 실행기·기능 시험이다. 채희주는 프록시·인증·관측·스캐너·배포·백업/복원을 실행하고 자원/지연·복구 시간을 측정한다. 결과는 함께 확인한다.

현재 기준은 v0.17.0의 로컬 모의 운영이다. 기존 177건 통과는 10/27 검증 기록이며 이번 예정 기능의 결과로 쓰지 않는다. 11/1까지 끝나지 않은 신호 권한 분리·범위 정의를 먼저 이월한다.

### 11월 2일부터 8일까지 우선 작업

1. 채희주와 인증/기기 신호별 증명 범위·정상/거부 예시를 확인하고 현재 입력·정책·시험에서 미완료인 항목을 정리한다.
2. M3·I1의 접수·저장·처리 상태와 응답 계약을 만든다. 저장 후에만 접수 성공을 반환하고 이벤트 ID·테넌트·입력 지문에 따른 중복·충돌을 정의한다.
3. 별도 처리기의 관련 세션 재평가·회수, 재시도·실패 보관·대기량 상한을 구현한다. 기존 아웃박스의 재사용 범위를 검토하고 수신 큐와 구분한다.
4. 저장 전 실패·처리 직전/직후 종료·중복·순서 역전·재시작·상한 초과를 시험한다. 정상 업무·무관 세션 유지와 회수 후 다음 접근 거부를 확인한다.
5. M7 자료·M6 평가 틀과 C01~C09의 공통 입력·인가 API·앱 지표·기대 결과를 준비한다. 채희주의 C03 검사 발견을 앱 의존성과 대조한다.

11/8 전달물은 입력·응답·오류 예시, 저장/처리 상태와 재시작 결과, 재현 절차·시험표, 데이터/평가 계약이다. 채희주에게 보호 자원·정책·통신/키 권한표·운영 목표·모델 질문을 받아 구현과 대조한다.

공동 작업은 위협 시나리오·라벨 검토, 통합 시험, 멘토 확인 자료와 주간 보고서·인스타·최종 발표다. 개인 성과에는 실제로 수행한 변경·검토·재현만 기록한다.

매주 보고서에는 내 API·자료·기능 시험·모델 평가 결과와 한계를 작성한다. 인스타에는 백엔드/평가 수치·화면·조건을 제공하고 채희주의 인프라 수치·구조도와 함께 확인한다. 발표·보고서는 공동 검토한다.

완료 기록에는 작업 ID·날짜·버전·기대/실제·원자료·상대 검증자·남은 결함을 남긴다. 인프라 실행/측정의 주담당은 채희주이며, 나는 앱 지표·상태 검증과 결과 대조·독립 재현을 기록한다. M6/C10 모델 평가 실행기·집계는 유지하고 자료 출처·라벨·세션 분리도 보존한다.

기능·장애 시험은 로컬 Docker Compose와 규칙·모의 응답으로 수행한다. 실제 모델 평가에는 합의한 한도를 별도 적용하고 모의 결과와 구분한다. AWS 생성·배포와 실계정 변경은 수행하지 않는다. GitHub 업로드·병합은 사용자가 요청한 개인 브랜치·PR 절차를 따른다. 비밀값·실사용자 식별정보를 시험 자료와 화면에 남기지 않는다.
