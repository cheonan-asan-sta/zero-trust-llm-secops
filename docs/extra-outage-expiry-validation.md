## 실제 분리 재현

동일한 로컬 mTLS 서비스에서 API 중단·관측 보관·collector/worker 실제 재시작·API 복구를 재현했다.
입력 envelope 지문은 유지됐고 수신 영수증은 completed·시도1회·changed_sessions1이었다.
해당 권한 이력은 다음 순서였다.

1. `ACTIVE/ALLOW`, 버전1.
2. 원래 증명 만료 후 watchdog의 `HELD/HOLD`, 버전2, `SIGNAL_PROOF_EXPIRED`.
3. 복구 후 위험 관측의 `REVOKED/DENY`, 버전3, `CONTINUOUS_IDENTITY_DENY`.

정책 회수가 중복 실행된 것이 아니라 별개의 만료 제한이 먼저 기록된 경우였다.
기존 시험의 무조건적인 이력2개 조건은 이 정상적인 제한 강화 순서를 실패로 처리했다.
분리 재현은 원인 확인이며 전체 통합 검증 완료를 대신하지 않는다.
소유 컨테이너·볼륨·네트워크 잔여0을 확인했다.

- 중간 단계는 없거나 하나의 만료 전용 HOLD여야 한다. 실제 signal 증명 만료 시각 이후인지 확인한다.
  grant 만료만으로 signal 증명 만료를 대신하지 않는다.
- tenant·세션·사용자·기기·자원·행위와 연속 버전, 예상 관측 event ID와 근거 추가를 검증한다.

- 중복 전달 및 inbox 보관/재시작 이후에는 검증된 전체 이력이 정확히 같은지 비교한다.
