## 구현한 동작

[직전 v109](extra-vpn-protocol-refinement.md)의 동결된 모델을 그대로 사용한다. 새 모델 학습·라벨 변경·목표 기준 변경 없이, 학습에서 공격 지지5행 이상이고 정상 지지가0인 특징 셀을 추가 검토 신호로 연결했다. 정상 학습1행이라도 있으면 추가 공격 신호로 쓰지 않는다. 동일 셀의 여러 행은 서로 독립된 공격5건이라는 뜻이 아니다.

[공격 근거 연결기](../scripts/f1_lab/vpn_attack_evidence.py)는 새로 발생시킨 위험만 같은 물리 소스·같은 연결에서60초간 유지한다. 원래 출처와 행 순서·UTC 시각을 검증하며, 같은 시각은 앞선 물리 행만 이용한다. 뒤쪽 로그를 앞선 미탐에 소급하지 않는다. 유지된 위험과 성공 응답/초기 패킷은60초 기산점을 연장하거나 지우지 않는다. 다른 IP/port/source로 전파하지 않는다. 원문 신원 값은 연결 키로만 쓰고 공격 계정/IP 예외로 학습하지 않는다.

기존 탐지와 현재 정책의 명시적 거부는 이유·점수를 보존한다. 앞선 v109의 정상 보정을 적용한 기준선도 정확히 결속해 사용할 수 있게 했다. 원래 탐지 경보만으로 새 위험 유지 기간을 시작하지 않는다. 추가 경보는 검토 대상으로만 전달하며 자동 집행·접근 허용을 하지 않는다.0.95 점수는 동작상 위험 표식이며 보정된 공격 확률이 아니다.

운영 기본 탐지기나 팀원 앱을 바꾸지 않았다. [판정 CLI](../scripts/run_vpn_protocol_review.py)와 [로컬 실행기](../scripts/run_local_vpn_protocol_batch.py)의 명시적 `--with-attack-evidence` 옵션으로만 적용한다. 기존 기본 실행 동작은 유지한다.

## 남은 문제와 다음 순서

1. 기존 VPN은 FP48→4 이하, 웹 감사는 FP15→2 이하가 필요하다. 현재 TP를 보존하며 새 관측으로 개선해야 한다.
2. 공유 감사의 TP0/FN6/FP24를 해결하려면 사건 시점의 실행 주체·명령 근거가 필요하다. 나중에 생성된 설정이나 현재 로컬 fixture를 과거 정답에 붙이지 않는다.
3. Wheeler의 초기 미탐9행과 Wilson 웹 감사 미탐3행도 남는다. 미래 근거 소급·지원 기준 완화·공격 사례 ID 예외로 숫자를 맞추지 않는다.
4. 이미 관측/학습에 소비한 자료와 별도로 원래6개 보안 영역의 독립 인수가 필요하다. 전체 완료 시점은 이 근거 확보와 검증에 달려 있다.
