# 새 공개 HTTP 접근 데이터의 독립 탐지 평가

2026년 11월 25일 · `extra` 제품 기준 `49b3b0f` · 평가기 커밋 `0b08741` · CPU 로컬.

[후속 CRS 보강 비교](extra-public-web-target-crs-20261125.md)에서 이 자료의 미탐 53건을 회복했다. 같은 자료를 다시 사용한 결과여서 기존 독립 결과와 별도로 기록한다.

## 출처와 평가 범위

Database Sample의 공개 Nginx·Apache 접근 기록 v1에서 요청 791건 전체를 사용했다. 정상 719건과 위협 72건이며, 메서드·경로 조합은 정상 14개와 위협 8개다. 경로마다 발행자가 주석을 붙였으므로 같은 경로의 반복 요청은 서로 독립적인 위협 유형이 아니다. 성능 지표는 이 합성 웹 요청 집단에 대한 결과다. 발행자의 공개 자료를 로컬에 받아 SHA-256 `42f840b5dfd0f92a5b6dea339bc2077927f2ac0f8bcc2a536c39c3ae95b0d0c7`을 대조했다. [발행자 자료와 라벨 방식](https://databasesample.com/datasets/nginx-and-apache-access-log-tables-with-attack-annotations)

기존 튜닝·평가에 쓰인 공개 Apache, OpenLiteSpeed, SR-BH, KREONET, RBA와 프로젝트 합성 사례를 포함하지 않았다. 저장소의 추적 파일과 브랜치 이력에서 새 자료의 명칭 및 지문과 일치하는 사용 기록을 확인하지 못했다. 실제 운영 HTTP 로그인 Biblio-US17은 기관 메타데이터에 접근할 수 있었으나 원본 다운로드가 HTTP 401로 거절돼 이번 채점에서 제외했다. [세비야대 Biblio-US17 데이터 기록](https://idus.us.es/items/53034f60-d215-44b0-a198-eb8a5229218e)

## 동결과 채점

- 기존 동결 웹 모델 v114, 임계값 0.95, 기존 웹 근거 보강, 성공 POST 보정의 설정과 모델을 유지했다. 최종 평가 전에 규칙이나 임계값을 조정하지 않았다.
- 예측은 원본과 분리한 관측 파일을 사용했다. 메서드·경로·응답 상태·크기·클라이언트 주소·요청 시각으로 요청을 표현하고, 가상 호스트별로 기존 시간 창을 적용했다. 주석·경로 ID·User-Agent 분류는 예측 자료에서 제외했다. 발행자 시각은 시간대가 없으므로 상대 시간 계산에만 사용했다. 원본에 없는 HTTP 버전은 파서 입력에서 `HTTP/0`으로 표시했고, 인증·권한·본문은 제공되지 않아 추가하지 않았다.
- 최초 입력 매핑은 상태 코드가 문자열이고 시각에 시간대가 없다는 점을 놓쳐 791행 전부를 파싱하지 못했다. 그 결과는 탐지 성능 비교에서 제외했다. 원본 스키마에 맞춰 입력 변환만 수정한 뒤 791행을 모두 예측했다.
- 먼저 관측 지문과 예측을 봉인했고, 이후 채점에서만 발행자의 경로 주석을 사용했다. 최종 봉인 SHA-256은 `068dcc7fcd78efe9397c4258c9ecacea19930e86ab48132838f99a08f387c6af`이다. 소켓 연결을 차단한 로컬 재실행에서 관측·예측·봉인 지문과 채점 결과가 모두 같았다.

## 재현과 증적

로컬 회귀 159개와 Ruff가 통과했다. AWS 계정 호출과 유료 API 호출은 0회였다. [집계·모델 지문·봉인](infrastructure-results/public-web-access-independent-20261125.json)

깨끗한 평가기 커밋 `0b08741`에서 발행자 JSON을 내려받고, 기존에 쓰지 않은 출력 경로를 지정한다. 원본과 관측·예측은 로컬 `runtime/`에 둔다.

```powershell
python -m scripts.evaluate_public_web_access score <출력경로> <발행자JSON> <seal.json-SHA256>
```
