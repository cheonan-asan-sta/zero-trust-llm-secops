# 김택희 담당 개발 인수표

기준일은 2026년 11월 13일이며 개발 마감은 **11월 16일 월요일**이다.
기능 기준은 PR #55 병합 커밋 `740028f49c08a9384693d3a8ede3b7237bb757c2`다.
이 문서와 함께 추가한 변경은 실패 진단과 검증 자료 대조 도구이며 앱의 탐지 규칙, 접근 허용
조건, 통신 권한과 기반 이미지는 변경하지 않는다. 채희주의 `extra` F1 작업은 제외했다.

## 원래 개인 계획과 실제 완료 범위

| 원래 계획 | 구현과 검증 | 남은 판단 |
| --- | --- | --- |
| 1~2주 개발 환경과 AI 입출력 | FastAPI, 입력 검증, API 권한, 공통 모델 평가 계약 | 최종 발표에 쓸 모델과 버전 선택 |
| 3~4주 합성 로그 구조 | 사용자, 기기, 자원, 인증과 행위 입력, 공개 자료의 출처 및 라벨 기록 | 공개 자료와 통제 사례의 성과를 구분해 보고 |
| 5~6주 생성기와 AI 입력 | 시나리오 생성, 정답을 제외한 요청, 입력 지문과 세션 분할 검사 | 이미 본 평가셋을 독립 최종평가로 재사용하지 않음 |
| 7~8주 정책 실행 엔진 | 상태 전이, 자원별 단일 사용 허용, 회수와 접근 거부, 고위험 대응 승인 API | 실계정 차단은 범위 밖이며 고위험 조치는 모의 실행 |
| 9~10주 리스크와 안전 조건 | 신뢰 출처, 서명, 신선도, 테넌트 검사, 기준선, 승인과 실제 실행 주체 및 목적지 연결 | 정보 부족은 보류, 실제 탐지 목표는 별도 확인 |

| 15~16주 문서와 발표 | 아키텍처, 재현 명령, API 인계, 보고서 문안과 시연 원고 준비 | 실제 발표 자료 통합, 녹화와 제출은 두 사람이 진행 |

주차는 최초 계획의 분류다. 미래 주차 전체를 먼저 수행했다거나 인프라 측정의 작성자가
김택희라는 뜻이 아니다. 영속 큐, 상시 점검, 격리 복원과 실행 증거 수집은 멘토링의
지속 검증 요구를 반영한 확대 범위다.

## 자동 대조한 인수 근거

[PR #55 병합 후 CI](https://github.com/cheonan-asan-sta/zero-trust-llm-secops/actions/runs/43353453310)의
**attempt 2**에서 16개 작업이 모두 통과했다. attempt 1의 실행 증거 mTLS 시험 실패는
별도 보존했다. 당시 HTTP 응답이 빠져 원인은 확정할 수 없고, 같은 소스의 재실행 성공을
원인 수정으로 기록하지 않는다. 이번 진단 보완은 다음 실패의 상태, 단계와 고정 오류 범주를
남기며 재시도나 통과 조건 완화는 추가하지 않는다.

| 경로 | 검사 수 | 앱 관점에서 확인한 의미 |
| --- | ---: | --- |
| application | 25 | 정비 복원과 전체 저장 상태의 일관성 |
| application-mtls | 13 | 격리 복원 후 기존 허용 거부와 새 허용의 단일 소비 |

| execution-mtls | 25 | 지속 실행 증거 수신, 장애 복구, 보관, 관련 403과 무관 200 |

합계 419는 각 런타임 보고서의 검사 수 합계다. 서로 다른 419개 공격이나 탐지 정확도
표본을 뜻하지 않는다. 인프라 구성과 원래 실측은 채희주 담당이며 이 표는 앱 의미의 자동
대조 기록이다. 실제 팀원 두 명의 독립 검토와 운영 승인으로 대신하지 않는다.

선정 시험은 정상 및 거부 HTTP 요청의 지연을 측정한다. mint와 Docker exec 시작은 시간에서
제외한다. 모델 응답 3초 목표와 혼합하지 않는다. 이 실행의 gateway 장애 중 자원 전달은
3회 모두 0이고 새 허용으로 재개했다. 재개에서 새 자원 전달까지 6.92~7.20초였으므로
복구까지 모두 3초 이내였다고 표현하지 않는다. 물리 호스트 HA와 최대 처리량은 미검증이다.

원본 자료는 전달 묶음의 다음 파일에 있다.

- `runtime/kim-final-20261113/retention-aitest-ci-final.json`
- `runtime/kim-final-20261113/retention-aitest-full-ci.log`
- `runtime/kim-final-20261113/app-review-base/review.json`

대조 JSON의 입력 SHA와 각 보고서의 정규화 SHA를 확인한다. 원본 로그가 GitHub에서
검증된 서명된 증명은 아니며 URL과 커밋으로 직접 대조할 수 있다. `execution-mtls` 보고서는
Git SHA가 내장돼 있지 않아 CI 작업과 내부 일관성 검사를 통과한 release 지문으로 연결한다.
다른 보고서의 내장 Git SHA와 같은 강도의 소스 증명으로 표현하지 않는다.

```bash
.venv/bin/python -m scripts.review_acceptance_evidence \
  --ci-json runtime/kim-final-20261113/retention-aitest-ci-final.json \
  --ci-log runtime/kim-final-20261113/retention-aitest-full-ci.log \
  --expected-commit 740028f49c08a9384693d3a8ede3b7237bb757c2 \
  --directory runtime/kim-final-20261113/app-review-new-run
```

정상 출력은 `completed: true`, `ci_jobs: 16`, `runtime_checks: 419`,
`human_independent_review: false`다. 누락, 실패, skipped 작업, 다른 커밋, 중복 검사,
미정리 자원과 실패한 release 지문은 성공 처리하지 않는다. 도구는 `aitest` push CI처럼
실행 커밋과 `headSha`가 같은 자료를 대상으로 한다. PR의 임시 merge 커밋과 PR head를
혼동하지 않으며 PR CI는 별도로 검토한다. 새 병합 후 CI에는 새 SHA와 별도 출력 폴더를 사용한다.

GitHub CLI가 단계 이름을 `UNKNOWN STEP`으로 내보내는 형식도 지원한다. 이때는 런타임 작업
이름과 정확한 보고서 스키마가 모두 맞는 보고서만 사용한다. 검증 명령과 출력 단계가
같은 최종 JSON을 두 번 출력한 경우는 정규화 해시가 같을 때만 하나로 센다.
다른 명령의 JSON, 서로 다른 내용의 중복 보고서와 다른 작업의 보고서는 받아들이지 않는다.

## 현재 평가 결과와 최종 버전

실행 증거 계약 기준으로 기존 240건은 정밀도 100%, 재현율 66.67%, F1 80%,
오탐률 0%, 보류 200건이다. 새 실행 증거 통제 사례 170건은 정밀도 80%,
재현율 57.14%, F1 66.67%, 오탐률 14.29%, 보류 80건이다.
응답 오류는 두 집합 모두 0건이다. 위협 보류도 미탐에 포함한 수치이며 자세한 정의는
[마감 기록](kim-midnight-closeout-20261113.md)의 표를 따른다.

410건은 이미 검토한 회귀 자료다. 공개 원천이 포함돼도 현재 변환 및 통제 라벨의
독립 일반화 검증이 되지는 않는다. 정상 0건을 확정한 240건에서 오탐률만 강조하지 않는다.
95% 품질 목표나 초기 정확도 70% 목표를 달성했다고 결론 내릴 자료가 아니다.
과거 세 모델 600회 실호출은 별도 실험이며 이번에는 추가 유료 호출을 하지 않았다.

월요일 기준 제안은 현재 `aitest`의 규칙 기반 집행을 기준선으로 고정하고 LLM은 설명과
조사 우선순위 보조로 명시하는 것이다. 최종 모델, 프롬프트, 채희주의 별도 F1 결과와
향후 독립 평가 채택은 팀 판단으로 남긴다. `extra`를 자동으로 합치지 않는다.

## 앱 보안 패치 인계

[앱 입력 영향 검토](kim-app-input-review-20261113.md)의 APT, setuptools와 NGINX 잔여 발견을
새 이미지에서 해결했다고 표시하지 않는다. 이번 소스는 이미지와 패키지 잠금을 바꾸지 않았다.
정리 도구는 로컬 콘솔이며 외부 HTTP에서 DB 파일, SQL, 파일 경로나 백업을 받는 API를
추가하지 않았다. 서명한 원문, 승인 사용량, 취소, 회수와 중복 판별 이력의 보존은 기능 시험과
실제 mTLS 복원으로 확인했다. 별도의 운영 공급망 승인은 남는다.

채희주가 패치 후보의 이전 및 새 이미지 ID와 발견 결과를 고정하면, 김택희는 기존
`scripts.verify_runtime_upgrade`로 같은 scratch 볼륨을 두 이미지에 연결해 `prepare`와
`verify`를 차례로 실행한다. scratch에는 모의 토큰이 있으므로 결과의 요약 JSON만 공유한다.
그다음 전체 pytest, `test_response_mtls_runtime`, `test_execution_mtls_runtime`을 새 이미지
빌드 기준으로 실행한다. 현재 인터프리터끼리의 호환 시험을 패치된 두 이미지 비교로 바꾸지 않는다.
이미지 ID를 모르는 상태에서 다른 사람의 기반 이미지 잠금을 임의로 바꾸지 않는다.

## 화면과 네트워크 범위

기존 공유 화면은 분석과 세션을 제공한다. 기준선, 실제 실행 증거, 고위험 대응 승인 API의
화면 연결 규약은 [백엔드 화면 연결 계약](backend-screen-contract.md)에 고정했다.
공유 브라우저나 단일 프록시에 두 검토자의 개인키와 API 키를 함께 넣어 두 사람 승인으로
취급하지 않는다. 배포 경로와 사용자 신원을 팀에서 정한 뒤 기존 화면에 연결한다.

M8 제안 범위는 인증 및 지속 세션 검증, 사용자와 기기 신호, GuardDuty 형식의 로컬 입력,
승인된 작업의 주체와 목적지 메타데이터다. IP, 호스트, 포트와 경로는 볼 수 있지만
패킷 payload, PCAP, 전체 흐름 수집, 네트워크 IDS는 구현하지 않았다.
실제 AWS EventBridge 구독과 실계정 차단도 제외한다. 이 범위와 한계를 멘토에게 보여주고
확인하는 일은 남겨둔다. 로컬 신호 재생을 실제 AWS 실시간 수집이라고 설명하지 않는다.
