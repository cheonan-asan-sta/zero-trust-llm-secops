이번 검토에서는 탐지 후보를 채택하지 않았다. 확정 성능은 [v115](extra-journal-service-review.md) 그대로이며 공유 감사 TP 2/FP 3/FN 4·F1 36.36%, VPN TP 84/FP 42/FN 0·F1 80%다. 인증·웹 감사의 관측 수치는 각각 100%를 유지한다. 원래 1,681,815행·정답·목표를 바꾸지 않았다. 신규 전체 기능/성능 인수 실행을 했다는 뜻은 아니며 마지막 확정 Linux 820건은 v115의 결과다.

## 실제로 조사한 자료

기존 공유 서버 프로세스 모니터링에는 명령행·PID·PPID·서비스 cgroup 필드가 있었지만 R/S/Shaw/Wheeler 각각 10개의 시작 시점 표본만 있었다. 해당 서비스 사건에 가까운 실행 표본은 없어 부족한 근거를 채우지 않았다.

Wilson의 같은 archive에서 공유 서버 journal·인증·syslog·프로세스 자료 29파일·10,075개 디코딩 기록을 추가 확인했다. 원래 [학습 계획](../infra/f1-lab/frozen-audit-native-normal-v113/bundle.json)의 Wilson training 역할을 유지했다. 보관 폴더의 옛 sealed/heldout 이름을 근거로 새 독립 평가라고 부르지 않았다. archive의 기존 게시자 MD5 확인 기록과 로컬 SHA를 대조하고 ZIP CRC·원본 member 지문을 보존했다. 기존 v115 journal 조건에 새로 맞는 신호는 0이었다.

## 제외한 주소·DNS 후보

같은 부팅에서 networkd가 이전에 관측한 IPv4 주소와 DNS 요청의 출발 주소를 연결했다. 기존에 봉인한 DNS 경보, 여러 긴 인코딩 형태 label, 원래 audit 사건 전의 제한된 시간 창을 사용했다. DNS 로그가 초 단위이므로 그 초의 끝을 시각 상한으로 사용했다. IP·unit 이름을 학습 예외로 넣지는 않았다.

그러나 오래된 주소 관측은 현재 소유권·기기 권한의 증명이 아니며 다른 호스트 사이의 실제 시계 오차도 검증하지 않았다. 주소와 시간의 일치만으로 특정 서비스의 실행 행위를 식별할 수 없었다. 다음은 이미 관측한 학습 자료의 탐색 비교다.

정상 서비스 작업 29행이 추가 경보로 올라가 **오탐을 늘리지 않는 조건을 위반**했다. 미탐 2행 감소를 채택 성능으로 보고하지 않는다. 후보 코드와 출력은 private runtime에 보존하고 실행 코드 변경은 기존 커밋 바이트로 복원했다. 초기 탐색 실행과 보존 코드 사이에는 정규식 alias의 동일 의미 표기 변경이 있어, 이 탐색을 바이트 고정 전체 인수 실험으로 주장하지 않는다. 실패 결과·모집단을 바꿔 성공으로 만들지 않았다.

## 제외한 서비스 작업 간격 후보

같은 호스트·부팅에서 앞서 받은 systemd manager의 unit/job 기록과 현재 audit 행 사이의 간격을 조사했다. 이것은 **가장 최근에 관측한 manager 기록과의 간격**이며 현재 프로세스의 실행 시간이나 동일 invocation을 증명하지 않는다. 구체적인 unit 값·절대 날짜·소스 시작부터의 경과시간은 학습 값으로 사용하지 않았다.

R/S/Wilson/Shaw/Wheeler의 training 자료에서 시작·종료를 별도 그룹으로 유지했다. 각 단계에서 정상 지지 5 이상, 정상 최댓값보다 긴 공격 지지 5 이상일 때만 만드는 단방향 head를 시험했다. 현재 처음 관측된 시작/종료 각각 정상 56행·공격 5행이었다. 정상 최대 간격은 약 405,658.58초, 공격 간격은 약 237,324.56~368,883.73초였다. 정상 최대보다 긴 공격은 0으로 head를 만들 수 없었다.

최소 지지 기준을 낮추거나 시작/종료를 합산하지 않았다. 정상과 겹치는 구간을 임의로 삭제하거나 공격 시점에 맞는 기간 대역을 추가하지 않았다. 이 결과는 **시험한 단방향 간격 가설의 실패**이며 모든 다른 관측/모델이 불가능하다는 증명은 아니다.

## LLM 자체의 수치도 개선했는가

최근 v105~v115의 F1 개선은 로그 수집·근거 연결·규칙/경량 분류기의 탐지 경로다. **공급자 LLM 자체의 품질이 좋아졌다는 수치가 아니다.** 이번에도 실제 LLM 호출은 0이며 새 LLM 품질 향상을 측정하지 않았다.

[과거 11주차 문서](week11/README.md)에는 직접 OpenAI 분석의 합성 8건·1회 결과가 남아 있다. 위험도 정확도 75%, 대응 정확도 62.5%, JSON 유효율 100%, 평균 약 4.2초·P95 약 5.73초다. 이는 문서에 기록된 과거 소규모 시험이며 이번에 원본 공급자 응답을 재검증한 최신 결과나 일반화 성능이 아니다. 최근 탐지 F1과 같은 평가 대상/분모가 아니므로 서로 대체하지 않는다.

[M6/C10 계약](m6-evaluation-contract.md)의 모의 평가·입출력 검증도 실제 새 모델 비교의 성공으로 세지 않는다. 실제 LLM에는 분류/보류 정확도, 근거 ID·설명 정합성, 위험한 조치 제안/지시문 추종, JSON 유효율과 실패 처리, 지연·사용량·비용을 별도로 평가해야 한다. LLM 답이나 모델 간 동의로 접근 권한을 발급하지 않는 정책 경계는 유지한다. 현재 목표 조건에 따라 유료 호출은 계속 보류한다.
