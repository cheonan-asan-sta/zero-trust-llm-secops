## M7 원본 전체에서 확인한 내용

[게시자 설명](https://github.com/KREONET/auth-anomaly-dataset/blob/5fd5cae2001a6b67cafb952709db37e366cfa276/README.md)과
[스키마](https://raw.githubusercontent.com/KREONET/auth-anomaly-dataset/5fd5cae2001a6b67cafb952709db37e366cfa276/schema.json)는
연합 인증용 합성 자료이며 `event_type`의 라벨 연관성을 경고한다. 기존 M7 변환은 이를 모델 피처에서 제외했다.
원본/파생 자료는 [CC BY 4.0 게시자 라이선스](https://github.com/KREONET/auth-anomaly-dataset/blob/5fd5cae2001a6b67cafb952709db37e366cfa276/LICENSE)를 따른다.

공개 HTTPS로 받은 원본91,592,665바이트의 SHA-256은 기존 계약과 동일한
`445f69377a2e12b4203a68f15cd9a4013fbc7e0ef21c19843969f671b1334a30`이었다.
실제130,767이벤트·22,750흐름에서 게시자 라벨은 정상9,088·공격9,573·anomaly4,089였다.
anomaly를 정상으로 몰아넣지 않았으며 아래 이진 oracle에서는 별도 제외 수를 명시한다.

`scripts.audit_m7_source`는 원문 전체를 메모리에 보관하지 않고 임시 SQLite spool과 한 흐름씩의
모델 검증을 사용한다. 임시 저장소 논리 크기는170,610,688바이트였고 종료 후 정리했다.
Windows와 network none Linux에서 기존 M7의 개발/평가/라벨/manifest **4파일이 바이트까지 동일하게 재현**됐다.
아래 수치는 원본 전체에서 실제 계산한 **관측 투영의 라벨 모호성**이다. 검출기를 실행한 F1이 아니다.

| 투영 | 이진 흐름 수 | 서로 다른 패턴 | 정상/공격 충돌 패턴 | 낙관적 최소 오류 | 라벨을 모두 아는 lookup의 최대 F1 |
|---|---:|---:|---:|---:|---:|
| module/method/status/level 순서 | 18,661 | 617 | 69 | 1,377 | 92.99% |
| 위 순서+정확한 duration 값 | 18,661 | 18,646 | 0 | 0 | 100% |

첫 투영에서는 P≥95%·FPR≤5%를 함께 요구할 때 최대 재현율도 약89.06%였다.
이 투영만으로는 네 점 목표가 동시에 가능하지 않다는 계산이며, duration/다른 의미 있는 관측을
포함한 모든 입력·모든 모델까지 불가능하다는 뜻은 아니다.
정확한 duration을 넣으면 거의 모든 흐름이 고유해져 lookup 상한이100%가 되지만,
그것은 학습·교차 환경 일반화·공급자 LLM 품질을 측정한 결과가 아니다.

기존 파일럿48세션 중 **11세션**은 첫 투영의 원본 정상/공격 충돌 패턴에 속한다.
개발 공격1·정상7, 평가 공격1·정상2다. 파일럿 내 중복이 없다는 기존 검증과 모순되지 않는다.
파일럿 밖의 원본 흐름에서 같은 관측에 다른 라벨이 있다는 뜻이다.
따라서 검토자는 duration의 의미·삭제한 payload에 있던 공격 근거·원본 라벨 기준을 함께 확인해야 한다.
라벨이나 기존 선택을 바꾸지 않고 판단 불충분/추가 신호로 기록한다.

재현 명령은 원본을 내려받은 뒤 네트워크 없이 실행한다.

```powershell
.venv\Scripts\python.exe -m scripts.audit_m7_source --source <고정_원본.jsonl> --directory <새_결과_폴더>
```

실제 원자료는 `runtime/f1/extra-m7-streamed-v8-20261112-02`이며,
공개 요약은 [v8 결과](infrastructure-results/extra-streamed-v8-20261112.json)를 따른다.
기존 M7 검토지48건과 F0/F1 오류 검토22계열은 이 자동 분석으로 완료되지 않는다.

## 다른 공개 자료를 바로 합치지 않는 이유

[LANL 게시자 안내](https://csr.lanl.gov/data/cyber1/)는 인증/프로세스/DNS/흐름 및 특정 red-team 사건을
제공한다. red-team 목록에 없다는 이유만으로 모든 나머지 행을 검토된 정상이라고 정하지 않는다.
인증 실패 수집에도 사용자 선택 조건이 있어 일반적인 인증 실패 모집단과 다를 수 있다.
원본에 없는 MFA·관리 기기·요구 역할·업무 승인을 기본 정상 값으로 만들어 채우지 않는다.
이 자료의 채택 여부와 추출 범위/라벨 정책은 별도 검토해야 한다.

[OpTC 게시자](https://github.com/FiveDirections/OpTC-data)는 연구용 자료의 불완전성을 명시하고
ground-truth/형식/errata 문서를 제공한다. 호스트/네트워크 분석 후보로 두되, 해당 자료에 실제 존재하는
관측과 정답을 확인한 후 영역별 비교에 사용한다. 접근 권한 정책을 직접 검증하는 자료로 간주하지 않는다.

[다중 로그/SLM 논문](https://arxiv.org/html/2606.18190v1)은870세션을 설명하고7이벤트 청크 분류와
기법 식별을 구분한다. 청크 정확도를 우리 세션 F1·회수 성공률로 대체하지 않는다.
현재 확인 범위에서는 고정 원본 배포본/라이선스·원 세션이 분할을 넘지 않는 조건을 아직 검증하지 않았다.

## 정상 업무 비율에 따른 목표의 해석

평가셋의 공격 비율은 실제 운영 비율의 추정치가 아니다. 아래는 **가상의** 공격 비율에서
TPR95%·FPR5%라고 가정했을 때 정밀도가 어떻게 달라지는지 계산한 예시다.

정밀도 = TPR×공격비율 / (TPR×공격비율 + FPR×정상비율).

| 가정한 공격 비율 | TPR95%/FPR5%일 때 정밀도 | 정밀도95%까지 요구할 때 허용 FPR 상한 |
|---|---:|---:|
| 50% | 95.00% | 5.0000% |
| 10% | 67.86% | 0.5556% |
| 1% | 16.10% | 0.0505% |
| 0.1% | 1.87% | 0.0050% |

균형 표본에서95%라는 수치와 저빈도 운영 환경의 경보 신뢰도는 다르다.
실제 정상 업무·공격 빈도·오탐 처리 부담을 별도로 수집하고, 기존 네 목표를 낮추지 않은 채
영역별·운영 조건별 한계를 함께 보고한다. 표본을 같은 틀로 늘리는 것은 독립 표본 확보가 아니다.

다음 확보 대상은 별도 검토자가 판정한 정상 업무/공격 흐름, IdP/EDR의 권한 있는 관측,
자원 소유자 정책, 실제 업무 승인/바이트 증분, 후보 고정 이후의 새 평가 분할이다.
새 자료를 받으면 출처·사용 조건·관측/정답 분리·분할 중복·누락/모호성부터 확인한다.
[raw 자료 입력 검증/검토지 도구](f1-data-intake.md)는 이 준비를 지원하며, 실제 출처 확인이나 독립 검토를 자동 완료하지 않는다.

## 공개 원본을 모두 유지할 때의 분할 연결성

`audit_m7_splits.py`는 이미 확보한 같은 고정 원본130,767이벤트/22,750흐름을 다시 읽고
분할을 만들지 않은 채 연결 성분을 계산했다. 같은 그룹 키를 가진 흐름을 연결하고 그 연결을
추이적으로 묶었다. 계열은 **category+subcategory**이며 정답 label은 계열 키에서 제외했다.
known subject는 `user_id`/`action_by` 값을 같은 namespace로, client는 명시된 `client_ip`로 해석했다.
이는 보수적인 분할 가정이다. 클라이언트 IP가 실제 기기/사람을 증명하거나 두 주체 필드가 실제로
같은 신원 체계라는 것을 입증한 것은 아니다. null은 공통 사용자/클라이언트로 묶지 않는다.

| 함께 분리하려는 그룹 | 전체3종 원본 연결 성분 | benign/attack 이진 연결 성분 |
|---|---:|---:|
| 의미 계열 | 136 | 100 |
| 관측된 주체 | 8,964 | 8,584 |
| 관측된 클라이언트 | 1,845 | 1,550 |
| 의미 계열 + 주체 | 42 | 41 |
| 의미 계열 + 주체 + 클라이언트 | 1 | 1 |
| 위3종 + module/method/status/level 순서 | 1 | 1 |

전체 자료를 유지하면서 모든 계열/주체/클라이언트를 분할 간 나누지 않으면 한 묶음이므로
세 개의 비어 있지 않은 분할을 만들 수 없다. 클라이언트를 빼도 계열+주체 조건에서
benign9,088흐름이 한 연결 성분에 포함돼 각 분할에 정상 흐름을 갖추는 필요조건을 충족하지 못한다.
이진18,661흐름에서 가장 큰 계열+주체 성분은13,137흐름(70.40%)이었다.
