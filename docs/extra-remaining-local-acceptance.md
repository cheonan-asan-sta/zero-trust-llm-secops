- OIDC 세션·호출 신원·보관 및 복원 후보 전환을 묶은 로컬 회귀는 Linux 118개 통과, Windows 103개 통과·15개 제외였다. Windows 제외는 POSIX 파일 검증 조건에 해당한다. 보관은 로컬 스텁으로 고정한 객체 버전과 보존 조건을 대조했고, 신원 검증은 로컬 서명과 신원 증거를 사용했다. 별도 CLI 프로세스의 원본 경로 없는 복원, 승인 후 재시작과 수집 재개, 게시 실패 시 기존 선택 보존을 확인했다. 원본 JUnit XML은 `runtime/remaining-local-identity-archive{,-linux}-9c83559.xml`에 있다.

## 8시간 연속 운영 시험

첫 사전 시험은 실제 126.96초 동안 17개 표본을 수집했다. 기존 완료 기준은 최소 23개라서 `native_source_soak_coverage_short`로 종료됐다. 최초 로그와 표본은 `runtime/remaining-soak-9c83559/preflight`에 보존했다.

두 번째 사전 시험은 임시 실행 환경의 Python 파일을 사전 컴파일하고 동일 소스와 완료 기준을 적용했다. 105.794초·19개 표본 이후 health 작업자의 `resource_receipt_binding` 오류로 종료됐다. 시험 도중 Windows가 14:39 KST에 배터리 부족으로 절전 전환을 기록했고, 15:13 KST에 시험 실패가 기록됐다. 작업자 오류의 직접 원인은 확정하지 않았다. 실패 로그, 진행 JSON, 해당 호스트 전원 이벤트를 `runtime/remaining-soak-precompiled-9c83559`에 보존했다.

세 번째 시도는 15:15 KST에 외부 전원과 충전 상태를 확인한 뒤, 새 경로 `runtime/remaining-soak-ac-9c83559`에서 시작했다. 사전 시험은 120.158초·24개 표본, 최대 관측 간격 5.486초로 통과했다. 15:19:28 KST에 별도 8시간 시험 프로세스를 시작했다. 사전 시험과 본시험 시간을 더하지 않는다.

초기 점검 후 15:20:49 KST 무렵 8시간 계측 구간이 시작됐다. 첫 표본에서 수집·보관·상태 점검 작업자의 기록을 관측했다. 현재 진행 중이며, 중단 없이 진행되면 23:21 KST 무렵 종료 판정이 가능하다.

Windows 실행기는 시험 프로세스가 살아 있는 동안 일시 절전 방지를 요청하고 종료 시 해제한다. `launcher.json`에는 각 단계의 시작 시각과 종료 코드가 기록되고, `continuous/soak-progress.json`의 `long_soak_8h_completed`가 본시험 완료 여부를 나타낸다.

## 운영 인수 준비

별도 보관 계정이 준비되면 불변 저장소에 합성 시험용 세대를 저장하고, 발행자와 권한이 분리된 복구 계정에서 정확한 버전·보존 기한·감사 최소 기준을 대조한다. 보관과 복구 권한 및 운영 비용을 먼저 확인한다. [불변 보관 운영 절차](extra-witness-archive.md)

기업 SSO 테스트 환경에서는 조직 소유의 테스트 계정을 사용해 운영자와 일반 사용자의 접근 차이, 만료, 세션 도중 권한 회수 및 새로운 로그인까지 확인한다. issuer·audience·키 배포 경로와 승인에 사용하는 역할 매핑을 운영자가 확정한다. 로컬 인증 시험은 실제 조직의 계정 정책이나 회수 지연을 측정한 결과와 별도로 보관한다.
