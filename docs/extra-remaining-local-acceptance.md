#### 새 원격 자료의 근거 연결 검사

평가 메타데이터 목록과 승인·MFA 참조 목록을 [로컬 검사기](../scripts/check_remote_evaluation_evidence.py)로 비교할 수 있다. 두 목록은 JSONL과 각각의 SHA-256으로 고정한다. 참조에는 사례 ID, 입력 SHA-256, 승인·MFA 기록별 SHA-256과 세션 그룹 지문, 기록이 최초로 이용 가능했던 시각과 관측 결과를 넣는다. 승인 거부와 MFA 비필수도 명시적으로 기록할 수 있고, 확인할 수 없는 결과는 미상으로 둔다.

```text
python -m scripts.check_remote_evaluation_evidence --catalog catalog.jsonl --catalog-sha256 CATALOG_PIN --evidence references.jsonl --evidence-sha256 REFERENCES_PIN
```

검사기는 입력 또는 세션 불일치, 사례 종료 후에 생긴 기록, 다른 세션에 재사용된 같은 기록과 미상을 구분한다. 참조 확인은 별도의 원본 무결성·출처·독립 라벨 검토나 추론·채점을 대신하지 않는다. 근거가 없는 사례의 정상·위협 라벨을 변경하지 않는다.

#### 외부 원격 접속 기록의 로컬 재생

Daniel Peng이 공개한 합성 인증 로그 180,000건에서 발행자가 지정한 보류 기간인 2026년 5월 16~30일의 성공한 `RemoteInteractive` 원격 로그온만 평가 대상으로 미리 고정했다. 기존 Sigma 원격 접속 경로에서 정답 없이 예측을 저장하고, 예측 파일의 해시 확인 후 발행자 라벨을 결합했다. #### 독립 평가에 사용할 실제 로그 수집과 연결

담당자는 VPN·RDP·게이트웨이, 승인 시스템, 인증원의 내보내기 위치 또는 읽기 전용 추출물을 전달하면 된다. 세 종류 기록에는 서로 대응시킬 수 있는 세션/요청 ID와 시간대가 포함되어야 한다.

| 기록 | 필요한 필드 |
| --- | --- |
| 접속 | 세션/요청 ID, 발생 시각, VPN·RDP·읽기 등 작업 종류, 대상, 허용·거절·보류 결과 |
| 승인 | 같은 세션 또는 연결 가능한 요청 ID, 결정 시각, 승인·거절, 대상·작업 범위, 유효 또는 회수 시각 |
| MFA | 요청 ID, 정책상 필수 여부, 검증 결과, 챌린지 결과·시각과 접속에 연결되는 식별자 |
| 검토 정답 | 정상·위협 판단과 그 근거를 별도 파일에 보관. 모델 입력에는 넣지 않는다. |

연결에 필요한 식별자는 같은 가명으로 치환한다. 실제 계정명·IP·비밀번호·토큰은 평가 입력에서 배제하고 출처·연결 근거·시각을 보존한다. 바이트 검증을 위해 `check_remote_evaluation_evidence.py`의 `--records-directory`에 승인·MFA의 익명화된 파일을 SHA-256 파일명으로 보관하도록 했다. 카탈로그와 연결 목록에 고정한 해시를 대조한다. 기록 생성 시점, 실제 발급원과 원본 라벨 근거는 별도로 확인해야 한다. 실제 조직 자료가 전달되기 전까지 이 단계의 독립 성능은 미측정이다.

#### 별도 로컬 인증원·보관 환경의 인수 시험

외부 인증원과 앱의 역할을 분리하기 위해 임시 RSA 키를 보유한 별도 루프백 OIDC 인증원을 사용했다. 앱은 HTTP로 공개 JWKS를 가져와 실제 서명을 검증했다. 정상 분석자 읽기, 뷰어의 회수 요청 거부, 대응 담당자의 세션 회수, 미사용 권한으로 회수 후 재접속 거부, 새 뷰어 토큰의 보호 작업 거부와 만료 토큰 거부를 테스트했다. 앱 세션 회수와 기업 IdP가 이미 발급한 토큰의 회수 전파는 별개 동작이다. 기업 IdP의 새 로그인·역할 매핑·강제 회수 정책 검증은 해당 조직의 환경이 있어야 진행할 수 있다.

별도 저장 HTTP 경로는 로컬 Docker 이미지 다운로드 권한 문제로 Moto 5.1.18의 별도 루프백 S3 서버를 사용했다. 격리 가상환경에 설치하고 검증 직후 서버를 종료했다. `AUDIT_LOCAL_S3_ENDPOINT=http://127.0.0.1:<port>`를 설정한 뒤 `tests/test_audit_witness_archive.py`를 실행하면 실제 HTTP 시험이 포함된다. 다른 테스트 클라이언트로 `COMPLIANCE` 보존 및 정확한 객체 버전을 확인했고, 보존 중인 버전 삭제는 `AccessDenied`로 거부됐다. 원본 경로 없이 내려받은 4,096개 서명과 암호화 백업을 복구 경로에서 검증하고 SQLite 파일을 열었다. 이 로컬 환경은 AWS 계정 간 IAM 강제, 실제 버킷 소유자 및 AWS 보존 정책의 운영 검증과 범위가 다르다.

로컬 회귀는 탐지·OIDC·보관·복원 214개 통과, 4개 제외였다. 자료 연결 변경과 새 OIDC 인수 시험은 46개, 루프백 WORM을 포함한 보관 묶음은 17개 통과했다. 묶음 간 중복이 있다. 결과는 `runtime/remote-scope-operational-regression-20261121.xml`, `runtime/remote-source-local-oidc-20261121.xml`, `runtime/local-worm-http-intake-verified-20261121.xml`에 있다. 이 두 운영 인수 실험의 AWS 호출과 외부 유료 API 호출은 0회였다.
