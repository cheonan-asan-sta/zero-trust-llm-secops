## 원격 접속 미탐 재생

저장된 개발 360건의 원래 LLM 결과와 로컬 규칙을 비교하는 [재생 도구](../scripts/replay_remote_disagreements.py)를 추가했다. `REMOTE_ACCESS`이고 전송 방식이 remote/VPN이며 규칙에서 위협을 탐지했지만 LLM이 위협으로 분류하지 않은 사례만 검토 후보로 표시한다. 라벨과 사례 계열은 선택 기준에 사용하지 않고 채점과 추적에 사용한다. 원격 LOGIN/READ만 관측된 사례는 이 조건에 해당하지 않는다.

검토 후보 35건은 기존 미탐 17건과 정상 18건이다. 미탐 17건 중 10건은 승인 근거, 7건은 MFA와 승인 근거를 함께 확인해야 한다. 정상 18건은 모두 범위가 일치하는 예외 주장을 담고 있다. 이 중 1건은 원래 LLM 형식 오류로 이미 보수적 오탐에 포함됐으므로 첫 가정의 새 오탐은 17건이다.

예외 주장의 범위 일치는 발급자의 승인 증명이 아니다. 검토 목록에는 해당 18건도 포함하고 발급자 확인 대상으로 표시한다. 두 번째 수치는 기존 개발 사례에서만 나온 가정이다. 승인 주장을 담은 위협과 승인 주장이 누락된 정상 접속을 넣은 합성 대조군에서 같은 가정은 미탐과 오탐을 각각 1건 냈다. 운영에 채택하려면 승인 발급자와 정책, 세션에 결속된 MFA 근거를 확인하고, 이런 반례를 포함한 새 자료에서 검증해야 한다. 운영 판정·차단은 연결하지 않았고 기존 결과·정답·평가 분모는 그대로다.

서명한 세션 신호와 서버 기록이 일치하는 `/analysis/verified-session`의 Hybrid 분석에 적용했다. 첫 원격 세션에서 일반 원격 로그인 Sigma 규칙만 일치했고 추가 인증 사유가 `ELEVATED_RISK` 하나일 때, 별도의 기기·인증·행동 위험 신호가 없으면 규칙의 포괄적인 내부 이동 판정을 제거한다. 확인된 정책의 정상 BYOD는 기기 관리 여부만으로 경보를 만들지 않는다. 모델의 개별 위협 판단은 유지한다. 모델 응답이 없으면 `UNKNOWN`과 사람 검토를 유지한다. 추가 인증 요구, 접근 제어 정책과 세션 상태는 변경하지 않는다.
