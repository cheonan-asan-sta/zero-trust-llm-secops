## 1 관측 모호성 점검

`scripts.audit_f1_features`는 현재 규칙이 읽는 필드와 별도로 선언한 보안 관측 묶음을 비교한다.
두 번째 묶음은 ID/부서/시각/원문 텍스트와 **서명 없는 승인 주장**을 제외한다.
동일 투영에 서로 다른 정답이 있는 경우를 찾고, 정답을 모두 알고 고를 수 있는 lookup의
낙관적 상한과 FP 한도 아래의 전체 그룹 선택 가능성을 계산한다.

이 계산은 **정답을 읽는 oracle 진단**이며 모델의 학습/검증 성능이 아니다.
상한은 정한 입력 투영에만 적용하고, 더 풍부한 신뢰 신호까지 불가능하다는 의미는 아니다.
F1 상한 계산과 그룹 선택 판정은 작은 집합의 모든 선택을 독립 완전 탐색한 시험과 대조했다.

실제 원자료: `runtime/f1/extra-observation-audit-20261112.json`.
관련9개 시험 통과. 승인 주장을 제외한 선언 관측의 개발360에서는 충돌30그룹·최소 오류30,
낙관적 최대 F1 약92.31%, P≥95%/FPR≤5% 조건의 최대 재현율 약87.78%였다.
이는 해당 개발 자료/투영만으로 네 점 목표를 동시에 달성할 수 없다는 진단이다.
따라서 승인 bool을 신뢰하거나 사례 ID/라벨을 학습해 점수를 올리는 방식을 해결책으로 삼지 않는다.

## 2 서명된 업무 맥락 실험

`scripts/f1_lab/approvals.py`는 Ed25519 공개키를 운영자 신뢰 설정으로 고정하고
tenant·발급자·키·사용자·기기·자원·행위·예외 종류를 함께 제한한다.
이벤트 지문·관측 신선도60초·승인 수명 최대5분·폐기·서명·크기/동일 키 alias를 검증한다.
원래 승인 bool/승인자 문자열은 권한 증거로 쓰지 않는다. 이벤트가 달라지면 서명 맥락을 재사용하지 못한다.

이 서명은 모의 탐지의 업무 맥락만 제공한다. 실제 계정 권한을 부여하지 않는다.
휴면/비활성 신원·MFA 거절·침해/위험 기기 신호는 유효한 업무 맥락으로도 지우지 않는다.
실제 권한 있는 조직 승인자가 발급한 맥락을 확보한 것은 아직 아니다.
정답·계열명·원본 bool에서 서명을 만들어 기본 비교의 ‘신뢰 증거’로 꾸미지 않는다.

## 3 초안 탐지기와 비교

`scripts/f1_lab/detector.py`는 관측 신호만 입력받는 local/test 전용 초안이다.
기기 규칙을 LOGIN 등 모든 행위로 확장하고, 실제 위험 기기·MFA/신원·일반 자원 역할 불일치,
원격 맥락·fanout·민감 bulk download의 가설을 별도 판단한다.
기본 수치3회/8자원/500MB는 기존 기준과 연결해 고정하고 사용자/계열별 조건을 넣지 않는다.
필요 시 서명 검증을 직접 수행해 허용한 예외 종류만 줄인다. 서명이 없거나 잘못되면 기본 탐지 신호를 유지한다.

`scripts.evaluate_f1_shadow`는 기존 개발/이미 본 holdout에서 원본과 초안을 비교한다.
실패 사례도 분모에 유지하고 전체/규칙별 지표·계열 bootstrap·게이트를 기록한다.
기존 원본은 일부 서명 없는 승인 필드를 읽지만 초안은 믿지 않으므로, 보안 가정의 차이도 함께 남긴다.
이 실행에서는 서명 맥락을 공급하지 않는다. 초안의 FP가 증가하더라도 그대로 보고한다.
LLM·외부 호출·접근 허용·세션 변경은0이다.
