낙관적 상한과 FP 한도 아래의 전체 그룹 선택 가능성을 계산한다.

이 계산은 **정답을 읽는 oracle 진단**이며 모델의 학습/검증 성능이 아니다.

### 추가 구현: 공개 승인 등록부와 시간창

승인 키의 활성 기간·주체/기기/자원/행위 범위를 추가했고, `registry.py`는 공개키만 든
JSON의 외부 SHA-256·최소 버전을 매 판단 시 대조한다. 파일 변경·폐기·키 활성 기간을 무시하지 않는다.
실제 조직 승인자의 등록부를 확보하거나 private key 파일을 불러오는 기능은 아니다.

`temporal.py`는 기존 서명 검증기를 재사용하되 **운영자가 event/delta 생산자로 지정한 출처**만 받는다.
평범한 세션 snapshot을 실제 신규 거래/바이트 증분으로 해석하면 안 된다.
tenant/운영자/session/사용자/기기를 묶고 event ID 재전송은 한 번만 집계한다.
서로 다른 로그인 실패 이벤트·민감 다운로드 증분·서로 다른 자원과 최근 침해 흔적을 시간창으로 유지한다.
관측 누락 전체를 증명할 수 없으므로 `collection_completeness_proven:false`를 명시한다.

SQLite와 별도 HMAC witness를 함께 사용한다. prepare→DB commit→witness publish의 실제 프로세스
종료4지점에서 정확히 이전/다음 head만 재조정하고 DB rollback·이력 수정·다른 DB는 거부한다.
승인/관측 키가 같으면 결합하지 않고, 현재 이벤트의 승인만으로 앞선 누적 이벤트를 승인하지 않는다.
출처가 폐기/변경돼 기존 근거가 신뢰되지 않으면 incomplete로 표시한다. 이를 건강한0건으로 쓰지 않는다.

초기 동시 접수 시험은 Windows byte lock을 읽다가94개 중1개가 실패했다.
기존 CA 잠금 구현은 바꾸지 않고 실험 저장소에서 lock byte를 초기화한 뒤 읽지 않고 잠그도록 보완했다.
이후24개 저장소 시험, 통합161개 및 Git 없는 snapshot 메타데이터를 포함한 Windows165개가 각각 통과했다.
서로 겹치는 회차 수를 합산하지 않는다. 전체 app 회귀나 CA 장애 행렬을 새로 수행한 것은 아니다.
별도 control/witness 전체를 동시에 과거로 되돌리는 특권 운영자나 OS 전체 침해를 막는 구조는 아니다.
운영 연결 전 source 등록부의 버전 고정/영구 폐기 절차와 실제 event/delta 어댑터가 필요하다.

### 점수100%와 목표 입증의 차이

v3 지연 측정은 producer 인코딩/서명·선택한 모의 발급·두 비교기의 실행을 포함한다.
