웹 접근 결과는 유지하고 오류 경고 FP와 VPN FN을 별도 비교했다. VPN 추가 FP로 전체 F1은 소폭 감소한다.

[전체 근거 JSON](infrastructure-results/extra-web-refinement-v39-20261112.json)에 모델·입력·코드·시험·잔여 오탐과 탐색 이력을 기록했다.

## 원인과 구현

기존 관측별 HTTP 트리의 첫 분기는 `http_requests_60s <= 1`이었다. 현재 bucket 계약에서 반대쪽은 분당25요청 이상이며, R 학습 자료에서 정상0/공격7,668행의 순수 leaf가 됐다. 이 leaf는 입력의 URL/사용자 에이전트/공격 구문을 추가 확인하지 않고 점수1을 반환했다.
관찰된 S/Fox의 정상 브라우저가 CSS·JavaScript·이미지·동적 페이지를 일괄 읽을 때도 이 분기를 탔다. 정답을 바꾸거나 브라우저를 신뢰하는 예외 목록으로 해결하지 않았다.

- `scripts/f1_lab/web_refinement.py`에 별도 HTTP 보정 모델을 구현했다. R만으로 학습하고 S/Fox는 학습에 사용하지 않았다. 전체 R295,243행을 검사한 뒤 HTTP 정상821/공격7,695행을 사용했다.
- 새 트리의 학습 분기에서 요청량/대상 수/오류 수의 다섯 특징을 제외했다. 기존 특징 스키마는 유지하며 model artifact를 복원할 때 이 특징을 사용하는 분기가 없는지도 검사한다.
- 후보는 기존 점수를 높이지 않는다. 정상 후보 점수가0.05 이하인 **성공한 GET/HEAD**만 기존 점수를 낮출 수 있다. 이 경험 점수는95% 정상 확률이나 인증 증명이 아니다.
- SQL·경로 탐색·명령/셸·업로드·민감 파일·스캐너 징후, 분당500건/초당100건 이상 bucket, 불완전 문맥, 파싱/인코딩 오류, POST·리다이렉트·오류 응답, 모호하거나 실패한 보정은 기존 점수를 유지한다.
- 비HTTP 점수는 기존 모델로 그대로 계산한다. 추론 함수는 정답·시나리오·행 번호·주체 식별자를 받지 않는다. 모델/기준선 해시와 정책 상수를 검증하며 잘못된 artifact는 시작 시 거부한다.
- `scripts/run_web_refinement.py`가 학습본을 동결하고 기존/새 점수를 같은 전체 입력에서 비교한다. 기존 점수 순서 SHA와 지표가 v38 기록과 같은지 확인한다.

이 코드는 분리된 F1 실험 후보다. `app/`의 기존 Sigma·LLM·PDP·권한 발급/회수/집행 코드는 바꾸지 않았다. 경보 점수가 낮아져도 접근 권한이나 기기·신원 신뢰를 부여하지 않는다.

최초 전체 비교는120.721초, LF 설정 재현은81.045초였다. 최초에는 회귀 시험이 동시에 실행됐고 재현은 캐시를 재사용했으므로 시간 차이를 모델 성능 개선으로 해석하지 않는다. 두 실행 모두 비HTTP 점수 확인과 오류/기권의 분모 보존을 포함한다. 큰 새 입력 복제나 원본 로그 재수집은 없었다.
저장소의 LF 규칙에 맞춘 protocol로 전체 비교를 다시 실행해 후보 바이트·모든 점수 순서 SHA·지표가 최초 실행과 같은지 확인했다. 최초 실행과 실행 당시 설정도 보존했다.
VPN·감사·웹 오류 로그의 기존 약점은 이번 HTTP 성공 읽기 보정으로 해결되지 않았다. 새 독립 평가·원래 여섯 영역 목표 달성을 대신하지 않는다.

## 잔여 오탐과 선택 이유

S 잔여7건은 POST5/GET2, Fox 잔여12건은 POST8/GET4다. 문맥/적용 범위 밖 또는 공격 징후 보존 조건에 해당해 기존 경보를 유지했다. Fox에는3xx3건·4xx1건도 있다. 본문/당시 권한 근거 없이 이 요청까지 정상 예외로 만들지 않았다.
최초 직접 교체 후보는 새 오탐과 일부 기존 TP 손실을 만들었다. 일방향 보정과 불확실성 보존을 추가해 이를 피했다. 초기의 더 넓은 보정은 Fox4/S1 FP였지만, 최종적으로 성공 GET/HEAD 범위에 한정해 Fox12/S7로 검증했다. 두 특징 제외안의 탐색과 표본 목록의0건 공격 항목 오류/수정도 JSON에 남겼으며, 최종 수치는 별도 전체 행 실행기에서 재계산했다.
새 형태의 브라우저 위장·성공 응답 공격이나 정상과 같은 관측을 가진 위협에도 TP 손실이 없다는 보장은 아니다. 원시 본문·검증된 권한/신원·새 분리 자료가 부족한 조건을 유지하며 운영 적용 전 독립 검증이 필요하다.
