2026-11-20 · `extra` · 시험 도구 `0ad59a2`. [08:00까지의 지속 목표](extra-until-0800-20261120.md)는 진행 중이다. 각 경계의 개별 통과에 이어 장애 순서가 달라도 수집기/백업/복원 상태가 보존되는지 확인할 제한된 로컬 시험을 추가했다. 탐지 성능 시험이나 실제 조직 배포 인수가 아니다.

## 시험 방법

매 회차는 append, 관측, 서명 전/후 응답 유실, 원본 rollback, 확인 기록 rollback, 백업 후보 handoff, 중단 복원 재개, 신선도/offline의 **9개 동작**을 seed로 섞는다. 테스트 소유 원본/키/DB만 사용한다. 부모가 보관한 최소 영수증을 매 성공 뒤 전진시키며, 원본 행 수·서명 횟수·확인 영수증 수·마지막 관측 행 수를 별도 counter로 비교한다. 응답 유실 뒤에는 새 실제 CLI 프로세스로 재개한다. 같은 ID 유지·서명 중복 없음·rollback 거부·원래 최소 기준/false flag 보존을 확인한다.

handoff는 시험 도구가 사용할 후보 변수를 명시적으로 바꾸는 동작이다. 운영 앱/서비스 설정을 변경하지 않는다. 실제 독립 호스트/운영자/SSO/WORM 인수를 증명하지 않는다. seed는 동작 순서/행 수를 정하지만 UUID·키·실제 timestamp까지 동일한 bytes로 재현한다는 뜻은 아니다.

Windows 파일 핸들 때문에 초기4순서가 임시 DB 정리에 실패했다. SQLite 연결을 명시적으로 닫고 정리가 끝난 뒤에만 완료 보고서를 저장하도록 수정했다. cleanup 실패는 실패 보고서만 남긴다. 일시적인 중지 신호가 사라진 뒤 완료로 잘못 표시되는1건도 재현해 중지 상태를 유지하고 전체 요청 단계 수를 완료 조건에 포함했다. 최초 실패 원본은 유지했다.

Linux CLI를 Windows 공유 폴더 결과 경로로 실행할 때 private 키/DB 권한 검사가 거부된 사례도 보존했다. 권한 검사는 유지하고 **시험용 키/DB는 플랫폼 기본 임시 저장소**, 공개 가능한 집계/trace만 지정한 결과 경로에 둔다. Windows 기능 시험을 POSIX/Windows ACL 운영 인수로 표시하지 않는다. 정상/시간 제한/명시적 중지/검사 실패 후 모두 시험 자원을 정리한다. 실제 강제 종료로 남는 private staging은 별도 정리가 필요하며 모든 강제 종료의 자동 정리를 주장하지 않는다.
