11/4 후속 [관리 영역 이중화](control-plane-high-availability.md)는 두 볼륨 묶음의 대기 우선 복제와

관리 Docker/물리 호스트 HA·전체 주간 완료와 구분한다. 아래 이전 결과는 당시 범위로 유지한다.

이 문서는 수행계획서의 개발 구간과 `aitest` 브랜치의 실제 구현을 연결한 색인이다. 기능을 계획보다 앞당겨 구현했으므로 **기능 진척 주차**와 실제 학사 일정은 구분해서 해석한다.

## 현재 진척

2026년 11월 3일에는 동료의 M3 PR #1을 받은 뒤 희주 담당 [인프라 재현·측정](m3-infrastructure-measurement.md)을 별도 이름 브랜치에서 진행했다. Windows 권한 검사 차이, 시험 개인키의 비저장, worker 네트워크 격리와 같은 조건의 반복 측정 범위를 기록한다. [브랜치·PR 절차](contribution-workflow.md)에 따라 통합 개발 브랜치 `aitest`에 PR로 변경·검증 근거를 남긴다. 아래 이전 건수·구현 범위는 날짜별 기록이며 새 결과는 연결 문서를 우선한다.

2026년 10월 29일부터 남은 실행 일정은 [멘토링 피드백 우선 주간 실행 계획](mentoring-priority-roadmap.md)을 기준으로 한다. 인증 이후 자동 세션 재평가, GuardDuty 공식 형식의 로컬 입력 검증, 안전한 대응 집행과 공개 세션 평가를 우선한다. 아래 주차는 기존 기능 진척 분류이며 학사 주차와 구분한다. 최종 제출은 12월 둘째 주로 잠정 가정하고 12월 6일까지 제출 가능본을 준비한다.

11월 1일 개정에서 Jev·Laya 등 판단 전용 모델과 생성형 LLM의 작업별 비교를 M6에 추가했다. 모델명은 예시 후보이며 채택 완료가 아니다. 임베딩·재정렬·이상탐지는 필요가 확인될 때 검토하며, [영역별 우선 추천·공식 근거·남은 검증과 후보 목록](model-candidate-review.md)을 별도로 관리한다. 모델 API 평가 비용 허용과 AWS 배포 금지를 구분한다.

같은 개정의 [인프라 보완 계획](mentoring-priority-roadmap.md) I1~I8은 M3~M6과 함께 진행한다. 11/8 내구 수신·처리, 11/15 서비스 인증·키·경보·AI 호출 제한, 11/22 별도 집행·백업 복원·버전 고정, 11/29 장애 통합 평가를 목표로 한다. 로컬 Compose 검증이며 AWS 배포·운영 전환 완료를 뜻하지 않는다. 11/29 기능 동결과 12/6 제출 가능본 일정은 유지한다.

개인별 실행은 기존 수행계획서의 역할을 유지한 [역할·협업 기준](team-responsibilities.md), [채희주 담당 계획](roles/chaeheeju.md), [김택희 담당 계획](roles/kimtaekhee.md)을 따른다. 각 문서에 이번 주 할 일, 주간 전달물, 인계·교차 검증과 공동 보고 업무를 분리해 기록했다. 문서 배정은 과거 개인 기여나 구현 완료의 증거가 아니다.

두 사람의 주차별 담당과 공동 완료 기준은 [역할분담·주간계획 한눈에 보기](역할분담_주간계획_한눈에보기.md)의 한 표로 비교할 수 있다.

운영 대시보드는 기존 자체 화면을 확장한다. Grafana·Perses는 필수 도입에서 제외하고, 메트릭·경보·접근 집행·공급망 검사 도구는 [전체 계획의 오픈소스 선정 기준](mentoring-priority-roadmap.md)에 따라 비교한다. step-ca·osquery 등 추가 후보는 핵심 경로 안정 후 필요가 확인될 때 검토하며 아직 설치하지 않았다.

오픈소스·다른 프로그램·직접 구현·기존 재사용은 [기술 비교·선정 실행 계획](technology-selection-plan.md)에 따라 시험 적용 후 비교한다. C01~C03 실제 비교, C04~C09 필요 판정·조건부 시험/보류, C10 AI 평가를 주간 작업과 개인별 역할에 연결했다. [선정 대장](technology-decisions/README.md)과 [근거 작성 양식](technology-decisions/decision-template.md)을 사용하며 현재 신규 도구의 실제 측정·채택 결과는 없다.

인프라 구성·실행·측정은 채희주, 백엔드·앱 지표·기능/상태 검증은 김택희가 주담당한다. [역할 기준](team-responsibilities.md)과 통합 표·개인별 계획·비교 계획의 실행/측정 책임을 함께 맞췄다. 통합 검증은 공동이며, 이번 수정은 예정 역할을 명확히 한 것으로 실제 수행 완료를 뜻하지 않는다.

11월 1일에는 보안·장애·경계 조건의 회귀 테스트를 204건 추가해 **전체 381건이 Windows 로컬에서 통과**했다. OIDC 테넌트 클레임의 잘못된 자료형 수용도 수정했다. [시험 묶음별 범위와 재현 방법](zero-trust-operations.md#2026년-11월-1일-회귀-테스트-확장)을 참고한다. 이번에는 Docker 엔진이 꺼져 있어 컨테이너 검증은 수행하지 않았으며, 예정된 M3~M5 기능의 완료를 뜻하지 않는다.

같은 날 탐지 성능 평가도 확장했다. 기존 공개 12건은 보존하고 **합성 720건·72계열**을 개발/평가 각 360건으로 나눴다. 평가용 정밀도 64.29%·재현율 50.00%·F1 56.25%·오탐률 27.78%로 **95%/5% 목표 미달**을 확인했다. 계열 단위 신뢰구간·중복 제거 지표·규칙별 미탐/오탐·전체 원자료와 제한 사항은 [확장 평가 명세](week04/detection-and-evaluation.md#2026년-11월-1일-확장-탐지-평가)에 있다. 입력 행 수를 독립 공격 표본 수나 자동 테스트 건수로 해석하지 않는다.

이 결과는 **개선 전 기준선**이며 탐지 규칙·임계값·정책 로직은 변경하지 않았다. 평가기 검증을 포함한 최신 로컬 자동 테스트는 전체 421건 통과했지만 탐지 품질 게이트는 미달 상태로 유지한다.

## 현재 MVP 기준선

- 버전: `0.17.0`
- 합성 시나리오: 정상 3건, 위협 5건
- 분석기: 규칙 기반, OpenAI 구조화 출력, 선택형 하이브리드
- 대응 방식: 실제 실행 없는 정책 미리보기
- 운영 흐름: 검토 대기, 조사 중, 해결 완료, 오탐 처리, 재검토
- 저장소: 로컬 JSONL 또는 AWS DynamoDB
- 기업 보안 기준선: OIDC·RBAC·테넌트 격리·요청 추적·감사 해시 체인·Prometheus 메트릭
- 보증 기준선: 공공·기업 기준 18개 통제, 코드·구성·시험 증적, 통제대장 무결성 해시, 관리자 상세조회
- 탐지 데이터 계보: OCSF 1.9.0 원본·매핑 해시, Sigma 2.1 규칙 버전·승인·시험·규칙집 해시
- 공개 로그 검증: Splunk RDP 공격 4건·AWS 인증 실패 4건과 Microsoft Sentinel 정상 4건의 커밋·라이선스·SHA-256 고정 재생
- 사건 상관분석: 사용자·IP·기기·자원·탐지 규칙을 결정적 그래프로 연결하고 5분·30분·24시간 창에서 OCSF Incident Finding 집계 및 중복 제거
- 탐지 품질: 공개 정답 라벨 기준 전체·규칙별 혼동행렬, Precision·Recall·F1·오탐률, 파싱 성공률, OCSF 매핑률과 평가 지문
- 사건 품질: 공개 데이터셋 기준 사건 혼동행렬, 잘못 묶인 비율, 시간창·그래프 구조·중복 제거 정확도와 평가 지문
- 사고 케이스: 테넌트별 중복 방지, 담당자·메모·증거 지문·변경 이력, 엄격한 수명주기와 버전 충돌 방지
- 연동 아웃박스: 케이스 버전별 CloudEvents 1.0, 결정적 중복 방지, 전달 상태·지수 백오프·실패 보관·누락 복구와 해시 체인
- 제로 트러스트 운영: 서버 자원 정책, 세션별 재평가, 단일 사용·단기 허용, 위험 변화 시 회수와 로컬 모의 PEP의 HTTP 접근 거부
- 신호 신뢰: 공개키로 고정한 Ed25519 수집기, 테넌트·사용자·기기·역할 범위, 현재 재인증 요청에 연결된 새 서명, 키 폐기·회전 후 기존 허용 차단
- 검증: pytest 177건(제로 트러스트 운영 28건·서명 신호 27건 포함), 합성 8건과 공개 12건 재생, 40건 반복 성능 평가와 비용 없는 로컬 검증 경로

v0.17의 제로 트러스트 운영 구조·서명 수집기 설정·재인증·실패 처리·시연 순서는 [별도 구현 명세](zero-trust-operations.md)에 정리했다. 서명은 출처·무결성을 확인하며 실제 인증 결과의 진실성을 보증하지 않는다. 새 집행 경로는 모의 자원에 한정하며 production에서는 비활성화한다.

기업 운영 전 남은 조직별 검증 항목은 [기업 적용 준비도](enterprise-readiness.md)에서 관리한다. 실제 도입 사례와 논문을 현재 코드의 고도화 순서로 연결한 근거는 [Zero Trust LLM SecOps 고도화 딥 리서치](deep-research-enterprise-secops.md)에 정리했다. 국내외 공공기관·금융권·표준·기업 프레임워크와 추가 논문을 구현 산출물에 연결한 목록은 [기업·공공부문 적용 참고자료 카탈로그](reference-catalog-enterprise-public-sector.md)에서 확인한다.

## 안전 범위

MVP는 실제 계정 차단, 권한 변경, 세션 격리를 실행하지 않는다. 모든 대응은 `simulation` 모드의 미리보기이며 고위험·불확실·파괴적 조치는 사람 검토 대상으로 남긴다. v0.15 연동 아웃박스도 외부 전송을 기본 비활성화하며 실제 SIEM·ITSM 목적지 호출은 운영 통합 단계로 남긴다.
