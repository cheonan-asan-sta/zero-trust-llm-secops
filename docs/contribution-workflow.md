# 담당자 브랜치와 PR 기록

2026년 11월 3일 사용자 요청에 따라 희주 담당 변경은 이름을 포함한 별도 브랜치에서 진행하고, 병합할 때마다 GitHub PR에 변경과 검증 근거를 남긴다.

## 브랜치와 병합 경로

- 통합 개발 기준은 `aitest`다. 시작할 때 원격 변경을 확인하고 충돌 없는 `--ff-only` 갱신을 우선한다.
- 희주 작업 브랜치는 `feature/chaeheeju-<작업명>`으로 만든다. 이번 작업은 `feature/chaeheeju-m3-infra-validation`이다.
- 담당 변경을 커밋한 뒤 해당 브랜치를 올리고 `aitest`를 대상으로 PR을 연다. 희주 작업을 `aitest`에 직접 푸시하거나 강제 푸시로 합치지 않는다.
- 병합은 GitHub PR 경로를 사용해 PR 번호·커밋·검증 결과를 보존한다. `main` 반영은 별도 릴리스 범위다.
- 완료하지 않은 항목이나 독립 검토를 하지 않은 항목을 통과·승인으로 기록하지 않는다. PR 생성과 실제 병합을 구분한다.

## PR에 남길 내용

1. 구체적인 문제, 변경 전후 동작, 작업 범위와 기준 커밋.
2. 설계·구현·실행·측정·독립 검증의 실제 수행 범위. 예정 역할을 과거 실적으로 소급하지 않는다.
3. 실행 환경·명령·표본 수·실제 통과/실패·경고·원자료·재현 방법.
4. 정상 업무 영향, 위조·권한·만료·회수·재시작·장애 중 해당 변경이 검증한 조건.
5. 미완료·미측정·남은 한계, 후속 작업과 이전 버전 호환/복구 경계.

현재 탐지 품질은 개선 전 기준선으로 보존한다. 자동 테스트 통과·인프라 기능 검증·탐지 성능 목표 달성을 별도로 기록한다. AWS 배포·실계정 변경·유료 모델 호출은 PR 생성이나 병합에 포함된 권한으로 해석하지 않는다.

인증정보·개인키·실행 DB·실사용자 로그·사용자 압축본은 커밋하지 않는다. 합성 자료와 비밀값을 제거한 실행 증거만 공유한다. 검증 자원은 해당 실험의 프로젝트·컨테이너·볼륨만 정리하고 다른 작업의 자원을 삭제하지 않는다.

PR 기록에는 코드·설정 작성과 도구를 통한 실행·측정 사실을 적는다. 실제 담당자 신원은 GitHub 계정 기록과 팀 확인을 따른다. AI 보조 실행을 팀원의 수동 수행이나 독립 검토로 바꾸어 쓰지 않는다.
