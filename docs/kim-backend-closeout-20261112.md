# 11월 12일 백엔드 마무리 기록

개발 마감은 2026년 11월 16일 월요일이다. 이번 작업은 김택희의 원래 담당인 앱 승인, 저장 일관성, 복원 후 상태와 접근 집행 검증에 한정했다. 채희주의 `extra` F1 개선 작업은 수정하거나 병합하지 않았다. 확인한 `aitest` 기준은 PR #52의 `c83b8579c59c96972648df55f446df018c4dd1bd`다.

## 구현한 내용

기존 로컬 변경 113개 파일을 별도 보존한 뒤 `aitest`를 반영했다. 정상 작업의 실행 주체와 목적지 검증, 원본 평가 자료와 과거 결과를 보존하고, 기기 침해 규칙과 탐지 점수의 추가 조정은 하지 않았다.

고위험 모의 대응 요청은 서버의 세션 상태에서 실제 대상과 버전을 가져온다. 요청자를 제외한 서로 다른 responder 두 명의 승인이 필요하며, 자기 승인과 승인 부족, 오래된 버전, 만료, 다른 테넌트, 변경된 재시도는 거부한다. 계정 비활성화와 기기 격리, 권한 축소는 모의 실행 결과만 기록한다. 기존 세션 회수와 실제 보호 접근 거부는 원래 경로를 유지한다.

요청 사유와 승인자별 검토 사유를 조회에 제공한다. 동일한 사람의 교체 API 키를 두 번째 승인자로 세지 않는다. 승인자별 인증서와 API 키를 일회용 클라이언트에만 전달하고, 상시 운영자와 수집기에는 마운트하지 않는다. 승인자 인증서는 승인 조회, 승인, 취소 경로만 사용할 수 있다.

별도 승인 DB를 만들지 않고 기존 context 저널에 요청, 승인, 취소, 실행 결과를 저장한다. 정상 작업 기준선 승인과 대응 승인은 종류와 사용량을 공유하지 않는다. SQLite 잠금으로 동시 실행을 한 결과로 수렴시키고, 저장 후 응답이 사라져도 같은 요청자의 정확한 재시도에는 기존 결과를 반환한다.

전체 앱 복원은 기록자를 정지하고 같은 암호화 백업에서 격리 사본을 만든 뒤 승인된 사본만 기동한다. 복원 전 미실행 대응 요청은 이전 세션 권한으로 실행할 수 없다. 실행 결과와 취소, 토큰 소비와 회수 이력은 보존한다. 기존 토큰은 403이고 새 세션의 토큰만 한 번 사용할 수 있다.

SQLite 종료 저널은 정상 이력을 검증한 뒤 SQLite 자체 복구로 처리한다. 정리나 상태 확인을 위해 상시 수집기와 watchdog 안에 추가로 띄우던 무거운 시험 프로세스는 별도 일회용 컨테이너로 옮겼다. 서비스 메모리 한도는 늘리지 않았다.

Linux 이미지는 앱, 실행 도구, 시험과 고정 자료 352개 파일의 SHA-256을 호스트와 대조했다. 관측 경로 75개 검증 이후에는 승인 조회의 사유 출력과 해당 시험만 추가했으며, 최종 승인과 복원 16개 검증은 그 출력을 포함한다. 실패한 시도도 원자료에 남겼고 성공 결과로 바꾸지 않았다. 두 플랫폼의 같은 시험을 서로 다른 데이터 표본으로 합산하지 않는다.

실제 mTLS 복원 시험은 네 개의 저장소 시험용 context 기록에 HTTP로 생성한 대응 기록 아홉 개를 더해 총 열세 개를 보존했다. 복원 중 파일 준비와 사본 승인 직전의 두 지점에서 프로세스를 종료했다. 별도 프로세스의 실행 경쟁, 커밋 전 종료와 커밋 후 응답 유실은 집중 시험에서 검증한다. 만료 때문이 아닌 복원 차단임을 확인하는 고정 시각 시험도 포함한다.

이번 검증은 서로 다른 인증 신원을 사용한 자동 시험이다. 실제 두 팀원의 독립 검토 완료를 뜻하지 않는다. 새 유료 모델 호출이나 실제 AWS, IdP, EDR 계정 변경은 수행하지 않았다. 탐지 정밀도, 재현율, F1과 오탐률 달성 여부는 이번 기능 시험 결과와 별도로 판정한다.

## 재현 순서

저장소 루트에서 실행한다. Docker 통합 시험에는 기존에 사용한 적 없는 새 디렉터리를 지정한다. 시험은 자기 프로젝트의 자원만 정리한다.

```sh
.venv/bin/python -m pytest -q
.venv/bin/ruff check app scripts tests
DOCKER_DEFAULT_PLATFORM=linux/amd64 .venv/bin/python -m scripts.test_response_mtls_runtime --directory runtime/c02/review-response-01
DOCKER_DEFAULT_PLATFORM=linux/amd64 .venv/bin/python -m scripts.test_continuous_mtls_runtime --monitoring --directory runtime/c02/review-monitoring-01
```

실행 환경은 macOS Apple Silicon과 Colima `secops-m3`의 Linux amd64 컨테이너다. 검증 동안 4 CPU, 5GiB와 기존에 설치된 Rosetta를 사용했다. 고정된 amd64 관측 바이너리는 이 환경에서 검증했으며, 기본 QEMU 실행에서 발생한 Go 프로세스 실패 기록은 보존했다. 이 실행 시간을 팀장의 실제 Linux 인프라 성능 수치로 사용하지 않는다. macOS 관측 재현 시 실행 중인 검증을 끝낸 뒤 해당 프로필의 `--vz-rosetta` 설정을 사용한다. Linux amd64에서는 이 Colima 설정이 필요 없다. 검증 종료 후 이 Mac의 Colima는 원래의 2 CPU, 3GiB와 Rosetta 해제 상태로 복구했고 실행 중인 시험 컨테이너는 없다.

## 공동 마무리에서 확인할 것

1. 실제 두 사람이 승인자 역할로 요청 사유와 대상, 실행 결과를 확인하고 검토 기록을 남긴다. 자동 시험 결과와 구분한다.
2. 채희주의 `extra` F1 개선본은 별도로 검토한 뒤 병합 여부를 정한다. 병합한다면 최종 후보의 코드와 입력 지문에 맞춰 지표를 다시 판정한다.
3. 현재 이미지와 실제 선정 인프라의 최종 검사, 성능 측정 원자료를 맞춘다. 과거 이미지 검사와 이번 소스 검토를 현재 이미지의 취약점 해소 증거로 대체하지 않는다.
4. 로컬 자동 검증과 접근 집행, 모의 고위험 조치, 실제 클라우드 미연동 범위를 발표와 보고서에 동일하게 표시한다.

API 계약과 자격증명 설정은 [고위험 대응 승인과 모의 실행](response-approval.md)에 정리했다. 이번 로컬 작업에서 GitHub push, PR 생성과 병합은 수행하지 않았다.
