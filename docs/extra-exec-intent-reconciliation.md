# 관리 실행의 내구 intent와 중단 후 원본 대조

2026-11-16 · v86 · 예비 집중378개·실제 process-loss/systemd44조건 통과, 최신 통합 전체 인수 전.

채희주 담당의 [outbox 복구](extra-exec-outbox-recovery.md) 후속이다. outbox 파일이 생기기 전에 브로커가 사라지면 어떤 요청을 처리하던 중이었는지 추적하기 어려웠다. 실행 전의 **제안된 의도**를 별도 개인 저장소에 남기고, 완성된 봉인이 있을 때 원래 bytes를 복구한다. 의도 파일은 사람 인증·인가·실행 성공의 증명이 아니다.

## 저장·복구 순서

| 시점 | 남기는 근거 | 중단 후 처리 |
|---|---|---|
| dispatch 전 | 요청 전체 지문·제안 호출자/앱 세션 지문·고정 자원/정책·worker 경로·원래 시각, 브로커 서명 | 같은 요청 재예약 금지. 아직 실행 여부를 주장하지 않음 |
| 앱 권한 소비·관리 실행·브로커 bound 후, 봉인 전 | 기존 앱 access 행·브로커 DB 상태/영수증·worker 파일이 남을 수 있음 | 완성된 봉인이 없으면 indeterminate. 인접 기록으로 잃어버린 인가 proof를 다시 만들지 않음 |
| 원래 완성 봉인 생성 후 | 별도 intent 저장소에 같은 전체 봉인 bytes를 내구 저장 | 호출자·정책·앱 사용 행·브로커 영수증과 대조한 원본만 복구 가능 |
| outbox 게시 | 앞서 내구 저장한 bytes를 기존 outbox/보관에 게시 | 명시적 resume은 같은 원본 재게시만 수행, 최신 근거 역행 금지 |

`dispatch_and_retain`의 내부 호출은 관리자 고정 `intent_root`를 필수로 받는다. outbox·보관·worker·intent 디렉터리는 서로 같거나 포함 관계가 될 수 없다. POSIX 소유자0700/파일0600·단일 링크·크기·알려진 inventory를 검사한다. 요청 디렉터리와 원본 파일은 배타적으로 생성하며 fsync한다. 중단으로 남은 불완전 디렉터리를 재사용하지 않는다.

개인 intent에는 ID token·app grant token·원문 명령 인자를 저장하지 않는다. 제안 호출자/세션은 지문이다. worker 경로와 요청 nonce 등 운영 메타데이터는 개인 저장소에만 남으며 공개 상태에 내보내지 않는다. 저장소·현재 관리자 pin·호스트/브로커의 신뢰는 계속 전제한다. 서명만으로 전체 저장소 rollback이나 관리자 침해를 방어한다고 주장하지 않는다.

## 대조 계약

`ExecIntentJournal.reconcile`은 고정 서비스/호출자 pin, 원래 요청과 브로커 상태/영수증, 앱의 정확한 `execution_request_sha256` access 행, 호출자·세션·자원·정책·행 SHA와 완성 봉인을 대조한다. 같은 원본의 원래 시각·서명·grant 소비 사실을 보존하며 현재 pin/정책이 바뀌거나 자료가 부족하면 거부한다.

봉인 전 중단에서는 worker 파일의 존재와 보고된 요청 지문만 관찰한다. 파일이 있다는 이유로 인증된 실행 성공·정당한 인가를 새로 주장하지 않는다. 완성된 인가 proof가 없는 경우 자동 봉인/재서명은 제공하지 않는다. broker가 bound이고 앱 권한이 소비됐어도 indeterminate다.

대조는 기본 조회이며 `resume=True`일 때만 봉인된 동일 bytes를 outbox와 기존 보관에 게시한다. `issue/dispatch/launch/access`나 서명 함수·grant 환급은 호출하지 않는다. 재게시가 실행 권한이 되지 않으며 과거 원본은 상태 검사에서 계속 stale이 될 수 있다. 같은 요청에 다른 bytes가 있거나 현재 pin이 다르면 재게시하지 않는다.

## 운영 연결

이 경로는 신뢰된 서버 컨트롤러 라이브러리이며 새 공개 실행 HTTP API가 아니다. 호출자는 기존 관리자 설정의 저장소/서비스·호출자 pin과 읽기용 브로커/앱 인터페이스를 전달한다. 요청 클라이언트가 임의 경로·키·명령을 넘기는 기능을 만들지 않는다.

```python
journal = ExecIntentJournal(intent_root, service_pin, caller_pin)
result = journal.reconcile(
    request_id, broker_audit_view, app_audit_view,
    evidence_root, outbox, resume=False,
)
```

`broker_audit_view`에는 registry·서비스 registry·기존 요청 조회 연결, `app_audit_view`에는 현재 정책 지문과 검증된 journal 조회만 필요하다. 실제 컨트롤러는 해당 인터페이스의 신뢰와 접근 통제를 책임진다. Python 객체 인터페이스가 별도 OS 보안 경계라는 뜻은 아니다.

## 검증과 다음 인수

집중162개에서 정상 원본·봉인 전 중단·outbox 전 중단·반복 복구·서명/필드 손상·symlink/hardlink·다른 worker 요청·브로커 영수증 손실·pin 변경·경로 중첩을 검사했다. 기존 보관/outbox/앱 실행 gate 검사를 함께 실행했다. 최초 외부 시험 도우미는 존재하지 않는 테스트 파일명을 지정해 수집 전에 종료됐고, 올바른 기존 파일명으로 수정한 새 경로에서 통과했다. 이 실패를 성공으로 덮어쓰지 않는다.

실제 systemd 예비 인수에서 두 별도 브로커 자식 프로세스를 실제 exec 뒤 `os._exit`로 종료했다. 하나는 봉인 전, 하나는 완성 원본을 내구 저장한 뒤 outbox 전에 종료했다. 새 대조 객체가 키/launch/grant 발급 인터페이스 없이 첫 요청을 indeterminate로 보존하고 둘째 원본만 byte 동일 재게시했으며 앱/브로커 DB bytes가 변하지 않았다. 기존 outbox 인수4건에 추가2건, 실제 실행 총6건이며 조건 수를 실행 수에 합산하지 않는다. 동일 소스 archive `38bfb1636ba4b358bfae989ba460c03d5b779073b4f12cd9abba4d45435a4ff5`의 집중378개·실제44조건을 통과했고 소유 컨테이너·unit·개인 상태·WSL 스냅샷을 정리했다. v85 코드 통합과 전체 회귀는 다음 인수에서 별도로 확인한다.

전체 인수·통합 기준·실패는 후속 결과로 갱신한다. 이 기능은 탐지 F1 개선이나 원래 여섯 영역의 독립 성능 평가가 아니다. 직전 v85의 웹 감사 FP21·FN1/F1 80.70%는 별도 개발 비교 결과다. AWS·유료 API0, 8시간/12시간 soak 유예를 유지한다.

남는 운영 항목은 intent 전체에 대한 주기적 pending/손상 경보, intent/worker·앱/브로커 DB의 일관된 외부 사본/보존·복원 계약, 봉인 전 중단의 사람 검토 절차, 실제 조직/다중 호스트 인수다. 완성된 봉인 없이 명령을 재실행하거나 잃어버린 권한을 재구성하는 방식으로 완료 처리하지 않는다.
