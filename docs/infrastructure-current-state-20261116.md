# 현재 구현·검증·남은 작업

2026-11-16 채희주 인프라 담당 작업. Codex가 구현·로컬 시험·문서화를 보조했다. 다른 팀원의 앱/대시보드 구현·독립 검토 성과로 기록하지 않는다. 11월의 4주 계획은 개발 단계이며 실제 학사 주차나 완료율과 같지 않다.

**목표 수치는 아직 미달이다.** 기능 검사 통과와 독립 탐지 성능 목표 달성은 구분한다. AWS/유료 API 호출0이며, 사용자가 미룬8/12시간 연속 시험은 시작하지 않았다. 운영 배포·조직 SSO·물리 호스트 장애·외부 저장소 재난 복구·팀원 독립 검토 완료를 주장하지 않는다.

## 실패와 검증 기록

최종 고정 소스 `99779191d514987e1b8c308996bf3b3df74c85d95378006fa50bf55e28e5b362`에서 집중475개·전체6,332개를 통과했다. 집중은 전체의 부분집합이며 이전 실행 수를 합산하지 않는다. v90 이후 신규262개다. 실제 Linux 재현 실행기로 bundle67·provider10·PAM18조건을 각각 통과했고, DB 통합 57조건도 통과했다. 소유 container/volume/network/unit/provider/상태/임시 소스의 정리를 확인했다. 원래 소스의 전체 파일 지문과 입력 지문을 다시 대조했다.

기존 v85 이후1,681,815행의 판정은 동일하다. 새FP0·기존TP 손실0이며 판정 회귀에는 정답을 전달하지 않았다. 별도 점수 진단에는 이미 관측한 정답을 다시 읽었고 접근8건을 기록했다. 기존 [AppArmor 보정](extra-apparmor-noop-review.md)의 웹 감사 FP37→21, 새FP/TP손실0 결과는 유지한다. 이번 관측/저장 기능을 과거 미탐 개선으로 소급 계산하지 않는다.

앞선 [추가 멤버 전이 검토](extra-audit-member-transfer.md)에서는 Wilson4,967행의 FP8을 줄이고 새FP/TP손실0을 확인했으며 Wardbeck3,941행은 동일했다. 원문/물리 행 겹침은0이지만 특징 겹침은 각각4,965/4,967과3,941/3,941이었다. 이미 관측한 같은 자료군의 전이 검토이며 새로운 독립 최종 성능으로 계산하지 않는다.

이 문서는 고정 로컬 결과다. CI/병합 완료는 이 결과에 미리 적지 않으며 최종 브랜치 PR의 실제 상태를 확인한다. [집계·소스 지문·실행 근거](infrastructure-results/extra-infrastructure-overnight-v97-20261116.json).

PR84 병합 뒤 DB 통합 CI가 authority JWK 전환 중 실패했다. 원래 보고서는 종료번호·자세한 사유를 잃어 원인을 확정할 수 없었다. 진단을 보강하는 과정의 새 외부 오류 코드 호환성 문제는 실제 로컬 부정 인수에서 발견해 기존 코드 유지와 회귀 검사로 수정했다. 테스트 실행기의 경로·읽기 전용 Docker 설정·Git/오프라인 공개 도구 준비 실패도 남기며 기능 통과로 계산하지 않는다. 원래 실패의 근본 원인과 새 검증에서 확인된 결과를 구분한다.

그 뒤 v96 최종 로컬 실행은17조건 뒤 CA 복구의 읽기 전용 SQL 준비 상태 조회에서 중단됐다. 보고된 것은 generic subprocess 오류였고 정확한 예외 유형은 남지 않아, 시간 초과는 경로 분석상 추정으로 표시한다. 소유 자원은 모두 정리했다. v97은 오류 유형/종료번호를 안전하게 남기고, 읽기 전용 조회의 TimeoutExpired만 원래45초 준비 대기 안에서 다시 확인한다. 실제 SELECT1·CA 건강/발급 성공 조건과 운영 RPC 제한은 그대로다. 소유권/신뢰 오류·변경 작업을 재시도하지 않으며 새 소스의 전체 인수를 다시 요구했다. 이 실패를 이전 성공 실행으로 덮지 않는다.

정답 재열람은 점수 진단의 무결성 확인/의미 해석으로 명시하고 접근8건을 기록했다. 별도 기존 판정 회귀에는 정답을 전달하지 않았으며 모든1,681,815행의 판정 지문·새FP0·기존TP 손실0을 확인한다. 진단·기능 조건 수·반복 실행을 독립 성능 표본에 합산하지 않는다.

## 다음 작업의 순서와 완료 기준

1. **실제 운영 관측 소비:** 새 PAM 대장의 보존/암호화 사본/격리 복원/경보 연결과 외부 pin·rollback 증거. 현재 실행 근거의 복구 흐름과 authentication 근거를 같은 schema로 혼동하지 않는다.
2. **누락된 신원·명령 근거:** 공유 감사에는 검증된 실행 주체·명령·원래 실행 회차, 인증/VPN에는 실제 인증원·기기/권한 증거를 연결한다. 과거 PID 없는 PAM 행을 근처 요청에 임의 연결하지 않는다. 출처가 부족하면 미상으로 남긴다.
3. **개선 후보와 새 평가 분리:** 관측 개발 자료로 개선하고 후보를 동결한 뒤, 출처/시나리오가 분리된 정상·위협 자료를 확보한다. 같은 데이터·상관된 행의 재평가를 독립 평가로 표시하지 않는다. 라벨 근거와 독립 검토자·불일치 판정을 실제 기록한다.
4. **운영 인수:** 목표 부하·RTO/RPO·실제 IdP/계정/ACL·물리 호스트/외부 복구의 범위를 팀이 정하고 검증한다. 장기 연속 시험은 사용자가 재개할 때 수행한다.
5. **최종 동결:** 모든 영역의 P/R/F1·FPR/FNR·모집단·미측정·보류·잔여 취약점과 승인자를 연결해 제출 범위를 확정한다. 코드를 모두 작성했다는 이유로4주 계획 인수가 끝났다고 하지 않는다.
