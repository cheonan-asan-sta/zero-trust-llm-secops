# 작업별 인공지능 모델 검토 목록

검토일: 2026년 11월 1일 · 상태: 후보 조사와 비교 계획, 모델 설치·실제 API 시험 결과 없음

우리 프로젝트는 **LLM 기반 지능형 제로 트러스트 보안 오퍼레이션 및 자동화 프레임워크 구축**이다. LLM은 여러 세션 근거의 해석·설명·조사를 보조하고, 짧은 분류·검색·이상탐지는 해당 작업에 적합한 모델을 별도로 검토한다. 이 목록의 Jev·Laya를 포함한 모든 모델명은 **역할을 설명하는 예시와 비교 후보**이며 최종 채택 목록이 아니다. 후보를 모두 연결하는 것이 목표가 아니다.

## 우선 비교할 후보

| 역할과 후보 | 공식 자료에서 확인한 특성 | 우리 프로젝트의 적용 가설 | 도입 전 확인 |
|---|---|---|---|
| Jev | 상태와 choice·score·noul 질문에 구조화된 판단값을 반환하는 판단 전용 모델 | 짧은 이벤트 분류·조사 우선순위·추가 분석 요청 여부 | 한국어·로그 혼합 입력, 선택지·표현 변화, 정보 부족과 신뢰도, 네트워크 포함 지연·API 사용 조건 |
| Laya | choice·score·예/아니오 판단을 위한 공개 가중치, Apache 2.0, 영어·다국어·typed-decisions 체크포인트 | Jev와 동일한 분류 과제의 자체 실행 비교 | 한국어에는 다국어 후보 사용. 기본/과제 학습 모델 구분, 확률 보정·선택지 순서·입력 잘림·하드웨어 |
| 생성형 LLM 기준 모델 | 현재 코드의 OpenAI 분석기는 단건 이벤트 구조화 결과를 반환. GPT 계열의 공식 모델별 기능·가용성 확인 가능 | 세션 근거 ID·의심 변화·반대 근거·추가 질문·한국어 설명 | 예: GPT-6.1 Sol, 비용/지연 비교가 필요하면 GPT-6 Luna. 계정 접근·추론 설정·출력 상한은 시험 때 고정 |
| 타 공급자 생성형 LLM | Claude·Gemini의 공식 모델 목록과 구조화 출력 문서 제공 | 동일 입력의 분석·설명 품질과 총비용 비교 | 예: Claude Sonnet 5.5, Gemini 3.8 Flash. 최초에는 이 중 1개만 비교군으로 선정 |
| 단순 분류 기준선 | TF-IDF 특징과 로지스틱 회귀 등 지도 분류로 구성 가능 | 판단 전용 모델이 단순 기준선보다 이득이 있는지 확인 | 라벨·훈련량 부족 시 성능 결론을 유보. 세션 중복·개발/평가 누수 방지 |

Jev는 작은 질문을 나눠 코드로 조합하는 방식을 권장한다. 이를 전체 세션의 복잡한 조사 설명을 생성하는 모델처럼 평가하지 않는다. [TypeSafe 공식 소개](https://docs.typesafe.ai/introduction)

Laya 공식 카드는 일부 과제에서 기본 모델의 무학습 성능, 확률 과신과 입력 길이·선택지 제약을 명시한다. 다국어 지원이나 정해진 출력 형식을 정확한 보안 판단의 보장으로 해석하지 않는다. 자체 실행도 장비·메모리·운영 비용이 있다. Laya Studio 같은 호스팅 상품은 공개 가중치 직접 실행과 별개로 운영자·요금·데이터 처리를 확인한다. [공식 모델 카드](https://huggingface.co/convaiinnovations/laya), [작성자 저장소](https://github.com/NandhaKishorM/laya)

GPT·Claude·Gemini 중 한 모델을 자동으로 우수하다고 가정하지 않는다. 선택형 질문에서는 동일 정보와 선택지를 제공하고, 생성형 설명에서는 같은 근거 이벤트를 제공해 별도로 평가한다. 모델별 응답을 서로 보여주지 않는 독립 비교를 먼저 수행한다. 모델 간 동의는 정답이나 안전 증거가 아니다. [OpenAI 모델 목록](https://developers.openai.com/api/docs/models), [Claude 모델 목록](https://platform.claude.com/docs/en/models/overview), [Gemini 모델 목록](https://ai.google.dev/gemini-api/docs/models)

## 필요가 확인될 때 확장할 후보

| 작업 | 예시 후보 | 검토할 이유 | 이번 학기 적용 조건 |
|---|---|---|---|
| 생성형 API 대안 | DeepSeek Flash/Pro, GLM 계열 | 다른 공급자에서 구조화 분석·품질·비용 비교 | 기존 생성형 후보가 요구에 미달하거나 대체 공급자가 필요한 경우 1개 추가 |
| 소형 생성형 모델 | Qwen3.5-4B, EXAONE-3.5-2.4B-Instruct 등 | 자체 실행·한국어 설명·외부 전송 제한 조건 비교 | 실행 메모리·지연과 개별 라이선스 확인. 최신·최고 성능 모델이라는 의미가 아님 |
| 다국어 임베딩 | BGE-M3, paraphrase-multilingual-MiniLM-L12-v2 | 유사 사건과 허용된 조사 절차 검색 | 검색용 정답·테넌트별 자료가 있고 검색 필요가 확인된 경우만 |
| 재정렬 모델 | bge-reranker-v2-m3 | 검색 결과에서 관련 근거를 앞에 배치 | 검색 기준선 대비 Recall@k·MRR/nDCG 등과 추가 지연을 평가한 뒤 선택 |
| 사용자 행동 이상탐지 | Isolation Forest, 필요시 로지스틱 회귀·트리 계열 | 시간대·접근량·실패율의 변화에서 조사 신호 생성 | 정상 업무 분포와 시간 기준 평가 자료 확보 후. 현재 소수 시연 사례로 학습·운영 승격하지 않음 |

임베딩과 재정렬은 근거 검색 도구다. 유사도만으로 두 이벤트를 같은 사용자·기기·세션으로 결합하거나 접근 권한을 부여하지 않는다. 검색에는 테넌트·자료 접근권한·문서 출처·버전 제한을 먼저 적용한다. 이상탐지는 침해를 확정하지 않으며 정상 업무 변화에 대한 오탐과 학습 데이터 오염도 평가한다.

확장 후보의 공식 자료:

- [DeepSeek 모델·가격·기능](https://api-docs.deepseek.com/quick_start/pricing/), [Z.AI GLM 모델 안내](https://docs.z.ai/guides/overview/quick-start).
- [Qwen3.5-4B](https://huggingface.co/Qwen/Qwen3.5-4B), [EXAONE 소형 한국어·영어 모델](https://huggingface.co/LGAI-EXAONE/EXAONE-3.5-2.4B-Instruct). EXAONE는 해당 모델의 별도 라이선스를 확인한다.
- [BGE-M3](https://huggingface.co/BAAI/bge-m3), [multilingual MiniLM](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2), [BGE 재정렬](https://huggingface.co/BAAI/bge-reranker-v2-m3).
- [scikit-learn 텍스트 특징](https://scikit-learn.org/stable/modules/feature_extraction.html#text-feature-extraction), [이상탐지](https://scikit-learn.org/stable/modules/outlier_detection.html).

## 선택 원칙과 실험 순서

1. **모델 없이 처리할 수 있는가:** 서명·권한·만료와 같은 정확한 검사는 코드로 수행한다. 분류도 규칙 기준선과 비교한다.
2. **출력이 무엇인가:** 선택·점수는 판단 모델/분류기, 설명·종합 해석은 생성형 LLM, 유사 자료는 임베딩·재정렬, 수치 행동 변화는 이상탐지를 검토한다.
3. **자료가 충분한가:** 학습·보정·튜닝은 개발 자료에만 수행하고 실제 평가셋을 따로 둔다. 작은 시연셋은 일반화 성능의 증거로 쓰지 않는다.
4. **전체 경로에서 이득이 있는가:** 단일 모델 추론보다 입력 준비·네트워크·재시도·두 번째 호출·사람 검토까지 포함한 미탐·정상 업무 유지·품질·비용·P95 지연을 비교한다.
5. **실패하면 어떻게 되는가:** 불명·분포 밖·오류·시간 초과에 규칙 경로와 검토 상태로 복구한다. 모델이 정상이라고 판단해도 필수 검증이나 위험 규칙을 생략하지 않는다.

실험 구성은 `규칙 전용`, `규칙+생성형 LLM`, `규칙+판단 모델+선택적 생성형 LLM`이다. 먼저 관찰 모드로 답을 기록하고 평가 기준을 만족한 기능만 점진적으로 채택한다. Jev·Laya의 정확도와 비용을 비교하는 실험, 생성형 모델의 한국어 설명을 비교하는 실험은 서로 다른 지표를 사용한다. 검색·이상탐지의 채택은 별도 과제로 승인된 범위 안에서 수행한다.

모든 후보를 동시에 시험하지 않는다. 11/8까지 생성형 기준 1개·타 공급자 비교 1개와 판단 후보 Jev·Laya·단순 기준선으로 첫 실험 범위를 좁힌다. 접근·라이선스·하드웨어 제약은 미측정 사유로 기록한다. 미측정 모델을 성능 순위에 넣지 않는다. 이후 교체·추가할 후보는 요구 미달의 원인과 해결 가설이 있을 때만 선정한다.

모델 API 비용은 사용자 허용 범위에서 실험별 요청·토큰·금액·시간 상한을 정해 관리한다. 현재 문서 수정에서는 호출·설치·계정 변경을 하지 않았으며 AWS 배포와 GitHub 업로드도 하지 않는다. 주간 일정과 평가 세부 기준은 [멘토링 피드백 우선 계획](mentoring-priority-roadmap.md)을 따른다.
