# 웹 저장 경로의 방화벽 요청·netfilter 동시 관측 — v112

2026-11-16 · 채희주 담당 · 무료 로컬 · 목표 active · 목표 충족 전 push/새CI/병합 보류

별도 **이미 노출된 학습 Wilson**의 웹 감사 미탐3→0·TP19→22, FP10 유지·재현율86.36%→100%·F1 74.51%→81.48%로 개선했다.3행은 같은 audit 시각/serial의 NETFILTER_CFG·SYSCALL·PROCTITLE이며 독립 공격3회가 아니다. 원래 전체1,681,815행은 직전 판정을 유지했고, 모든 비교에서 새FP/기존TP손실/추론 오류0이다. 전체95% 목표와 원래6개 보안 영역의 독립 인수는 여전히 미달/미완료다.

## 무엇을 연결했는가

미탐 앞에 웹 업로드 작업 경로의 인코딩된 `iptables -L` 요청, 같은 보고 PID·TTY·auid/session의 sudo root CRED_REFR와 PAM USER_START가 있었다. 이어0.272초 뒤 동일 호스트 원본에 netfilter 사건이 기록됐다. 이 시간상 관측을 추가 검토 신호로 연결한다. **해당 명령이 완료됐거나 modprobe의 실제 부모/호출 사람이 확인됐다고 주장하지 않는다.** 당시 auid/session의 unset 값은 미확인으로 유지한다.

[관측기](../scripts/f1_lab/web_firewall_context.py)는 현재/이전 물리 행만 읽고 출처 SHA·행 순서·audit 시각/serial을 확인한다. 웹 업로드/cache/tmp 경로, shell 메타문자가 없는 고정된 방화벽 조회 문법, 같은 PID/TTY/보고 세션의 root sudo CRED_REFR→USER_START가 모두 필요하다. 원래 요청부터5초까지만 유지하고 PAM/후속 기록으로 시간을 연장하지 않는다. 동시에 확인된 요청이 여러 개면 추가 경보를 만들지 않는다.

이후 NETFILTER_CFG가 나오면 해당 행과 뒤에 나오는 같은 audit 사건의 SYSCALL/PROCTITLE에만 위험 문맥을 붙인다. 한 요청은 한 사건에만 소비한다. 뒤쪽 요청이나 다른 사건의 PID를 앞선 행에 소급하지 않는다. 먼저 나온 PROCTITLE/SYSCALL을 나중의 NETFILTER_CFG로 고치지 않는다. PAM 종료·부팅·시각/serial 역행·원문 결속 실패·중복/다른 사건은 추가 전파를 막는다.

NETFILTER_CFG는 정상 테이블 등록/교체/해제에서도 생성될 수 있어 단독 악성 판정 근거가 아니다. [Linux x_tables.c](https://github.com/torvalds/linux/blob/master/net/netfilter/x_tables.c)의 audit 호출을 참고했다. 이번 규칙은 **웹 저장 경로의 방화벽 요청과 인접 netfilter 기록의 동시 관측**을 표현한다. 실제 운영자가 같은 경로에서 같은 작업을 해도 일치할 수 있다. 권한 위반·명령 성공·프로세스 인과·사람 신원을 증명하지 않으며 자동 집행·접근 허용을 하지 않는다. 기존 현재 거부/독립 경보와 오류는 보존한다.

운영 기본 탐지기/팀원 앱은 변경하지 않았다. [판정 CLI](../scripts/run_audit_intent_review.py)와 [로컬 Docker 실행기](../scripts/run_local_vpn_protocol_batch.py)의 명시적 `--with-network-audit-context` 옵션으로만 적용한다. 기존 AppArmor/감사/인증/VPN 모델과 최소 지지/공격 veto·목표 기준을 재학습하거나 완화하지 않았다.

## 검증 범위

[실제 JUnit](infrastructure-results/extra-web-firewall-v112-20261116.xml), [전체 행렬·전후 지문 JSON](infrastructure-results/extra-web-firewall-v112-20261116.json), [재현 가이드](web-firewall-test-guide.md)를 제공한다.
