# 김택희 담당 11월 13일 마감 기록

개발 마감은 11월 16일 월요일이며 이번 작업 기한은 11월 13일 23시 59분이다.
PR #54를 `aitest`의 `596dae2913f10dd535421cd54ff70f3cb16f09de`로 병합한 뒤 후속 작업을 진행했다.
[병합 후 CI](https://github.com/cheonan-asan-sta/zero-trust-llm-secops/actions/runs/43344982267)는 전체 16개가 통과했다.
채희주의 extra 브랜치, 탐지 규칙과 F1 개선은 수정하거나 병합하지 않았다.

## 이번에 마무리한 백엔드

| 항목 | 동작 | 확인 범위 |
| --- | --- | --- |
| 실행 증거 큐 보관 | 완료한 요청과 묶음, 평가 영수증을 압축 보관하고 활성 큐에서 이동 | 원본 서명, 해시, 재시도, 중복과 충돌 이력 유지 |
| 미처리 보호 | 전송 대기와 평가 영수증 미확인 자료는 활성 큐에 남김 | 응답 유실, 전송 중 동시 정리, 재시작 |
| 입력 파일 회전 | 보관된 완료 입력만 `.retired`로 이동 | 덮어쓰기 거부, 하드 링크 후 중단과 재개, 교체 및 심볼릭 링크 거부 |
| 서버 행위 기록 보관 | 원래 해시 체인의 앞부분을 같은 DB의 압축 세그먼트에 보관 | 1만 건 초과, 기준선과 승인, 사용 한도와 취소, 중복과 타 테넌트 격리 |
| 저장 형식 이관 | 검증한 v1을 트랜잭션에서 v2로 이관 | 기존 복원 승인 핀과 논리적 접두 이력 유지 |
| 전체 복원 | 정리한 서버 기록과 수집 큐를 유지한 채 격리 복원 | 복원 중단 시 maintenance, 재개 후 기존 토큰 403과 새 토큰 200 |
| 평가 회귀 준비 | 기존 입력과 라벨을 새 디렉터리에 복사하고 현재 소스 지문을 별도로 고정 | 원래 manifest 보존, 노출된 사례 재실행 표시, 추가 모델 호출 없음 |

활성 수집 큐는 10,000건과 32 MiB, 전체 증거 ID와 입력 접수 이력은 각각 100,000건으로 제한한다.
수집기의 보관 본문과 완료 입력 파일 보관은 각각 256 MiB로 제한한다. 서버의 전체 논리 이력은
100,000건과 128 MiB다. 한도에 도달하면 오래된 승인이나 중복 판별 이력을 지우지 않고 실패를
명시한다. 무제한 보관, 무한한 디스크 수명 또는 장기간 부하 성능을 검증한 것으로 표현하지 않는다.
전체 앱 백업에는 기존의 별도 파일 및 합계 크기 제한이 계속 적용된다.
1만 건 초과 검사는 서명 자료를 일괄 준비한 저장 계층의 기능 시험이다. 실제 HTTP 접수와
권한 집행은 별도의 mTLS 종단 검증으로 확인한다.

수집기는 완료 입력을 옮기기 위해 자신의 입력 볼륨에 쓰기 권한을 갖는다. 행동 서명키와 별도
검토자 자격 증명은 전송기에 주지 않는다. 일반 전송자는 기준선을 승인하거나 토큰을 발급할 수 없다.
추가 관리 HTTP API를 만들지 않고 로컬 콘솔 명령만 제공했다.

## 최종 로컬 검증 결과

최종 변경 기준 ruff와 전체 pytest가 통과했다. pytest는 **3,483건 통과와 환경별 제외 2건**이다.
보관 기능 커밋 `5d3807f`의 실제 mTLS Docker 종단 검증은 **25개 모두 통과**했고 시험용 컨테이너와
볼륨을 정리했다. 경로 이식 보완 커밋 `812e46f`에서는 전체 pytest와 다른 경로의 깨끗한 체크아웃에서
410건 평가 재현을 완료했다. 최신 커밋의 전체 Docker 및 mTLS 검증은 PR #55의 전체 CI로 다시 확인한다.
마지막 실행 디렉터리는 `runtime/c02/execution-retention-20261113-r4`다.
기존 평가 410건을 현재 코드로 다시 실행한 결과는 응답 오류 0건이며 기존 집계와 같았다.
다른 체크아웃에서는 40개 이전 자료와 연결된 manifest를 포함한 전달 묶음을 풀고
이전 폴더의 새 위치를 명시해 재현했다. 원래 manifest, 입력, 라벨과 과거 예측의 해시는 유지됐다.
Colima 설정도 원래 2 CPU와 3 GiB, Rosetta 비활성으로 복원했다.
입력 및 라벨 해시, 소스 지문, 실행 이미지와 검사 결과는
[검증 요약 JSON](acceptance-results/kim-retention-20261113.json)에 기록했다.

기본 Docker 연결 대상이 초기화돼 기동 전에 실패한 첫 실행과 오래된 평가 실행기의 호환 실패는
별도 로그로 보존했다. 성공 검사 수에 합산하지 않았다. 이후 최종 검토에서 파일 동기화와 보관 자료의
활성 영역 중복 검사를 추가하고 해당 변경까지 전체 시험과 mTLS 검증을 다시 수행했다.

## 새 환경 재현

저장소 루트에서 실행한다. 유료 모델 API 키는 필요하지 않다. 이미 존재하는 실행 디렉터리는
재사용하지 않는다. 실제 운영 데이터 대신 자신이 생성한 시험 프로젝트를 대상으로 한다.

```bash
.venv/bin/ruff check .
.venv/bin/python -m pytest -q
.venv/bin/python -m scripts.test_execution_mtls_runtime \
  --directory runtime/c02/execution-retention-new-run
```

정상 결과는 `verification.json`의 `completed: true`, 모든 `checks[].passed: true`,
`cleanup.purged: true`다. 정리 후 관련 접근은 403, 무관 접근은 200이어야 한다.
복원 중단 후에도 기록자가 정지돼 있어야 하며 재개 후 기존 토큰은 403, 새 토큰은 200이어야 한다.
실패한 디렉터리와 로그도 보존하고 재실행 성공 기록으로 덮어쓰지 않는다.

기존 DB의 수동 정리는 다음 명령을 사용한다. 실제 mTLS 수집기의 콘솔에서는 초기화 때 사용한
`--base-url`과 `--tls-profile`을 함께 지정한다. 서비스 실행 중에는 자동으로 완료 자료를 정리한다.

```bash
.venv/bin/python -m scripts.context_maintenance status --database EXISTING_CONTEXT_DATABASE
.venv/bin/python -m scripts.context_maintenance compact --database EXISTING_CONTEXT_DATABASE
.venv/bin/python -m scripts.behavior_execution_collector status --directory COLLECTOR_DIRECTORY
.venv/bin/python -m scripts.behavior_execution_collector compact --directory COLLECTOR_DIRECTORY \
  --input-directory INPUT_DIRECTORY
```

## 현재 코드의 평가 결과를 읽는 기준

기존 240건과 실행 증거 170건의 입력 및 라벨 바이트를 유지한 회귀 실행이다. 이미 검토한
통제 실험 사례이므로 독립 공개 로그 일반화나 새로운 탐지 정확도를 주장하지 않는다.
정답 라벨은 판정 요청에 넣지 않고 모든 예측을 저장한 뒤 해석해 채점한다.
기존 manifest와 보고서는 수정하지 않는다. 새 복사본에는 과거 manifest와 현재 소스 지문을 따로 둔다.

| 현재 실행 증거 계약 | 세션 | 위협 탐지 | 오탐 | 미탐, 보류 포함 | 판단 보류 | 응답 오류 | 정밀도 | 재현율 | F1 | 오탐률 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 기존 입력 회귀 | 240 | 40 | 0 | 20 | 200 | 0 | 100% | 66.67% | 80% | 0% |
| 실행 증거 통제 사례 | 170 | 40 | 10 | 30 | 80 | 0 | 80% | 57.14% | 66.67% | 14.29% |

기존 240건은 실행 주체와 목적지의 증거가 없어 정상으로 확정했던 일부 작업도 현재는 보류한다.
이 집합에서 정상 판정 0건과 보류 200건을 숨기고 F1만 제시하지 않는다.
170건에서는 관측된 주체와 목적지가 같아도 숨겨진 악용을 놓치는 경우와 정상 바이너리 변경을
승인 위반으로 보는 경우가 남는다. 탐지 임계값이나 규칙을 이번 작업에서 조정하지 않았다.

근거 대조는 코드가 판정에 인용한 자료와 실제 접수 기록이 맞는지 확인하는 기계적 검사다.
모델 설명의 품질을 사람이 독립 검토했다는 뜻이 아니다. 과거 세 모델의 600회 실호출 결과는
별도 과거 자료이며 이번 회귀 실행은 추가 모델 요청 0회다. 탐지 목표 최종 달성과 운영 배포
승인을 완료로 표시하지 않는다.

오래된 `evaluate_m7_context` 실행기는 이전 승인 계약을 전제로 한다. 현재 코드에 원래 240건을
그대로 실행하면 `context_provenance_prior_use_record`로 중단되는 호환 문제를 확인했다.
이 실패를 성공 지표에 넣지 않고, 과거 승인 사용 기록의 재현을 지원하는 현재
`evaluate_m7_execution_context`의 legacy 경로를 사용한다. 원래 provenance 검사를 완화하지 않았다.

```bash
.venv/bin/python -m scripts.replay_evaluation_evidence \
  --source runtime/m7/behavior-execution-evaluation \
  --previous-directory runtime/m7/behavior-context-evaluation \
  --directory runtime/m7/execution-regression-new-run
.venv/bin/python -m scripts.evaluate_m7_execution_context evaluate \
  --directory runtime/m7/execution-regression-new-run
```

이 명령에는 기존 로컬 평가 자료가 필요하다. 다른 경로에 복사한 프로젝트에서도
`--previous-directory`로 실제 위치를 지정할 수 있다. 이전 입력, 라벨, 예측과 보고서의 모든
원본 해시가 일치할 때만 경로를 바꾸며, 원래 manifest는 수정하지 않는다.
기존 자료와 중복 여부를 재검사할 때 필요한 이전 입력과 해당 manifest도 전달 묶음에 포함한다. 저장소만 받은 새 환경의 기능 검증은 위 mTLS
명령과 pytest로 수행하고, 평가 재현에는 별도로 해시가 고정된 자료 묶음을 사용한다.

## 보고서에 넣을 개인 활동 문안

김택희는 FastAPI 백엔드, 대응 엔진과 자동 시험을 담당했다. 초기 계획의 자동 대응 안전 조건과
예외 처리를 확장해, 검증된 출처의 지속 신호를 접수하고 worker가 처리하며 새 입력이 없을 때도
watchdog이 세션 증명 만료와 키 폐기를 확인하는 로컬 운영 경로를 구성했다. 접근 허용은 자원과
동작, 시간, 세션 버전에 제한하고 검증된 불리한 신호 또는 복원 후 기존 허용의 사용을 거부한다.

이번 마감 작업에서는 실행 증거 수집과 서버 행위 기록의 용량 상한으로 상시 처리가 중단되지 않도록
완료 자료의 보관 정리를 추가했다. 미전송 자료와 응답 미확인 자료를 보존하고, 정리 중 장애와
재시작에도 승인 사용, 취소, 중복과 충돌 이력을 유지하도록 구현했다. 실제 mTLS Docker 환경에서
정리 후 접근 거부와 앱 전체 복원 절차를 함께 검증했다. 기존 평가 입력으로 현재 코드의 판정과
근거를 다시 집계했으며, 기능 시험 통과와 탐지 품질 목표 달성을 구분해 결과를 정리했다.

최초 계획보다 확대된 부분은 영속 큐, 자동 재시작과 복원, 신뢰된 신호와 승인 및 실행 증거의
연결이다. 멘토링에서 요구한 지속 검증과 제로트러스트 요소를 구체화하기 위한 확장이다.
실제 AWS 구독, 패킷 IDS, 외부 계정 차단과 EDR 센서는 현재 로컬 구현 범위에 포함하지 않는다.

## 공동 인수와 프로젝트 마감의 경계

김택희의 백엔드 자동 시험과 본인 검토를 두 팀원의 독립 재현으로 서명하지 않는다.
실제 팀원의 재현은 실행자와 시각, 커밋, 이미지 ID, `verification.json`을 별도 기록해야 한다.
공유 화면은 기존 분석과 세션 화면을 제공하며 행동 평가와 고위험 대응 API의 화면 연결은 공동
통합 항목이다. 이 기록만으로 해당 화면까지 구현했다고 표시하지 않는다.

인프라 담당과 함께 기반 이미지 및 패키지 발견의 실제 영향과 패치 후 호환성을 확인해야 한다.
PR #54의 APT, setuptools, NGINX 검사 결과를 이번 새 이미지가 모두 해결했다고 표시하지 않는다.
최종 탐지 규칙과 모델의 채택, 희주의 extra F1 개선 반영 여부도 별도의 팀 결정이다.
김택희 쪽에서 새 유료 모델 호출, 실제 AWS 배포나 계정 변경은 수행하지 않았다.

발표 흐름과 전체 아키텍처는 [최종 인수 안내의 시연 원고](kim-final-acceptance-20261113.md#3분-시연-원고)를
사용하고, 보관 정리 후에도 접근 거부와 복원 이력이 유지되는 결과를 추가한다.
