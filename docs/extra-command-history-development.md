# 웹 명령 요청의 선행 위험 문맥 — v51

후속 [v52 POST 보정](extra-post-refinement-development.md)에서 이 미탐 개선을 유지하면서
기존 개발 자료의 오탐122건을 추가로 줄였다. 아래 v51 결과는 당시 기준선으로 보존한다.

2026-11-14 · 최신 `aitest` 병합 기준의 v49 후보와 v50 회전 로그 준비를 이어서 검증했다.
이미 관측한 4개 개발 데이터, 총 **1,681,815행**에서 미탐 **9건 감소**, 새 오탐 **0건**,
기존 참양성 손실 **0건**, 추론 오류 **0건**을 확인했다. 원래 여섯 영역의 독립 성능 목표는 아직 미달이다.

[공개 실행 근거](infrastructure-results/extra-command-history-v51-20261114.json)에 파일별 혼동행렬,
이전/신규 예측·원본·코드 SHA, 기각한 후보와 관련 Linux 시험 결과를 기록했다.
원시 로그·인증 정보·개인키는 이 자료에 넣지 않았다.

## 추가한 판단

단독 `tar`, `wget` 등은 정상 관리 작업일 수도 있다. 이번 후보는 명령 이름만으로 경보를 올리지 않는다.
같은 물리 로그·클라이언트 IP·업로드 스크립트 경로에서 **자격증명 파일 읽기 의도**가 먼저 관측되고,
그 후 **60초 이내**에 구조화된 명령 요청이 이어지면 추가 검토 경보를 만든다.

- 선행 근거는 v49의 제한된 파서가 확인한 `cat /etc/shadow`, 설정 비밀 파일 등 읽기 의도다.
  `/etc/passwd` 같은 계정 목록 읽기나 일반 명령은 이 후보의 이력을 시작하지 않는다.
- 동일 시각·미상 시각·미래 행은 과거 근거가 아니다. 로그 순서대로 처리하며 시각 역행 시 이력을 지운다.
- 다른 클라이언트·스크립트·물리 파일에는 이력을 전달하지 않는다. 경로의 대소문자도 보존한다.
  일반 후속 명령은 60초 유효 기간을 연장하지 않는다.
- IP/경로는 관측 연결용 키이며 인증된 사용자·기기 신원이 아니다. 읽기 의도를 성공한 유출로 단정하지 않는다.
- 기존 점수를 낮추지 않으며 추가 점수의 하한만 0.95로 둔다. 모든 결과는 `automatic_enforcement_allowed=False`다.
  운영 PDP/PEP의 차단·접근 허용·권한 복원을 실행하지 않는다.

구현은 [web_command_history.py](../scripts/f1_lab/web_command_history.py), 재생 실행기는
[run_web_command_history.py](../scripts/run_web_command_history.py)다. 오프라인 비교 경로에 추가했으며
운영 탐지 서비스에 채택한 상태는 아니다. 기존 모델·v49 예측·원본 라벨·과거 프로토콜은 보존했다.

## 같은 개발 모집단의 전후 비교

| 자료와 범위 | 행 수 | FP 이전→신규 | FN 이전→신규 | 신규 F1 | 신규 오탐률 |
|---|---:|---:|---:|---:|---:|
| Russell/Mitchell, 기존 전체 선택 로그 | 295,243 | 85→85 | 1,001→998 | 99.1182% | 0.0364% |
| Santos, 기존 전체 선택 로그 | 295,976 | 79→79 | 944→940 | 98.9145% | 0.0318% |
| Fox, 기존 전체 선택 로그 | 668,418 | 137→137 | 702→702 | 99.9081% | 0.0648% |
| Harrison, v50 회전 웹 로그 | 422,178 | 361→361 | 10→8 | 99.9557% | **6.6178%** |

앞의 세 자료는 웹뿐 아니라 기존에 선택한 다른 로그도 포함한다. Harrison 행은 웹만 포함한다.
따라서 동일 도메인 구성으로 비교하거나 큰 전체 F1으로 VPN 약점을 가리지 않는다.
Harrison VPN의 별도 v49 전이 결과는 TP28/FP168/FN0, 정밀도14.29%·F1 25%로 그대로다.

각 시나리오의 예측은 정답 파일을 열기 전에 모두 기록하고 SHA-256을 고정한 뒤 채점했다.
기존/신규 예측은 사례 ID·물리 파일 순서로 대조했으며 오류 행도 분모에서 제외하지 않는다.
이미 본 자료로 설계한 개발 후보이므로 이 절차만으로 새 독립 평가가 되지는 않는다.
Harrison은 이미 소비한 자료이며 **Wilson 원문/라벨 본문은 아직 열지 않았다.**

## 기각한 오탐 감소 후보

성공한 브라우저 정적 파일 요청에 대해 기존 학습 점수가 낮으면 극단적 요청률 보호 조건을 완화하는
후보도 시험했다. Harrison 오탐은 361→200으로 줄지만 미탐이 10→11로 늘었고,
Fox에서도 기존 참양성 1건을 놓쳤다. **이 후보는 기각했으며 위 신규 결과에 포함하지 않았다.**
파일 확장자·브라우저 문자열·성공 응답만으로 위험한 요청 흐름을 안전하다고 취급할 수 없었다.
특정 사례 ID나 관측한 공격의 query 유무를 예외로 만들어 수치를 맞추지도 않았다.

## 검증과 재현

| 검증 | 결과 |
|---|---|
| 새 이력 경계/반례 Windows 테스트 | 39 통과 |
| Linux Docker 관련 묶음 | 152 통과, 실패/skip 0, 전체 Ruff + RUF100 통과 |
| 추가 예측 재생 경계 Windows 테스트 | 5 통과 |
| 실제 기존 로그 비교 | 4개 시나리오 완료, 1,681,815행, 추론 오류0 |

152개 묶음에는 신규 이력39개와 기존 전이 평가, mTLS 재시작 관련 시험이 함께 들어 있다.
서로 다른 실행의 중복 개수를 한 번의 전체 회귀 건수로 더하지 않는다.
Linux 시험은 캐시 이미지를 사용한 network none 컨테이너에서 실행했으며 소스 불변과 소유 컨테이너 제거를 확인했다.
유료 LLM/AWS 호출은 0이다.

로컬 원자료가 있는 환경에서 새 출력 경로로 재현한다. 계획에는 준비/원본 경로와 이전 예측의 정확한 SHA가 필요하다.

```text
python -m scripts.run_web_command_history --plan <plan.json> --expected-plan-sha256 <SHA256> --output <fresh-output-directory>
```

실제 산출물은 `runtime/f1/command-history-development-v51-20261114/run.json`과 옆의 신규 예측·근거 파일이다.
로컬 절대 경로가 든 계획은 공개 요약과 구분한다. 부분 출력은 최종 완료 보고서로 사용하지 않고 덮어쓰지 않는다.

## 이어서 할 일

1. Harrison 정상 웹 오탐361건의 추가 관측을 검토한다. 미탐 증가 후보는 채택하지 않는다.
2. VPN에 없는 인증된 기기·권한 사실을 임의로 채우지 않고 실제 수집과 별도 기능 검증을 구분한다.
3. 회전 로그 포함 규칙·후보·범위·지문을 사전 고정한 후 아직 보지 않은 출처에서 전이 평가한다.
4. 여섯 영역별 지지, 세션 단위, 노출/중복과 라벨 근거를 확인해 최종 목표와의 차이를 보고한다.

PR60의 monitored CI에서 발견한 재시작 관측 경계 문제는 별도 수정 중이다.
실제 Docker 재시작 검증이 진행 중이며 위 탐지 지표나 단위 테스트 통과로 대체하지 않는다.
