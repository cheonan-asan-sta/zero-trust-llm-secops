2026-11-14. v62까지 적용한 기존 Russell/Santos/Fox 개발 비교의 **1,259,637행**을 종류별로 다시 묶었다.
새 자료나 독립 성능 평가가 아니며, 새로 학습·분류하거나 정답을 고치지 않았다.
이미 완료된 v62 실행의 파일별 혼동행렬을 합산하고 원래 출처 전체 수치와 일치하는지 확인한 문서다.
Harrison은 이 실행에서 웹만 포함하므로 아래 여덟 종류 비교에 섞지 않았다.

## 이어서 필요한 작업

1. **VPN의 검증된 식별·기기·업무 승인 근거 확보.** 공개 접속 로그의 이름·주소를 실제 인증/승인으로 바꾸지 않는다.
   기존 연결 관측은 단일 위협 구간에 집중돼 있다. 서명된 신호의 기능 시험과 실제 악성 분류 평가는 구분한다.
2. **감사·인증 로그의 사건 결속과 정답 검토.** 행별 성공 문구만으로 악성을 추정하지 않고, 실제 audit event/process/주체의
   결속 가능한 증거와 해당 행의 라벨 근거를 먼저 확인한다. 로그에 없는 사용자 의도나 권한을 만들어 채우지 않는다.
3. **DNS의 오탐 없는 추가 근거.** 질의 문맥 트리에서 미탐732행을 줄였지만 새 오탐96행이 발생해 채택하지 않았다.
   임계값만 반복 조정하기보다 다른 출처에서도 유지되는 추가 증거를 검증해야 한다. 기존 판정과 실패 기록은 보존한다.
4. **새 정상 오류와 서로 다른 공격·사용자·기간 표본.** 정상4행을 복제하거나 같은 공격의 많은 로그 행을 독립 사례로 세지 않는다.
   새 자료의 역할과 후보를 먼저 고정하고 예측 봉인 후 채점한다. 수집 종류별 결과와 원래 보안 영역별 포괄성을 함께 공개한다.

현재 진행하는 Wardbeck 검증은 원래 계획의 **보정 출처**이며 위 최종 독립성 요건을 대체하지 않는다.
현재 오프라인 경보 후보를 접근 허용·권한 복원·자동 차단에 연결하지 않았다.

## 감사·인증 관측의 추가 확인

기존 R/S/F의 감사·인증9파일을 해시 대조 후 진단했다. 공유 서버 감사의 위협 라벨6행은 각각
systemd의 SERVICE_START/SERVICE_STOP이며, 모두 기존 `raw_features` 값이 같은 정상 행도 있었다.
이 한 행의 일반 특징만으로 서비스 시작/종료 전체를 위협으로 올리면 정상 동작도 영향을 받을 수 있다.
공격 일정·서버 이름을 외워 해당6행만 잡는 규칙을 추가하지 않았다.

웹 감사와 인증에도 정상/위협이 같은 일반 특징을 갖는 행이 있다. 이 결과는 **기본 행 특징의 충돌**이며
모든 원시 내용·시간 문맥으로도 구별이 불가능하다는 증명은 아니다. 기존 모델의 전체 특징 충돌이나
새 미탐 집계로도 부르지 않는다. 후속은 원본 audit 사건·프로세스·명시 세션의 결속 가능 여부와
사건 라벨 근거를 검토하는 방향이며, 접속 주소·성공 문구만으로 권한 상태를 추정하지 않는다.

[진단 근거](infrastructure-results/extra-audit-auth-observation-diagnostic-v65-20261114.json)에 파일별
위협 행 수와 기본 특징 충돌 행 수를 남겼다. 원시 계정·주소·명령 내용은 공개 파일에 포함하지 않았다.
이 사후 진단은 예측/정답/기존 성능을 변경하지 않는다.
