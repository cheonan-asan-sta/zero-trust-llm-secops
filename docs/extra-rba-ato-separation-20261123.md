# 반복 실패 경보와 계정 탈취 검토 분리

`extra` · 무료 로컬 검사 · Keycloak 통합과 RBA 계정 분리 평가.

## 판단 경로

- **반복 실패 경보**는 기존 계정 이력 규칙의 결과를 그대로 전달한다. 실패한 로그인은 계정 탈취 추정으로 변환하지 않는다.
- **계정 탈취 검토**는 성공한 로그인에서 이전과 다른 접속 환경이 관측되면 생성한다. 인증원에서 같은 요청에 결속한 필수 MFA 거부와 성공 판정의 충돌, 또는 검증된 새 기기 근거가 있을 때 우선 검토로 올린다. 검증된 OTP 성공만으로 환경 변화 검토를 해제하지 않는다.
- **공개 자료의 프로필 후보**는 OS 계열 변화로 높은 우선순위를 비교하는 오프라인 실험이다. RBA에는 MFA와 기기 등록·검증 결과가 없다. OS·브라우저·기기 유형은 환경 변화 단서로 쓰며 실제 기기 신뢰나 MFA 결과로 바꾸지 않는다. [RBA 필드와 생성 방법](https://zenodo.org/records/6782156)

판단은 검토용 출력이며 계정 잠금·세션 회수·접근 결정에는 연결하지 않았다. 이전 접속 환경 후보의 넓은 탐지 신호는 검토에 남긴다. 우선순위는 검토 순서를 결정하는 별도 지표다.

## 계정 분리와 후보 고정

앞서 결과를 확인한 두 계정군에서 기기 유형·OS·브라우저·새 프로필 조건과 시간 상한을 비교했다. 넓은 탐지의 참양성을 모두 유지하는 조건을 먼저 찾고, 가능한 조건이 없으면 절반 이상을 유지하는 후보에서 F1이 높은 조건을 선택했다. 고정 후보는 새 출발 주소와 직전 성공 대비 국가·ASN 변화에 OS 계열 변화까지 요구한다. 앞서 본 두 계정군에서는 참양성이 27건에서 15건, 오탐이 29,949건에서 15,209건으로 바뀌었다. 이전 예측 및 라벨의 지문과 새 후보의 SHA-256을 고정했다. [이전 환경 변화 검증](extra-rba-login-environment-20261123.md)

새 평가에는 기존 해시 구간 0~19의 계정 861,603개, 로그인 3,516,562건을 모두 사용했다. 이전 두 모델 평가 구간 70~99와 최초 probe 계정은 제외했다. 0~19 구간은 이 실험 이전에 원본의 집계와 구조 검토만 수행했다. SHA-256으로 예측을 봉인한 뒤 ATO 라벨을 결합했다. 같은 공개 자료 안에서 계정을 분리한 시험이다.

| 이전 방식, 반복 실패와 환경 경보 합산 | 18 / 64,587 / 22 | 0.0279% | 45.00% | 0.0557% | 1.8367% |

기존 방식의 탐지 여부와 새로운 두 경로의 합집합을 전체 행에서 비교했다. 판정 차이와 기존 탐지 손실은 각각 0건이다. 이전에 해제한 반복 실패 경보 1,460건도 그대로 해제 상태였다. 반복 실패 경보 44,330건은 해당 경로에 남아 있으며 ATO 정답 기준의 오탐 집계에서 분리됐다. 두 경로를 합친 전체 검토 대상은 이전과 같은 64,605건이다.

OS 계열 변화를 추가해 ATO 우선 검토 오탐을 환경 변화 기준보다 10,064건 줄였다. 우선순위에서 빠진 탈취 7건은 일반 ATO 검토로 남았다. 전체 ATO 검토는 18/40건을 유지했다. 오탐률은 목표 5% 이하였고 정밀도·재현율·F1은 95%에 미달했다. 공개 자료의 미표식 행에는 확인되지 않은 공격이 포함될 수 있으며, 실제 MFA·검증 기기를 이용한 탐지 성능은 이 표본에서 측정하지 못했다.

## 실제 OTP 통합 시험

Keycloak 26.8.0의 서명 검증과 로그인 이벤트를 같은 토큰·세션에 연결했다. 검증된 OTP 성공과 알려지지 않은 기기, 시험용 환경 변화가 함께 있을 때 ATO 일반 검토로 남았다. 잘못된 OTP 입력에서 공급자가 반환한 일반 오류는 MFA 실패로 단정할 수 없어 MFA 상태를 `unknown`으로 유지했다. 해당 실패 로그인에 반복 실패 경보를 전달해도 ATO 검토는 생성되지 않았다. 새 기기와 필수 MFA 거부 시 우선 검토 분기는 단위 테스트로 확인했다. [Keycloak 이벤트 공식 문서](https://www.keycloak.org/docs/26.8.0/server_admin/)

## 재현

고정 RBA ZIP, probe 근거, 이전 환경 평가의 두 예측 디렉터리를 사용한다. 예측 및 정답 원본은 로컬 `runtime`에 둔다. 확인용 출력은 새 디렉터리를 지정한다.

```powershell
go run scripts/experiments/rba_login_projection/main.go --confirmation <rba.zip> <probe.json> <new-projection>
python -m scripts.evaluate_rba_ato_separation freeze <previous-projection> <new-candidate.json> <reviewed-output> <previous-holdout-output>
python -m scripts.evaluate_rba_ato_separation capture <new-projection> <new-output> <new-candidate.json> <candidate-sha256>
python -m scripts.evaluate_rba_ato_separation score <new-projection> <new-output> <seal-sha256>
python -m scripts.run_keycloak_remote_acceptance <new-keycloak-report.json>
```
