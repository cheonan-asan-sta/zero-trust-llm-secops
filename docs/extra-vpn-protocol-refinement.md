## 어떻게 개선했는가

이전 모델은 일부 새 연결의 일반 핸드셰이크·채널 초기화에도 높은 이력 보조 위험을 부여했다. [새 관측기](../scripts/f1_lab/vpn_protocol_review.py)는 같은 물리 소스의 현재/이전 행에서 연결 단계, 앞선 인증서 주체의 peer 관계, 클라이언트가 보고한 OS/버전의 제한된 범주를 추가한다. IP/port/CN은 파일 내부 연결 키일 뿐 원래 값을 학습하지 않는다. 미래 인증서 정보를 앞선 패킷의 특징으로 되돌리지 않는다. 출처 SHA·연속 행·원문 UTC 시각이 맞아야 하며 순서/시각이 모호하면 추가 정상 분류를 중단한다.

[고정 의도 표](../scripts/f1_lab/vpn_protocol_head.py)는 R/S/Shaw/Wheeler 개발 자료의 실제 라벨로 만든 셀 집계다. 정상 지지5건 이상·관측 공격0인 셀만 이력 보조 경보를 낮춘다. 공격이1건이라도 있으면 정상 수가 많아도 낮추지 않는다. 기존 기본 점수가0.95 이상인 경보, 현재 명시적 거부, 실제 인증/TLS/인증서/공격 관측은 낮추지 않는다. 앞선 실제 실패는60초 동안 유지하고 성공 응답·초기 패킷 재등장·port 변경으로 지우지 않는다. 이60초는 기존 위험 유지 경계이며 결과에 맞춰 줄이지 않았다.

클라이언트 주장과 로그의 VERIFY OK는 검증된 기기 상태·사람 신원·업무 권한이 아니다. 경보를 낮춰도 **검토는 유지하고 자동 집행/접근 허용을 하지 않는다.** 이 표의 경험적 점수는 보정된 공격 확률이 아니다. 기본 운영 탐지기를 바꾸지 않고 별도 로컬 판정 CLI에 연결했다.

## 이미지 환경 정정

첫 v109 실행의 새 mount에는 정답·문서·테스트를 제외했지만, 기본 캐시 이미지 자체의 `/workspace/docs`·`tests`와 설치 프로젝트 사본에 접근할 수 있음을 뒤늦게 확인했다. 따라서 그 실행을 이미지 전체에서 문서/테스트가 물리적으로 차단된 실험이라고 표현할 수 없다. v105~v108의 같은 취지 문구도 추가 mount 검사 범위만 확인했다는 한계를 정정한다. 이전 원본·라벨·예측·보고서는 덮어쓰지 않는다.

수정한 실행기는 이미지의 `/workspace`, 설치된 app, 프로젝트 배포 metadata를 빈 읽기 전용 tmpfs로 가린다. 시작 시 비어 있는지 확인하고 실행 코드가 `/work/app`에서 오는지 기록했다. 같은 입력과 모델로 전체9개 묶음을 재실행했으며 **모든 예측 파일 SHA가 첫 실행과 정확히 일치**했다. 최종 수치는 차단을 확인한 v109b 실행으로 채점한 결과다. 이 재현이 이미 노출된 자료의 독립성을 새로 만들어 주는 것은 아니다.
