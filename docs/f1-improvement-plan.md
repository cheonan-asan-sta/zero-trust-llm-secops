# 탐지 F1 목표 달성 실험 계획

2026-11-12 · 상태: **extra에서 F0/F1 도구 실행, F3 shadow 초안 실험 진행·최종 인수 미완료**.
[extra 기준선/오류 검토](extra-f1-baseline-review.md)에 실제 후속 실행과 한계를 기록한다.
[지속 실험 기록](extra-f1-experiments.md)은 이후 사용자 지시에 따른 shadow 후보 구현/시험이다.
독립 검토가 대기 중인 실험 후보를 운영 인수나 F3 최종 완료로 표시하지 않는다.
[4주차 잔여 인수](week4-remaining-and-handoff.md)의 후속 품질 작업으로 연결한다.
현재 규칙·임계값·라벨·평가 파일을 바꾸지 않는다. 목표에 맞춰 정답을 고치지 않는다.
팀원의 실제 검토·목표 달성·운영 인수가 끝났다는 의미가 아니다.

## 순서와 시작 조건

현재 잔여 기능의 필요한 신뢰 경계·복원 계약 인수(R1/R2), 데이터 검토 기반(R4),
탐지 범위 판단(R9)을 먼저 확보한다. 이후 별도 개선 실험을 수행하고 그 결과를 R5와 연결한 뒤
R10의 **최종** 기능 동결에 반영한다. 최종 동결을 승인한 뒤 몰래 규칙을 바꾸는 순서가 아니다.
운영 물리 HA·실제 유료 모델 비교까지 모두 끝나야 무료 규칙 실험을 시작할 수 있는 것은 아니다.
이미 승인한 동결본이 있다면 개선본은 다음 후보 버전으로 분리한다.

## 현재 기준선과 목표

아래는 기존 Sigma **이벤트 탐지** 결과다. LLM 분류 정확도·세션 회수 성공률과 구분한다.
출처는 [기준선 오류 분석](detection-baseline-error-review.md)과 그 원자료 지문이다.

| 분할 | TP | FP | FN | TN | 정밀도 | 재현율 | F1 | 오탐률 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 기존 개발360 | 170 | 50 | 10 | 130 | 77.27% | 94.44% | 85.00% | 27.78% |
| 기존 holdout360 | 90 | 50 | 90 | 130 | 64.29% | 50.00% | 56.25% | 27.78% |
| 목표 | — | — | — | — | ≥95% | ≥95% | ≥95% | ≤5% |

정밀도=TP/(TP+FP), 재현율=TP/(TP+FN), F1=2TP/(2TP+FP+FN),
오탐률=FP/(FP+TN)다. 정확도=(TP+TN)/전체도 함께 보고하지만 정상 사례를 많이 넣어
정확도만 높이는 것으로 위 목표를 대체하지 않는다. 분모0은 완벽한 성능으로 처리하지 않는다.

현재처럼 위협180·정상180인 **같은 크기의** 평가라면 FN≤9·FP≤9가 위 네 점 목표를
동시에 충족한다. 경계 예시는 TP171/FP9/FN9/TN171로 네 지표가 95%/95%/95%/5%다.
기존 holdout에서 이 경계로 가려면 미탐90→9 이하, 오탐50→9 이하가 필요하다.
이 계산은 필요한 개선 규모를 설명하는 예시이며 기존 holdout에 맞춰 조정하라는 뜻이 아니다.
평가 크기·정상/위협 비율이 바뀌면 허용 건수를 다시 계산한다.

## 단계별 실행

| 단계 | 실제 작업 | 담당과 산출물 | 다음 단계로 넘어갈 조건 |
|---|---|---|---|
| F0 기준 고정 | 코드·규칙·OCSF 매핑·기존 결과·라벨·분할 지문을 고정하고 지표 단위를 정의 | 채희주: 범위/실험 조건. 김택희: 지표/실행기 대조. Codex: 원자료/해시/재현표 보조 | 기존 결과 재현, 평가 단위와 목표 계약 확정. 기능 통과와 품질 통과 구분 |
| F1 오류 독립 검토 | 기존 FN90/9계열·FP50/5계열의 실제 관측과 규칙 조건을 대조. 라벨 불일치·정규화·신호 부족·시간 맥락·예외 범위·규칙 조건 문제로 분류 | 김택희: 라벨/코드 근거 대조. 채희주: 신호/정상 업무 의미 확인. Codex: 사례표/분해 보조 | 계열마다 원인 근거·필요 신호·수정 가설·반례가 있음. 이름만 보고 원인을 확정하지 않음 |
| F2 새 평가 설계 | 개발/보정/최종 평가를 세션·주체/기기·계열·시간 기준으로 분리. 최종 라벨은 다른 검토자가 관리 | 공동 데이터 수집/검토. Codex: 중복·출처·변환·누락 검사. 독립 검토자가 최종 평가셋 동결 | 정보 누수·관측만으로 구분 불가능한 라벨·출처/사용 조건을 검토. 표본 부족은 부족으로 기록 |
| F3 규칙/신호 개선 | 아래 가설을 작은 묶음으로 구현. 개발셋 회귀와 반례를 함께 추가. 임계값은 개발/보정셋에서만 선택 | 김택희: 탐지/정규화/상태 구현. 채희주: 수집/자원/실행 조건. Codex: 구현·단위/계약 시험 보조 | 개발/보정 결과에서 FP와 FN을 함께 줄이고 필수 보안 경계 회귀0. 후보 설정 고정 |
| F4 선택적 AI 비교 | 규칙 원본, 규칙 개선, 규칙+선택적 모델을 동일 입력으로 비교. 맥락 부족 사례의 실제 개선 여부 확인 | 채희주: AI 역할/호출 조건. 김택희: 평가/집계. Codex: 실행/분석 보조 | AI가 개선에 기여한 경우만 유지. 새 API 호출은 별도 실행 조건/예산을 확정한 경우에만 수행 |
| F5 독립 최종 평가 | 고정 후보와 기준선을 새 평가셋에서 함께 측정. 영역/규칙/계열·중복 제거·불확실성·정상 업무 영향 보고 | 독립 검토자: 데이터/실행 확인. Codex: 집계 보조. 팀장: 해석/결론 | 사전 기준 충족 여부를 그대로 기록. 실패하면 평가본을 개발용으로 전환하고 다음 회차에는 새 평가본 준비 |
| F6 통합 인수와 동결 | 선정 후보 하나에 전체 회귀·필요 Docker 종단·자원/지연·오류 복구를 묶어 검증. 버전/설정/결정 고정 | 채희주: 인프라 실행/측정. 김택희: 앱 의미 독립 인수. 팀장: 최종 승인 | 탐지·회수·접근 집행·안전 회귀·품질/불확실성·한계와 검토자 연결 |

F0~F2의 선행 작업은 병행할 수 있다. 실험 시간이 정해졌다는 이유로 F1/F2 검토를 생략하지 않는다.
날짜는 남은 인수와 데이터 확보 결과에 따라 배정하고, 목표 달성일을 보장하지 않는다.
기존 11/29 동결 목표에 미치지 못하면 검증된 후보와 미달 사유를 제출하고 개선본은 후속으로 둔다.

## 개선 가설의 우선순위

| 우선순위 | 개발셋에서 확인할 가설 | 반드시 함께 추가할 반례/경계 |
|---|---|---|
| 1 입력/정규화 | 실제 관측이 OCSF·Sigma 필드로 누락/오매핑되는지 확인하고 같은 의미를 일관되게 변환 | 필드 누락·타입 오류·미지원 값·위조 입력. 정답/계열명·공격 여부를 피처로 넣지 않음 |
| 2 정상 업무 오탐 | 배포·사고 대응·승인 야간 지원·VPN 정비·훈련의 정상 근거를 검증 가능한 맥락으로 표현 | 클라이언트가 준 승인 bool/설명만으로 예외를 인정하지 않음. tenant·대상·행위·승인자 권한·유효기간을 제한하고 위조/만료 예외 거부 |
| 3 미탐 신호 | 정상 로그인 후 탈취·관리 기기 침해·권한 밖 다운로드 등에서 어떤 입력이 부족한지 먼저 확인 | 같은 관측을 가진 정상 사례와 구분 불가능하면 센서/신호 보강 대상으로 남김. 보이지 않는 정답을 규칙에 삽입하지 않음 |
| 4 세션/시간 맥락 | 분산 저속 시도·저속 유출 등에서 단일 이벤트 외의 순서/누적 신호가 필요한지 검증 | 서명·시각·scope·중복/역순·재시작·누락 검증. 별도 시간 창/세션 집계를 실제 구현하고 새 지연/저장 계약 시험 |
| 5 선택적 모델 | 규칙만으로 다루기 어려운 관측의 분류·근거 정리를 모델이 보완하는지 비교 | 공급자 오류·정보 부족·입력 내 지시문·근거 없는 답변·한도 초과. 모델은 접근 허용/권한 발급/회수 해제의 권한을 갖지 않음 |

위 항목은 원인 확정이 아닌 **시험할 가설**이다. 현재 데이터에 필요한 신호가 없다면 모델이나
임계값만으로 해결할 수 있다고 가정하지 않는다. 전송 mTLS·CA 이중화 자체가 F1을 올리는 것으로
계산하지 않고, 신호 신뢰성과 운영 안전을 보장하는 별도 축으로 유지한다.

## 데이터·실험 계약

- 기존 holdout은 이미 결과와 오류를 봤으므로 오류 분석/회귀 자료로 사용한다. 파일과 기존 결과는
  보존하고 이를 새 blind 평가라고 부르지 않는다. 새 평가 라벨·출력은 후보 고정 전에 튜닝 담당자에게 공개하지 않는다.
- 최종 평가의 **확보 목표안**은 정상300·위협300개의 독립 세션이다. 개발/보정 자료는 이와 분리한다.
  이 수치만으로 통계적 충분성을 주장하지 않는다. 실제 확보 수·고유 계열·신호 패턴·영역별 지지와
  군집 불확실성을 확인한 뒤 필요한 추가 표본을 결정한다. 같은 틀의 문자열/ID 변형을 독립 세션 확보로 세지 않는다.
- 현재 720건 합성 벤치마크와 M7 공개 인증48세션은 단위·관측 스키마가 다르다. 두 자료의 TP/FP를
  한 분모로 합치지 않는다. 공개 인증 세션을 이벤트 평가에 사용할 경우 변환/라벨/정보 소실을 별도 검토한다.
- 정상·위협의 근거가 불확실한 원본은 최종 동결 전에 별도 검토 대상으로 표시하고 전체 수/이유를 공개한다.
  모델이 틀린 사례라는 이유로 평가 후 삭제하거나 정상/위협 라벨을 바꾸지 않는다.
- 시간 창/세션 탐지기는 이벤트 탐지와 별도 표를 만든다. 한 세션의 여러 이벤트를 독립 정답으로
  반복 집계하지 않으며, 이벤트 기준 F1과 세션 기준 F1을 바꿔치기하지 않는다.
- 한 번에 가설1~2개를 묶고 원본/개선/개선+모델의 차이를 기록한다. 모델 도입은 선택 사항이다.
  API 없이 가능한 개선을 먼저 비교하고, 실제 모델 미호출 결과를 모델 품질·비용 실측으로 표시하지 않는다.
- AI 오류/abstain/timeout은 평가에서 빼지 않는다. 혼합 후보는 미리 정한 규칙 fallback으로 모든 사례의
  최종 alert/no-alert를 생성하고 오류율·fallback률도 함께 보고한다. 위험한 입력의 정책 거부는 별도로 유지한다.
- 개발/보정 평가와 변경 경계 시험은 작은 묶음마다 수행한다. 무거운 전체 Docker 인수는 후보 고정 후
  F6에서 한 번에 수행하고, 실패가 있으면 바뀐 경계를 재검증한다.

## 완료 판정과 중단 기준

1. 새 평가셋에서 정밀도·재현율·F1≥95%, FPR≤5%를 **동시에** 만족해야 점 목표 달성으로 쓴다.
   목표를 낮추거나 F1 하나만 통과한 결과로 대체하지 않는다.
2. 기존 평가기의 `gate_passed`는 점 목표 외에도 평가 오류0·각 규칙의 목표/계열 지지·정상 계열 지지를
   검사한다. 전체 F1만 통과한 결과로 이 gate를 통과했다고 쓰지 않는다. 이벤트/세션 새 실행기도 같은 원칙으로
   대상별 사전 계약을 두며 기존 기준을 조용히 완화하지 않는다.
3. `statistical_target_supported`는 기존 계열 군집 bootstrap의 지표 하한/상한까지 보는 별도 판정이다.
   점 목표 통과와 구분하고 표본/계열 부족 시 불확실성을 그대로 보고한다. 기업 일반화까지 증명하는 것은 아니다.
4. 기존 세션/테넌트·서명 권한·만료·일회 소비·회수·복원·2인 승인 경계가 약해지면 품질 수치가 올라도 채택하지 않는다.
5. 개발/보정에서 사전 합의한 소수의 후보 묶음을 비교한 뒤 개선이 정체되면 원인을 다시 검토한다.
   신호/라벨 공백이면 수집/데이터 단계로 돌아간다. 최종 평가셋을 반복 조회하면서 통과할 때까지 조정하지 않는다.

## 역할과 전달물

채희주는 범위·신뢰할 수 있는 신호·AI 역할·실행/측정·예산/운영 한계를 맡고,
김택희는 정규화/탐지·시간/세션 상태·평가 실행기·앱 회귀·독립 대조를 맡는다.
Codex는 요청한 구현·자료·집계·로컬 시험을 보조한다. Codex가 생성한 시험/라벨을 팀원의 독립 검토로 기록하지 않는다.
공동 라벨 검토와 최종 인수는 실제 검토자·시각·불일치 해결 기록을 남긴다.

최종 전달물은 기준선 고정표, 오류 원인/반례 대장, 새 데이터/라벨/분할·동결 지문,
후보별 변경·설정·실행 결과, 지표/불확실성·오류/정상 업무 영향, 종단 회귀와 채택/미채택 이유다.
목표 미달이면 검증된 수치·남은 관측 공백·후속 계획을 제출하며 달성으로 바꾸어 적지 않는다.

## 11/12 지속 실험의 중간 상태

F0 기계적 재현과 F1 검토지22계열은 준비됐으며 사람의 원인 검토는 대기 중이다.
