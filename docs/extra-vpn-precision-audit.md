# extra: VPN 정상 오탐 감소 검증 — v41

후속 [v42 검증된 기기·권한 신호](extra-vpn-verified-signals.md)는 새로운 서명 신호가 있는 로컬 통제 경로를 구현했다.
기존 공개 로그에는 이 근거가 없어 아래 오탐/미탐과 진단 하한은 그대로다.

2026-11-13 · 비용 없는 로컬 비교. **미탐을 늘리지 않으면서 오탐을 줄이는 후보는 이번 비교에서 찾지 못했다.**
[v40b](extra-error-vpn-refinement.md)의 VPN 미탐0건 설정과 모델·원래 라벨을 유지했다.
[전체 근거 JSON](infrastructure-results/extra-vpn-precision-audit-v41-20261113.json)에 실패한 후보, 혼동행렬·사례 결속·시험 지문을 보존한다.
시험 완료와 오탐 감소 달성은 별개다. `target_achieved=false`이고 운영 적용은 없다.

## 시도와 선정 결과

오탐 일부는 데이터 채널의 암호/해시 초기화 선언이었다. 아래 가설을 별도 오프라인 코드로 비교했다.

- 정확히 파싱된 일반적인 채널 선언만으로 새 VPN 보조 위험을 만들지 않는다. 알고리즘·사용자 이름의 예외 목록은 사용하지 않는다.
- 기존 기준선 경보와 같은 연결의 엄격히 이전 위험은 유지한다. 같은 시각 배치는 보류하고 유지된 위험은 만료를 연장하지 않는다.
- 미상 시각/접속점·추가 공격 문장·미상 문법은 예외로 처리하지 않는다.

## 같은 관측이 갖는 구분 한계

원시 코어/의미 특징, VPN 과거 이력, 유지 위험 점수/경과 초, 일반 채널 선언 여부를 묶어 같은 벡터를 대조했다.
원시 계정명·IP 값·절대 시각·원본명·행 번호·정답은 관측 특징에 넣지 않았다.
벡터의 SHA와 정상/위협 case ID 증인을 근거 JSON에 기록했다.

| 자료 | 현재 FP | 기존 TP 전부 유지 시 같은 벡터에 묶여 남는 정상 FP | 위협과 섞이지 않은 FP |
|---|---:|---:|---:|
| russellmitchell | 60 | 56 | 4 |
| santos | 60 | 60 | 0 |
| fox | 88 | 86 | 2 |

이는 **정답을 사용한 진단 하한**이다. 학습한 모델·독립 평가 성능·미래 모든 모델의 불가능성 증명이 아니다.
같은 입력에 같은 출력을 내는 함수가 기존 위협 벡터를 모두 양성으로 유지한다면, 그 벡터의 정상 행도 양성으로 남아야 한다는 뜻이다.
특히 S의60건은 모두 이 조건에 해당한다. 현재 특징으로 임계값/모델만 바꿔 S 오탐을 줄이면서 모든 기존 TP를 지킬 수는 없다.
R/Fox의 비혼합4/2행은 위험 경과2초인 구간이다. 이를 제거하려고 기존60초 유지 정책을 관찰된1초 위협 구간에 맞춰 축소하지 않았다.
새로운 관측이나 업무 권한 근거가 추가되면 이 하한도 달라질 수 있다.

## 구현한 검증 도구

`scripts/f1_lab/vpn_precision_audit.py`:

- 별도 선언 보정 가설과 고정 임계값 비교를 위한 평가 함수.
- **기존 TP 한 건도 잃지 않음 + FN 증가 없음 + FP 감소 + 추론 오류 없음**을 함께 검사한다.
  잃은 위협을 다른 새 탐지로 상쇄해 총 FN만 같게 만드는 후보도 거부한다.
- 중복 case·잘못된 자료형/지문·빈 모집단을 거부하고 추론 오류를 분모에 남긴다.
- 관측 벡터 충돌과 정상/위협 증인을 만드는 정답 기반 진단. 그 정답은 후보 추론으로 되돌리지 않는다.

`scripts/audit_vpn_precision.py`:

- pinned 원본/라벨/시각 계약·준비 receipt·이전 모델/코드/결과 지문을 검증한다.
- 실제 VPN18,458행 전체에서 v40b 혼동행렬을 재현한다. 정상 행을 제거하거나 라벨을 바꾸지 않는다.
- 후보별 손실과 선택을 저장한다. 앱/집행에 자동 적용하는 경로는 없다.

## 다음 개선에 필요한 근거

VPN 연결과 묶이는 **검증된 기기/사용자·자원/행위의 권한 근거**, 당시 승인 범위와 만료/회수 상태,
선행 기기 상태·IdP/MFA 결과·수집기 무결성 정보가 필요하다.
서버가 TLS 성공을 기록했다는 사실만으로 업무 권한이나 기기 건강을 만들 수는 없다.
실제 연결 키·시각과 검증된 세션/주체를 결속하는 수집 경로를 먼저 확인하고, 해당 근거가 있는 새 정상/위협 자료를 분리 평가한다.
현 공개 VPN 로그에는 이 근거가 없어 기존 정상 행에 임의의 정상 승인 라벨을 덧붙이지 않았다.
현재 후보는 검토용이며 원래 여섯 영역 독립 목표와 운영 인수는 미완료다.
