## 문제와 구현

이전 모델은 일부 성공한 SSH 로그인 기록에서 데몬 프로세스 `uid=0`과 실제 로그인 대상의 권한을 구분하지 못했다. Linux Audit의 `uid`는 사건을 낸 프로세스의 실제 UID이고, `auid`는 원래 로그인 UID다. 이 차이는 [Linux Audit 공식 설명](https://github.com/linux-audit/audit-userspace)의 필드 의미를 따른다. 정상 로그인 성공 자체를 권한 승인으로 해석하지 않는다.

[AuditIntentReview](../scripts/f1_lab/audit_intent_context.py)는 같은 물리 파일의 앞선 USER_ACCT/CRED_ACQ→LOGIN→USER_START→USER_LOGIN 흐름을 파싱한다. 보고 PID·로그인 계정·auid/session·터미널이 모순되지 않고 로그인 대상이 nonroot인 경우에만 역할 특징을 만든다. 원본 SHA·연속 행·원문의 숫자 시각을 결속하며, 파일/순서/시각 역행·재부팅 시 연결을 재사용하지 않는다. 계정·주소·PID·session은 로컬 연결 키이며 모델 입력 값이 아니다.

이전 인증 실패·민감 파일·shell 공격 관측은 PID/auid/주소 단위로 300초 동안 이 후보의 정상 분류를 막는다. 현재 성공한 로그인으로 과거 실패를 지우지 않는다. 기존 명시적인 실행/호출자 거부 등 위험 이유도 덮어쓰지 않는다. 누락된 USER_AUTH를 만들어내지 않고, 관측된 USER_ACCT/CRED_ACQ를 사용했다는 한계를 남긴다.

같은 세션에서 hex 명령이 정확한 직접 cat/head/tail의 운영 로그 조회이고, 같은 sudo PID·auid/session·터미널의 후속 PAM 단계라면 별도 명령 의도 특징을 만든다. shell 복합문·리다이렉션·민감 파일·인식 못한 명령은 후보가 아니다. **현재 이 명령 흐름은 학습 지지가 부족해 경보를 낮추지 않는다.**

[IntentHead](../scripts/f1_lab/audit_intent_head.py)는 역할·이벤트 종류·실행 파일 역할·UID 역할·AUID 역할·성공 여부의 6개 범주를 사용한 학습 표다. SHA로 고정한 표에서 정상 지지 5건 이상이고 관측된 공격이 0건인 셀만 보조 경보를 낮춘다. 학습 공격이 1건이라도 있으면 정상 수가 많아도 낮추지 않는다. 해당 점수는 보정된 공격 확률이 아니다. 검토 표시는 유지하고 자동 집행·접근 허용·인증된 사람/기기 신원으로 사용하지 않는다.

## 학습과 평가의 분리

[학습 CLI](../scripts/train_audit_intent.py)는 명시적으로 training 역할을 선언하고 SHA로 고정한 계획만 받는다. truth의 사례 ID·순서·모집단과 원문 지문을 대조한다. 이번 R/S/Wilson 학습에 원래 정답을 사용했으며, Wilson은 v87 이후 이번에 **학습 역할로 추가 소비**했다. v87 당시 동결 결과를 덮어쓰거나 계속 독립 평가로 부르지 않는다. Wardbeck의 기존 보정 역할을 유지했고 Fox/Wardbeck/Harrison은 이번 학습에 넣지 않았다. 이들도 이미 노출된 같은 생성 계열이므로 새로운 독립 자료가 아니다.

SSH 대상 역할 셀은 정상 8·공격 0의 학습 지지다. 운영 로그 조회 5개 단계 셀은 각각 정상 2·공격 0으로, 사전에 둔 최소 5건에 못 미친다. Fox의 남은 오탐을 보고 이 기준을 낮추거나 Fox를 학습에 넣지 않았다. 지원되지 않는 셀과 이전 명시적 위험은 기존 판정을 유지한다.

평가 전에 코드·모델·이전 예측·원본을 고정했다. [예측 CLI](../scripts/run_audit_intent_review.py)는 학습된 표를 읽지만 평가 정답을 읽지 않는다. 학습된 정상/공격 집계는 **모델 파라미터로 제공**되므로, 모든 라벨 유래 정보가 없다고 주장하지 않는다. 평가 정답·평가 정상/위협 집계·문서·테스트 파일은 예측 컨테이너에 제공하지 않았다. 준비/원본 메타데이터는 필요한 필드만 projection하고 그 지문을 원래 manifest에 연결했다. 전체 예측 봉인과 소유 컨테이너 삭제 뒤 호스트에서 채점했다.
