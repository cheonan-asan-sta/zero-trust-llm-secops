# 이전 미선택 감사·인증 파일의 전이 평가 계약

2026-11-16 · v87 · 메타데이터 점검·코드 준비, 새 선택 로그/라벨 본문 접근 전.

[v85](extra-apparmor-noop-review.md)는 이미 관측한 R/S/F 개발 자료의 웹 감사 FP37→21·F1 70.77%→80.70% 개선이다. 다른 자료에서의 적용 범위·손실을 확인하기 위해, 기존 Wilson/Wardbeck 압축파일 안에서 이전에 선택하지 않았던 정확한 감사·인증 파일 쌍을 평가한다. 압축파일 전체는 이미 일부 소비했으므로 **완전히 새로운 출처 holdout이나 원래 여섯 영역의 독립 최종 평가라고 부르지 않는다.**

## 고정 범위와 기존 노출

메타데이터만 열어 전체 audit/auth 후보를 확인했다. Wilson17개 후보 중 정답과 정확히 짝이 있는3개, Wardbeck18개 후보 중3개를 선택한다. 나머지14/15개는 정답 파일이 없으므로 정상으로 채우지 않고 제외 사유를 보존한다. 임의의 행·호스트·공격 결과를 보고 선택하지 않는다.

대상은 원래 경로를 유지한 `/logs/auth.log`, `/logs/audit/audit.log`의 정확한 gather↔labels 미러다. 같은 basename·다른 호스트·회전 파일로 확장하지 않는다. 고정된 모든 선택 파일의 모든 물리 행을 유지한다. source/계정/기기/공격 계열 독립성이나 세션 기준 성능까지 확보한 자료가 아니다.

Wardbeck의 원래 보정 역할을 유지한다. Wilson도 이전 웹/VPN 평가로 이미 부분 노출된 출처다. 이전 `evaluation-access.json`과 선택 manifest의 SHA·내용을 동결하며 덮어쓰거나 삭제하지 않는다. 새 `audit-auth-member-access-v87.jsonl`에 선택 멤버의 raw 접근→예측 봉인→label 접근을 append/fsync로 기록한다. 잘린 기록·다른 후보 지문은 거부한다. 이 대장은 신뢰된 로컬 호스트의 재현 근거이며 외부 rollback 방지·독립 사람 검토의 증명이 아니다.

## 선정·모델·라벨 계약

- 기존 게시자 파일명·버전·MD5/라이선스·기간과 SHA를 대조한다. 기존 [Wilson 계약](extra-wilson-source-transfer.md)·[Wardbeck 역할](extra-wardbeck-calibration-result.md)을 보존한다. CC BY-NC-SA4.0 공개 자료의 비상업적 연구 평가이며 원시 자료를 Git에 재배포하지 않는다.
- 원시 본문 전에 코드·선택 metadata·원본/기존 노출 지문·모델·정책·0.95 임계값을 동결한다. v49의 기존 고정 모델→v67의 감사/인증 연결→v85의 명시적 변경 생략을 순서대로 비교한다. 새 자료로 재학습하거나 예외 목록을 추가하지 않는다.
- 호스트 facts의 UTC 설정을 확인한다. 추정 시간대를 넣지 않는다. 각 원본64MiB/10만행·전체20만행, 정확한 쌍/행 순서·SHA를 검사한다. 설정 한도 초과는 모집단을 잘라 진행하지 않고 실패로 보존한다.
- 특징 준비와 예측은 정답 없이 수행한다. 모든 단계의 예측 지문을 먼저 봉인하고 소유 예측 컨테이너를 제거한 뒤, 기존 게시자의 정확한 미러/trimmed 행 라벨로 채점한다. 공격 관련 행 라벨이며 독립적으로 심사한 실제 기업 사고 정답과 다르다.
- 새로운 FP·기존 TP 손실·미탐·추론 오류를 출처/종류별로 전부 공개한다. 정상/위협 표본이 없으면 해당 비율은 산출 불가다. 큰 전체 집계로 공유 서버/인증 실패를 가리지 않는다. 같은 원문·특징의 겹침은 사후 진단에만 쓰며 행을 지우지 않는다.
- 같은 감사 사건의 완결 후 문맥인 v85는 엄격한 과거 행 전용 실시간 탐지와 구분한다. 검토는 유지하고 접근 허용/회수·자동 집행은 추가하지 않는다.

선택/노출 대장은 `scripts/f1_lab/audit_member_transfer.py`, 단계 CLI는 `scripts.run_audit_member_transfer`다. 코드/원문/정답/모집단이 달라지면 이전 결과를 재사용하지 않는다. 실패 후 자료를 재관측하면 그 노출을 보존하며 새 독립 자료로 재분류하지 않는다. 결과가 나쁘더라도 범위·정답·기준을 바꾸지 않는다.

AWS·유료 API0, 기존 로컬 Docker와 캐시 자료만 사용한다. 장기8시간 soak는 계속 유예한다. 현재는 평가 준비이며 새 성능 수치는 확정하지 않았다.
