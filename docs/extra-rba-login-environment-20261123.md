# RBA 계정 탈취 미탐과 로그인 환경 변화 평가

`extra` · 로컬 CPU 평가 · 웹·접근 정책과 별도로 검토.

## 기존 미탐 26건

직전에 평가한 647,026개 계정(2,575,003행)을 이번 후보의 진단 자료로 사용했다. 기존 두 기준의 예측을 2,575,003행에서 이전 봉인 결과와 대조했고 모두 같았다.

| 관측 | 미탐 26건 중 |
| --- | ---: |
| 현재 로그인 성공 | 26 |
| 동일 계정의 10분 내 반복 실패 경보 | 0 |
| 비교에 사용할 선행 성공 기록 | 19 |
| 선행 성공 기록과 24시간 넘게 떨어진 로그인 | 13 |

| 최근 이력에 없는 완전한 브라우저·OS·기기 조합 | 6 |

반복 실패 기준은 이미 성공한 채로 나타난 탈취를 포착하지 못했다. 선행 성공 기록이 없는 7건에서는 동일 계정의 변화 여부를 계산할 수 없었다. 짧은 시간 안의 재로그인만 보면 오래 떨어진 이력도 놓친다. 국가·ASN·브라우저 등은 발행자가 합성한 값이므로 실제 위치 이동, 물리 기기 또는 인증 위반을 증명하지 않는다. [RBA 데이터와 합성 방식](https://zenodo.org/records/6782156)

## 후보와 판정 범위

같은 계정의 앞선 성공 최대 12건만 사용한다. 출발 주소, 국가, ASN, 브라우저·OS 계열, 기기 유형의 변화와 이전 성공과의 상대 간격을 비교한다. 브라우저와 OS 버전 번호, 원문 사용자 ID·IP·User-Agent, 발행자의 공격 IP 표식 및 ATO 정답을 예측에서 제외했다. 같은 시각의 기록은 서로의 이력으로 쓰지 않고, 상충하는 환경의 동시 성공은 다음 기록의 비교 기준에서도 제외한다.

검토한 분할에서 60개 조건을 비교했다. 기존 탐지와 앞서 해제한 경보를 유지하는 조건을 포함했고, 새 오탐 0건을 만족하며 이전 미탐을 잡는 조건은 없었다. 별도 계정으로 전이 검증할 후보는 **새 출발 주소와 직전 성공 대비 국가·ASN 변경이 모두 관측된 성공 로그인**이다. 이 후보는 계정별 최근 12건만 사용하며 시간 간격 상한은 두지 않는다. 진단 분할에서 기존 미탐 16건을 찾았고 오탐을 15,023건 추가했다. 기기·브라우저까지 요구한 조건도 비교했으며 선택한 후보는 관찰용으로만 실행한다.

선행 성공 기록이 있던 미탐 19건은 모두 같은 변화 신호와 시간 구간으로 표현되는 ATO 미표식 행과 겹쳤다. 그 13개 관측 조합에는 미표식 행 192,720건이 있었다. 이 특징 조합이나 시간 기준만 조정해 19건을 구분하기 어렵다는 진단이다. 미표식 행에는 확인되지 않은 공격이 포함될 수 있다.

## 새 계정군 검증 방법

이전에 모델 개발과 사례 진단에 사용하지 않은 동일 공개 자료의 다른 계정 해시 구간을 사용했다. 기존 계약의 70~84 구간 전체에 해당하며 계정 644,492개, 행 2,572,078개다. 앞서 검토한 85~99 구간 및 개발 probe 계정은 들어가지 않는다. 이 분할의 지원 건수는 기존 메타데이터 감사에 있었고, 이번 후보를 고정한 뒤에만 개별 예측과 라벨을 결합했다. 같은 발행자 내 계정 분리 검증이며 새로운 외부 시스템에서의 검증은 남아 있다. [계정 분할과 출처 감사](extra-rba-metadata-audit.md)

| 분리 평가 2,572,078건 | TP / FP / FN | 정밀도 | 재현율 | F1 | 오탐률 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 원래 반복 실패 규칙 | 0 / 33,420 / 18 | 0% | 0% | 0% | 1.2993% |
| 이전 오탐 감소 후보 | 0 / 32,415 / 18 | 0% | 0% | 0% | 1.2603% |
| 이전 후보에 접속 환경 경보 추가 | 11 / 47,341 / 7 | 0.0232% | 61.11% | 0.0464% | 1.8406% |

앞서 해제한 경보 1,005건의 재발과 기존 탐지 손실은 각각 0건이었다. 다른 행에서 새 오탐이 14,926건 생겨 회귀 조건은 미달이다. 수치 목표는 오탐률 5% 이하만 만족했고, 정밀도·재현율·F1은 95%에 미달했다. 접속 환경 후보를 관찰용에 두어 기존 오탐 개선을 보존했다.

이 표본에서 이전 32,415개 오탐을 전부 그대로 경보로 남기고 탐지만 더하면, 18건을 모두 찾아도 정밀도는 최대 0.0555%, F1은 최대 0.1109%다. ATO를 구분할 추가 근거를 수집하고, 기존 반복 실패 신호와 ATO 판단을 각각 검증할 필요가 있다. 접근 정책, 웹 탐지, 원격 세션 회수에는 이 실험 결과를 적용하지 않았다.

## 재현

기존 RBA ZIP과 probe 근거를 사용하고 출력 디렉터리는 새 이름으로 지정한다. `capture` 단계는 `observations.tsv`만 읽고, 채점은 예측 봉인 SHA-256을 받은 뒤 `truth.tsv`에 접근한다. 개별 환경, 계정, 예측, 라벨은 로컬 `runtime` 아래에 둔다.

```powershell
go run scripts/experiments/rba_login_projection/main.go --environment <rba.zip> <probe.json> <projection>
python -m scripts.evaluate_rba_login_environment <projection> <reviewed-output> reviewed
python -m scripts.evaluate_rba_login_environment <projection> <reviewed-output> reviewed --score-seal <reviewed-seal-sha256>
python -m scripts.evaluate_rba_login_environment <projection> <holdout-output> holdout --candidate <frozen-candidate.json> --expected-candidate-sha <candidate-sha256>
python -m scripts.evaluate_rba_login_environment <projection> <holdout-output> holdout --score-seal <holdout-seal-sha256>
```

로컬 회귀 34개, Ruff, Go 빌드를 통과했다. 유료 API·AWS 호출·병합은 0회다. [집계와 봉인 SHA-256](infrastructure-results/rba-login-environment-20261123.json)

[후속 반복 실패·ATO 검토 분리](extra-rba-ato-separation-20261123.md)에서 새 계정군의 오탐 감소와 우선 검토 재현율의 변화를 별도로 측정했다.
