# 원문 명령 문맥을 이용한 인증 미탐 개선 — v105

2026-11-16 · 채희주 담당 · 로컬 전용 후보. v104의 정책 fixture 결과와 달리, 이번에는 기존 공개 로그의 실제 미탐을 대상으로 원문 관측을 판정에 연결한다. 같은 평가 모집단·정답·원래 모델·임계값을 보존하며, 목표 전체가 충족되기 전 push·새 CI·병합은 하지 않는다.

## 실제 로그에서 추가로 사용한 관측

미탐 root PAM 열기 기록에는 보고 PID나 이름 있는 호출자 근거가 부족했다. 그러나 같은 인증 원문의 바로 앞 sudo 기록에는 자격 증명 파일 읽기 요청 또는 웹 저장 경로 형태에서의 root 디렉터리 재귀 탐색 요청이 있었다. 이것은 **인접한 위험 관측의 동시 발생**이다. PAM과 명령을 같은 사람·같은 실행으로 인증했다는 뜻이 아니다.

[SensitiveAuthReview](../scripts/f1_lab/sensitive_auth_context.py)는 다음 경우에만 추가 위험 신호를 낸다.

- 한 물리 원본의 SHA를 매 호출에 고정하고, 행 번호는 정확히1씩 증가한다. 다른 파일/호스트로 연결하지 않는다.
- 실제 syslog prefix와 전달된 UTC 관측 시각이 일치해야 한다. 역행·출처 변경·행 순서 불일치는 추가 연결을 중단한다.
- 바로 앞 행이 구문 분석되는 sudo의 `USER=root` 직접 명령 요청이어야 한다. 다음 행은 동일 호스트 sudo의 root PAM 열기여야 하며 간격은0~1초다. 중간 행·미래 명령·재사용된 명령은 연결하지 않는다.
- 위험 요청은 직접 `cat/head/tail`의 `/etc/shadow`, `/etc/gshadow`, `/etc/security/opasswd` 접근, 또는 웹 콘텐츠 경로의 uploads/cache/tmp 형태에서 직접 `ls`로 `/root`를 재귀 탐색하는 경우다. 호스트명·계정명·case ID·날짜·IP·고정 사건 번호를 분류 예외로 넣지 않는다. 웹 경로 형태가 실제 쓰기 권한을 증명하지도 않는다.
- shell 복합문·리다이렉션·명령 치환처럼 이 파서가 명확하게 해석하지 않는 형태는 이 추가 신호의 대상이 아니다. 기존 탐지 결과는 계속 유지한다. `/etc/passwd` 일반 읽기나 단순/일반 작업 경로의 파일 목록 조회를 이 규칙으로 확대하지 않는다.
- 양쪽에 보고 PID가 있고 서로 다르면 연결하지 않는다. PID가 없을 때는 여전히 알 수 없음이며 호출자 신원·명령 성공·업무 권한을 만들지 않는다.

[audit_auth_review.refine](../scripts/f1_lab/audit_auth_review.py)는 이 근거가 있을 때 기존 경보를 보존하면서 경보와 검토를 추가한다. 자동 권한 부여/집행은 없다. 기존 실행기의 기본 동작을 바꾸지 않고 선택적인 `auth_review_factory`를 전달하는 [예측 CLI](../scripts/run_sensitive_auth_review.py)에만 연결했다. 신호는 원문 로그의 위험 관측이며 v103/v104의 서명된 사람/기기 권한 증명과 혼동하지 않는다.

## 검증 구분

관련 경계·회귀 시험과 같은1,681,815행의 v104 대비 전후 비교를 분리한다. 예측 컨테이너에는 코드와 필요한 원문·이전 예측·집계를 제거한 원본/준비 메타데이터만 제공한다. 정답·문서·테스트 파일과 정상/위협 집계는 제공하지 않고, 예측 봉인·컨테이너 삭제 뒤 호스트에서 채점한다. 원래 source/group 역할은 이미 관측한 개발/보정 자료이며 새 독립 holdout으로 바꾸지 않는다.

처음의 자격 증명 읽기 연결은 미탐2건을 회수했다. Fox에서 추가로 관측된 자격 증명 읽기 연결1건은 기존 정탐이어서 새 회수로 세지 않았다. 당시 합산 인증 재현율은96.875%였지만 Fox 자체는91.6667%로 미달이었다. 이후 남은 Fox 미탐의 직전 root 재귀 탐색 요청을 별도 문맥으로 검토했다. 중간 결과와 최종 후보를 구분하고 새 TP를 중복 계산하지 않는다.

공개 결과 지문과 집계는 [결과 JSON](infrastructure-results/extra-sensitive-auth-v105-20261116.json)을 따른다. 기존 전체 회귀 수천 건이나 systemd 인수를 이번 새 탐지 규칙에서 다시 실행했다고 주장하지 않는다.

## 남은 목표

이 자료에서 인증 수치가 충족되더라도 공유 감사·웹 감사·VPN과 원래6개 보안 영역의 독립 인수는 별도다. 희소한 양성 표본과 같은 생성 계열의 자료만으로 실제 기관의 성능을 일반화하지 않는다. 다른 종류의 자격 증명 접근, 정상 관리자의 민감 파일 점검, 위조/불완전 로그에 대한 새 자료도 필요하다. 원래 목표 P/R/F1 각각95% 이상·FPR/FNR 각각5% 이하는 유지한다.
