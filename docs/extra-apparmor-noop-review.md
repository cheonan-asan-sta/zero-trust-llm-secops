## 문제와 근거

기존 오류 진단에서 AppArmor `STATUS/profile_replace`와 짝을 이루는 PROCTITLE가 위협으로 분류됐다. 이 중에는 현재 정책과 동일해 변경을 건너뛰었다는 명시적인 커널 설명이 있다. 이 메시지의 실제 사례는 [AppArmor 프로젝트의 이슈183](https://gitlab.com/apparmor/apparmor/-/issues/183)에서 확인했다. 단순 STATUS나 정책 교체 전체를 정상으로 처리할 근거는 아니다.

교체·캐시 관련 인자 의미는 [AppArmor 공식 parser 설명서](https://www.apparmor.net/man/master/apparmor_parser/)로 확인했다. `-r/--replace`는 교체 요청이며 `-T`와 `-W`는 캐시 읽기/쓰기 옵션이다. 정책의 안전성·사용자의 정당한 승인을 증명하지 않는다. 이 후보는 그중 커널이 명시적으로 변경을 생략한 사건만 따로 설명한다.

아키텍처 `c000003e`에서 syscall1은 write로 대조한다. [Linux 원본 syscall 표](https://kernel.googlesource.com/pub/scm/linux/kernel/git/torvalds/linux.git/+/e2457a664ea02c414c6b9828bff3a0df4c300f63/arch/x86/entry/syscalls/syscall_64.tbl)에 근거하며 다른 아키텍처/번호로 추측해 확장하지 않는다.

## 동작과 제한

1. 원래 전체 파일 SHA가 같은 물리 감사 출처 하나에서만 묶는다. 동일한 audit 시각·serial의 SYSCALL/AVC/PROCTITLE가 각각 정확히 하나씩 필요하다. PID나 인접 행만으로 묶지 않는다.
2. STATUS·profile_replace·변경 생략 문구, 오류/denied/requested mask 부재, 동일 PID, 성공한 x86-64 write, 표준 parser exe/comm, 디코딩된 제한 인자와 단일 `/etc/apparmor.d/` 경로를 모두 확인한다. 삭제·complain·shell·임의 옵션·경로 이동·중복 필드/기록·추가 이벤트 형식·시간 역전·한도 초과는 후보 문맥을 주지 않는다.
3. 실제로 정책이 바뀐 교체, DENIED/ALLOWED, 실패, 누락된 기록에는 적용하지 않는다. 일반 기준 모델의 `unchanged/missing_context` 판정만 score 최대0.05로 제한한다. 별도 인과적 위협·서명 실행 근거의 위험 판정은 보존한다.
4. 상태·인자 설명 두 행만 보정하며 성공 SYSCALL 행은 변경하지 않는다. 보정한 경우에도 검토를 유지한다. 계정 신뢰·SSO·업무 승인·PDP 허용·세션 회수·자동 집행을 추가하지 않는다. 원문 문자열은 인증된 실행 근거가 아니다.
5. 원본 SHA·행 순번·원본 행 SHA·같은 사건의 완료 순번으로 문맥을 결속한다. 파일명·호스트/계정/정책 이름·공격 시각·정답 라벨을 특징이나 예외 목록으로 쓰지 않는다.
6. 이 경로는 **같은 사건이 완성된 뒤 판단하는 오프라인 후보**다. 같은 이벤트의 뒤쪽 PROCTITLE를 이용하므로 엄격한 과거 행 전용 실시간 탐지라고 부르지 않는다. 실제 수집기에서 사건 완결/시간 제한 버퍼를 운영하는 일은 별도다.

## 평가 계약

R/S/F/H의 이미 관측한 고정1,681,815건을 전부 유지한다. 기존 모델과 임계값을 재학습/조정하지 않는다. 진단에서 이미 라벨을 봤으므로 이번 결과는 개발 비교이며 새 독립 성능이 아니다. 본문 일부를 지우거나 라벨·분모를 변경하지 않는다.

후보 코드·정책·출처 SHA·기존 예측 SHA와 모집단을 고정한다. network-none·비root·read-only root의 로컬 컨테이너에 원본 압축파일/정답 파일을 넣지 않고 예측한다. 선택된 audit 원본과 공개 메타데이터·기존 예측만 전달한다. 모든 예측 지문을 봉인하고 소유 컨테이너를 제거한 뒤 기존 정답으로 채점한다. 종류/출처별 TP·FP·FN·TN과 추가 FP·기존 TP 손실을 비교하며 정상/위협 표본이 없는 비율은 산출 불가로 남긴다.

새 오탐·기존 탐지 손실·추론 오류가0이고 제거된 오탐이 있을 때 개발 후보 통과로 표시한다. 후보 통과와 원래 여섯 영역의 독립 목표 달성은 별도다. 정상·위협의 부족한 실행 주체/명령·조직 승인을 추정해 채우지 않는다. AWS·유료 API 호출0, 장기8시간 soak 유예를 유지한다.
