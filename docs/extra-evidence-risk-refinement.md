# 수집 근거를 적용한 실행·인증·VPN 판정 개선 — v104

2026-11-16 · 채희주 담당 · 로컬 전용 후보. **새 근거가 있는 운영 정책 제어 사례와, 근거가 없는 기존 공개 로그의 탐지 지표를 분리한다.** 정상/위협 라벨·모집단·원래 탐지 모델·목표 수치는 변경하지 않는다. 목표 충족 전 push·CI·병합은 하지 않는다.

## v103에서 이번에 발전한 부분

v103은 실제 MainPID·부팅/서비스 실행 ID·시작 tick·실행 파일/명령·UID를 수집하고, 정확한 PAM 기록·로컬 OIDC 영수증·TLS 연결의 인증서/채널을 결속했다. 공유 감사·PAM은 실행 거부 근거로 경보를 추가할 수 있었지만, 확인된 신원으로 보조 경보를 해소하는 경로가 없었다. VPN도 명시적으로 폐기된 인증서 등록과 확인 불가능한 등록을 같은 unavailable로 처리했다.

| 대상 | 이번 처리 | 허용하지 않는 처리 |
|---|---|---|
| 공유 감사 | 별도 출처가 보존된 신원 불확실성 경보만, 정확한 살아 있는 실행·명령 허용 정책·요청 결속 호출자·현재 호출자 위험 정책이 확인되면 해소. 검토는 유지 | 일반 모델의 높은 점수나 독립 위험을 사후에 신원 불확실성으로 바꾸기, 허용 목록만 보고 경보 지우기 |
| 인증 | 위 조건에 정확히 같은 프로세스 수명의 서명된 PAM 열기 관측을 추가 확인. 명시적으로 폐기된 호출자는 현재 실행 위험 경보로 연결 | PID 없는 과거 PAM 행에 인접 sudo PID·사람 이름 붙이기, UID0을 사람 인증으로 취급하기 |
| VPN | 현재 등록 파일에서 정확한 tenant/gateway/certificate/user/device가 일치하면서 명시적으로 폐기된 경우 adverse로 처리. 낮은 기존 점수에서도 경보·검토 추가 | 등록 파일 누락/변조·알 수 없는 인증서·기기 불일치·신원 서명 누락을 확인된 폐기라고 추정하기 |

공유 감사·인증의 명시적 호출자 폐기도 일반 모델 점수가 낮을 때 경보·검토를 추가한다. 새로운 위험 정책은 **이미 유효한 OIDC 영수증을 검증한 뒤** 적용한다. 기존 영수증의 인증원 SHA·서명·요청 nonce·event·실행 증거 결속을 느슨하게 만들지 않았다. 독립 경보, 고위험 독립 점수, 기존 VPN 위험 보존 창은 유지한다. 모든 새 판정은 advisory이며 권한 부여·자동 집행을 수행하지 않는다.

## 구현과 입력 경계

[execution_risk_evidence.py](../scripts/f1_lab/execution_risk_evidence.py)의 `ContextRiskDecision`은 독립 탐지 결과와 추가 신원 불확실성 점수를 분리해서 보존한다. `add_identity_uncertainty`는 서버의 신뢰된 탐지기가 새 실행 관측을 판정할 때만 사용한다. 과거의 일반 `OperationDecision`을 이 타입으로 해석하거나 사용자/LLM이 제출한 점수를 독립 점수로 받는 공개 API가 아니다.

`service_evidence`는 서비스 proof의 역할·서명·정책·시간을 검증하고 실제 프로세스가 같은 PID/start/boot/UID/명령인지 다시 확인한다. `pam_evidence`는 여기에 v103의 정확한 cursor·부팅/실행 ID·PAM 원래 시각 검증을 추가한다. 종류와 event SHA가 맞지 않거나 근거 digest가 없으면 경보를 낮추지 않는다. 만료 시점과 완료 시점도 확인한다.

`PinnedCallerRiskPolicy`는 별도로 고정한 SHA·최소 버전·현재 유효 기간·인증원 SHA를 요구한다. 명시적인 `revoked_caller_refs`만 현재 폐기로 인정한다. 파일 자체가 손상·만료·중복·다른 인증원용이면 unavailable이며 기존 판단을 유지한다. 이 파일은 운영자가 신뢰 설정으로 배포하는 정책이며, 원격 보안 주체가 별도로 서명한 조직 승인 체계를 구현했다는 뜻은 아니다. 로컬 호스트/운영자의 변경·rollback에 대한 독립 원격 증명도 아니다.

긍정적 신원 근거로 해소할 수 있는 것은 독립 경보가 없고 독립 점수와 원래 baseline 점수가 각각0.9 미만인 **추가 신원 불확실성 경보**다. 경보를 낮춘 뒤에도 `review=true`, `automatic_enforcement_allowed=false`다. 독립적인 공격/권한 위험은 별도로 보존해야 하며 이를 보조 점수로 재분류해서는 안 된다. 이 경로는 local/test 환경에서 검증했다.

[vpn_enrollment.py](../scripts/f1_lab/vpn_enrollment.py)는 `active/revoked/unavailable`을 구분하고, 기존 `verify`는 여전히 active만 허용한다. [VPNTrustBridge](../scripts/f1_lab/vpn_verified_signals.py)는 게이트웨이·신원·기기 상태 서명과 요청/채널 결속을 확인한 뒤에만 명시적 등록 폐기를 경보로 반영한다. 권한/등록 파일을 다시 읽어도 같은 근거인지 확인하며, 확인된 위험 직후 재등록만으로 기존60초 위험 보존을 지우지 않는다. TLS 수집 adapter의 검증 범위는 [v103](extra-live-evidence-ingress.md)을 따른다.

## 시험 해석 기준

실제 Linux 제어는 UUID로 한정한 systemd 서비스에서 sudo를 실행하고, native journal·`/proc`·로컬 OIDC 영수증·고정 정책으로 판정 경로를 확인한다. VPN은 실제 loopback TLS 연결에서 읽은 인증서/채널을 사용한다. OIDC person·기기 상태·승인 발급원은 로컬 fixture다. **신원 불확실성/독립 탐지 점수도 시험용 입력값**이므로 여기서 줄어든 정책 제어 오류를 독립 공격 탐지 F1 개선으로 합산하지 않는다.

기존 공개 로그 비교는 v103의 고정된 같은1,681,815행을 사용한다. 이미 관측한 R/S/F/H 자료이며 새 독립 holdout이 아니다. 문서·테스트·정답 파일이 없는 코드 전용 예측 컨테이너와, 정상/위협 집계를 제외한 preparation/source manifest projection을 사용한다. 같은 코드의 기능 시험 영수증은 예측 종료·컨테이너 삭제 뒤 연결하고, 정답 채점도 그 뒤 호스트에서 수행한다. Windows bind I/O 지연을 줄이기 위해 같은 SHA의 입력/출력을 컨테이너 tmpfs에서 처리한다.

최종 수치·검증 지문은 [공개 결과 JSON](infrastructure-results/extra-evidence-risk-v104-20261116.json)에 기록한다. 전체 프로젝트 회귀 수천 건을 새로 실행한 결과로 확대하지 않는다.

## 남은 작업

새 근거가 없는 과거 공유 감사·인증·VPN 기록은 기존 판정을 유지한다. 미탐/오탐 수치를 낮추려고 주체·명령·권한을 추정해서 채우지 않는다. 실제 조직 SSO·기기 상태 발급원·VPN native hook과 정책을 연결하고, 실행 주체·명령·권한·시간이 함께 수집된 새 정상/위협 자료를 별도로 라벨 검토해야 한다. 원래6개 보안 영역의 독립 인수와 사용자 요청으로 유예한 장기 soak도 남아 있다.
