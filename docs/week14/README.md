# 14주차: 오류 진단·품질 대시보드 고도화

## 계획 목표

반복 평가에서 실패 원인과 취약 시나리오를 빠르게 찾고 시연 화면의 품질 정보를 보강한다.

## 구현 결과

- 분석 실패를 `timeout`, `provider`, `validation`, `runtime` 네 범주로 집계한다.
- 실패 응답에는 예외 원문이나 민감한 공급자 정보 대신 안전한 오류 범주만 반환한다.
- 기대 위험도와 실제 위험도를 비교하는 혼동 행렬을 추가했다.
- 시나리오별 표본 수, 위험도 정확도, 대응 정확도, 오류 수, 평균·P95 지연을 계산한다.
- 대시보드에 오류율, 처리량, P50·P95 지연, 목표 판정, 시나리오별 진단표를 추가했다.
- 오류가 포함돼도 전체 평가를 중단하지 않고 성공·실패 사례를 함께 보고한다.
- 버전을 `0.6.0`으로 올리고 Docker 종단 시험을 40건 안정성 평가로 강화했다.

## 오류 분석 검증

고의로 `RuntimeError`를 발생시키는 시험 분석기를 사용해 8건 모두 `runtime` 범주로 집계되고, 혼동 행렬의 `ERROR` 열에 반영되는지 확인했다. 원래 예외 메시지는 API 결과에 포함하지 않았다.

## 화면 검증

- 브라우저에서 40건 안정성 평가 실행과 결과 렌더링을 확인했다.
- 9개 품질 지표 카드와 8개 시나리오 진단 행이 정상 표시됐다.
- 목표 통과 상태와 오류율 0% 표시를 확인했다.
- 기존 사건 분석·검토·감사 기록 기능과 충돌하지 않는지 자동 테스트로 회귀 검증했다.
