# 6주차: 합성 로그·Few-shot 프롬프트와 구조화 출력

## 계획 목표

수행계획서의 5~6주차 목표인 합성 로그 생성 규칙, 10개 이상의 Few-shot 예시, JSON 출력 스키마 초안을 완성한다.

## 구현 결과

- 사용자, 기기, 네트워크, 자원, 인증, 행위를 포함하는 `SecurityEvent` 계약을 합성 로그 생성기에 연결했다.
- 정상 3건과 위협 5건으로 구성된 8개 기준 이벤트를 만들었다.
- 8개 기준 이벤트에 프롬프트 인젝션형 정상·위협 예시 2건을 더해 10개 Few-shot 쌍을 구성했다.
- 현재 이벤트와 가까운 시나리오 예시만 선택해 불필요한 입력 토큰을 줄이도록 했다.
- `ground_truth`는 평가에만 사용하고 실제 분석 입력에서는 제거했다.
- 자연어 출력 대신 `SecurityAssessment` Pydantic 모델을 OpenAI 구조화 출력 형식으로 사용했다.
- 이벤트 안의 자유 텍스트는 지시가 아니라 비신뢰 데이터로 취급하도록 시스템 지침과 테스트를 추가했다.

## 코드 근거

| 구현 | 위치 |
|---|---|
| 합성 이벤트와 시나리오별 기준 답안 | `app/scenarios.py` |
| 이벤트·분석 결과 스키마 | `app/models.py` |

| 프롬프트 인젝션·라벨 누출 검사 | `tests/test_prompting.py` |

## 한계

합성 이벤트는 반복 가능한 기능 검증용이며 실제 조직의 공격 분포나 오탐률을 대표하지 않는다. 실데이터 검증은 개인정보 제거, 승인 절차, 별도 보안 저장소를 마련한 뒤 수행해야 한다.
