# extra: 웹 오류 로그 오탐·VPN 미탐 감소 — v40/v40b

2026-11-13 · 무료 로컬 개발 비교. [v39 정상 웹 보정](extra-web-false-positive-reduction.md)과 기존 라벨·입력·모델·결과를 보존했다.
**웹 오류 정상 오탐4건을 제거했고, VPN 미탐은 자료별28건→0건으로 줄였다. VPN 정상 오탐이 늘어 정밀도는 아직 낮고 전체 F1은 소폭 감소한다.**
[전체 근거 JSON](infrastructure-results/extra-error-vpn-refinement-v40-20261113.json)에 두 후보·세 자료의 전체 혼동행렬·코드/입력/모델/시험 지문과 한계를 남겼다.

## 변경 이유와 구현

웹 오류 FP는 PHP `scandir`가 존재하지 않는 디렉터리를 읽는 경고였다.
경로·호스트·사용자·행 번호의 예외 목록 대신 `php숫자:warn` + `scandir` + ENOENT 문법에만 적용한다.
유효한 클라이언트/시각이 있고, 명령 실행·SQL·경로 탐색·민감 파일 등 공격 징후와
**같은 물리 로그/클라이언트의 엄격히 이전60초 보안 오류**가 없을 때만 경험 점수를 최대0.05로 제한한다.
다른 함수/심각도·파싱/시각/클라이언트 미상·공격 징후·최근 보안 오류는 기존 판단을 유지한다.
동일 시각의 기록끼리는 선행 근거로 쓰지 않는다. 경고 감소는 신원 신뢰나 접근 허용을 뜻하지 않는다.

VPN은 TLS 성공 문장만으로 정상·위협을 구분하기 어려웠다.
[v32 과거 접속 모델](extra-vpn-history-candidate.md)을 **재학습 없이 동결 재사용**하고,
원시 로그에서 프로필3의24시간 과거 이력을 다시 계산해 v39 점수와 큰 값을 취한다.
이름/IP/절대 시각을 학습 값으로 넣지 않고 IP/연결 해시는 내부 묶음 키로만 쓴다.
원시 SHA·행 번호 기반 case ID·코어 특징 SHA·VPN 특징 SHA를 대조한다. 별도 정답 파일은 평가기에만 들어간다.

v40b는 직전 위험을 인증 성공 문장으로 지우지 않게 보완했다.
**동일 물리 원본 + 정확한 IP:port**에서 엄격히 이전에 관측된 모델 점수0.95 이상을 최대60초 유지한다.
같은 시각 배치를 모두 질의한 뒤 그 배치의 새 관측을 추가하며, 유지된 위험 자체는 만료를 연장하지 않는다.
미상 시각/연결은 근거를 만들지 않는다. 연결 키는 인증된 사용자/기기 ID가 아니며 NAT·포트 재사용 혼합 위험도 남는다.
후보의 모든 결정은 `automatic_enforcement_allowed=False`이고 실제 차단·접근 허용·회수에 연결하지 않았다.

새 코드:

- `scripts/f1_lab/operation_context.py`, `operation_refinement.py`: 원시 근거 결속·오류 경고 보정·동결 VPN 재사용.
- `scripts/f1_lab/vpn_risk_retention.py`: 엄격한 과거 위험 유지·근거 case 참조·만료.
- `scripts/run_operation_refinement.py`, `run_vpn_risk_retention.py`: 모든 행의 이전/후보/검토 기준 비교.

## 웹 오류 로그: 같은0.95 기준

| 자료 | 정상 / 공격 | FP 이전→후보 | FPR 이전→후보 | TP 이전→후보 | FN 이전→후보 |
|---|---:|---:|---:|---:|---:|
| russellmitchell | 0 / 36 | 0→0 | —→— | 36→36 | 0→0 |
| santos | 2 / 42 | 2→0 | 100.0000%→0.0000% | 42→42 | 0→0 |
| fox | 2 / 1336 | 2→0 | 100.0000%→0.0000% | 1332→1332 | 4→4 |

정상0건인 R의 FPR은 정의되지 않는다. S/Fox 정상은 **각2행뿐이며 같은 원인의 연관 경고**다.
관측된4건의 정상 경고 제거를 일반적인 오류 로그 오탐률0%로 해석하지 않는다.
전체 오류 로그 공격1,414행의 기존 TP/FN은 유지했다. Fox의 기존 FN4는 해결되지 않았다.

## VPN: 같은0.95 경보 기준

아래 최종 후보는 v40b의 과거 위험 유지 방식이다. 세 자료가 비슷한 시나리오를 포함하므로84개 독립 공격으로 합산하지 않는다.

| 자료 | 정상 / 공격 | FN 이전→후보 | FP 이전→후보 | 후보 정밀도 | 후보 재현율 | 후보 F1 | 후보 FPR |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| russellmitchell | 5,509 / 28 | 28→0 | 0→60 | 31.8182% | 100.0000% | 48.2759% | 1.0891% |
| santos | 5,594 / 28 | 28→0 | 0→60 | 31.8182% | 100.0000% | 48.2759% | 1.0726% |

관측된 VPN 재현율은100%지만 정밀도/F1은95% 목표에 크게 못 미친다.
정상 오탐이60/60/88건 생겼다. **검토용 실험 후보로만 두며 운영/자동 차단 모델로 채택하지 않는다.**

| russellmitchell | 26 / 56 / 2 | 28 / 60 / 0 | 28 / 80 / 0 |

같은 기준에서 위험 유지는 마지막 위협2행과 정상4/4/6행을 추가한다.
기준을0.9로 낮춘 검토보다 정상 오탐은 적지만 여전히 많다.
0.9 검토 결과도 보존하며 더 나은 일반 성능으로 포장하지 않는다. 미래 로그로 앞선 행을 재분류하지 않았다.

## 전체 입력 비교와 채택 판단

기존과 같은1,259,637개 **물리 로그 행**을 전부 비교했다. 행을 독립 공격/세션 수로 해석하지 않는다.
입력·정답의 행 수와 파일 SHA, 원본 case 결속을 끝까지 검증했고 기존 v39 전체 점수 순서 SHA·혼동행렬을 재현했다.
웹 접근·감사·인증 등 비대상 원본은 이전 판단을 유지한다.

| 자료 | 전체 행 | FP 이전→v40b | FN 이전→v40b | 전체 F1 이전→v40b | 전체 FPR 이전→v40b |
|---|---:|---:|---:|---:|---:|
| russellmitchell | 295,243 | 25→85 | 1029→1001 | 99.1411%→99.1157% | 0.0107%→0.0364% |
| santos | 295,976 | 21→79 | 975→947 | 98.9379%→98.9070% | 0.0084%→0.0318% |

VPN 미탐 감소보다 추가 오탐이 많아 **전체 micro F1은 이전보다 낮아졌다**.
웹 오류 보정의 효과와 VPN 검토 후보의 상충 관계를 분리해 판단한다.
`app/`·PDP/LLM/권한 집행·기존 benchmark는9c67889와 같고 운영 적용은 하지 않았다.
R/S/Fox는 반복 관찰한 개발/보정 자료다. 예약 harrison/wilson 본문은 읽지 않았다.
원래 여섯 영역의 새 독립 최종 평가와 목표 완료를 대신하지 않는다.

## 로컬 시험과 재현

- v40 Windows F1 관련 **714개**, network none Linux 전체 **3534개** 통과.
- v40b 추가 후 Windows/Linux 집중 **각47개** 통과. 이 중32개는 앞선 묶음과 중복이며 두 스냅샷을 한 번의 전체 실행으로 합산하지 않는다.
- 좁은 경고 문법·인코딩 공격 징후·미상 근거의 기존 경보 유지, source/case/core/모델/정책 변조 거부,
  같은 시각/미래 정보 차단·연결/서버 격리·60초 경계·자기 만료 연장 금지를 검사했다.
- Linux는 캐시 이미지 고정·network none·읽기 전용 root·비root·cap drop·메모리/프로세스 제한으로 실행했다.
  두 스냅샷 바이트 불변·OOM false·정확히 소유한 시험 컨테이너 제거를 확인했다.
- 실제 데이터 실행은 v40 170.585초, v40b 191.322초다.
  fixture 테스트 컨테이너에는 실제 자료/키를 넣지 않았으며 데이터 비교 실행과 구분한다.
- AWS·유료 API·GitHub push0. 기존 모델을 재사용했고 추가 다운로드는 없었다.

로컬 자료가 있는 환경에서 새 출력 폴더로 재현한다. 줄바꿈은 저장소 LF 계약을 따른다.

```powershell
.venv\Scripts\python.exe -m scripts.run_operation_refinement `
  --plan infra/f1-lab/operation-refinement-protocol.json `
  --expected-plan-sha256 f7fd853011b6eb6d3fa07d95146e6c8e774bf13395fb027c16961eb6813ce629 `
  --output runtime/f1/operation-repro-new

.venv\Scripts\python.exe -m scripts.run_vpn_risk_retention `
  --plan infra/f1-lab/operation-refinement-protocol.json `
  --expected-plan-sha256 f7fd853011b6eb6d3fa07d95146e6c8e774bf13395fb027c16961eb6813ce629 `
  --prior runtime/f1/operation-refinement-v40-20261113/run.json `
  --expected-prior-sha256 87136d908635bfcb891c7ed4c1373db24be93185358e21b92c961f685674da2c `
  --output runtime/f1/operation-retention-repro-new
```

두 번째 명령은 보존된 v40 receipt를 사용한다. 첫 명령으로 새 receipt를 만들었다면 그 경로와 실제 SHA를 명시한다.
`load_operation_refinement`에 정책/웹/기준선/VPN 기대 SHA를 넘겨 복원하고 `RiskRetention`으로 감싼다.
시각·원본 결속 문맥은 `retained_contexts`로 만들며 결과는 검토용 위험 신호다.

## 남은 개선

웹은 새로운 정상 오류 자료와 경로/실행 공격 반례를 더 확보해 좁은 예외의 일반화를 확인한다.
VPN은 인증된 IdP/MFA 결과·기기 상태·계정 권한·실제 세션과 연결되는 선행 보안 신호가 필요하다.
원시 IP/이름을 권한 증명으로 쓰거나 정상과 같은 문장을 가진 위협을 임의로 정상 처리하지 않는다.
기존 정상 웹 잔여 오탐·감사/인증 미탐, 원래 여섯 영역의 독립 관측/정답·분할과 운영 인수도 남는다.
