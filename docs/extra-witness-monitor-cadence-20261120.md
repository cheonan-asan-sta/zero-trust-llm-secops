## 재현한 문제

기본 관측 주기는60초인데 기존 집계 TTL이 고정30초였다. 정상 관측 후45초는 다음 관측 전이고 서명 유효 기간180초 이내지만, exporter는 상태 불가로 표시했다. 실제 제어 시각 시험에서 status_success1을 기대한1건이 실패했다. 초기의1초 간격 기능 시험만으로 기본 주기의 간격 문제까지 확인하지 못한 것이다.

또 정상 수집 사이에 새 행이 생기거나 짧은 pending이 존재하면, 그 사실을 `healthy=false`로 표시하는 것과 즉시 critical 경보를 발생시키는 것은 다른 운영 판단이다. 미확인 행/작업을 정상 관측으로 바꾸지 않고, 실제 수집 실패와 허용 시간을 넘긴 미관측/작업 지연을 구분했다.

## 변경한 계약

새 producer는 `zt-witness-observer-status-2`에 고정한 프로필의 interval을 포함한다. reader는 interval1~3600초, max_age≥2×interval 정책을 다시 확인하고 캐시 TTL을 **max(30초, 2×interval)**로 계산한다. 기본값에서는120초이며 서명 관측의 만료180초와 별도로 검사한다. 최대 설정에서도 유한한7200초다. 실제 관측 시각은 그대로이며 새 조회로 서명을 갱신하지 않는다. 캐시가 이 한계를 넘으면 예전 counter 없이 상태 불가로 표시한다.

`observation_healthy`와 원래 state/미관측 수는 그대로 표시한다. 별도 `observation_action_required`는 운영 경보 판단용이다.

| 상태 | 표시/경보 기준 |
|---|---|
| 정상 주기의 미관측 행 | unobserved·healthy0 유지. 원래 서명의 max_age를 넘기면 critical |
| 짧은 pending | pending·healthy0 유지. pending이2주기를 넘거나 원래 관측이 만료되면 critical |

| 용량 압박/고갈 | 압박은 warning, 고갈은 critical 판단도 함께 적용 |
| 시각 역행·알 수 없는 witness 전진·불가/미검증 상태 | 경계 거부와 critical 판단 유지 |

이 값으로 데이터 신뢰/접근 권한을 부여하지 않는다. 미관측을 서명 완료로 계산하지도 않는다. 변경은 운영 경보의 시간 예산이며 정밀도/재현율/F1 평가의 판정/정답/분모를 바꾼 작업이 아니다.

새 reader는 v1 집계도 읽되 v1에는 기존30초 한계를 유지한다. 같은 외부 pin과 단조로운 checked_at이면 v1→v2 게시 형식을 전환할 수 있다. 새 필드를 v1이라고 넣으면 거부한다. **reader/규칙을 먼저 업데이트한 뒤 v2 producer를 적용**해야 하며, 이전 reader는 v2를 거부한다. 새 경보 규칙은 새 action metric이 없는 이전 exporter에는 기존 healthy0 판단을 유지해 조용히 경보가 사라지지 않게 했다. profile/최소 pin을 자동 교체하지 않는다.
