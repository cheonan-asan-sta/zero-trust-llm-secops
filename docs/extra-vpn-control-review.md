# VPN 제어 메시지의 인과적 관측으로 잔여 오탐 개선 — v114

2026-11-16 · 채희주 담당 · 무료 로컬 · 전체 목표 active · 목표 전 push·새 CI·병합 보류

원래 1,681,815행의 동일 모집단 비교에서 VPN **FP 48→42, TP 84/FN 0 유지, 정밀도 63.64%→66.67%, F1 77.78%→80.00%**를 확인했다. 별도 Harrison·Shaw·Wheeler VPN도 오탐이 각각 2건 감소했다. 모든 묶음에서 새 FP·기존 TP 손실·추론 오류는 0이다. 인증·웹 감사의 관측 100%와 이전 Wheeler 미탐 개선도 보존했다. 전체 목표는 여전히 미달이며 새 독립 평가가 아니다.

## 어떤 근거로 바꿨는가

잔여 오탐을 기존 모델 셀로 분해했다. 초기 TLS·발급자·KU/EKU 관측은 실제 정상과 위협이 섞여 있어 공격 veto를 해제하지 않았다. 한편 일부 정상 PUSH 요청/응답 셀은 정상 지지가 4건으로, 최소 5를 충족하지 못했다. 이 문제를 표본 복제나 기준 완화로 해결하지 않았다.

새 [관측·보충 모델](../scripts/f1_lab/vpn_control_review.py)은 같은 출처·같은 연결의 앞선 TLS initial·leaf VERIFY OK·KU·EKU 기록이 모두 있는 **이름이 붙은 PUSH 제어 메시지**만 다룬다. 로그에 기록된 단계 완료를 관측할 뿐 실제 사람·기기 상태·현재 권한을 검증한 것으로 해석하지 않는다. 프로토콜 관측은 현재/이전 물리 행만 사용하며 다음 행의 인증 정보를 앞선 초기 패킷에 붙이지 않는다.

클라이언트의 OS/버전 주장과 정확한 위험 점수/경과초, 문자열 길이를 새 학습 특징에서 제외했다. 대신 제어 단계, 앞서 관측한 TLS 단계, 인증서 주체의 앞선 peer 관측 관계 등 제한된 불리언을 사용한다. IP·port·이름·CN은 출처 내부 관계를 확인하는 데만 쓰며 원래 값을 학습하지 않는다. 이 일반화는 본 프로젝트의 설계 선택이며 OS가 같다는 이유로 기기를 신뢰하지 않는다.

[OpenVPN 제어 코드](https://github.com/OpenVPN/openvpn/blob/master/src/openvpn/push.c)와 [공식 2.6 설명서](https://openvpn.net/community-docs/community-articles/openvpn-2-6-manual/)를 메시지/옵션 형식의 참고 근거로 삼았다. 정해진 PUSH_REQUEST와 성공 상태의 PUSH_REPLY만 파싱하고 요청/응답을 별도 셀로 유지한다. 응답 이름 불일치, 실패 상태, 중복/미지원 옵션, 잘못된 IP/넷마스크·숫자, shell 모호성은 보정하지 않는다. 지원 옵션 목록은 파서 범위이며 실제 라우트의 업무 승인 목록이 아니다.

이전에 선언한 R/S/Shaw/Wheeler 학습 라벨만 사용해 새 head를 적합했다. 평가 역할의 Fox/Wardbeck/Harrison을 학습으로 바꾸지 않았다. 실제 학습 제어 기록은 946행(정상 936·위협 10)이며 요청/응답은 각각 별도로 센다. 관측한 6개 셀 중 요청/응답별 두 순수 정상 유형의 지지는 각각 14 또는 441건, 혼합 유형은 각 정상 13·위협 5건이다. 혼합 셀은 정상 수가 많아도 완화하지 않는다. 이는 946개의 독립 접속/공격이라는 뜻이 아니며 같은 접속의 단계·갱신 기록이 포함된다.

새 모델도 **최소 정상 지지 5, 학습 공격 한 건이라도 있으면 완화 금지**다. 이전의 기본 탐지 점수 0.95 이상, 현재 명시적 거부, 독립 공격 근거와 실제 인증/TLS/인증서 실패를 보존한다. 실제 실패를 60초간 보호하는 기존 경계도 그대로다. 성공 메시지·PUSH·port 변경으로 실패를 지우거나 기산점을 연장하지 않는다. 현재 거부/독립 판정과 맞지 않는 기준선은 그대로 남긴다.

경보를 낮춘 뒤에도 검토 상태를 유지하며 자동 차단·접근 허용·신뢰 부여를 하지 않는다. `--profile vpn-control`과 명시적 보충 모델로만 실행하고 운영 기본 탐지기는 변경하지 않았다. v109 기본 가중치와 v110 공격 근거 연결은 보존했다.

## 실제 검증

Linux 집중 회귀 **776건 통과**, 실패/skip 0, Ruff+RUF100 통과다. 새 제어 시험 43건과 추가 staging 시험 1건은 불완전/다른/재시작/만료 연결, 식별자·OS 주장·절대 시각의 비학습, 요청/응답 지지 분리, 4/5 경계·공격 veto, 실제 실패 60/61초, 현재 거부·기본 고위험 보존, 원문/source/행 결속, 잘못된 옵션, 모델 pin/계수/최소 지지 변조, 기본 비활성, 기존 오류·모집단 보존을 확인한다. 이 시험 통과율을 탐지 F1에 합산하지 않는다.

## 남은 목표

VPN은 TP 84를 유지할 때 정밀도 95%에 도달하려면 FP 4 이하가 필요하다. 현재 42건으로 38건을 더 줄여야 한다. 초기 단계의 정상/위협 혼합 셀을 이번 모델로 일괄 정상화하지 않았다. 별도 Wheeler FN 9와 공유 감사 TP 0/FP 3/FN 6도 남는다. 과거 사건의 미확인 실행 주체·기기/권한을 나중의 자료로 채우지 않는다.

이미 관측한 개발·보정 자료의 개선이며 원래 6개 보안 영역의 새 독립 인수는 미완료다. 전체 목표를 달성한 것으로 보고하거나 전체 종료 시각을 확정하지 않는다. 유료 API/AWS·새 CI·push·병합·장기 soak는 0이며 이번 작업에서 기존 운영 systemd/mTLS 인수를 재실행하지 않았다.
