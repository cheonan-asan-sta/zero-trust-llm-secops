# 실제 SSH·sudo 감사 기록을 이용한 웹 감사 오탐 개선 — v113

2026-11-16 · 채희주 담당 · 무료 로컬 · 목표 active · 목표 충족 전 push·새 CI·병합 보류

원래 1,681,815행을 그대로 비교해 웹 감사 **FP 15→0, TP 47/FN 0 유지, 정밀도 75.81%→100%, F1 86.24%→100%**를 확인했다. 별도 Wilson 학습·Wardbeck 비학습 보정 자료도 웹 감사 FP가 각각 10→0이며 기존 TP 22/19와 FN 0을 유지했다. 모든 묶음에서 새 FP·기존 TP 손실·추론 오류는 0이다. 이 결과는 이미 관측한 개발·보정 자료의 전후 비교이며 새 독립 평가나 전체 목표 달성이 아니다.

## 실제로 수집한 근거

기존 정상 로그 조회 흐름은 sudo 단계마다 정상 학습 지지 2건뿐이었다. 최소 지지 5를 낮추지 않고, 소유한 Ubuntu QEMU 게스트에서 별도 8개 SSH 세션으로 실제 `sudo -n /usr/bin/tail /var/log/syslog`를 실행해 커널·auditd가 생성한 기록을 수집했다. 8개 세션 모두 SSH/sudo 종료 0, 서로 다른 실제 sessionid, uid=loginuid=1000과 TTY 관측을 확인했다. 세션 생성 이전부터 게스트의 제한된 sudoers 정책으로 허용한 정상 작업이다.

총 **169개 물리 행·45,441바이트를 수정 없이 보존**했다. 이 중 인과 문맥을 만족한 48행(SSH 로그인 8행과 sudo 5단계 각 8행)을 학습에 사용했다. sudo 단계별 정상 지지는 2→10, 공격 지지는 0, 최소 지지 5와 학습 공격 한 건이라도 있으면 완화하지 않는 veto는 유지했다. 같은 8개 작업의 단계별 기록이므로 48개 독립 작업이나 독립 공격으로 세지 않는다. 추가 169행은 통제된 정상 학습 자료이며 원래 성능 분모에 더하지 않는다.

WSL 커널 감사 조회가 권한 오류를 반환해 호스트 설정을 바꾸지 않고 게스트 전용 커널을 사용했다. 도구 설치 후 외부 컨테이너 네트워크를 끊고 `lo`만 남긴 상태에서 수집했다. 앞뒤 부팅 ID·UTC·정책 지문이 같고 audit lost=0이다. QEMU 게스트는 종료했고 소유 컨테이너도 제거했다. 클라이언트 개인키는 컨테이너 tmpfs와 함께 제거됐지만 게스트 SSH 호스트키는 로컬 비공개 테스트 디스크에 남을 수 있다. 이 디스크나 개인키를 Git 자료에 포함하지 않는다.

게스트는 [Ubuntu 공식 이미지](https://cloud-images.ubuntu.com/noble/current/)의 20261017 빌드와 [공식 SHA256SUMS](https://cloud-images.ubuntu.com/noble/current/SHA256SUMS)를 HTTPS로 받아 SHA를 대조했다. GPG 서명 검증은 하지 않았으며 수집 영수증은 로컬 제어기가 기록한 것으로 독립 검토나 하드웨어 원격 증명이 아니다. [게스트 수집 코드](../infra/f1-lab/native-audit/)와 [실제 원문·정상 라벨·영수증](../infra/f1-lab/native-audit/captured-v113/)을 함께 보존한다.

## 실환경 형식 차이를 처리한 방법

실제 auditd ENRICHED 행에는 원본 뒤 ASCII GS(0x1D)와 UID/AUID의 표시용 이름이 붙는다. [공식 enrichment 명세](https://github.com/linux-audit/audit-documentation/wiki/SPEC-Audit-Event-Enrichment)에 따라 의미 해석은 앞쪽 원본 필드만 사용하고, 전체 원문 바이트·지문·물리 행 수는 보존한다. 표시용 계정 이름으로 원래 uid/auid를 덮어쓰지 않는다. GS도 줄바꿈으로 나누는 `str.splitlines()` 대신 실제 newline 기준 입력을 유지한다.

현대 sudo의 PAM 행은 uid가 호출 사용자이고 대상 acct가 root일 수 있다. 기록된 uid를 0으로 고치지 않고, 같은 PID/TTY/보고 session의 실제 sudo·root 대상·성공 PAM 흐름을 조건으로 **관측된 대상 역할**을 표현했다. USER_CMD에 exe가 없는 구형 형식은 명령 요청 역할로 처리하며 누락된 실제 실행 파일을 만들어 넣지 않는다. 명시된 exe가 다른 경우나 uid가 일관되지 않는 경우는 이 완화에 사용하지 않는다. 원래 필드와 확인 불가 상태는 그대로 남는다.

특징 버전은 `causal-audit-operation-role-2`다. [보충 모델](../infra/f1-lab/frozen-audit-native-normal-v113/)은 R/S/Wilson/Shaw/Wheeler 학습과 이번 실제 정상 자료로 다시 적합했다. Fox/Wardbeck/Harrison을 학습으로 바꾸지 않았다. 구체적인 사용자 ID·session 값·IP·호스트 이름·절대 날짜를 예외 목록으로 학습하지 않는다.

이 결과는 검토용 경보의 정상 문맥 판단이다. 현재의 명시적 거부·독립 위험 근거를 보존하고 사람 신원·프로세스 부모·현재 권한을 증명하거나 접근을 허용하지 않는다. 운영 기본 탐지기는 바꾸지 않았으며 명시적 `audit-native-normal` 프로필과 보충 모델 pin으로만 적용한다. 직전 v112의 방화벽 위험 문맥도 유지한다.

## 검증과 한계

Linux 집중 회귀 **732건 통과**, 실패/skip 0, Ruff+RUF100 통과다. 실제 캡처 intake·소스 SHA·격리·8세션·lost 0·169행 보존, ENRICHED/GS, 원래 uid 보존, 잘못된 exe/uid 거부, 보충 모델 기본 비활성·쌍 pin, 기존 거부 보존과 v112 위험 관측 유지 등을 확인했다. 잘못된 Git 실행 모드 때문에 첫 Linux Ruff 실행이 실패한 기록도 남겼고, 실행 모드를 고친 새 실행에서 통과했다. 실패한 실행을 통과로 덮어쓰지 않았다.

성능 예측 컨테이너는 network none·UID10001·read-only root로 실행하고 이미지 안의 기존 프로젝트 자료를 차단했다. 평가 정답/집계와 새 정상 원문/라벨은 넣지 않고 동결 모델의 학습 계수만 제공했다. 예측 봉인과 소유 컨테이너 제거 후 호스트에서 정답을 결합했다. 원문·정답·모집단·기준은 유지했고 source/입력 지문 불변 및 기능 시험과 예측 코드 지문 일치를 확인했다. 포함한 영수증·원문으로 오프라인 재섭취해 기존 preparation/truth 지문도 재현했다.

## 남은 작업과 시간 전망

공유 감사는 TP 0/FP 3/FN 6·F1 0%, VPN은 TP 84/FP 48/FN 0·F1 77.78%로 여전히 미달이다. 별도 Wheeler 학습 VPN FN 9, Harrison 별도 VPN FP 38도 남아 있다. 원래 6개 보안 영역의 독립 인수·새 정상/위협 자료 검증은 별도 미완료다. 공유 감사의 사건 당시 실행 주체/명령과 VPN의 당시 기기/권한 근거가 없는 부분은 확인 불가로 유지한다.

이번 v113 구현·기능 시험·전후 채점은 완료했다. 전체 목표 완료 시간은 남은 근거 확보와 후보의 실제 전후 검증에 달려 있어 확정하지 않는다. 단순 테스트 실행 시간과 목표 수치 달성 시간을 구분한다. 전체 목표 전 push·새 CI·병합은 보류하며 AWS·유료 API·장기 soak는 실행하지 않았다. 기존 운영 systemd/mTLS 인수를 이번에 다시 수행한 것으로 보고하지 않는다.
