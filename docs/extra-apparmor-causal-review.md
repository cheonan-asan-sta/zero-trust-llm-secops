## 오탐 원인과 구현

남은 공유 감사 오탐은 AppArmor의 실제 프로필 교체 STATUS와 인자 설명 기록이었다. `profile_replace`는 실제 정책 변경이며 승인이나 무해함을 보증하지 않는다. 기존 [변경 없음 관측](../scripts/f1_lab/apparmor_noop.py)의 `same as current profile, skipping` 조건을 완화하지 않았다.

[새 관측기](../scripts/f1_lab/apparmor_causal_intent.py)는 같은 원본 SHA·연속 물리 행·정확한 audit UTC 시각의 현재/이전 기록만 읽는다. 현재 PROCTITLE에는 이미 관측한 동일 audit 시각/serial의 AVC·성공한 parser SYSCALL을 결속하고, NUL 경계를 보존해 parser·replace 옵션·표준 설정 경로를 검사한다. 현재 AVC에는 같은 PID에서 **앞서** 완성한 parser 실행 관측이5초 안에 있을 때만 문맥을 제공한다. 상태 기록만으로 기산점을 갱신하지 않는다.

첫 AVC의 명령은 뒤의 SYSCALL/PROCTITLE로 소급하지 않아 호스트별 첫 오탐1건이 남는다. 다른 PID/source,5초 만료, 시간 역행/불일치, 원문/순서 오류, 부팅, 중복 사건, 다른 실행 파일 관측은 연결을 끊는다. PID·comm·로그 실행 파일 경로는 관측 연결 정보이며 PID 재사용을 막는 커널 시작 tick이나 실행 파일 무결성·실제 사람 신원 증명이 아니다.

[학습된 고정 표](../infra/f1-lab/frozen-apparmor-causal-v111/bundle.json)는 기존에 명시한 R/S/Wilson/Shaw/Wheeler 학습 자료의 실제 라벨을 사용한다. 원본 이름·계정·PID·시각·프로필 파일명을 학습 값으로 넣지 않는다. 정상 지지5행 이상·공격 관측0 셀만 일반 보조 경보를 낮추고, 공격1행이라도 있으면 낮추지 않는다. changed/unchanged 상태와 AVC/PROCTITLE을 다른 셀로 유지했다. 현재 changed 상태의 지지는 AVC15/공격0, PROCTITLE20/공격0이며, 행들이 독립된 승인20건이라는 뜻이 아니다.

검토를 유지하고 자동 집행·접근 허용을 하지 않는다. 현재 명시적 거부나 별도 위험 이유가 있는 판정은 보존한다. 낮춘 점수는 보정된 공격 확률이 아니다. 프로필 본문/별도 승인을 확인한 것으로 주장하지 않는다. 운영 기본 탐지기나 팀원 앱 대신 명시적 로컬 CLI 옵션으로 연결했다.
