# 조건부 후보 C05~C09 범위 제안

2026-11-12 · 현재 프로젝트의 구현/요구를 기준으로 작성한 제안이며 팀의 최종 채택 승인이 아니다.
새 제품 설치·우열 실측·최신 제품 기능 조사를 이번 변경에서 수행하지 않았다.
원래 후보와 비교 계약은 [기술 비교 계획](../technology-selection-plan.md)을 유지한다.

| ID | 현재 제안과 근거 | 실제 비교 여부 / 재개 조건 | 직접 결정할 사람 |
|---|---|---|---|
| C05 기기 수집 | 서명된 로컬 수집 경로 유지. osquery 등 호스트 센서 추가는 보류 제안. 서명 출처와 실제 기기 안전 증명은 구분 | 새 센서 비교 미실행. 실제 수집할 질문·대상 OS·관측 권한·기기 매핑·보관 범위가 정해지면 격리 시험 | 채희주가 수집/인프라 범위, 김택희가 신호 입력·누락 계약 |
| C06 브로커 | 기존 내구 수신함·worker 유지 제안. 중복/재시도/처리 상태의 현재 계약을 먼저 독립 인수 | NATS/RabbitMQ 새 비교 미실행. 여러 호스트/처리기 확장이나 현재 큐의 측정된 한계가 요구로 확인되면 공통 장애 시험 | 채희주가 배포/부하 요구, 김택희가 수신·저장 원자성/중복 의미 |
| C07 앱 상태 DB | 현재 로컬 앱 SQLite 유지 제안. CA가 사용하는 PostgreSQL과 앱 저장소를 혼동하지 않음 | 앱 PostgreSQL 전환 비교 미실행. 동시 writer·다중 앱 호스트·실제 잠금 한계가 요구되면 이행/복원/회수 계약 비교 | 채희주가 환경/복구 기준, 김택희가 저장·버전/일회 소비 일관성 |
| C08 IdP | OIDC 검증·모의 재인증을 현재 로컬 경계로 유지하고 실사용 IdP 연결은 별도 운영 인수로 남김 | Keycloak/authentik/기존 IdP 새 실연동 미실행. 실제 조직·MFA/재인증·issuer/audience·그룹/tenant 매핑이 확정되면 비교 | 팀장이 운영 포함 여부, 앱 담당이 토큰·세션/회수 계약 |
| C09 정책 도구 | 현재 코드·정책 파일 유지 제안. 새 엔진이 기존 세션 상태·grant 단일 소비·회수를 대신한다고 표현하지 않음 | OPA/Cedar 새 공통 실측 미실행. 정책 배포 분리·복수 서비스·관리 변경 요구가 확인되면 작은 동일 정책부터 비교 | 채희주가 정책 운영 경계, 김택희가 판단·오류·버전 계약 |

각 항목을 ‘비교 완료’로 처리하지 않는다. 팀이 유지/보류를 확정하면 결정자·일자·수용한 공백·재검토
조건을 기록한다. 도입하지 않기로 결정하는 작업과 제품 간 실제 비교는 구분한다.
C01~C03은 원래 필수 실제 비교를 유지하고 C04의 운영 조건/독립 인수도 남는다.
