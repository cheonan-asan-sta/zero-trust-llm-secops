# 4주차 잔여 작업과 직접 확인할 일

2026-11-12 · 기준 로컬 커밋 `e55e65c`와 이후 이 문서에 연결된 변경.
여기서 4주차는 원래 11/23~11/29의 **독립 통합 평가·기능 동결 단계**다.
실제 학사 주차나 모든 작업의 완료율을 뜻하지 않는다. 전체 회귀 통과로 독립 인수를 대신하지 않는다.

후속 품질 작업은 [F1 목표 달성 실험 계획 F0~F6](f1-improvement-plan.md)을 따른다.
현재 잔여 기능/데이터 인수 기반을 먼저 확보하고 개선 후보를 별도로 검증한 뒤 최종 동결에 반영한다.
이번에는 계획만 추가했으며 탐지 규칙·임계값·라벨은 그대로다.

## 채희주가 직접 할 일: 우선 네 가지

1. **범위와 운영 기준 결정:** 로컬 학술 MVP의 인수 범위, 목표 부하, RTO/RPO, 실제 AWS/IdP/EDR 검증의 포함 여부를 정한다. 배포를 지금 해야 한다는 의미는 아니다.
2. **팀원에게 독립 인수 배정:** 김택희에게 R1·R2·R4·R7을 전달한다. 검토 명령을 직접 실행하고 기대/실제·검토자·시각·불일치를 남기게 한다. 내가 대신 ‘김택희 검토 완료’를 적을 수 없다.
3. **모델 비교 실행 조건 결정:** R3의 후보와 작업별 목적, 공통 표본, 예산·외부 전송 허용을 확정한다. 현재 무료 로컬 지시를 유지하므로 새 유료 호출은 실행하지 않는다. 키를 문서나 채팅에 붙이지 않는다.
4. **멘토 확인과 최종 판단:** R8·R9의 제안을 확인받고, 품질 목표 미달·미측정·보류를 포함해 최종 기능 동결/제출 범위를 승인한다.

구현·Docker 명령·자료 복사를 전부 직접 할 필요는 없다. 인프라 실행/측정은 기존 채희주 담당을
Codex가 보조하며, 다른 팀원의 앱 구현/독립 검토 성과로 바꾸어 기록하지 않는다.

## 현재 확정된 수치와 구분

이전 묶음은 Linux 전체2,749, 관측75, 선정37, 앱 복원13, 후속 집중57 및 DB/백업25가 통과했다.
서로 다른 실행·소스를 합쳐 하나의 전체 성공이나 팀원 독립 검토로 계산하지 않는다.
후속 변경은 [승인 원장 복원](response-workflow-recovery.md)의 Windows 로컬181개 통과로 별도 기록한다.
빈 M7 검토지48건·M8 범위안·조건부 후보 제안·기존 탐지 오류14계열 집계까지 준비했다.
시험 원자료·코드 지문은 [후속 공개 결과](infrastructure-results/week4-followup-20261112.json)를 따른다.
holdout360의 정밀도64.29%·재현율50%·F1 56.25%·오탐률27.78%는 **Sigma 탐지 기준선**이다.
이번 후속은 규칙·임계값·평가 라벨을 바꾸지 않으며 이 수치를 LLM 성능으로 부르지 않는다.

이전 문서에서 M8을 ‘동결·보고·인수’로 쓴 것은 번호 연결 오류였다.
M8의 원래 의미는 네트워크 트래픽 범위 판단이고 최종 동결은 R10의 단계 종료 절차다.
