# 감사·인증 로그의 과거 관측 연결 — v67

2026-11-14. PR60 병합 aitest `34157ee` 기준에서 기존 오프라인 v62 예측을 유지하면서,
명시적 웹 서비스 계정 전환과 그 직후 감사 기록을 연결했다.
**개발 비교에서 미탐15행 감소·새 오탐0·기존 TP 손실0·추론 오류0**을 확인했다.
공유 서버 감사는 근거가 부족해 개선하지 못했다. 세 항목 모두의95%/5% 목표 달성으로 기록하지 않는다.

## 구현한 관측과 제한

- `su` 전용 syslog 문법의 성공 메시지 또는 성공 표식에서 고정 정책의 서비스 계정 이름
  (`www-data`, `apache`, `nginx`, `httpd`)이 다른 계정으로 전환한 사실을 보조 경보로 표시한다.
  문자열은 보고된 관측값이며 검증된 업무 역할·권한 위반 판정은 아니다. 정당한 운영 전환도 일치할 수 있다.
- 동일 호스트의 정확한 auth/audit 파일 짝만 연결한다. audit의 성공한 `USER_AUTH`가
  정확한 su PID·대상 계정 및 엄격한 과거 auth 관측과 일치해야 문맥을 시작한다.
- 최초 auth 관측부터5초만 유지하며 반복 메시지로 연장하지 않는다. 이후 명시된 같은 계정의
  systemd 계정/자격/세션 기록, 이전에 관측한 같은 PID의 LOGIN, 명시된 UID와 일치하는 user-manager 시작만 연결한다.
- 같은 시각을 과거 프로세스 증거로 쓰거나, PID가 이웃한다는 이유로 부모/자식 관계를 만들지 않는다.
  미상 시간·시각 역행·다른 호스트·다른 계정·재사용 PID·unset auid/session은 근거를 차용하지 않는다.
- 누락된 승인/MFA/기기 건강을 채워 넣지 않는다. 원래 경보와 오류 행을 유지하고,
  새 후보가 기존 경보를 낮추거나 접근 허용·권한 회수·자동 차단을 실행하지 않는다.
- 공유 서버의 짧은 서비스 이름이나 START/STOP 자체를 악성으로 분류하지 않는다.

구현은 [관측기](../scripts/f1_lab/audit_auth_review.py)와 [재현 CLI](../scripts/run_audit_auth_review.py)에 있다.
입력 원본·준비·기존 예측의 SHA와 물리 행 순서·사례 ID를 대조한다. 모든 출처의 예측을 봉인한 뒤 정답을 읽는다.
정답·공격 일정·IP/대상 계정의 실제 값은 학습 특징이나 허용 목록으로 쓰지 않았다. 학습 모델을 다시 맞추지 않았다.

## 남은 오류와 공유 서버의 추가 확인

- 공유 서버는 TP0·FP24·FN6을 그대로 유지했다. 원래 위협 라벨6행은 주체가 unset인 systemd START/STOP이다.
  캐시 배포본에서 추가 auth/syslog 멤버와 직접 서비스 설정18개도 확인했다.
  해당 사용자 정의 unit의 설정에는 root 실행 계정과 실행 파일 경로가 있지만, 호출 주체·실제 실행 내용·당시 승인 여부는 없다.
  수집된 설정의 mtime은 사건 당시 수집·검증 시각의 증명이 아니므로 예측에 소급 적용하지 않았다.
  추가 로그 본문·실행 파일·비밀 설정을 이번 후보 특징으로 사용하지 않았다.
- 웹 감사의 남은1행은 동시각 프로세스 연결 근거가 부족한 LOGIN이다. 인접 PID나 미래/동시각 근거로 채우지 않았다.
  기존 FP37도 남아 있어 정밀도와 F1 목표는 미달이다.
- 인증의 남은3행은 보고된 PID/계정 결속이 부족한 root PAM 세션 열기다.
  F1은95.08%지만 재현율90.625%·미탐률9.375%라 전체 목표는 미달이다.
- 다음에는 공유 서버의 수집 시각이 검증된 unit/실행 파일 관측과 SYSCALL/EXECVE·부모 프로세스,
  인증 세션·현재 업무 승인 근거를 연결해야 한다. 새로운 정상 업무 자료와 별도 출처 검증도 필요하다.
