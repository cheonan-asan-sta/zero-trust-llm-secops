후속 [v39 정상 웹 오탐 감소](extra-web-false-positive-reduction.md)에서 같은 입력의 Fox 웹 FP483→12,
S116→7을 기존 위협 탐지/비HTTP 점수 유지와 함께 확인했다. 아래는 변경하지 않은 v37~v38 기록이다.

2026-11-12 · v37~v38. 공간 확보 후 사용자 지시에 따라 로컬 작업을 재개했다. 이전 17:11 KST 종료 시각은 이번 재개에 적용하지 않는다.

**중단됐던 Fox 전체 평가를 완료했다. 원래 여섯 영역의 새 독립 최종 목표 달성은 미완료다.**
[전체 근거 JSON](infrastructure-results/extra-streaming-calibration-v37-v38-20261112.json)에 소스·입력·모델·실행·시험 지문을 보존했다.

## 구현한 변경

- `scripts/prepare_native_stream.py`: 기본 입력 캐시를 다시 저장하지 않고 원시 파일을 한 번 읽어 특징·정답·참조를 분리한다. 기본 입력은 같은 바이트의 SHA-256만 계산한다.
- HTTP의 클라이언트·대상 해시·상태·시각을 SQLite에 저장하고 인덱스로 `(event_time, 원래 행 번호)` 순서를 재생한다. 시각 미상은 뒤에 두며 원래 출력 행 순서는 유지한다.
- `scripts/f1_lab/streaming_context.py`: 1·10·60초 큐와 증분 카운터로 시간창을 계산한다. 현재 요청을 포함하고 경계 시각을 포함한다. 클라이언트/과거 큐 전체를 매 요청마다 재순회하지 않는다.
- 누적 요청 10만 건 상한을 데이터 삭제로 우회하지 않았다. 전체 행 수·DB·출력·활성 요청·클라이언트·디스크 여유 공간을 각각 제한하는 별도 경로다.
- `scripts/run_native_stream_validation.py`: R/S 동일성 확인 후 Fox 전체를 두 고정 모델로 비교한다. `scripts/diagnose_native_scores.py`는 고정 점수/임계값·오류 벡터를 분석하며 모델을 재학습하거나 임계값을 자동 채택하지 않는다.
- 실패한 시도는 완료로 재사용하지 않는다. 이전 실패 증거를 보존하고 같은 해시의 원본에서 새 출력 폴더로 재실행한다. 자동 이어붙이기 복구는 지원하지 않는다.

SQLite 페이지 캐시는 16 MiB, DB 상한은 4 GiB, 출력은 8 GiB, 최소 여유 공간은 5 GiB다. 사전 검사는 DB와 rollback journal까지 합쳐 21 GiB를 요구한다. Python 전체 메모리가 16 MiB라는 뜻은 아니다.
활성 HTTP 요청은 전체 500,000개·클라이언트 10,000개·클라이언트당 100,000개 한도다. 인증 이력의 기존 100,000행/64 MiB 한도는 유지했다.

## 시험과 실패 이력

- Windows F1 묶음 635개 통과. 작은 스트림 시험의 자원 예산 보완 후 변경된 15개를 다시 통과했다.
- 최초 Linux 전체는 3,450통과/5실패였다. 2 GiB tmpfs의 작은 시험에 기본 21 GiB 사전 예산을 사용한 원인이었다. 10행 기능 fixture에만 DB/출력/여유 각 1 MiB를 명시했다. 실제 준비기의 기본 안전 한도는 유지했다.
- 그 수정 후 Linux 전체 **3,455개 통과**. 소스 684개 스냅샷 기준이다.
- 점수 분석기 최종 **Windows13/Linux13 통과**. 소스 686개 스냅샷의 별도 신규 묶음이다. 이를 Linux 전체 3,468개를 한 번에 실행한 기록으로 바꾸지 않는다.
- 새 시험은 기존 창과의 3,000개 무작위 경계 비교, 동시각·역순·유효기간·주체 격리, 누적 100,005요청/활성 상태 상한, R/S 방식의 바이트·동결 예측 동일성, 라벨 반전, 변조/중단/새 폴더 복구, DB/출력/디스크 예산, 미지원 head/오류의 분모 보존과 CLI 재현을 검증한다.
- 마지막 전체 Ruff 통과. 모든 Linux 시험은 캐시 이미지·network none·비루트·읽기 전용 root와 자원 제한으로 실행했고 OOM false·해당 소유 컨테이너 제거를 확인했다. 새 이미지 pull/빌드, AWS 배포, 유료 API, GitHub push는 수행하지 않았다.

## 남은 우선순위와 원래 목표

1. 웹 정상 오탐의 동일 특징/동일 leaf 충돌과 관측 부족을 분해한다. 시간창·URL/응답·과거 행동 보강은 개발 가설로 시험하고 라벨·원시 ID·소스 이름을 정답 지름길로 넣지 않는다.
2. VPN·감사의 실제 과거 신호/당시 권한 맥락을 보강한다. 성공 로그인·같은 주소·나중에 발생한 경보를 그 시점의 침해 근거로 만들어 넣지 않는다.
3. 원래 여섯 영역의 정상·위협 의미·권한 있는 관측·정답·중복/분할 근거를 갖춘 새 최종 자료를 확보한다. 예약 harrison/wilson 본문은 이번에 읽지 않았다. Fox 보정이나 높은 micro F1으로 이 조건을 대체하지 않는다.
4. 다음 후보를 동결하고 새 독립 평가 및 통합 인수를 진행한다. 원본 `app/`와 `docs/benchmark-results/`는 `9c67889` 대비 변경 0이며 기존 기준선 수치는 유지한다. 조건부 후속 LLM 개선은 아직 시작하지 않았다.

## 재현 명령

출력 폴더는 새 이름을 쓴다. 공개 원시/정답은 이미 확보한 로컬 파일을 사용하며 유료 호출이 없다.

```powershell
.venv\Scripts\python.exe -m scripts.run_native_stream_validation `
  --plan infra/f1-lab/streaming-calibration-protocol.json `
  --expected-plan-sha256 674d426e8caf4f565f5183d59a0070c9749103d392166bf760c261252035926d `
  --output runtime/f1/streaming-calibration-repro-new
```

Fox 점수 진단의 명시적 격자 재현:

```powershell
.venv\Scripts\python.exe -m scripts.diagnose_native_scores `
  --directory runtime/f1/streaming-calibration-v37-20261112/fox `
  --expected-preparation-sha256 d03d22bd2aa708364dd1853ec45af22728e5be5b1451f26dde5e9fe5b2adb28b `
  --model runtime/f1/ait-semantic-fit-heads-russell-20261112/model.json `
  --expected-model-sha256 4ebbcb6bb5fce286e80beeedbc18139d566d00998575487a867f129330344075 `
  --model-kind heads --thresholds .5 .75 .9 .95 .99 `
  --output runtime/f1/heads-score-fox-repro-new
```

원자료: `runtime/f1/streaming-calibration-v37-20261112`, `score-diagnostic-v38-fox-20261112`, `heads-score-diagnostic-v38b-20261112`. 최종 CLI 보완은 입력/점수 알고리즘을 바꾸지 않았으며 명시적 격자를 재현하는 신규 시험을 추가했다.
