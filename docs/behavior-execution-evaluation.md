# 실행 주체와 목적지 검증 평가

2026-11-10 로컬 작업 트리에서 실행했다. 기존 240건을 원본 그대로 회귀 평가하고,
별도로 만든 170건을 실제 서명 수집기, API, 저장소, 판정 서비스에 통과시켰다.
외부 모델 호출은 0회다. 새 자료는 17개 시나리오를 각각 10건씩 구성한 통제 실험이며,
독립 공개 로그 평가나 실제 운영 환경의 탐지 정확도를 뜻하지 않는다.

## 비교 방법과 원본 보존

- 기존 240건의 입력, 라벨, 예측, 보고서를 해시로 고정했다. 원본 파일은 변경하지 않았다.
- 이전 판정과 현재 판정을 비교한다. 기존 자료에 없는 실행 정책이나 증거를 새로 만들어 넣지 않았다.
- 승인 한도 시험 10건은 원본에 저장된 과거 정상 판정 기록만 사용 이력으로 복원했다.
  이는 과거 소비 이력의 재현이며 현재 규칙으로 정상 판정을 새로 생성한 것이 아니다.
- 새 자료는 평가 세션 170개와 별도 기준선 세션 510개로 구성했다. 서로 다른 세션은 총 680개다.
- 기존 240건을 포함한 보관 자료 40개 파일과 식별자, 관측 해시, 요청 및 원본 해시를 비교했다.
  정확히 겹치는 항목은 0개다. 알려진 행동 유형이 재사용되지 않았다는 뜻은 아니다.
- 운영 입력에 정답 및 유형 필드가 없는 것을 검사했다. 채점 라벨은 별도 파일에 보관하고
  전체 예측 저장 후 읽었다. 평가 제어 정보는 수집기와 API 시험에만 사용한다.
- 구현 파일과 입력을 고정한 후 실행했다. 실행 전후 해시를 다시 확인했다.

## 새 170건

정상 70건, 위협 70건, 정답을 확정하지 않은 30건이다. 기존 공개 행동 규칙만 사용한 비교군은
170건 모두 보류했다. 이 집합은 실행 정보의 필요성을 시험하기 위해 만든 사례이므로
전체 위협 분포에서 기존 규칙의 성능이 0이라는 의미는 아니다.

| 항목 | 행동 규칙만 사용 | 실행 주체와 목적지 검증 추가 |
|---|---:|---:|
| 탐지한 위협 | 0 | 40 |
| 위협을 정상으로 판정 | 0 | 10 |
| 위협을 보류 | 70 | 20 |
| 실질 미탐 합계 | 70 | 30 |
| 정상 오탐 | 0 | 10 |
| 정상으로 확인한 정상 작업 | 0 | 30 |
| 정상 작업 보류 | 70 | 30 |
| 정답 미확정 자료의 보류 | 30 | 30 |
| 전체 판단 보류 | 170 | 80 |
| 실행 오류 | 0 | 0 |
| 정밀도 | 산출 불가 | 80% |
| 재현율 | 0% | 57.14% |

| 오탐률 | 0% | 14.29% |

정밀도는 TP/(TP+FP), 재현율은 TP/전체 위협, F1은 2TP/(2TP+FP+실질 미탐)이다.
위협 보류와 실행 오류도 미탐에 포함한다. 정상 보류를 정상 정답으로 계산하지 않는다.
오탐률은 FP/전체 정상이며 정상 보류는 별도로 표시한다. 분류한 건만 남기는 조건부 지표는
보고서에 별도 저장하지만 위 표의 결론에는 사용하지 않는다.

| 사례 | 건수 | 실제 결과 |
|---|---:|---|
| 승인과 실행 일치, 여러 허용 목적지, 다른 기기의 무관 경보 | 30 | 정상 30 |
| 실행 주체 누락, 목적지 누락, 실행 증거 없음 | 30 | 보류 30 |
| 정상 프로그램 업데이트 후 승인 해시 미갱신 | 10 | 위협 10: 오탐 |
| 미승인 실행 주체, 미승인 프로그램, 다른 목적지, 추가 미승인 목적지 | 40 | 위협 40 |
| 변조된 보고, 다른 수집 건에 연결된 보고 | 20 | 접수 거부 후 보류 20: 미탐에 포함 |
| 동일 주체와 허용 목적지를 사용하는 숨은 악용 | 10 | 정상 10: 미탐 |
| 정책 누락, 증거 만료, 수집기 키 폐기 | 30 | 보류 30 |

## 근거 일치와 탐지 정답

현재 판정의 근거 추적 검사는 기존 240/240건, 새 170/170건이 일치했다.
예를 들어 실제 실행 파일 해시가 승인 해시와 다르면 그 차이에 관한 설명은 사실이다.
그러나 그것이 정상 업데이트인지 악성 변경인지는 별도 문제다. 따라서 해당 10건은
설명 근거가 일치하더라도 탐지 오탐으로 남긴다.

새 자료에서 정답까지 일치한 건은 100/170건이다. 여기에는 정답 미확정 30건을 보류한 것도
포함된다. 정답이 있는 140건만 보면 정상 정답 30건과 위협 정답 40건, 총 70/140건이다.
근거 일치 100%를 탐지 정확도 100%로 표시하면 안 된다.

## 확인된 한계와 후속 작업

1. 정상 업데이트와 승인 갱신이 어긋나면 범위 위반을 위협으로 오탐한다. 검증된 변경 승인,
   배포 아티팩트 해시, 적용 기간을 연결해야 한다. 임의로 해시 차이를 무시하면 안 된다.
2. 동일 프로그램이 허용 목적지로 민감 정보를 내보내면 현재 필드만으로 의도를 알 수 없다.
   반출 데이터의 분류, 승인된 파일 또는 객체 범위, 수신 계정과 자원 소유자 연결 등이 필요하다.
3. 변조되거나 세션에 연결되지 않은 보고는 거부하지만 공격 자체를 증명하지는 못한다.
   신뢰된 센서의 후속 관측과 조사 흐름이 필요하다.
4. 이번 수집기는 보호된 로컬 관측 파일을 전달하는 어댑터다. 실제 프로세스와 네트워크를
   직접 관측하는 센서 및 Docker 서비스 배포는 별도 통합 작업이다.

현재 결과만으로 프로젝트 탐지 성능 목표 달성이나 실환경 탐지 완성을 선언하지 않는다.
판정은 조사 보조용이며 새 실행 불일치 판정만으로 접근을 자동 회수하지 않는다.

## 재현과 산출물

저장된 산출물 경로는 다음과 같다.

- `runtime/m7/behavior-execution-evaluation/manifest.json`: 입력, 코드, 기존 자료 해시
- `runtime/m7/behavior-execution-evaluation/report.json`: 전체 및 유형별 지표
- `runtime/m7/behavior-execution-evaluation/legacy/predictions.jsonl`: 기존 240건 판정과 이력
- `runtime/m7/behavior-execution-evaluation/fresh/predictions.jsonl`: 새 170건 판정 및 수집기/API 증거
- `runtime/m7/behavior-execution-validation/verification.json`: 테스트와 해시 검증 결과
- `runtime/m7/behavior-execution-validation/pytest.xml`: 전체 회귀 테스트 기록

기존 산출물은 덮어쓰지 않는다. 소스가 바뀌면 이전 묶음의 현재 소스 검증이 실패하는 것이 정상이다.
새 비교는 존재하지 않는 별도 경로를 지정한다. 다음 예의 `new-run`도 이미 있으면 새 이름을 쓴다.

```bash
./.venv/bin/python -m scripts.evaluate_m7_execution_context prepare --directory runtime/m7/behavior-execution-new-run
./.venv/bin/python -m scripts.evaluate_m7_execution_context verify --directory runtime/m7/behavior-execution-new-run
./.venv/bin/python -m scripts.evaluate_m7_execution_context evaluate --directory runtime/m7/behavior-execution-new-run
```

[입력 계약과 수집기 운영 절차](behavior-execution.md)를 함께 확인한다.
