# 실행 중단·게시 누락의 독립 관측과 경보

## 목적과 경계

기존 sealed outbox 관측은 outbox 파일이 생긴 뒤의 누락을 검사한다. v86의 실행 의도 저널은 실제 명령 실행 후 seal 전, 또는 seal을 영속화한 뒤 outbox 작성 전에 부모 프로세스가 사라진 경우도 기록한다. 이 저널과 실제 hot/cold 게시 상태를 함께 검사해야 `outbox=0`을 복구 완료로 오인하지 않는다.

새 관측기는 승인·재실행·grant 재발급·환불 API를 갖지 않는다. 제안된 intent는 인증 또는 실행 증명이 아니며, seal이 없는 건은 계속 **indeterminate**다. 완료된 원본도 현재 서비스·호출자 공개 신뢰 핀, 서명, 요청·세션·앱 정책 결합을 검증한 뒤 게시된 정확한 바이트와 비교한다. 이 검사는 실제 사람의 조직 SSO를 인증하는 기능이 아니다.

## 구현

- `scripts/f1_lab/exec_recovery_inventory.py`: 소유자 전용 intent 디렉터리와 live 저장소를 협력 잠금 아래 읽는다. intent별 최대 두 파일, 최대 10,000건/1GiB/15초를 제한한다. 원본 worker 디렉터리·앱/브로커 DB·개인키·토큰은 읽지 않는다. cold DB는 기존 검증 로더로 순회한다.
- `scripts/exec_recovery_status.py`: `zt-exec-recovery-status-1` 공개 집계만 원자적으로 쓴다. 요청 ID, 사용자, 경로, 명령, 토큰은 공개 보고서에 포함하지 않는다. 손상·권한·범위·현재 신뢰 검증 실패 시 unavailable, 카운터 없음이다.
- `scripts/f1_lab/exec_recovery_status.py`: 보고서 TTL 60초. 미래 시각·만료·잘못된 스키마는 실패 처리하고 캐시 값을 재사용하지 않는다. `intents=sealed+indeterminate`, `sealed=published+unpublished`를 강제한다. 불확실 건 또는 미게시 원본이 하나라도 있으면 pending이다.
- `scripts/signal_metrics_exporter.py`: `--exec-recovery-profile`을 명시한 경우에만 집계를 연다. 기존 인증된 metrics 수집에 결합하며 기본값에서는 새 경보가 활성화되지 않는다.
- `infra/systemd/secops-exec-recovery-status@.service`와 timer: 배포 검토용 템플릿. 자동 설치·활성화하지 않는다. 기존 협력 잠금 두 파일과 공개 캐시만 쓰기 허용한다. 실제 수집 서비스 계정/소유권/ACL 전환은 운영 인수 항목이다.
- `infra/observability/alerts.yaml`: unavailable, indeterminate 기한 초과, 원본 게시 기한 초과, 보관량 압박의 네 경보. 첫 세 경보는 critical, 용량은 warning이다. 미관측 때문에 개별 경보가 사라지는 것은 복구 성공을 뜻하지 않는다. unavailable 경보와 함께 해석한다.

## 로컬 검증 시나리오

실제 systemd 실행 검증의 기존 명령 실행 6회와 실제 부모 프로세스 중단 2회를 재사용한다. 관측용 명령을 추가 실행하지 않는다. 기본 보존 시험에서 live cold DB를 유실시키고 별도의 격리 복원만 했으므로, 저널에 원본이 남은 과거 미게시 1건도 의도적으로 유지하여 검사한다.

| 실제 단계 | intent | seal 있음 | 확인 불가 | 게시됨 | 미게시 | 상태 |
|---|---:|---:|---:|---:|---:|---|
| 첫 실행의 seal 전 중단 | 4 | 3 | 1 | 2 | 1 | pending |
| 둘째 실행의 seal 후 outbox 전 중단 | 5 | 4 | 1 | 2 | 2 | pending |
| 둘째 실행만 원본 게시 재개 | 5 | 4 | 1 | 3 | 1 | pending |
| 별도 명시적 컨트롤러가 과거 원본 게시 재개 | 5 | 4 | 1 | 4 | 0 | pending |
| 실제 intent 서명 손상 | — | — | — | — | — | unavailable |
| 정확한 원본 바이트 복원 | 5 | 4 | 1 | 4 | 0 | pending |

과거 원본을 재게시해도 latest는 최신 실행을 유지하고 앱/브로커 DB 바이트는 바뀌지 않아야 한다. 확인 불가 1건의 원래 발생 시각은 모든 정상 관측 단계에서 그대로여야 한다. 서명 복원이나 후속 성공으로 그 건을 승격하지 않는다.

별도 실제 systemd `nobody` 프로세스는 서명된 데이터 사본과 공개 신뢰 파일만 받는다. capability 0/NoNewPrivileges와 증거 파일의 실제 쓰기 거절을 관측한다. 이는 원래 live 수집 소유권을 이미 전환했다는 뜻이 아니다.

실제 Prometheus/Alertmanager 검증은 위 원래 시각의 공개 보고서를 입력으로 사용한다. 미게시 2→1 단계에서는 같은 경보가 계속되고, 실제 과거 원본까지 복구하여 0이 된 뒤에만 게시 경보를 해제해야 한다. 확인 불가 경보는 정상 관측 중 지속한다. 실제 60초 경과 후 보고서가 만료되면 집계를 없애고 unavailable을 알린다. 로컬 파일 브리지 검증이며 물리 호스트 이중화나 운영 다중 호스트 mTLS 인수를 대신하지 않는다.

## 결과

진행 중인 v88 검증 결과는 완료 후 고정된 소스 해시와 함께 추가한다. 초안 집중 448개와 수정 후 실제 systemd 53조건이 통과했다. 최초 실제 실행은 Windows 마운트 결과 디렉터리가 Linux의 비쓰기 소유권 조건을 충족하지 않아 보고서 게시를 거부했다. 검사 조건을 낮추지 않고 native 전용 디렉터리에 먼저 발행한 뒤 공개 사본만 내보내도록 수정했다. 실패 실행과 수정 후 소스/결과를 각각 보존한다.

기존 v85/v87 탐지 성능은 별도 모집단이며, 운영 복구 검사 수를 정밀도·재현율·F1 표본에 합산하지 않는다. 8시간/12시간 연속 관측은 사용자 요청대로 유예한다.

## 남은 항목

intent·worker 원본·앱·브로커의 일관된 암호화 묶음 백업/격리 복원, 실제 조직 SSO와 기기 신뢰 설정, 실제 호스트/외부 저장소 장애 인수는 별도다. 격리 복원으로 확인 불가 실행의 누락된 승인 증거를 만들어내거나 운영 앱을 자동 활성화하면 안 된다.
