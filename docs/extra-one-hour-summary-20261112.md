# extra: 11월12일 한 시간 작업 정리

작업 창:16:11~17:11 KST. 전체 탐지 목표는 **미완료**이며, 지정 시각에 작업을 정리한다.
이번 개선은 `scripts/f1_lab`의 분리된 후보다. 앱 통합/최종 채택은 독립 평가 이후 단계다.

## 구현·개발 비교

HTTP 의미 특징과 명시 계정의 이전 활동을 추가하고 두 트리 후보를 고정했다.
같은 개발 자료295,976행에서 단일 후보의 결과는 다음과 같다.

| 항목 | 기존 단일 후보 | 새 단일 후보 |
|---|---:|---:|
| 정밀도 | 99.727% | 99.966% |
| 재현율 | 97.912% | 97.958% |
| F1 | 98.811% | 98.952% |
| 오탐률 | 0.0511% | 0.00644% |
| 웹 접근 오탐 | 112건 | 1건 |
| 인증 탐지 | 2/12건 | 9/12건 |

이 자료는 이미 관찰한 개발 자료다. 위 수치를 원래 여섯 영역의 새 독립 목표 달성으로 쓰지 않는다.
VPN0/28·공유 감사0/2 등 문제가 남는다. 관측 종류별 후보는 오탐이 많아 미채택했다.
[구현/시험 설명](extra-http-auth-semantics.md), [성분 비교](extra-semantic-component-results.md)를 따른다.

새 필드를 끄면 이전 트리/혼동행렬이 정확히 재현됐다. HTTP 성분은 오탐111건 감소·탐지15건 증가,
계정 과거 이력은 탐지7건 증가에 기여했고 정적 인증·감사 필드만으로는 이번 비교가 개선되지 않았다.
원본 앱·규칙·정답을 바꾸어 점수를 올리지 않았다.

## 검증과 남은 문제

관련 Windows287개·격리 Linux287개 통과, 실패/오류/건너뜀0을 확인했다.
최초 Windows281통과/6실패와 데이터 준비의 저장 공간 오류도 보존했다. 보호 조건을 낮추지 않고 회복 후 재검증했다.
이후 문서/자료 조사 단계에서는 같은 시험을 새로 실행한 것으로 세지 않았다.

미관찰 보정 ZIP688MB를 수집하고 원시/정답668,418행을 대조했으나,
디스크 부족과 별도 확인한412,904 HTTP 요청의 메모리 준비 상한 때문에 보정 지표는 산출하지 못했다.
[정확한 보정 상태와 다음 스트리밍 작업](extra-fox-calibration-status.md)에 실패/복구·전체 범위 유지 조건을 적었다.

[OpTC 스키마·정오표](extra-optc-observation-review.md)도 고정 버전으로 검토했다.
명시 프로세스/흐름 연결의 후보이며 원시 수집·학습·전체 목표 충족 근거는 아니다.

## 보존·비용·다음 순서

원시 로그·정답·실패 기록·동결 모델은 보존한다. 중복 prefix와 재생성 가능한 중간 캐시의 정리는
기대 SHA·기존 원본·복원 방법을 남겼다. 사용자 ZIP은 변경하지 않았다.
소유 F1 컨테이너0, AWS·유료 API·GitHub 업로드0이다. 변경은 extra의 로컬 커밋으로 남겼다.

다음은 스트리밍 입력 준비와 기존 결과의 동일성 검증, 전체 보정 평가, 남은 영역의 관측/정답 보강,
후보 동결 후 별도 최종 평가 순서다. LLM 개선은 현재 목표 달성 뒤의 후속 요청으로 유지한다.
