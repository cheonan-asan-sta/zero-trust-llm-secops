## 현재 입력 공백에 도움이 될 가능성

OpTC는 Windows 호스트 관측과 네트워크 자료를 제공하며 FLOW-START와 네트워크 흐름을 잇는 식별자도 설명한다.
공격 기간에도 정상 활동이 함께 있으므로 evaluation 폴더 전체를 공격으로 라벨링하면 안 된다.
원시 데이터가 매우 커서 전체를 로컬로 받는 대신 파일 목록·정답 대응·제한 추출 계약부터 확인해야 한다.
[발행자 README](https://github.com/FiveDirections/OpTC-data/blob/5b108604f11f767aa11ea79ff827595f3fad15fd/README.md)

| 발행 문서의 관측 | 다음 검증에 사용할 가능성 | 지켜야 할 경계 |
|---|---|---|
| actorID/objectID·호스트·process 정보 | 임의의 IP/가까운 시각 대신 명시 프로세스 연결 | 주체의 신뢰나 실제 사용 권한으로 확대하지 않음 |
| principal | 로그상 사용자·대리 실행 맥락 | 계정 활성·소유자 정책·MFA 승인으로 추정하지 않음 |
| 타임스탬프·행위/대상 종류 | 과거 행위/누적 맥락의 인과적 처리 | 문서 표의 timestamp_ms와 예제 timestamp 차이부터 실제 자료에서 확인 |

스키마는 일부 PID/TID/PPID의 -1, PID0과 zero UUID를 정보 부재로 설명한다.
따라서 이를 모든 미상 사건의 공통 사용자/프로세스 키로 묶지 않는다. 이 관측 스키마만으로
기기 관리·건강, 자원 소유자의 권한 정책, 실제 업무 승인이나 여섯 영역의 정답을 확보한 것은 아니다.
[eCAR 스키마](https://github.com/FiveDirections/OpTC-data/blob/5b108604f11f767aa11ea79ff827595f3fad15fd/ecar.md)

## 구현 전에 처리할 정오표

발행자는 중복 process 객체, 모듈 로드의 누락된 실행 해시, 일부 FLOW OPEN의 범위 밖 acuity 값,
표준 드라이브와 장치 경로 표현 차이를 명시한다. 중복을 마지막 값으로 덮어쓰거나 acuity0을 정상으로,
누락된 해시를 일치한 파일로 보완하지 않는다. 경로 합치기도 실제 호스트의 매핑 근거를 확인해야 한다.
[정오표](https://github.com/FiveDirections/OpTC-data/blob/5b108604f11f767aa11ea79ff827595f3fad15fd/errata.md)

## 다음 수집/평가의 시작 조건

1. 공개 파일 목록·크기·배포 지문·사용 조건을 고정하고, 공격/정상 지지와 필요한 연결 정보를 포함하는 제한 범위를 선정한다.
2. 원시 관측과 정답을 분리한다. red-team 설명이 개별 행의 악성을 뜻하는지 검토하고 미확정 행을 정상으로 채우지 않는다.
3. 미상/충돌 연결과 시간 단위·수집 누락을 먼저 감사한다. 크기가 작다는 이유만으로 결측이 있는 short 자료를 최종 평가로 선택하지 않는다.
4. 주체·프로세스·호스트·캠페인·중복과 개발 예제 노출을 점검해 개발/보정/최종 용도를 정한다. 의미 있는 반복 특징 자체를 무조건 누수로 판정하지 않는다.
5. 이 출처가 지원하는 영역과 지원하지 않는 영역을 따로 보고한다. 원래 여섯 영역의 부족한 정답을 임의로 생성해 전체95% 목표로 치환하지 않는다.

현재 판정은 **명시적인 프로세스/흐름 연결의 후속 연구 후보**다. 도입·전체 범위 적합성·독립 성능은 미판정이다.
추가 원시 수집·제품 통합·AWS 배포·유료 API·GitHub 업로드는 이번 조사에서 수행하지 않았다.
